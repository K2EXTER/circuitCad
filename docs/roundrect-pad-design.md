# 角を丸めたパッド (候補 C5) の設計メモ

`docs/candidates.md` の C5 から移した (2026-11-21)。まだ作っていない。

## 案

角を丸めたパッド(`PadShape::RoundRect`、半径は短い辺に対する割合。KiCad の既定は 25%)。DRC の距離・ガーバー(マクロか領域)・ベタの逃げ・3D・部品フォーム・KiCad の取り込み(今は `part-lib/src/kicad.rs` で `roundrect` を四角にしている)・同梱部品の既定。**仕上げ(`Board.finish`)ではなくパッドの形のデータとして持つ**: 角丸の効き目(すき間が広がる)を使うのは配線と DRC なので、表示・ガーバーのときだけ丸めると、配線と DRC は四角のまま計算して効き目が出ない。仕上げは配線から銅を足す処理で、部品ごとに決まって銅を削る角丸とは性格が違う。仕上げの側は、涙型(`pad_fillet`)と切り戻し(`pad_clip`)を角丸の形に合わせるだけ。手間を減らすには「表面実装の四角いパッドを 25% の角丸にする」ボタン(押した時点でデータを書き換える)と、新しく作る部品の既定を角丸にする。**重さ**: DRC は形のまま式で距離を出す(`drc/geo.rs` の `shape_geo`。角丸=「r だけ縮めた四角までの距離 − r」で点は増えない)、3D は銅を絵として貼るので三角は増えない(光る表示 `view3d/glow.rs` だけ)。ベタの逃げ(`zonefill.rs` の `pad_path`)は四角の 4 点が約 30 点になる(`circle_steps` に合わせる。リード部品の丸いパッドは約 41 点)。エディタの絵は、マルチサンプリングのとき四角が三角 2 つ(`ribbon.rs` の `add_rect`)で、egui の `rect_filled` に角の半径を渡すと描けるが、長円と同じく、まとめたメッシュがパッドごとに切れて重くなる → `add_disc` と同じように四隅を扇にした `add_rounded_rect` を `ribbon.rs` に作り、1つのメッシュに入れ続ける(三角 10〜20。長円もこれで描けば今の切れ目も無くなる)。ついでに、四角いパッドの逃げが今は角のとがった四角で、角ではすき間が √2 倍に広がっている。角を丸めた形にそろえる

## 理由

細かいピッチ(0.4 mm の QFN、0201 以下)や 45° に置いた部品では、四角い角どうしが一番近くなって、発注先の最小間隔を守れないことがある。メタルマスクからのはんだの抜けもよくなる。IPC-7351 の新しい版も角丸を勧めている。0805・リード部品の手はんだでは差は小さい
