## 実マウスでの確認 (同じ日の2回目)

実際のマウスで、空の画面から「部品を置く → 線を引く → DC解析 → 値を変える → 基板に取り込む → 並べる → 自動配線 → DRC → 発注の準備 → プレビュー」と、レッスン1の最初の2手順を通した(リリース版、1920×1080、設定は空の一時フォルダ)。通ったもの: 部品の配置、配線(ピンからピンへ、右クリックで確定)、DC解析、値の書き換えと再計算、取り込み、自動配置、自動配線、DRC、発注の準備のチェック、レッスンの自動チェック。

見つかって、その場で直したもの:

| 見つかったこと | 直し方 |
|---|---|
| 「未配線を全部つなぐ」のあと、ツールが「配線」に切り替わり、左パネルが伸びて、手順の欄 (DRC・3D・発注の準備) が画面の外に出る(案内文は「DRC を実行」を押すよう言う)。原因: 自動配線は先に回路の電流を取り、その結果の欄 (配線の太さ) を開くため | 自動配線のために電流を取ったときは、その欄を開かない(`main.rs`、`width.rs close_width_panel`)。欄は「③ 確認する」の「電流と電圧降下」(2026-11 に「高度な配線」から移した)に常にある |
| 「発注の準備」の出来上がりプレビューが、細い緑の帯(約35px)にしか見えない。原因: 窓の中のスクロール枠が、既定の最小の高さ (64px) に縮む | 最小の高さを 380 にした(`order.rs`) |
| 起動直後は「抵抗を置く」状態で、レッスンやサンプルの回路をクリックすると、抵抗が1個増える(回路の上に抵抗の影が出る) | レッスン・サンプル・開いたファイルは、選択ツールで始める(`lessons/mod.rs`、`file.rs adopt`) |

あとで直したもの(同じ日): 左パネルの幅が、部品を選ぶ・タブを切り替えるたびに変わって回路が約20px横にずれた → 初期の幅を400pxにして、どの状態でも回路の左端が同じ位置になった(`main.rs` の `PANEL_WIDTH`)。取り込みで部品が追加されたとき、表示を全体に合わせ、右上の「物の表示とロック」をよけて、基板と部品が見えるようにした(`file.rs`、`view.rs fit_view`)。

レッスンの窓が回路の右端にかぶる → レッスンの回路は、窓の左に合わせて表示する(`symbols.rs fit_view`)。ステータスの行で、状態の文が長いと豆知識が消える → 状態の文は行の3分の2まで、豆知識を残し、全文はポインタを合わせると読める(`main.rs`)。

見つかって、直していないもの(F6、`docs/candidates.md`): 基板のパッド名が、ネット名 (`N$1`・`GND`) で出る。

やり方の注意(次にやる人へ): 道具は `tools/screenrec.ps1`(実際のマウスを使う。動かしている間は、マウスとキーボードに触らない。デバッグ版は遅くてクリックが抜けるので、リリース版を使う)。複数の呼び出しで1つのアプリを操作するときは、画面全体の座標 (`FullShot` と `ClickAbs`) を使う。ウィンドウの基準位置 (`Client`) が、呼び出しごとにずれた。PowerShell では、関数名 `ac` が `Add-Content` の別名と衝突して、マウスが動かないまま、数字の名前のファイルができる(`AC`・`AR` は使わない)。

## 3回目 (2026-10-29。新しい画面を、先入観のない別のエージェントに見てもらった)

撮った画面は 10 枚(起動・サンプル・DC 解析・設計の要件・レッスン・学習パス・操作ガイド・基板・発注の準備・部品作成)。報告は、画面で確かめてから採用した。

直したもの:

| 報告 | 直し方 |
|---|---|
| 学習パスの「完了 5 / いま学べる 24 (全体 24)」が、地図の凡例「橙の枠 = いま学べる」と別の意味で、数が合わない。灰色が「準備中」とだけ書いてあるのに、「先に済ませるレッスンがある」灰色も混ざっている | 「完了 5 / 24 レッスン (準備中 N 件)」に。凡例は「灰色の枠 = 先に済ませるレッスンがある」と「暗い灰色 = 準備中」の2つに(`learn.rs`) |
| 降圧コンバータの DC 解析で VOUT が約 0 V。正しいのか分からない | 時間で変わる電源(パルス・正弦)がある回路の DC には、「DC 解析は時間 0 の状態で計算する。落ち着いた出力は過渡解析で」の警告を出す(`sim-core/dc/mod.rs` の `floating_warnings`。GUI と CLI の `warnings` に出る。部品の中の電源は名前を出さず数えるだけ) |

確かめて、採らなかったもの: 「レッスン1が空」(撮影の引数が間違いだった。`--lesson` は番号ではなく ID を取る)、「枠のラベルが切れる」(窓がかぶっていただけ)、「ピア」と「ビア」の表記ゆれ(コードは「ビア」。小さい文字の見え方)、「起動の案内が弱い」(撮影の環境がウェルカムカードを閉じた状態だった)。

直していないもの: サンプルを開いたとき、長い値の文字(`PULSE(…)`)が画面の左端で切れる(`fit_view` は文字の幅を数えていない。画面を動かせば読める)。窓の小さい文字(操作ガイドの右列、発注の準備の説明)が詰まって読みにくい、という指摘もあった(未確認)。

## 4回目 (2026-11-01。新しい機能を、実際のマウスで通した)

リリース版・1920×1080・実マウス(`tools/screenrec.ps1`)で、`buck_converter` と `logic_blinker` を使って通した。通ったもの: 設計の要件の表(開く → 「ネットの役割を足す」で行が増え、「理由が空の行が 1 件あります」の案内と、理由欄の「なぜ?(理由を一言)」が出る → 削除 → 閉じる)、NC(線を1本消す → ERC が「U1 ピン4 が未接続です」を出し、黄色い丸で場所を示す → 指摘を押すと、画面がそのピンへ動いて説明が出る → 「使わないピン (NC) にする」で × が付き、ERC が「問題は見つかりませんでした」)、解析タブの「モデルの前提」(部品ごとの注意書き)、基板への取り込みと自動配置、「ゲートを入れ替えて交差を減らす」→「入れ替えを回路図に反映」(回路図の U1 のピンの付き替えが、ステータスの「配線の端 7 本を動かしました」と一致した)。

直したもの:

| 見つかったこと | 直し方 |
|---|---|
| 左パネルの「設計の要件の枠」は表示の切り替えで、文字を押しても表が開かない。表の入口は「学ぶ」メニューだけで、初学者には見つけにくい | 横に「表を開く…」ボタンを足した(`schematic/panel.rs`) |
| ERC の指摘の説明(原因と直し方)が、小さい文字(9px 前後)で読みにくい | ふつうの大きさにした(`panel.rs`) |
| 「モデルの前提」の部品ごとの注意書きが、小さい灰色の文字で、2倍に拡大しないと読めない | ふつうの大きさにした(`schematic/coverage.rs`) |
