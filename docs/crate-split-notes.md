# `app` のクレートを分ける (候補 G1、保留) のメモ

`docs/candidates.md` の G1 から移した (2026-11-21)。2026-11-18 に測って保留。

## 案と測った結果

**`app` のクレートを分ける**: `app` は約 8.4 万行の 1 つのクレート(`schematic/` 約 3.1 万行・`board_editor/` 約 2.0 万行・`part_form/` 約 1.5 万行・直下のファイル約 1.0 万行)で、どこを 1 行変えても全体をコンパイルし直す。共通の土台(`theme`・`widgets`・`plot`・`icons`・`prefs` など)を下のクレートにし、その上に回路図・基板(3D を含む)・部品作成フォームを別のクレートとして並べ、`app` は窓とメニューとつなぎ(`link.rs`・`main.rs`)だけにする。まず `cargo build --timings` で今の時間の内訳を測り、分けた後と比べる。注意: エディタは 1 つの型を複数ファイルの `impl` に分けて親の非公開フィールドを見ているので、クレートの境目では見せる範囲(`pub(crate)` → `pub`)の整理が要る。回路図と基板が互いを呼ぶ所(連動・回路図に反映)は、つなぎの側に寄せるか、小さな型を土台に置く。一度に分けず、つながりの少ない部品作成フォームから 1 つずつ。

**2026-11-18 に測って保留**: 普段の変更は incremental が効いて速い(関数を 1 つ足す 5〜6 秒・テストのビルド 6 秒・`theme::ROW_GAP` や `SchEditor` の型を変える 13〜14 秒)。効くのは一から作るとき(`CARGO_INCREMENTAL=0`、worktree の最初のビルドも自分たちのクレートはこれ)だけで、全体 85 秒のうち app が 44 秒(sch-core → part-lib を待って 42 秒目に始まる)、app のテストのビルドは 61 秒。部品作成フォームだけ分けても数秒、回路図と基板まで分けて 20 秒前後の見込み。切り出す時の調べ: `part_form/` が外で使うのは `theme`・`widgets`・`icons`・`prefs` と `schematic::glyphs` の `symbol_lines`・`symbol_pin_labels`・`glyph_fits`(`symbols.rs` の描かない前半 `Sh`・`symbol` に頼る)と `board_editor::capsule` だけ。土台を `crate::theme` の名前で引き直せば app の残りは書き換えずに済む。`include_str!("../../../part-lib/…")` は 1 段浅くなる

## 理由

変えたクレートだけがコンパイルし直しになり、別のクレートは並列にビルドできる。子のセッションを並べたときの待ち時間(2026-11-18、3 本の取り込みの全体のテストは大半がコンパイル)も減る
