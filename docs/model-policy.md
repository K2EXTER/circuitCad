# 部品のモデルの方針 (同梱するモデルの作り方・表示・誤差)

2026-11-11 作成。同梱の部品(`crates/part-lib/examples/`)にシミュレーションのモデルを入れるときの決まり。

シミュレータそのものの精度(ngspice と同じ答えが出るか)は `docs/accuracy.md`。このページは、**部品のモデルが実物の部品とどれだけ合うか**の話。

> 法律の専門家の判断ではない。配る範囲が広がるときは、各社の最新の利用条件を読み直し、必要なら専門家に聞く。

## 1. モデルの 3 つの種類

| 種類 | 何か | 同梱 |
|---|---|---|
| **メーカーの公式モデル** | メーカーが配る `.subckt` / `.model`。利用者が自分で手に入れたファイルを、その場で読む(`part import`、メーカーのモデルの zip の索引 `part-lib/vendorzip.rs`) | **しない**。再配布を禁じるメーカーが多い。ファイルの場所だけ覚える |
| **等価モデル** | circuitCad が、公開された情報(データシート・自分の測定)から独自に作ったモデル | する |
| **一般のモデル** | 理想の素子、または値と寄生成分を並べたもの(`passive.rs` のチップ部品、`docs/passive-model.md`) | する |

暗号化されたモデル(LTspice の `<Binary File>` など)は読まない(`part import` が断る)。

## 2. 等価モデルの作り方

### 使ってよい情報

- **データシートの数字と図**(電気的特性の表、代表特性のグラフ、ブロック図)。出典として、型番・版(Rev.)・表や図の番号を残す。
- **自分で測った値**(評価基板 `eval-board/`、自作の測定器 `bench/`)。測り方と日付を残す。
- 教科書・論文にある、一般的な回路の作り方(オペアンプのマクロモデルの形など)。

### 使わないもの

- **暗号化されたモデルの中身**(復号しない)。
- **メーカーのモデルの出力に合わせ込むこと**。とくに暗号化されたモデルは「中を見せない」ためのもので、外から出力を細かく測って同じ動きを作るのは、リバースエンジニアリングと見られるおそれがある。
- **再配布できないモデルの文や数字を写すこと**(式の形・パラメータの値を移して作り直すのも同じ)。メーカーの利用条件が明示的に許す場合だけ、その条件の範囲で。
- 店の API で取ったデータ(`docs/shop-api-design.md`。配れない)。

### LTspice の使用許諾で効く所

ADI の LTspice の使用許諾(`20191031-LTS-CTSLA`、2019-10 版。2026-11-11 に ltwiki.org の写しで読んだ。最新版かは未確認):

- 対象は「この許諾に付いてくるソフトと関連の文書」。LTspice に付いてくるモデルも入ると読める。
- 第 1 条: 社内で使ってよい目的は「ADI 製品の評価」と「一般の回路シミュレーション」。
- 第 4 条: 改変・**リバースエンジニアリング**・逆コンパイル・**派生物の作成**を禁止。
- 第 5 条: **LTspice で行ったベンチマーク・比較試験の結果を、ADI の書面の同意なしに第三者へ公開・提供しない**。ADI の商標・商号を同意なしに使わない。
- Linear Technology の時代の古いヘルプにも「ソフトや LTC 製品のモデルをリバースエンジニアリングしない」とある。

だから:

- **合わせ込みに LTspice を使わない。** 「LTspice で見てずれていたから直す」を繰り返さない。
- **LTspice で比べた結果を、文書・記事・テストの期待値・コミットに入れない。** 「LTspice と一致」を信頼の根拠として掲げない。
- データシートだけから作ったモデルが、結果として公式モデルと似た動きになるのは問題ない(独自に作ったものは、似ていても侵害にならない。許諾は LTspice を使った行為を縛るもので、使っていなければ関係しない)。それを説明できるように、**作った過程を残す**(3 節)。

## 3. 作った過程の記録

等価モデルごとに、次を残す(部品の JSON の欄と、長いものは `docs/models/<部品名>.md`):

- 出典: データシートの型番・版・表と図の番号、測定なら日付と測り方。
- 各パラメータを、どの数字からどう決めたか(例: 「GBW 2.7 MHz(表 7.5)から、主極を 0.27 Hz、利得 140 dB に置いた」)。
- 再現していないこと(部品の JSON の `sim.limits`。ライブラリと部品の選択で表示される。`docs/part-format.md`)。

git の履歴とこの記録が、「データシートから作った」ことの証拠になる。

## 4. 画面と部品の説明での表示

部品ごとに、次の 3 つを出す。

1. **何から作ったか**: 「データシート(Rev. x)の表 n と図 m から作った**等価モデル**です。メーカーのモデルではありません」
2. **再現しているもの**: 利得、GBW、スルーレート、オフセット、雑音の曲線 …
3. **再現していないもの**(`sim.limits`): チョッパのリップル、過負荷からの戻り、温度の依存 …

最終の確認の案内は、特定の道具の名前ではなく「メーカーの公式モデル」で書く。部品ごとに正しい道具が違う(TI のモデルは PSpice や TINA、ADI のモデルは LTspice …)。まず circuitCad の中の道を示す。

> この部品のモデルは、データシートの値から作った**等価モデル**です(メーカーのモデルではありません)。再現しているもの: …。再現していないもの: …。最終の確認は、メーカーの公式モデルで行ってください(公開されていれば「部品の取り込み」で読み込めます。暗号化されたものは、メーカーが用意するシミュレータで)。

## 5. 誤差の表

等価モデルには、**何と比べた誤差か**を書いた表を付ける。

### 比べる相手

| 相手 | 公開 | 使い方 |
|---|---|---|
| **データシートの値・図** | できる | 主な仕様のすべて。どのモデルにも付ける |
| **自分で測った値**(`eval-board/`・`bench/`) | できる | 代表的な部品だけ。いちばん説得力がある |
| メーカーの公式モデル | LTspice で動かした結果は**公開しない**(2 節の第 5 条)。暗号化されていないモデルを circuitCad や ngspice で動かして比べるのは、そのモデルの利用条件を読んでから | 開発者の手元の確認だけ。期待値にしない |

### 表の形

| 項目 | データシート(条件・表や図の番号) | モデル | 差 | 部品のばらつき(typ → max) | メモ |
|---|---|---|---|---|---|
| GBW | 2.7 MHz typ(表 x) | 2.6 MHz | −4% | (min・max が無ければ「—」) | |
| 入力換算雑音 1 kHz | 5.8 nV/√Hz(図 n) | 6.1 nV/√Hz | +5% | | |
| オフセット | 2.5 µV typ / 5 µV max | 0 | — | 2.5 → 5 µV | モデルは理想の値。ばらつきはモンテカルロで |

(数字は書き方の例。実在の部品の値ではない)

- **表はテストから作る。** 各項目を測るテスト(GBW は AC 解析で 0 dB の周波数、スルーレートは過渡で傾き、雑音は雑音解析 …)を書き、データシートの値との差が決めた幅を超えたら落とす。表はテストの結果から作るので、モデルを直しても表が古くならない。既にある `spec`(仕様の判定)や測る道具の上に作る。
- **部品のばらつきを並べる。** typ と max の差は、モデルの誤差より大きいことが多い。「モデルの誤差は数%、部品のばらつきはそれ以上」と並べると、どこまで気にすればよいかが分かる。
- **確かめていない項目は、確かめていないと書く**(「過負荷からの戻り: 未確認」)。空欄にしない。
- 合格の幅の目安(項目ごとに決め直してよい): 直流の値(オフセット・電流・出力の振れ幅)は データシートの typ から ±10%、周波数の特性(GBW・位相余裕)は ±10%、スルーレートと雑音は ±20%。図から読んだ値は読み取りの誤差があるので、そう書く。

## 6. やること(順に)

1. 部品の JSON に「モデルの出どころ」の欄を足す(公式 / 等価 / 一般、出典)。部品の一覧・部品の選択・ホバーに 4 節の 3 行を出す。`docs/part-format.md` に書く。
2. 同梱の部品のモデルの出どころを洗い出す(どれが等価モデルで、何から作ったか分からないものはどれか)。
3. 誤差の表のテストの仕組み(5 節)を作り、最初は DMM で使う部品(ADA4522-2、ADR4525 など)から。実測とも比べる(`bench/`)。
