# シミュレーションの精度 (どこまで確かめたか)

circuitCad のシミュレータは自前のエンジンです (`crates/sim-core`)。「正しいか」を、オープンソースの [ngspice](https://ngspice.sourceforge.io/) と同じ回路を解いて比べることで確かめています。このページは、**何を・どの基準で・どれだけ比べて、何が合わないか**を、数字で書いたものです。

> **先に読んでください。** ここで言えるのは「ngspice と同じ答えが出る」までです。**実物の回路と合うことは、まだ確かめていません。** ngspice が間違っている所は、両方が間違います。基板の発注の実績もありません。安全に関わる用途の根拠にしないでください。

数字は 2026-10-19 時点です。コードを変えると変わるので、最新の値は下の「自分で確かめる」の手順で出してください。

## 1. 同梱サンプルとの比較 (毎回の変更で自動チェック)

| 比べるもの | 件数 | 合格の基準 | 確かめる場所 |
|---|---|---|---|
| DC 動作点 (各節点の電圧と電源の電流) | サンプル 41 本のうち 38 本 | 電圧: 絶対 10µV + 相対 0.1%、電流: 絶対 1nA + 相対 0.1% | CI のテスト `dc_points_still_match_the_stored_ngspice_answers` |
| AC 解析 (周波数応答、10Hz〜10MHz、1デケード5点) | AC電源のあるサンプル 9 本のうち 6 本 | 複素数の差が 相対 0.1% + そのノードの最大値の 1ppm 以内 | CI のテスト `ac_sweeps_still_match_the_stored_ngspice_answers` |
| 過渡解析 (時間波形) | サンプル 32 本 | 10 個に分けた時間の窓ごとの平均は振れ幅の 1%、最小・最大は 3%、リップルは 10% | CI のテスト `transient_runs_still_match_the_stored_ngspice_statistics` |

- ngspice の答えは `docs/xcheck/ngspice_dc.json`、`docs/xcheck/ngspice_tran.json`、`docs/xcheck/ngspice_ac.json` に保存してあります。CI に ngspice は要りません。
- 保存してあるのは、**一致した回路だけ**です。外してある回路と理由は、下の「合わないもの」にあります。
- 過渡を波形そのものではなく「窓ごとの統計」で比べるのは、スイッチング波形は点の取り方でエッジの形が変わるためです。
- 比べるときは、ngspice の許容を厳しくして (`reltol=1e-6`)、ngspice 自身の誤差が混ざらないようにしています。
- Windows・Linux・macOS の全部で同じ答えになることも、CI で見ています。

## 2. 理論値との比較

- **555 の発振周期** (総合デモ): 自前 1.47 ms、理論 `0.693(R1+2R2)C` は 1.455 ms で、**1% 以内**です (起動直後の最初の周期は、起動のぶん長くなります)。

## 3. 公開されている部品メーカーのモデルとの比較 (開発用・手元で実行)

KiCad-Spice-Library (約 4800 個の `.subckt`) を使って、実在の部品のモデルを読めるか、解けるか、ngspice と合うかを調べています。リポジトリにはモデル自体を入れていません (ライセンスのため)。

この節の数字は、2026-10-19 に開発ノートへ記録した値です (セクション 1 のテストは毎回走りますが、この節はモデル集が手元に要るので、ここでは再計測していません。件数は「約」としてください)。

| 項目 | 結果 |
|---|---|
| 読める割合 | 最初 52% → 現在 **93.3%** |
| DC 動作点の比較 (150 個を抜き出し) | 一致 65、ズレ 10 前後、ngspice が読めない 約 74 |
| 過渡の比較 (98 個) | 一致 45、ズレ 2、ngspice が読めない 51 |

- 「ngspice が読めない」ものは、比べられません。比べられた中での一致は、DC で約 86% (65/約 76)、過渡で約 96% (45/47) です。
- 過渡の比較は、入力が変わった直後のスパイクを除いています。そこはエンジンの刻みの取り方で高さが変わり、答えが違うわけではないためです。この除外は基準を甘くしているので、書いておきます。
- この比較で、自前の不具合を複数見つけて直しました (`limit()` の引数の順序、逆向きのスイッチ、名前の衝突、節点名の大文字小文字など)。**比べると不具合が見つかる**ので、続けています。

## 4. 合わないもの (分かっている範囲)

| 対象 | 状況 | 理由 |
|---|---|---|
| `logic_blinker`、`variable_supply` の浮いた 2 次側 | 一致しない | 電源投入直後の双安定回路は、自前が釣り合い点にとどまり、ngspice は片側に倒れる。どちらが「正しい」と言えない |
| `ip2332_charger` | 設定しだいで一致 | `gmin` (収束を助ける微小な電導) の値に答えが依存する |
| `bridge_rectifier`、`variable_supply` の AC 解析 | 一致しない | 2 次側が浮いていて、共通電位が整流ダイオードの微小な漏れだけで決まる。差 (AC1−AC2) は 0.1450 対 0.1449 で合う |
| `mixed_signal` の AC 解析 | 比べられない | 自前の動作点が収束しない (フリップフロップを含む大きな混在回路) |
| トランス、`led_blinker` | 比べられない | ngspice のほうが止まる |
| MOSFET の LEVEL 2 以上 (`74HCU04` など) | ズレる | 未対応 (LEVEL 2 以上の式は実装していない) |
| PSpice 独自のダイオード記述の一部 | ズレる | 一部だけ対応 |
| 比較器が同じ値をにらみ合う簡易回路 | ズレる | 互いの答えがどちらも正しい可能性がある |
| 読めない書き方 (約 7%) | 解けない | PSpice の一部のデジタル部品など |

## 5. このページに書いていないこと (=まだ分からないこと)

- **実物との一致。** 部品の個体差・温度・基板の寄生成分は、実物でしか分かりません。各レッスンの「実物との違い」と「実機で確かめよう」に、確かめ方を書いています。学習パスの「実測値との比較」機能で、自分の測定値を並べられます。
- **部品の数値の正しさ。** ライブラリのピン配置・寸法・モデルは概算です。データシートで確かめてください。
- **基板の製造。** Gerber・ドリルの書き出しと、読み戻しの検査、発注前チェックは作ってありますが、このソフトのデータで実際に製造してもらった実績はありません。
- **速度。** 公開モデルの過渡 20µs、47 個では、中央値は自前 0.065 秒・ngspice 0.061 秒でほぼ同じですが、大きなモデルでは ngspice のほうが速い場合があります (合計: 自前 39 秒、ngspice 5 秒)。

## 自分で確かめる

ngspice が必要です (パスは `--ngspice` か環境変数 `NGSPICE`)。

```bash
# DC 動作点を ngspice と比べる (結果は xcheck_report.txt)
circuitCad --xcheck docs/examples

# 過渡解析を比べる (結果は xcheck_tran_report.txt)
circuitCad --xcheck docs/examples --tran

# AC 解析を比べる (結果は xcheck_ac_report.txt。--golden <json> で一致した答えを保存)
circuitCad --xcheck docs/examples --ac

# 保存した答えとの比較だけなら ngspice は要らない
cargo test -p app dc_points_still_match_the_stored_ngspice_answers
cargo test -p app transient_runs_still_match_the_stored_ngspice_statistics
cargo test -p app ac_sweeps_still_match_the_stored_ngspice_answers
```

公開モデルとの比較の手順 (環境変数など) は [docs/code-notes/sim-core.md](code-notes/sim-core.md) の「公開モデル集での ngspice との検算」にあります。比較の仕組みは [docs/code-notes/app.md](code-notes/app.md) の「開発用の検算 (xcheck)」にあります。
