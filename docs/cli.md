# ccad: 画面なしで使う (AIエージェント・自動化向け)

`ccad` は circuitCad の計算部分を、窓を開かずに使うコマンドです。**1行に1コマンド**の短いスクリプトを渡すと、**1コマンドにつき1行のJSON**で答えます。回路は座標ではなく**部品名とピン名**で作るので、AI(LLM)が書いても、つながらない事故が起きにくくなっています。

```bash
cargo run -p cli -- script.ccad        # ファイルから
cargo run -p cli -- -c 'new\nadd R 1k' # その場で (\n で改行)
cat script.ccad | cargo run -p cli -- - # 標準入力から
```

- 失敗した行で止まります(終了コード1)。続けるには `--keep-going`。
- **`"ok": true` は「コマンドが動いた」という意味で、「回路が正しい」という意味ではありません。** 回路の点検は `erc` の答えの `errors`(0なら配線の誤りなし。`circuit_ok` も同じ)で見ます。`--strict` を付けると、`erc` にエラーがあるとき `erc` が失敗して止まり、`dc`・`tran`・`board import` も実行を拒みます。AIが書くときは `--strict` を勧めます。
- 部品ライブラリは、アプリと同じ場所を読みます。別の場所は `--lib DIR`。
- `ccad help` で、コマンドの一覧が出ます。

## 約束事
- **名前が `GND` のネットが、0V の基準です。** どの回路にも1つ必要です(`net GND V1.- R1.2` のように作ります。最初の `GND` が、GNDの記号も置きます。手で置く必要はありません)。
- **ピンは番号でも名前でも書けて、大文字小文字は区別しません**(`U1.out` と `U1.OUT` は同じ)。部品のピンは、先に `part 部品名` で調べます。基本の部品のピン: `R`/`C`/`L` は `1` `2`、`D`/`LED` は `A` `K`、`V` は `+` `-`、`NPN` は `C` `B` `E`、`VR` (ボリューム) は `1` `2` `3` (2 が真ん中の足)。
- 1つのピンに、別の名前のネットは付けられません(エラーになります)。直すには `remove REF` で部品を消して、置き直します。
- `add R` で値を省くと、既定値(R は 10k、C は 100n、LED は LED)が入ります。値は書くほうが安全です。
- `parts 語` は、部品名・カテゴリ・説明文(日本語が多い)を検索します。英語の機能名では見つからないことがあるので、`parts 7805` のように型番で探してください。
- `dc` は、ライブラリ部品のモデルの内部の素子とノード(`U1.Ex`、`U1.xh` のように名前に `.` があるもの)を隠します。内部の電圧や電力は回路の実際の値ではありません。見るときは `dc full`。
- **`heat [temp=27] [top=10] [guess=NET=V,...]`** は、電流が流れる抵抗・ダイオード・トランジスタを自分の電力で温めたDC(定常状態。半導体はその温度のモデルで。接合が 1 つの部品は `junction_cold_v`・`junction_warm_v` に電圧): 部品ごとの電力 `power_w`・上昇 `rise_k`・温度・値の変化 `change_ppm` と、動いたネット `nodes`。熱抵抗は **`thermal REF theta=K/W tc=ppm tmax=C`** で決める。θ のうち接合部からケースまでは `jc=K/W`(θjc。基板の銅と放熱板はケースから先にだけ効く)、放熱板は `sink=K/W`(ケースから空気まで、取り付けを含む。θ = θjc + 1/(1/(θ−θjc) + 銅 + 1/放熱板))。`heat` の部品ごとに `theta_jc_k_per_w`・`heatsink_k_per_w`(0 で既定に戻す。既定は、θ=パッケージの定格電力からの目安、θjc=θ の 12/110(銅の式を合わせた SOT-223 の割合)、放熱板なし、係数=モデルの `TC=`、最高温度=ライブラリ部品の定格か種類からの目安)。部品ごとに最高温度 `t_max_c`・その出どころ `t_max_from`(part / datasheet / guess)・余裕 `margin_k`・周囲温度で下げた定格電力 `derated_power_w`・判定 `temperature`(ok / caution / over)、上限に近いか超えた部品は `temperature_problems`(原因と直し方つき)。係数のない部品は温まっても値が変わらない(`notes` に出る)。DC が収束しない回路(発振回路を含む全体など)は計算できないので、確かめたい部分だけの小さい回路で。`board postlayout on` のときは、ピンにつながった基板の銅(部品の中心から 20 mm 以内)で θ が下がる(`theta_k_per_w` が銅込み、`own_theta_k_per_w` が部品だけ、`board_copper_mm2` がパッドのほかの銅。`heattran` も同じ)。さらに、電力の大きい部品(1 mW 以上、最大 24 個)は基板の熱の地図の升目で解いた θ と、部品どうしが基板を通って温め合う分を使う(`board_grid` が true、`from_others_k` がほかの部品から受けた上昇。`heattran` では部品どうしの結合になる)。配線も地図の温度にして(銅は 0.393 %/K)もう一度解き、`wiring_warm` に温まった配線(`pad`・`net`・`temp_c`・`resistance_factor`)。
- **`heatsweep FROM TO STEP [guess=NET=V,...]`** は、周囲の温度を振りながら自己発熱を解く(部品は周囲 + 自分の熱の上昇)。部品ごとに、いちばん熱い温度 `hottest_c` とその周囲 `at_ambient_c`、上限 `t_max_c`(`t_max_guessed`)、上限に届く周囲 `over_from_ambient_c`(届かなければ null)、注意の帯に入る周囲、範囲の両端での上昇 `rise_low_k`・`rise_high_k`、温度で下げた定格電力を超えるか。動くネット `nets`(両端の電圧)。熱暴走で止まったら `runaway`。`board postlayout on` なら基板の熱抵抗の行列も(`heat` と同じ)。
- **`heattran TSTOP parts=Q1,RS1 [couple=Q1:RS1:300] [tstep=] [temp=27] [uic] [samples=8]`** は、過渡解析の電力を温度の時間変化にする(`sim_core::heat_tran`)。部品は熱の1段(`thermal REF theta=K/W cth=J/K`: 周囲への熱抵抗と熱容量)で、`couple=A:B:K/W` が2つの部品の間の熱抵抗(基板の銅を通る熱。`couple=` を省くと、回路図に保存してある結合を使う。保存は `thermal link=Q1:RS1:150`、K/W を 0 にすると消す)。部品ごとに、電力の最大・平均、上昇の最大と時刻 `rise_peak_k`・`peak_at_s`・終わりの上昇、定常状態の上昇 `steady_state_rise_k`(比べるため)、相手から受けた熱 `added_by_neighbours_k`、抵抗の値の変化 `change_ppm`、時刻・電力・上昇の標本を返す。熱容量が無い(0)部品は定常値になるので注意が出る。抵抗・ダイオード・トランジスタが対象(ライブラリ部品の中の素子を含む)。温度係数のある抵抗と半導体(ダイオード・BJT・MOSFET)は、電力を出している間の平均の温度で値・モデルを決め直して計算し直す。`moved` は、温まったことで動いた節点電圧(`moved_at_s` の時刻での、冷えた実行との差)。 部品ごとに最高温度を上限と比べた `t_max_c`・`margin_at_peak_k`・`temperature`(平均の電力は周囲温度で下げた定格 `derated_power_w` と)、上限に近いか超えた部品は `temperature_problems`(いちばん熱い時刻つき)。 部品に過渡熱抵抗の段があれば(`thermal REF zth=R:τ,...`、または `zthfit=時間:Zth,...` でデータシートの単一パルスの曲線の点から最大 4 段に当てはめる。`zth=0` で消す)、その段と θ の残りの 1 段で計算し、`heat_stages` に段の数を出す。
- **`coverage`** は、シミュレーションが何を知らないかの一覧(`ignored`=モデルがなく計算に入っていない部品、`generic`=ダイオード・LED・NPN が型番ではなく標準の値で計算されているもの、`caveats`=ライブラリのモデルの注意書き、`test_sources`=シミュレーション専用の部品、`total`・`clean`)。`dc`・`tran`・`ac` の答えの `models` に、その数(`ignored` は部品番号)が付く。モデルがない部品は回路にないものとして計算されるので、`models.ignored` が空でないときは結果を疑う。
`heat`・`heatsweep`・`poweron`・`board heatmap` の `guess=` は `dc` と同じ(ラッチを含む回路で、どの答えから解くかを決める)。部品の熱は、開いているシートだけでなく全部のシートの部品から集める。

`dc` の答えには、**回路が「動いた」だけでなく「使える」かを見るための知らせ**が付きます。`ratings` は定格のチェック(アプリと同じ。抵抗・トランジスタ・LED などが、形ごとの電力の目安を超えている/近い。`level` は `over`/`caution`。データシートではなく目安)、`warnings` には、オペアンプの IN+ と IN- の電圧が違うとき(負帰還が効いていない = 出力が電源の手前で頭打ち)の注意が出ます。コンパレータとして使うオペアンプなら無視してかまいません。`tran` にも同じ形で付きます(`ratings` と `warnings`。後半の半分だけを見て、立ち上がりは除きます): 抵抗の消費電力(実効値)、LED の最大電流、電解コンデンサのリップル電流(部品のデータシートの定格がある場合。アプリと同じ計算)、オペアンプの入力差(時間の2割を超えて続くとき)。発振回路やコンパレータのオペアンプには、警告が出ることがあります(文に「無視してよい」と書いてあります)。トランジスタ・ダイオードの電力は、`dc` だけが見ます。
- `dc`・`tran`・`board import` の答えにも `circuit_ok` が付きます。`false` なら、ERCにエラーが残っています(`warnings` に理由)。数値を信用する前に `erc` を見てください。
- **`tran` は、DC動作点から始めます**(コンデンサは最初から充電されています。直流電源につないだRCなら、最初から定常値で、変化しません)。**ゼロから立ち上がる様子(ステップ応答、発振)を見るときは `uic` を付けます。** 付けないと「壊れた回路」に見える結果になります。
- `tran` の `samples` は、0 から終了時間までを等間隔に取った点で、最後の点は終了時間です。特定の時刻の値が欲しいときは、その時刻を終了時間にして実行します。

## 例: LED を 5V から(いちばん小さい回路)
```
new
add V 5 as=V1
add R 270 as=R1
add LED as=D1
net VCC V1.+ R1.1
net LEDA R1.2 D1.A
net GND V1.- D1.K
erc
dc
```
`dc` の答えの `elements.D1.current` が、LED に流れる電流(約 11 mA)です。

## 例: RC フィルタのステップ応答(`uic` を付ける)
```
new
add V 1 as=V1
add R 1.6k as=R1
add C 100n as=C1
net IN V1.+ R1.1
net OUT R1.2 C1.1
net GND V1.- C1.2
erc
tran 160u 1u probe=V(OUT) samples=5 uic
```
時定数 R×C = 160 µs のとき、`V(OUT)` の `final` は 0.632 V(= 1 − 1/e)です。`uic` を付けないと、最初から 1 V のままになります。

## 例: 間違いを直す
ピン名を間違えると、使えるピンが答えに出ます。その一覧から選んで、書き直します。
```
net LEDA R1.2 D1.ANODE
→ {"ok":false,"error":"D1 has no pin 'ANODE' (pins: A K)"}
net LEDA R1.2 D1.A
```

## 例: 抵抗の分圧
```
new
add V 12 as=V1
add R 10k as=R1
add R 4.7k as=R2
net VIN V1.+ R1.1
net MID R1.2 R2.1
net GND V1.- R2.2
erc
dc
```
`dc` の答えの `voltages.MID` が 3.8367 V(= 12 × 4.7k / 14.7k)になります。

## 例: 555 の点滅を、基板と製造データまで
```
new
add V 5 as=V1
add NE555 as=U1
add R 1k as=R1
add R 68k as=R2
add C 10n as=C1
add C 100n as=C2
add LED as=D1
add R 330 as=R3
net VCC V1.+ U1.VCC U1.RESET R1.1
net GND V1.- U1.GND C1.2 C2.2 D1.K
net DIS R1.2 R2.1 U1.DISCH
net TIMING R2.2 C1.1 U1.TRIG U1.THRES
net CTL U1.CONT C2.1
net OUT U1.OUT R3.1
net LEDA R3.2 D1.A
erc
tran 5m 5u probe=V(OUT)
save blink.schjson
board import
board autoplace
board route
board drc
board fab out/
```
`tran` の答えには `period`(約 0.94 ms。理論値 0.693 × (R1 + 2 R2) × C1 = 0.95 ms)と `duty` が入ります。`blink.schjson` はアプリでも開けます。

## コマンド
| コマンド | 内容 |
|---|---|
| `new` / `open F` / `save F` | 回路図(`.schjson`)。アプリが同じファイルに入れているスペック表・実測・許容差・解析の設定は、`open` で取っておき `save` で書き戻す(`new` で消える)。`open FILE.ccproj` は基板 1 枚のプロジェクトの回路図と基板(セッションの基板に)を読む。 |
| `import_ltspice F` | LTspice の回路図(`.asc`)を取り込む。部品を並べ直し、つながりはネットの名前で表す。記号(`.asy`)は `.asc` と同じフォルダ → パソコンの LTspice の `lib/sym`(下のフォルダも)の順に探し、基本の記号(res・cap・ind・diode・voltage・npn など)は内蔵。`.param`/`.params` と `{式}` は計算して値にし(`.step param` は最初の値)、`SINE` は `SIN`、コンデンサの `Rser` は `ESR=`、コイルの `Rser` は `DCR=`(無ければ LTspice と同じ 1 mΩ)。型番がライブラリにあるダイオード・トランジスタ・IC はその部品に、無い PNP・MOSFET は 2N3906・2N7000・AO3401A で代用(`notes` に出る)。答えの `directives` に `.tran` などがそのまま入る |
| `import_kicad F` | KiCad 6 以降の回路図(`.kicad_sch`)を取り込む。部品を並べ直し、つながりはネットの名前で表す。答えの `notes` に、読めなかったもの(子シート・バスなど)と直してほしいところが出る。抵抗・コンデンサ・コイル・ダイオード・LED・NPN・`VDC`/`VSIN`/`VPULSE` は基本の部品(シミュレーションできる)、ほかは KiCad の記号のピンから作った部品(モデルは付かない)。 |
| `parts [語...]` / `part 名前` | 部品ライブラリの検索と、ピン(番号と名前)・シミュレーションの有無。`part` は基本の部品(`R` `LED` など)のピンも出す。メーカーのシリーズ(値ごとの部品の一式。`docs/part-format.md` の「シリーズ」)は `parts` の `series` に 1 つずつ出し(作られている値・品質の印・例の型番)、値ごとの部品は型番そのものを検索したときだけ `parts` に出る。 |
| `add 種類 [値] [as=U1] [unit=A] [rot=0..3] [at=X,Y]` | 部品を置く。`unit=B` は複数ユニットの部品 (デュアルのオペアンプ) のそのユニットを置き、`as=` で同じ部品のほかのユニットと同じ番号にできる (答えに `unit`・`units`・`shown` (U1B))。ピンは `U1.5` (番号はどのユニットでも) か `U1B.IN+` (名前はユニットの名で)。種類は `R C L D LED V I NPN VR HEADERn HEADER2xN` か、ライブラリの部品名。`HEADER2xN` (N = 1〜20) は 2 列のピンヘッダ (2.54 mm。番号は 1 2 / 3 4 / … と列をまたぐ。基板は `PinHeader_2xN`)。シリーズの名前と値(`add ERJ-3EKF 4.7k`。`4k7`・`1M`(メガ)も読む)なら、その値の型番の部品を置く。作られていない値は、近い値と型番を添えて断る。位置は自動。`VR` はボリューム(値は `10k POS=30` = 全体 10kΩ、つまみを 30 % の位置に)。`I` は電流源(シミュレーション専用。正の値で `+` ピンから回路へ電流を押し出す。`PULSE(0 100m 1m 1u 1u 2m 4m)` で負荷の急変)。 |
| `value REF 値` / `remove REF` | 値の変更 / 部品の削除。値にスペースが入る電源(`PULSE(0 5 1m 1u 1u 2m 5m)`、`0 AC 1`)は、引用符なしで書ける。抵抗・コンデンサ・コイルの値にも、付加パラメータを書ける(`22u ESR=5m BIAS=60`: コンデンサは `ESR` `ESL` `IC` と、直流の電圧で下がる容量の割合 `BIAS`(%)、コイルは `DCR`)。 |
| `simonly REF [off]` | その部品を**シミュレーション専用**にする(試験用の電源、測る相手の代わりに置いた抵抗など)。`board import`・部品表・購入リストに出ず、`dc`/`tran` などでは使われる。`list` に `sim_only: true` と出る。`off` で元に戻す。アプリでは、部品の編集欄の「シミュレーション専用 (基板に載せない)」。実際に作る回路図とシミュレーションの試験用の源を、1 つのファイルで両立させるため。 |
| `shop REF [akizuki=番号] [digikey=型番] [lcsc=番号]` / `shop REF -` | その部品を買う店の型番を決める(抵抗・コンデンサのような、部品JSONを持たない基本部品用。`-` で消す、`digikey=` と空にするとその店だけ消す)。`board import` で基板に写り、購入リスト(`board shopping`)と BOM に出る。店のページで確かめた型番だけ書く。部品JSONが型番を持っているときは、ここに書いたものが優先される。画面は、部品を選んだときの「買える店の型番」欄 |

## MCPサーバーとして使う (Claude Code などから)

`ccad mcp` は、同じコマンドを [MCP](https://modelcontextprotocol.io/) のサーバーとして出します(標準入出力、依存の追加なし)。回路図と基板は**サーバーが動いている間、呼び出しをまたいで残る**ので、AIが1コマンドずつ答えを見ながら組めます。

| ツール | 内容 |
|---|---|
| `ccad_run` | `script`(1行1コマンド)を実行して、1行1個のJSONを返す。最初に失敗した行で止まり、`isError` が true になる(`keep_going: true` で続ける)。 |
| `ccad_help` | コマンドの一覧と約束事(GND、ピン名、`ok` の意味、`uic`)。最初に読ませる。 |

登録の例 (Claude Code。パスは自分の場所に直す):
```bash
cargo build -p cli --release
claude mcp add ccad -- /path/to/target/release/ccad --strict mcp
```
他のクライアントは、`command` に `ccad`、`args` に `["--strict", "mcp"]` を設定します (`--lib DIR` で部品ライブラリの場所も変えられます)。

- 手元で試すだけなら、`target/debug/ccad` でも動きます。
- **このサーバーは、AIが指定したパスにファイルを書きます**(`save`、`board save`、`board fab DIR`)。信頼できるクライアントだけにつなぎ、書き込み先に気をつけてください。
- `--strict` は、ERCにエラーがあるあいだ `dc`・`tran`・`board import` を拒みます。AIには勧めます。ただし `erc` 自身も失敗扱いになり、答えには最初のエラーだけが出ます。一覧とヒントが見たいときは、`--strict` なしの実行で `erc` を見てください。

## 注意
- 答えの数値は、アプリと同じエンジンの結果です。精度と限界は [accuracy.md](accuracy.md) にあります(実物との一致は未確認です)。
- AIが作った回路は、**`erc` と、`dc`/`tran` の答えを必ず確かめてください。** 部品のピン配置・モデルは概算です。
- 発注の実績はまだありません。`board fab` の出力を使う前に、発注先のプレビューで確かめてください。
- 作りの詳細は [code-notes/cli.md](code-notes/cli.md)。
