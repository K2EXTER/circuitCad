# 部品定義ファイル (`*.part.json`)

1つの部品の **回路図記号・基板パッケージ・シミュレーションモデル** を1ファイルで定義します。
置き場所: `%APPDATA%\circuitCad\library\`（アプリの「＋ 部品を作る…」の窓の「① 基本」にある「JSONから追加…」でも追加できます）。
同梱の例: `crates/part-lib/examples/`。

データシートの PDF から作るときは、PDF を Claude に渡して「この部品の part.json を作って」と頼めます。
ピン表と推奨ランドパターン(Recommended Land Pattern)の寸法を読み取ります。
**読み取りの誤りがありうるので、ピン番号と寸法は必ずデータシートで確認してください。**
アプリは保存時に整合性(ピン番号とパッドの対応、モデルのノード数など)を検証します。

## フィールド

| フィールド | 必須 | 内容 |
|---|---|---|
| `name` | ○ | 部品名 |
| `category` | | ライブラリ一覧でのグループ名(例: `MOSFET`、`オペアンプ`)。省略すると「その他」 |
| `description`, `datasheet` | | 説明、データシートURL |
| `prefix` | | 部品番号の頭文字(既定 `U`) |
| `value` | | 回路図に出す値(既定 `name`) |
| `footprint_name` | | 基板上のフットプリント名(既定 `name`) |
| `land_unverified` | | `true` なら、パッドの位置・大きさがデータシートの推奨ランドパターンから読み取ったものではなく概算(基板の取り込みで `Board.land_unverified` に写り、発注前チェックが「ランドパターンが概算の部品があります」と警告する)。図面と照合できたら消す。`ccad part import` で作った部品(パッケージを借りたもの)は `true` |
| `shops` | | 買える店の型番(`{"akizuki": "I-xxxxx", "digikey": "...", "lcsc": "C..."}`)。基板の取り込みで基板に引き継がれ、BOM の `LCSC Part #` 列と購入リスト(`*-shopping.csv`、`ccad board shopping`)に使う。確かめた型番だけ書く(間違った型番より空欄がよい) |
| `height` | | 部品本体の基板からの高さ(mm、データシートの値)。3D表示と「ケースに入る高さ」の確認に使う。省略すると名前から推測する |
| `pins[]` | ○ | `number`(データシートのピン番号、パッド名と一致させる)、`name`、`side`(`left/right/top/bottom`、省略で前半が左・後半が右)。同じ辺では配列の順に上→下/左→右へ並ぶ。`"gap": 1` で、そのピンの前に(同じ辺で)ピン1本分の空きを入れる(電源ピンを信号から離すなど。0 なら書かない)。名前が `NC` のピンは ERC で未接続を報告しない 。`"sim_only": true` を付けると**シミュレーション専用ピン**(パッドが不要。センサに光・磁界などを電圧で与える入力口で、基板の取り込みでは無視される。例: `LDR_GL5528` `SS49E`) |
| `programming[]` | | 書き込みの方法とそのピン(`{"name": "ISP (SPI)", "pins": ["PB5/RESET", "PB0", "VCC", "GND"]}`。ピンは名前で、同じ名前が複数あれば(GND など)どれか 1 つがつながっていればよい)。回路図の ERC が、どれか 1 つの方法の全部のピンがヘッダ(コネクタ)に出ているかを調べる(抵抗・コンデンサを 1 つ挟んでもよい)。省略すると点検しない。ATtiny85・ATmega328P・ATmega2560 に入れてある |
| `package` | ○ | 下記 |
| `sim` | | 下記 |

## package (単位 mm、パッドの `y` は上が正)

- `{"type":"chip2","pitch":..,"pad_len":..,"pad_width":..}` — 2端子チップ。`pitch` はパッド中心間
- `{"type":"dual","pins":8,"pitch":1.27,"row_spacing":5.4,"pad_len":1.55,"pad_width":0.6}` — SOIC/SSOP/TSSOP。`drill` を付けるとスルーホール(DIP)。ピン1は左上、反時計回り。`row_spacing` は2列の中心間距離、`pad_len` は列間方向、`pad_width` は列に沿う方向
- `{"type":"quad","pins":32,"pitch":0.8,"span":8.4,"pad_len":1.6,"pad_width":0.5}` — QFP 等。`span` は向かい合うパッド中心間
- `{"type":"single_row","pins":4,"pitch":2.54,"pad_d":1.7,"drill":1.0}` — 1列ヘッダ。ピン1は角パッド

- `{"type":"double_row","pins":10,"pitch":2.54,"row_spacing":2.54,"pad_d":1.7,"drill":1.0}` — 2列ヘッダ (2×N・ボックスヘッダ)。番号は列をまたいで 1 2 / 3 4 / …(奇数が左の列、偶数が `row_spacing` だけ右の列)。ピン1は原点の角パッドで、列は -y へ進む。ピン数は偶数。IC の DIP(反時計回り)は `dual` に `drill` を付ける
- `{"type":"explicit","pads":[{"pin":"1","x":0,"y":0,"shape":"rect|circle|oval","w":1,"h":1,"drill":0.8}]}` — 座標を直接指定(サーマルパッド等)。
  - パッドに `"slot": 長さ` を足すと、その穴は**長穴**(めっきあり)になります。`drill` が穴の幅、`slot` が長さ(`drill` 以上)。向きは横(x方向)が標準で、`"slot_v": true` で縦。
  - `"holes": [{"x":0,"y":-3,"drill":1.0,"slot":2.0,"slot_v":false}]` で、部品に付く**めっきなしの穴**(位置決めの突起用の穴など)を書けます(`slot` 以降は省略可)。部品を置くと基板の取付穴として一緒に付き、動かす・回すとついてきます。ガーバーのドリル(NPTH)にも出ます。
  - 同じ `pin` のパッドを複数書けます(USBのシェル脚など)。ピン表に `SH` のようなピンを足して、回路図でGNDなどにつなぎます。
  - 例: `part-lib/examples/USB_DEMO_TH.part.json`(寸法は仕組みの見本)。部品作成フォームの「追加のパッドと穴」でも同じものを作れます。
  同じ `pin` のパッドを複数書くと(SOT-223 のタブなど)、1つの接続として扱われ、すべてのパッドにネットが付きます

## sim (部品の特性)

```json
"sim": {
  "kind": "model",            // "model" = .model カード / "subckt" = .subckt ブロック
  "element": "D",             // model のとき SPICE 素子記号 (D, Q, M, J ...)
  "name": "1N4148",           // 実体化行で使うモデル名 / サブサーキット名
  "text": ".model 1N4148 D(IS=2.52n RS=0.568 N=1.752)",
  "pins": ["A", "K"],         // モデルが期待するノード順に並べた記号のピン番号
  "params": { "vf_typ": 0.72 }, // 任意。自作シミュレータ用の特性値
  "limits": [                  // 任意。このモデルが扱わないこと・簡略にしていること (1行に1つ)
    "接合容量と逆回復時間は扱いません。",
    "耐圧や定格電流を超えても壊れません。"
  ],
  "origin": {                  // 任意。モデルの出どころ (docs/model-policy.md の 1 節)
    "kind": "equivalent",      // "equivalent" = データシートから作った等価モデル / "vendor" = メーカーのモデル / "generic" = 一般のモデル
    "source": "TI SLOS068AB(2024-10 改訂)" // データシートの型番・版、またはメーカーのファイル
  }
}
```

`limits` は、ライブラリの部品一覧にカーソルを合わせたとき、部品を選んだとき、配置した部品を選んだときに「このモデルの限界 (実物との違い)」として表示されます。
シミュレーションの結果を実物と取り違えないための欄なので、モデルを作ったら、扱っていない特性を書いてください (フォームの「＋ 部品を作る…」にも欄があります)。

`origin` は、部品を選んだときと配置した部品を選んだときに「データシートの値から作った等価モデル」「出典: …」のように表示されます。無ければ「記録なし」。部品作成フォームのひな形 (チップ部品・ダイオード・レギュレータ) とメーカーのモデルの取り込みは自動で入れます。フォームでモデルの文を書き換えると、`origin` は外れます (書き換えたモデルは、記録した出どころのものではないため)。

### 部品ごとのばらつき (`* spread`、モデルの文の注釈)

同じ型番でも 1 個ずつ違う値 (オペアンプのオフセット、レギュレータや基準電圧 IC の出力電圧) は、モデルの文に注釈の行を書くと、「温度とばらつき」のばらつき解析・最悪ケース (と CLI の `mc`・`worst`、スペック表の最悪ケースの判定) で、データシートの min〜max の範囲で動きます。ふだんの解析 (DC・過渡・AC …) はモデルの値のままです。

```
* spread <素子> <最小> <最大> <何か> [メモ]
* spread Vos -7m 7m offset (data sheet: max 7 mV either way)
```

- `<素子>` はモデルの中の、直流の電圧源・電流源、抵抗・コンデンサ・コイル。その値を `<最小>`〜`<最大>` に置き換えます (値そのもの。typ からの差ではない)。出力電圧のように式で決まる値は、式から読むだけの 0 V の電源を足して、それを動かします (同梱の LM317 の `Vtol vt adj DC 0` と `+V(vt,adj)`)。
- `<何か>` は画面の表示: `offset` (入力オフセット電圧)・`vout` (出力電圧)・`vref` (基準電圧)。ほかの語はそのまま出ます。
- ほかの SPICE のソフトには、ただの注釈です。名前の無い素子や値を変えられない素子を書くと、解析の警告に出て、使われません。
- ばらつき解析では範囲の中で均等に動かします (実物は typ の近くに多いので、少し広めに出ます)。

同梱の等価モデルには、データシートとの比べの表 (`crates/part-lib/model_checks.json`) が付き、部品の欄の「データシートとの比べ」に出ます。表はモデルを測るテストが書き出し、モデルの文の指紋が同じときだけ出ます (書き換えたモデルや、別の版の写しには出ません)。

## データシートの情報 (`ratings`、任意)

部品の最大定格と、データシートの代表値を、部品の JSON に書けます。部品を作る画面の「データシートの情報 (定格・最大定格)」でも入力できます。

```json
"ratings": {
  "v_max": 40,        // 最大電圧 [V]: ダイオードの逆耐圧、トランジスタの Vce、MOSFET の Vds など
  "i_max": 1,         // 最大電流 [A] (連続)
  "p_max": 1,         // 最大電力 [W] (許容損失)
  "rows": [           // そのほかの定格・代表値 (自由に書けます)
    { "name": "順方向電圧", "value": "0.6V (最大)", "condition": "IF = 1A" }
  ]
}
```

- すべて省略できます。分からない項目は、書かないでください (空欄は「不明」として扱います)。
- 回路の DC 解析の結果が、最大定格に近づく (電圧・電流は 8 割、電力は 5 割) か、超えると、解析パネルに警告が出ます。`p_max` がなければ、パッケージごとの一般的な目安 (0805 の抵抗は 0.125W など) と比べます。
- 部品を選ぶと、「部品選びのヒント」に、データシートの情報と、この回路で必要な定格 (余裕 2 倍)、条件を満たす同じ種類の部品が出ます。
- 数値は、データシートの値を、自分で確かめて書いてください。同梱の部品の値は、代表的な値で、概算です。

使える SPICE の記述:
- `.model` カード: ダイオード `D(IS N RS BV IBV)`、バイポーラ `NPN` / `PNP`(`IS BF BR NF NR RB`。RB はベース抵抗で、ノイズ解析にも効きます)、
  MOSFET `NMOS` / `PMOS`(`VTO KP LAMBDA CGS CGD`。`element` は `M`、ノード順は ドレイン・ゲート・ソース)
  電圧制御スイッチ `SW`(`RON ROFF VT VW`。`element` は `S`、ノード順は スイッチの2端子・制御の+・制御の−。制御電圧が `VT ± VW` の間でなめらかにオフ→オンします)
- `.subckt` の本体: `R C L V I E G D Q M S B`。それ以外の素子を含むと、黙って無視せずエラーになります
  (スイッチの行: `S1 a b cp cn モデル名`)

### 式で書く電源 (`B` 素子)

IC の「外から見た動き」(電流の制限、しきい値での切替、小さいほうを選ぶ、など) は、`B` 素子に式で書くと短く書けます。

```
B名前  ノード+ ノード-  V=式      ← 電圧源: V(ノード+) - V(ノード-) = 式
B名前  ノード+ ノード-  I=式      ← 電流源: 式 [A] が ノード+ から電源の中を通って ノード- へ流れる
```

例: `Bcmd cmd 0 V=min(60*(4.2-V(bat)), 2.4)` (電池が 4.2V に近づくと、充電電流の指令を絞る)

| 書けるもの | 内容 |
|---|---|
| 数と演算 | `4.7k` `100u` `1e-3`、`+ - * / ^` (`**` も可)、`( )`。比較 `< > <= >=` は 1 か 0 になります |
| `V(ノード)` `V(a,b)` | ノードの電圧、2点間の電圧 (GND は `0` または `gnd`) |
| `I(電源名)` | V 電源・コイル・E 素子・`V=式` の B 素子を流れる電流。抵抗や G、I 電源の電流は読めません (読みたいときは 0V の電圧源を直列に入れて、その名前を書きます) |
| `time` | 過渡解析の時間 [s] (DC では 0) |
| `temp` | 回路の温度 [℃] (既定 27。温度設定・温度スイープで変わる)。温度センサやサーミスタの式に使う。例: `V=0.01*temp` (LM35)、`I=V(a,b)/(10k*exp(3950*(1/(temp+273.15)-1/298.15)))` (NTC) |
| 関数 | `abs(x)` `min(a,b)` `max(a,b)` `limit(x,下限,上限)` `sqrt` `exp` `ln` `pow(a,b)` `tanh` `if(条件,a,b)` `step(x[,幅])` |

- **しきい値で切り替えるときは `step(x, 幅)` を使う**と、収束しやすくなります。`step` は x が `-幅` 以下なら 0、`+幅` 以上なら 1 で、その間をなめらかにつなぎます (幅を省くと 1mV)。`if` と比較は、切り替わる所で値が飛ぶので、そこで解が定まらないことがあります。
- 2つの値のうち小さいほう・大きいほうは `min` `max`、上下の制限は `limit` で書きます。
- `V=式` の電源が、自分自身や他の B 素子の出力を読む (帰還がある) 回路も書けます。収束しないときは、`limit` や `step` を挟んで、式をなだらかにしてください。
- AC 解析では、動作点のまわりで式を微分した値 (小信号の利得) が使われます。ノイズは出しません。
- 式の書き間違い (カッコの閉じ忘れ、未対応の関数名、読めない電流など) は、どこが原因かを日本語で知らせます。


SPICE ネットリストの書き出し時に、使われているモデルが1回だけ出力されます。`sim` が無い部品は
コメント行になり、シミュレーションには含まれません。

## チップ部品 (コンデンサ・抵抗・コイル)

- `"glyph": "capacitor" | "resistor" | "inductor"` を付けると、箱ではなく基本部品と同じ記号で描きます (左右 1 ピンずつの 2 ピン部品だけ)。
- コンデンサの種類(回路図の「コンデンサ」の木に出る分け方)は、名前の頭で決まります: `CE_` = 電解、`CT_` = タンタル、`CF_` = フィルム、`glyph` が `capacitor` のそれ以外 = 積層セラミック (説明に「フィルムコンデンサ」と書いてもフィルムになります)。
- 電解コンデンサの `ratings` には、`ripple` (定格リップル電流 `{"i_rms": 0.3, "freq_hz": 100000, "coeffs": [[120, 0.55], [1000, 0.77], [10000, 0.94], [100000, 1.0]]}`。`i_rms` は A の実効値、`coeffs` はデータシートの「周波数補正係数」の表 (周波数 Hz と係数)) と、`life` (寿命 `{"hours": 6000, "temp_c": 105}`。最高温度でのデータシートの耐久時間) を書けます。過渡解析のあと、波形パネルの「部品の定格 (リップル電流・寿命)」に、後半の波形の電流の交流分 (実効値) が定格を超えていないか、推定寿命がどれくらいかが出ます。寿命は「温度が 10℃ 下がると 2 倍」の目安で、内部の温度は、周囲の温度に、リップルによる発熱 (定格のとき 10℃、電流の 2 乗で増減) を足して見積もります。フォームの「① 基本」の「データシートの数字 (定格)」の「電解コンデンサの項目」から入力できます。
- `"body"` を書くと、データシートの外形寸法の本体を、フットプリントのシルク (白い線) に描きます: `{"shape": "rect" | "circle", "w": 幅 (円は直径), "h": 長さ, "x": 0, "y": 0 (中心のずれ), "mark": "none" | "dot" | "bar" | "plus", "mark_pin": "1"}`。`dot` は1番ピン側の角の内側の点 (IC)、`bar` はそのピン側の端の棒 (ダイオードのカソード、LED の平らな側)、`plus` は極性のあるコンデンサの ＋ 側です。パッドに重なる部分は自動で避けます。部品作成フォームの「本体の外形」から入力できます (フォームの下の絵で確かめられます)。
- 放熱パッド (QFN・ESOP の裏のパッドなど) は、フォームの「放熱パッド」で幅・長さ・ピン番号を入れると、パッケージの中心に置きます (JSON では `package` の `explicit` にパッドを足します)。ピン表にもそのピンの行が必要です。
- `"glyph"` に次を書くと、箱の中に規格 (新JIS C 0617 / IEC 60617) の記号を描きます。ピンの位置は箱のままなので、ピン名を下の表のとおりにしてください。`glyph` を省くと、同梱部品は名前やピン名から自動で決まります。
  | glyph | 記号 | 必要なピン名 |
  |---|---|---|
  | `diode` `zener` `schottky` `tvs` | ダイオード (ツェナーは Z 形、ショットキーは S 形の棒) | `A` `K` |
  | `npn` `pnp` | バイポーラトランジスタ (エミッタの矢印) | `B` `C` `E` |
  | `nmos` `pmos` | エンハンスメント形MOSFET | `G` `D` `S` |
  | `opamp` `comparator` | オペアンプ・コンパレータの三角形 (コンパレータは出力の近くに段の印) | `IN+` `IN-` `OUT` (+電源ピンは上下) |
  | `box` | 名前やピンからの推測をやめて、箱にピン名を並べる | (制限なし) |
  | `regulator` | 3端子レギュレータ。箱の中にDC記号 (実線の下に破線)。ピンは箱のまま | `IN`(`VIN`) `OUT`(`VOUT`) `GND` |
  | `gate_and` `gate_or` `gate_not` `gate_nand` `gate_nor` `gate_xor` `gate_schmitt` `gate_buffer` | ロジックゲートIC。箱の中央にゲートの記号を1つ描く (1パッケージに複数のゲートがあるので、箱とピン名はそのまま)。74HC00/02/04/08/14/32/86 は名前から自動で決まる | (制限なし) |
  | `ff_d` `counter` `shift_reg` | フリップフロップ・カウンタ・シフトレジスタのIC。箱とピン名はそのまま、中央にクロックの三角つきの小さな箱を描く (カウンタは階段、シフトレジスタは矢印つき)。74HC74・4017・595 などは名前から自動で決まる | (制限なし) |
  | `transformer` | 巻線2つと鉄心 | `P1` `P2` `S1` `S2` |
  | `battery` | 電池 (長い線が +) | `+` `-` |
  | `ldr` `photodiode` | 光センサ (光の矢印) | `A` `B` (ダイオードは `A` `K`)、光は `L`/`LIGHT` |
  | `shunt_reg` | TL431形のシャントレギュレータ | `CATHODE` `REF` `ANODE` |
  | `crystal` | 水晶振動子 (2枚の板の間に長方形)。4端子は、ケースの `GND` を下の棒につなぐ。端子は基本のコンデンサと同じ小ささ (左右の先が±2、GNDの先が下3)。部品名と値は上に出す | `X1` `X2` (2端子なら `1` `2`)、4端子は `GND` ×2 も |
- モデルは、値とデータシートの寄生成分 (ESR・ESL・DCR・並列容量) を並べた `.subckt` にします。部品作成フォームの「チップ部品」の欄で、数値を入れるだけで作れます。
- コンデンサは、データシートのインピーダンスの表 (周波数と |Z|) から ESR と ESL を最小二乗で求められます。表が共振の近くを含まないときは、注意を出します。
- 自己共振周波数から、コンデンサの ESL・コイルの並列容量を求められます。
- DCバイアスによる容量の低下は、使う電圧での減り方 (%) を入れると、その分小さい容量の固定値として扱います (電圧が変わっても追従しません)。
- 見本: `C_100n_0603`、`C_10u_0805`、`L_10u_0805`、`R_10k_0603` (数値は代表的な例)。

## シリーズ (`*.series.json`、値だけ違う実在の型番の一式)

同じメーカーの同じシリーズで、値だけが違う部品 (チップ抵抗の E24・E96 の全部の値など) は、部品ごとのファイルを並べずに、シリーズのファイル 1 つで書きます。読み込むと値ごとの部品 (名前はメーカーの型番) に展開され、回路図・基板・CLI からはふつうの部品に見えます。部品一覧ではシリーズが 1 行になり、部品を選んだあと、下の欄に値を入れて型番を切り替えます。いまはチップ抵抗だけで、同梱は `crates/part-lib/series/` (ライブラリのフォルダには書き出しません。同じ型番の部品ファイルがライブラリにあれば、そちらが使われます)。

```json
{
  "series": "ERJ-3EKF", "maker": "Panasonic", "category": "抵抗",
  "summary": "厚膜チップ抵抗 ±1% 0603 (1608)",
  "size": "0603",
  "datasheet": "https://...", "checked": "どの資料のどこを見て、いつ確かめたか",
  "values": { "sets": ["E24", "E96"], "min": 10.0, "max": 1000000.0 },
  "mpn": "ERJ-3EKF{code}V", "code": "sig3",
  "tolerance_pct": 1.0, "tc_ppm": 100.0,
  "p_max": 0.1, "v_limit": 75.0, "v_overload": 150.0,
  "derate_from_c": 70.0, "derate_zero_c": 155.0, "temp_min_c": -55.0, "temp_max_c": 155.0,
  "quality": ["AEC-Q200 Grade 0"],
  "height": 0.45, "footprint_name": "R_0603_Panasonic",
  "package": { "type": "explicit", "pads": [ ... ], "holes": [] },
  "land": "ランドの出どころ", "body": "本体の寸法 (文)"
}
```

- `size`: インチの大きさ。部品一覧の行に「ERJ-3EKF 0603 … 10k」のように出ます。
- `values`: 作られている値。`sets` の E 系列 (`E24`・`E96`) を合わせ、`min`〜`max` (Ω) の範囲だけ。
- `mpn` と `code`: 型番の作り方。`{code}` に値の符号が入る。`sig3` は「有効数字 3 桁 + 0 の数、100 Ω 未満は `R` が小数点」(`1002` = 10 kΩ、`10R0` = 10 Ω、`1004` = 1 MΩ。Panasonic ERJ・KOA RK73H・ROHM MCR がこの形)。
- 定格: `p_max` は `derate_from_c` までの定格電力 (それより上は `derate_zero_c` で 0 W になる直線)。値ごとの定格電圧は √(電力 × 抵抗値) と `v_limit` (素子の最高電圧) の小さいほう。
- `quality`: データシートの品質の印 (`AEC-Q200 Grade 0`・`耐硫化` など)。部品一覧の行と部品の欄に出ます (メーカーは歩留まりを公開しないので、選ぶ目安として見せる)。
- モデルは値だけの抵抗で、許容差は `* spread` (上の「部品ごとのばらつき」)。温度係数は保証の範囲 (向きは個体ごと) なのでモデルでは 0。寄生成分はデータシートに無いので入れない。
- 新しいシリーズは `series.rs` の `BUNDLED` に足し、テスト (型番の作り方・値の数・ランド) を足します。
