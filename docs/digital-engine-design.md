# デジタルエンジンの設計(候補 G3、2026-11-04)

目的: 数千ゲート(12桁電卓、約 3000〜5000 ゲート)を、1クロックあたり 0.01 秒台で動かす。今は 1クロック 0.3 秒前後(2561 ゲート + FF 512 個、`candidates.md` の G1)。**速さの見積もりは、実装して測るまで見立て。**

## 今の仕組み(読んで分かったこと)

- FF・ラッチ・シュミットは `Element::Seq`(`dc/seq.rs`)。**状態は回路方程式の未知数ではなく**、出力 q・qb は「状態のレベルを出す電圧源」(`Ce::Seq`、`dc/mna.rs`)。状態は、解と解の間に `seq_update` が、採用した節点電圧から更新する(`tran.rs` の 254・463 行)。だから状態の変化は最大で1刻み遅れる。
- ゲートは 1 つの B 電圧源の式(`74HC00` などの部品 JSON)。**ゲートの出力も入力もアナログの節点で、行列に入っている**。2561 ゲート + FF 512 個のとき、未知数は数千で、刻みごとに(ニュートン反復のたびに)行列を組み立てて LU 分解する。1 ms(100 クロック)で 28 秒かかるのは、この部分だと見ている(プロファイルは取っていない)。
- 刻みは、電源の折れ点に合わせて自動で調整する(`tran.rs`)。

## 方針: 「デジタルの島」

**デジタルだけでつながる節点を、行列から外す。** 速さの理由は、行列が小さくなることと、変化したゲートだけを計算することの 2 つ。

1. **セル**: ゲートと FF を、行列の外で評価する素子(セル)にする。`Element::Gate { kind, ins, out, levels, rout }` を足し、`Seq` も同じ枠に入れる。セルは、入力の節点の電圧(しきい値と比べる)を読み、出力に「電圧源 + 出力抵抗 `rout`」を出す。
2. **デジタル網の除去**: コンパイルのとき、**セルのピンだけがつながる節点**(抵抗・コンデンサ・LED などのアナログ素子が付かない節点)を「デジタル網」にする。デジタル網の値(0/1)は表で持ち、行列には入れない。出力の `rout` は、デジタル網につながるときは意味がない(入力のインピーダンスは無限大)ので無視する。アナログ素子が付く節点(LED、プルアップ、外に出るピン)は、今までどおり行列に入れ、セルの出力は電圧源 + `rout` として入れる。
3. **評価**: 刻みの前に、変化した入力から、セルを評価して、デジタル網の値を落ち着かせる(ゼロ遅延ではキューが空になるまで)。ラッチのような帰還のループは、反復の回数の上限を決めて、超えたら「振動」として警告する。
4. **遅延(G2)**: 出力の変化を、時刻 `t + td` のイベントとして予約する。次のイベントの時刻を、刻みの折れ点として過渡解析に伝える(電源の折れ点と同じ扱い)。
5. **アナログからデジタルへ**: セルの入力がアナログの節点のとき、前の採用点の電圧としきい値を比べる。しきい値をまたいだ刻みの中の時刻は、線形補間で見積もる(エッジの時刻合わせ。今は最大 1 刻みの遅れ)。

## 部品の書き方

セルは、部品 JSON の SPICE モデルの中の `A` 素子(LTspice の `AND/OR/XOR/BUF/SCHMITT/DFLOP`、XSPICE の `d_and` など。すでに読める)から作る。足りないのは**電源に対する相対のレベル**(`Vhigh`・`Vlow`・`Vt` を数値でなく、電源ピンの電位に対する比にする)と出力抵抗。拡張する書き方の案: `A1 a b 0 0 0 0 y 0 AND Vcc=vcc Vss=gnd Rout=60`。

## 段階

| 段階 | 内容 | 目安 |

## 危ないところ

- **既存の部品とサンプルの書き換え**: 埋め込まれた部品の定義(`docs/examples`)も、置き換えが要る。ngspice は `AND` などの `A` 素子の電源相対レベルの書き方を読めない(拡張の文法)ので、検算の対象外になる部品が増える。
- **画面の表示**: セルの中の節点(`U2.m1` など)がなくなる。デジタル網の電圧を波形に出す仕組みが要る(出力の振幅は電源から計算する)。
- **DC の双安定**: ラッチの状態が複数ある。今の `guess` と `dc states` の仕組みと、折り合いをつける。
- **収束**: アナログとデジタルの境で、しきい値付近のチャタリングが出る(今も同じ)。
- **規模の割に効果が小さい回路**: アナログの素子が多い回路では、速くならない。効くのは、デジタル網が大きい回路だけ。

## 測る基準

アキュムレータ(256bit、2561 ゲート + FF 512 個、100 クロック)で、今の 28 秒から、**M1 で 3 秒以下**(10 倍)を目標にする。届かなければ、プロファイルで原因を見直す。

## 実装の状況(2026-11-04)
M1 を実装した。詳細は `docs/code-notes/sim-core.md` の「デジタルセル」。目標の「256bit で 3 秒以下」は **1.35 秒**で達成した(前は 28 秒、最初は 72 秒)。設計との違い: 部品の書き方は `A` 素子の拡張ではなく、新しい 1 行 `Y …`(`A` 素子の `AND` などの解析を増やさずに済む。ngspice は読めない)。節点は行列に残し(gmin だけの行)、解のあとに電圧を書き戻した(節点の番号の付け直しをしなかった)。

M2(遅延、2026-11-04)も実装した。詳細は `docs/code-notes/sim-core.md` の「デジタルセルの伝搬遅延」。
