# app: 基板エディタ・3D ビュー・ネットの窓・描画の軽さ

(`docs/code-notes/app.md` の目次から分けた。内容は元のまま)

- 学習パス(`learn.rs`): `PATHS` は7本(安定化電源・Arduino・Mega・基板づくり・スイッチ・電池・信号)。**項目の `id` はパスの中で一意で、複数のパスで同じ項目を共有できる**(進み具合は `id` で記録)。共有する項目は `I_…` の定数にして、パスごとに前提だけ付け替える。`requirements(path, item)` は前提を、いまのパスの中 → 他のパスの順に探す(同じ `id` の前提がパスごとに違うため)。テスト `a_shared_item_has_the_prerequisites_of_each_path`・`every_lesson_of_a_path_exists_and_ids_are_unique_in_a_path`(同じ `id` はどのパスでも同じタイトルと種類)
- 発注の準備の窓(`board_editor/order.rs`): 窓の中だけ、小さい注釈の文字(`TextStyle::Small`)を 12px にしている(標準は約9px で、初めて発注する人が読む説明が読みにくかった)。手順4に「ガーバー=工場に渡す設計図のデータ」の一行、書き出したあとに「発注先に渡すのは `<基板名>_gerber.zip` の1つ(部品実装も頼むなら BOM と CPL)」を緑で出す
- 3Dビューの案内(`view3d/window.rs`): 絵の下に、回す・動かす・拡大・戻すの操作と「ケース高さ」の一言を出し、一度でも絵を回す・拡大する・ダブルクリックしたら出さない(`View3d.touched`。窓を開き直すと、また出る)
- 名前のないネット(`netglow.rs` の `net_caption`): 基板で `N$` で始まるネットにカーソルを合わせると、札に「N$1 (回路図で名前のないつながり: R1-2・U1-15 ほか3)」と、つながるピンを出す(最大4つ)。回路図側でそのピンを探せる
- ネットの設定の窓(`board_editor/netwindow.rs` の `net_window`): 選択ツールで配線・パッド・ビア・ベタを右クリックすると(`interact.rs` が `net_menu` に入れ、`net_menu_ui` のメニュー「ネットの設定…」が `open_net_window`)、そのネットの窓が開く。流れる電流(0.5/1/2/3A のボタンつき)、推奨の線幅(`width_for_current` を 0.05mm に切り上げ。今の最も細い配線との比較、「配線を推奨幅にする」「この幅で引く」)、ネットクラスの選択と、そのクラスの線幅・間隔・ビア(「このネット専用のクラスを作る」)。窓が開いている間だけ、左クリックで別のネットに切り替わり(`netglow.rs` の `update_net_focus`)、何もない所のクリックで閉じる。ベタの角・辺の右クリックは、これまでどおりベタの編集メニュー。クラスの変更は `commit_classes`(値のドラッグは1回の元に戻す)。テスト `the_net_window_draws_and_follows_the_net`
- ビアのネット(`netglow.rs` の `via_net_at`、`tools.rs`・`route.rs`・`panel.rs`): ビアツールの設定に「ネット」(自動 / 一覧から)。「自動」は置いた場所のネット(`net_under`: パッド→ビア→配線→ベタ)。カーソルに「ビア → ネット GND」の札と、ビアの大きさの円。選んだビアのパネルにもネットを選ぶ欄。配線しながら置くビア(V キー)は、引いているネットのビア。テスト `a_via_is_placed_for_the_net_under_it_or_the_net_chosen`
- インピーダンスの目安(`netwindow.rs`・`netclass.rs` の `panel_stackup`): ネットの窓に「インピーダンス (目安)」(スライダーの線幅 → 約 ○ Ω)と、目標(Ω)と「目標の線幅にする」(層構成から線幅を求め、配線とクラスの線幅にし、クラスがなければ作って、クラスに目標を保存)。目標から10%以上ずれていれば窓で橙の注意。左パネルの「層構成 (層数・材料)」(「作業の設定」のすぐ下。配線ツールの設定の中ではない)で、銅箔の層数(`layer_count_ui`)と、誘電率・外層から基準面まで・内層の上下のベタの間・銅箔を直す(発注先の積層構成の値に直す前提の説明つき。「この層数の目安を入れる」は、2層=1.53mm、4層以上=0.2mm の例)
- ネットの電流一覧の窓(`board_editor/currentwindow.rs` の `current_window`): 全ネットの電流(編集できる)・推奨の線幅・今の最も細い配線(✔/✖)、過渡解析があれば実効・10msの最大・ピーク(⚠)を1つの表にする。ネット名のクリックでそのネットの窓を開く。「DC解析の電流を入れる」「過渡解析の電流を入れる」「足りないネットを推奨幅にする」。左パネルの「配線の太さ」には、この窓を開くボタン(`current_win_open`)と、細いネットの数、電圧降下だけを置く(以前の、ネットごとの電流・必要な幅の表と、DC/過渡の電流を入れるボタンは、窓に移した)。シミュレーションの電流を入れると、パネルではなくこの窓が開く(`use_simulated_currents`)
- ネットの窓の線幅スライダー(`netwindow.rs`): 対数のスライダー(最小線幅〜3mm、推奨の2倍が3mmより大きければそこまで)で、そのネットの全配線の太さと、ネットクラスに入っていればクラスの線幅を、ドラッグ中ずっとそろえて変える(ドラッグ全体で1回の元に戻す)。値は、クラスの線幅か、配線の最も太い太さ。推奨と比べて「足ります ✔」「足りません」と「推奨まで上げる」。パネルの値のドラッグは `checkpoint_once`(`history.rs`。ポインタが離れるまで1回。`canvas` が毎フレーム、離れていれば解除する `drag_edit`)で1回にまとめる。「角を丸める」の半径が、ドラッグ中ずっと1フレームごとに元に戻すを積んでいた不具合も、これで直した。テスト `a_dragged_panel_value_is_one_undo_step`・`the_width_slider_leaves_the_net_alone_until_it_is_moved`
- ネットクラス(`board_editor/netclass.rs`): 配線ツールの設定の「高度な配線」の中の「ネットクラス (線幅・間隔・ビア)」。クラスごとに名前・線幅・間隔・ビア径・穴・ネット(×で外す・コンボで足す)。「クラスを追加」「電源のクラスを作る」(GND と電流を決めたネット。0.5/0.25/0.8/0.4mm)。値のドラッグは1回の元に戻す(`class_editing`)。手で配線するとき、始点のネットにクラスがあれば、その線幅・ビア(探索の格子も、クラスの間隔で作る `router_for`)で引く(`route_settings`)。テスト `a_route_of_a_classed_net_uses_the_class_width_and_via`
- 1フレームの時間(基板の窓、実基板、`app_frame_split_time`): 図形を作る 4.2 → 3.0 ms、三角形に分ける 2.3 ms。毎フレームやり直していた物を直した: (1) 基板が変わったかを見る鍵(`geometry_key`・`requirements_hash`・`silk_hash` など)は `pcb_core::zonefill::FastHasher`(変化の検出専用、標準の約4倍速。`geometry_key` 81 → 25 µs、1フレームに何度も呼ばれる)。(2) 部品の箱 `part_boxes`(パッドとシルクの状態で1回だけ作る。色分けと要件の組が 196 部品ぶん毎フレーム全パッドをなめていた 0.6 ms)。(3) 要件の印 `cached_marks`(`requirements::marks` は 180 µs)。残りの時間の中身(ms): 配線の鎖 0.66、ベタ 0.82、穴とシルク 0.46、要件の枠と線 0.31、左パネル 0.25。どれも動かない物を毎フレーム画面の座標へ直しているので、さらに削るなら、画面の座標のメッシュを、拡大・位置・基板の状態が同じ間は使い回す(マウスが動くだけの再描画が0に近くなる。ただし egui の図形の順序の扱いを作り替える大きめの仕事)
- パッド・ビア・穴の円(`draw.rs` の `disc`): egui は半径7 px 未満の塗り円を板1枚(2三角形)で描き、7 px 以上は多角形(97〜200三角形)にする。MSAA がオンのときは、7 px 以上だけ `ribbon::add_disc`(扇形、弦のずれ 0.17 px 以内、15〜30三角形)にし、小さい円は egui のまま(扇形のほうが多いため)。四角いパッドは `add_rect`。順序を保つため、egui の図形を挟む前に `ribbon::flush` でメッシュを渡す。実基板の全体表示で 7.6万 → 6.9万三角形(パッドと部品の銅 7,072 → 430)。円の三角形数の比較は `disc_cost`
- ベタの塗りの三角形と縁の線は、同じ「間引いた形」(`PourLod`、`draw.rs` の `pour_lod`。角が `POUR_THIN_PX`=1 px 以内の差なら落とす)から作る。間引きの段(拡大率)が変わったときだけ、塗りを三角形に分け直す(数 ms)。ネットにカーソルを合わせたときの光り(`netglow.rs`)も同じ形を使う。実基板の全体表示でベタ 5.1万 → 2.5万三角形、全体 10.1万 → 7.6万。0.5 px との画面の差は目立つ画素が数十個。計測は `pour_triangle_split`(塗り・縁・穴の内訳)と `pour_thinning`(間引く強さごとの三角形数)
- 線の縁の描き方は2通り(`ribbon.rs` の `set_plain_strips`、設定「線の縁をなめらかにする」= `Prefs.smooth_edges`、既定オン)。オン: 窓を MSAA 4(`NativeOptions.multisampling`。窓を作るときに決まるので次の起動から。`--no-msaa` でその回だけオフ)にして、帯は縁をぼかさない四角形(1区間2三角形、端は扇)。オフ: 縁を1 px かけて消す帯(1区間6三角形)。実基板の全体表示で全体 13.5万 → 10.1万三角形、CPU のフレーム時間 8.8 → 8.0 ms(GPU 側の負荷は未測定)。`set_plain_strips` はスレッドごとの設定で、描く(UI)スレッドで `main` が最初に決める。ほかの egui の図形は今までどおり縁をぼかす。比較は `plain_strips_frame_cost`、場所を決めた画面は起動引数 `--view <x mm> <y mm> <px/mm>`
- 配線の鎖の丸い端(キャップ)は、見えない所では作らない(`ribbon.rs` の `mark_caps`、`Chain.cap_start/cap_end`)。(1) 同じ点で2本以上の端が会い、2本が一直線(曲がり20°未満・太さが最太の3/4以上)なら無し(涙型の段・T字)。(2) それ以外の合流は最も太い1本だけ。(3) 同じ層でより太い(同じ太さの)鎖の途中にある端は無し。(4) パッド・ビアの下(`Covers`。パッド・ビアは銅のあとに描くため)は、キャップの進む側の半円がパッドに収まれば無し。パッドを隠すとキャップが戻るので、`Covers` の鍵が `CopperCache::is_for` に入る。実基板の全体表示で配線の鎖 4.5万 → 1.9万三角形(キャップ 2.9万 → 0.3万)、画面は元と最大 69/255 違うだけ(涙型の縁の1画素)。診断は `track_triangle_split`(直線・カーブ・キャップ・面の内訳)と `cap_ends`(残ったキャップの場所)
- 三角形数がフレームで変わる理由(`cargo test --release -p app triangle_settling -- --ignored --nocapture`、実基板で毎回同じ数): (1) 配線の仕上げ(`finished_async`)は別スレッドで、編集の直後 約0.1秒は仕上げ前の素の配線を描くので約3.3万個少ない(仕上げを切ると差が消える)。(2) egui の窓は出して最初の1フレームは描かれず、物の表示のパネルなどの約6.3千個が最初の1フレームだけ無い。(3) ベタは別スレッドでも、できるまで前のものを描き続けるので、数は揺れない。測るときは、編集のあと 0.3 秒ほど待つ
- シートの色分け(`sheets.rs`)と設計要件の枠・線・円(`requirements.rs`)は、egui の `rect_filled`/`line_segment`/`circle_stroke` を1つずつ呼ばず、`ribbon.rs` の `add_rect`・`add_frame`・`add_ring`・`add_chain` で1つのメッシュに入れ、札(タグ)の前に `ribbon::flush` で渡す(札が上に載る順序のため)。実基板(部品196個、ベタを切って測ると、数が毎回そろう)で 6.1万 → 1.1万三角形(色分け 3.6万→0.3万、要件の線 2.0万→0.7万、枠 0.5万→0.2万)。角丸は無くなった。円は `add_ring`(帯でなく輪っかの面。縁取りの上の円は縁を溶かさない)、縁取りは端を平らにして(`add_flat_chain`)2 px 長くする。計測は `cargo test --release -p app part_triangle_breakdown -- --ignored --nocapture`
- 配線の絵(`ribbon.rs`): 端と端がつながった同じ層・同じ太さの配線を1本の鎖にして(`chains`。一直線の途中の点は省き、120° を超えて折り返す所で切る)、1本の帯の三角形で描く(`add_chain`。曲がり角は角を合わせ、縁は1pxかけて薄くしてギザギザを消し、両端だけ丸い。「線 + 端の丸2つ」を配線ごとに作っていたのをやめた)。鎖と、仕上げ(涙型・凹み)の多角形の三角形分割は `CopperCache`(`copper_cache`)に持ち、配線か仕上げの結果が変わるまで使い回す。ズームに合わせて、画面で 1/4 px 未満の角を省いた版(`Lod`、`LODS`。ダグラス・プーカー)を、初めて使うときに作る。シルクの線と文字の字画も同じく鎖にして(`SilkCache`、`silk_cache`。シルクが変わるまで保持。部品に付いたものは `of_parts` に分け、部品の表示と一緒に出す)、層をまたいで1つのメッシュで描く(選んだ文字の枠だけは別)。幅が 2.5 px 未満の線は端の丸を省く(`ROUND_ENDS_FROM`。見分けがつかない)。ベタの輪郭線(`draw_zones`)も同じ間引き(`pour_outlines`。1px の線なので許す誤差は 0.5 px、ベタか間引きの段が変わるまで保持)をして、egui の線(1 区間 約6三角形)ではなく、1px 幅の四角(`add_hairline_ring`。2三角形、縁のぼかしと角の継ぎ目なし)を層ごとに1つのメッシュにして描く(ミリオームメーター基板で、ゾーンの三角形 179k → 57k)。選択・強調・DRC の印は、配線のネットとは別に上に重ねて描く(帯にはネットの情報を持たせない)。実測は `cargo test --release -p app frame_breakdown -- --ignored --nocapture`(種類ごとの図形・三角形・時間。ミリオームメーター基板で配線 11.6 ms → 約 2 ms)
- 部品のドラッグ中の軽さ(`view.rs` の `moving_parts_only`): 部品だけを動かしている間(1個のドラッグ・部品だけのグループ移動)は、ベタ(`draw_zones`)と整えた配線(`smoothing.rs` の `finished`)を前の結果のまま使い回し、ドラッグが終わったときに1回だけ計算し直す(どちらも小さな基板で 10〜30ms かかる)。配線が動くドラッグは対象外(配線が元の場所に残って見えるため)。ラッツネストは軽いので毎フレーム更新。シルクの鎖は部品ごとに持ち(`SilkCache::update`。変わった部品の分だけ作り直す。全体 20ms → 3ms で、ドラッグ中は動かした部品の分だけ)、配線の銅の鎖(`CopperCache`。パッドの位置がキーに入る)はドラッグ中は作り直さず前のものを使う(`is_for` の `moving_pads`。パッドの下のキャップが少し違って見えるのは離したときに1回で直る)。パッドの下のキャップの判定は遠いパッドを先に除く(`Cover::near`。12.5ms → 8ms)。実基板 196 部品で 1 フレーム 57ms → 8ms、ドラッグ開始の最初のフレームは 31ms → 6ms、離した瞬間は 47ms → 約 19ms(2回目以降の実測。離した直後は、エアワイヤの全体計算(ベタの分断の確認を含む)を別スレッドで行い(`view.rs` の `cached_airwires`・`airwire_job`。できるまでドラッグ中の線 `drag_shown` を出す)、パッドの位置だけが変わった銅の鎖の作り直しも別スレッドで行う(`draw.rs` の `refresh_caps`・`copper_job`。できるまで前の鎖を描く。配線そのものが変わったときは今までどおり同期)。結果待ちの間は `request_repaint_after` で描き直す)。計測は `cargo test --release -p app part_drag_frame_cost -- --ignored --nocapture`・`drag_start_cost`・`cache_rebuild_cost`。テスト `the_silk_and_copper_caches_are_kept_while_a_part_is_dragged`。ラッツネストも、ドラッグ開始時の銅のグループ(`drag_groups`)を使い回し、動かしている部品のパッドだけ別グループにして引き直す(`view.rs` の `drag_airwires`。毎フレームの `connectivity` を省く。ドラッグ中は配線が動かない前提の近似で、離したときに全体の計算に戻る。テスト `a_dragged_part_gets_airwires_to_the_copper_it_left`)。テスト `pours_are_kept_while_only_parts_are_dragged`
- 延長線トラッキング(`board_editor/tracking.rs`): 配線・ビア・外形・ベタのツールで、`snap_object` の点(パッド・ビア・配線の端)にカーソルを `HOLD`=0.3秒置くと拾い(最大3点)、その点を通る横縦のガイドの近く(10px)で吸い付く(`guided` は純関数でテストあり。2本のガイドは交点)。ガイドに沿う向きはグリッドのまま。既存物への吸着が先。`pointer`(interact.rs)から `track_guides` を呼ぶ。F11・Esc・`set_tool` で消す。選択ツールでは、ボタンを押していないときだけ点を拾い、部品のドラッグ中は部品の位置(ポインタから `drag_part` のオフセットだけずれた点)をガイドに吸わせる(グループ移動は未対応)。設定は保存しない
- ネットを一目で(`board_editor/netglow.rs`): 選択ツールでカーソルの下のネット(パッド→ビア→配線→ベタの銅の順で `net_under`)が光る(水色。クリックで固定する機能は、いらないので作っていない)。光らせるのは配線・パッド・ビア・ベタ(`draw_net_focus`)。大きなベタには、ネット名を文字で出す(`draw_pour_name`、「ネット名」の目のスイッチに従う。`merged_fills` がネット名も返す)。テスト `the_net_under_a_point_is_found_for_pads_and_tracks`

### schematic/net_hints.rs — ネットの電流・差動ペア
ネットラベルを選ぶと、左パネルに「流れる電流 (A)」と「差動ペアの相手」が出る。`Schematic.net_currents`(ネット名→A)と `Schematic.diff_pairs`(+側,−側)に保存(空なら書かない)。基板への取り込み(`board_editor/file.rs` の `import_from_schematic`、CLI の `board import`)で `pcb_core::netlist::import_hints` が、基板にパッドがあるネットだけ `Board.net_currents` と `Board.diff_pairs` に入れる。電流は回路図の値で上書き、ペアは既にあれば足さない。基板側だけで決めた設定は消さない。ネット名はラベルの文字なので、自動名(N$1 など)のネットには指定できない。

### schematic/requirements.rs・board_editor/requirements.rs — 設計の要件の表
「編集」メニューの「設計の要件 (表)…」(と回路図の左パネルの「設計の要件の表…」)で開く窓。設計全体(全シート)で1つの表を、3つの折りたたみで編集する: ネットの役割(名前・ネット・役割・線幅・間隔・電流・メモ)、近くに置く部品の組(部品・上限 mm)、離す組(A・B・下限 mm)。`Schematic.requirements`(`design_spec::DesignSpec`。空なら書かない)に直接書くので Undo は履歴の比較に乗る。カンマ区切りの欄は、打っている途中の文字を `req_buf` に持つ(読み戻すと、末尾のカンマが消えて打てなくなるため)。回路にない部品・ネット名は、窓の上にオレンジの ⚠ で出す(`Schematic::requirement_problems`。30 フレームごとと、変えたとき)。基板の画面は、左パネルの「③ 確認して発注」(DRC を実行 の下)に、取り込んだ組と距離のいまの配置での点検を出す(`requirements_check`。違反は組の部品を選ぶボタンつき)。サンプルは `buck_converter.schjson`(と `buck_cout_*`)。CLI は `req`・`board req`。ネットの役割の下の「詳細: 部品間の線幅」(折りたたみ。行ごとに 部品A — 部品B と幅。取り込みで `Board.link_widths` に)。「解析から入れる」(折りたたみ): 「DC解析の電流を調べる」で `dc_net_currents` から提案(`design_spec::suggest_from_currents`)を作り、チェックを付けたものを表に入れる。電流が空の行にはその行のネットの最大(2桁に切り上げ)、どの行にもないネットで 0.1 A 以上のものは行の追加(0.5 A 以上は役割 power)。書いてある電流と、スイッチングの行(DC では電流が出ない)は提案しない。CLI は `req suggest [apply=1]`。起動引数 `--requirements`(.schjson と一緒に。`--dc` も付けると、提案まで出す)で窓を開いたまま `--screenshot` できる。文字の欄は `add_sized` で幅を決める(グリッドの中の `desired_width` は、最初のフレームで残った幅に縮められて、名前の欄が数文字しか見えなかった)。 各行の「理由」(型では `note`)が空の行は、窓の上に「⚠ 理由が空の行が N 件あります」と名前を並べる(`DesignSpec::unexplained`)。数字は「何を」、理由は「なぜ」で、あとで読む人に意図を伝えるため。解析の提案で足した行は理由を空にしてある(書いてもらう)。同梱の降圧サンプルの表には、数字の理由を書いてある。
 窓の「回路図の上に枠を出す」(`req_frames`、既定オン)で、回路図の上に表を重ねる(`draw_requirement_frames`): 近くに置く組は色つきの枠と「近くに置く: 名前 (N mm 以内)」、離す組は A・B の二重の枠と「離す A: 名前 (N mm 以上)」。その回路図(シート)にある部品だけ囲む(ネット名で書いた側は囲まない)。表を開かなくても、回路図を見た人に意図が伝わる。基板の側は `board_editor/requirements.rs` の `draw_requirement_marks`(「組と離す距離を基板の上に出す」、`show_req_marks`)。（足りないときの色はピンク。上面の銅が赤・内層が緑なので、赤や緑だと配線に紛れる。線と枠の下に黒い縁取り `HALO` を敷く）`pcb_core::requirements::marks` が数字(組の広がり・離す組のいちばん近い2パッドと距離・守れているか)を返し、組は緑(守れていれば)か赤の枠と「組「名前」 31.2 / 25 mm」、離す組はいちばん近い2パッドを結ぶ線と距離(足りなければ赤)を描く。 表示の切り替えは3つで、設定ファイル(`prefs.rs` の `req_frames`・`req_groups`・`req_lines`)に保存される(`main.rs` が毎フレーム比べて、変わったときだけ書く。起動時に読む): 回路図の枠(左パネルの「設計の要件の枠」の目のアイコン。表が空のときは出ない。窓のチェックと同じ設定)、基板の組の枠と離す距離の線(右上「物の表示とロック」の「要件の組 (枠)」「要件の距離 (線)」。パネルの「組と離す距離を基板の上に出す」は両方をまとめて切る)。アイコンは `icons.rs` の `Frame`・`Gap`。シートの色分けも同じ一覧の行(「シートの色」。シートのある基板だけ出る。パネルの「シートごとに色分け」と同じ設定 `show_sheets`)で、`sheet_colors` として保存する。 「バイパスの対応」の欄(IC・コンデンサ・理由)と「回路から提案を作る」(`Schematic::bypass_suggestions` → `design_spec::suggest_bypass`。両側の電源を持つ IC → 同じシート → コンデンサの少ない IC の順で、提案ごとに決め手を文で出す。決まらないものは「確かめてください」と出る。ミリオームメーターで 42 件のうち、ルールで決まったのは 13 件)。

- **シートをまたぐ接続は、同じ名前のネットラベルと電源記号だけ。** ネット抽出・ERC・SPICE出力・シミュレーション・基板への取り込みは `Schematic::flat()`(全シートを `SHEET_STRIDE`=100000マスずつ右にずらして1枚に並べたもの)で処理する。`extract`・`net_at`・`erc`・`to_spice_for`・`from_schematic` の `build`・`netlist_of`(app と cli)が入口。座標がずれているので、シートが違えば線は絶対につながらない。
- 基板(段階4): 展開後の部品番号で、取り込み・配置・配線がそのまま通る(`sheet_name(slot)` が「子 (CH1)」を返すので、基板のシートの色分けと `autoplace sheets=1` も、コピーごと)。バックアノテーションは、コピーの部品(`BackAnnotation.copies`)を回路図に戻さず知らせる。テスト `the_copies_of_a_child_sheet_go_onto_a_board_and_are_routed`(cli)。
### part_form/step3d.rs — 部品の3Dの形 (STEP)
部品を作るフォームの「部品の形」タブの下に、「3D の形 (メーカーの STEP ファイル)」。「STEP を読み込む…」で `pcb_core::step::read_step` を呼び、`thin_out`(頂点を格子に寄せて、12000三角形以下に間引く)してから `step_base` に持つ。向き(X・Y・Z 軸に90°)・「本体の中心をパッドの中心に」・「本体の底を基板の面に」を `step_apply` で `model3d` に反映する。上から・横からの小さな図(`mesh_view`。赤い枠がパッド、緑の線が基板の面)で確かめる。**図は `egui::Mesh` で描くこと**(`convex_polygon` は角が羽毛化されて、細長い三角形がトゲになる)。`PartDef.model3d`(ライブラリの JSON に入る。空なら書かない)→ 回路図から基板への取り込み(`board_editor/file.rs`、CLI の `board import`)で `Board.models3d` へ。基板の3D(`view3d/scene.rs`)は `Scene.meshes` を三角形ごとに描き、高さ・ケースの高さの確認にも使う(メッシュの `z` の最大)。`--form-step <file>` は撮影用。限界: 既存の部品を開いて3Dだけ付け直す入口はない(部品の編集そのものが無い)。

### 基板への取り込み: ライブラリの部品のフットプリント(2026-10-25)
- `import_from_schematic`(`board_editor/file.rs`)は、ライブラリの部品が自分のフットプリントを連れてくる。**ライブラリが起動時のままだと、起動後にフォルダへ足した部品(`ccad part import`、ファイルのコピー)のフットプリントが見つからず**「フットプリント … が見つかりません」になった。今は、`SchEditor.library` に無いときは、既定のライブラリのフォルダ(`part_lib::default_dir()`)を一度だけ読み直して探す。それでも無いときは、警告に「回路図の『ライブラリ』の『再読み込み』を押すか、部品を作り直してから、もう一度取り込んでください」を足す(`import_notes`)。テスト `a_missing_library_footprint_says_to_reload_the_library`。
- **シミュレーション専用の部品(`Component.sim_only`。2026-10-25)**: 試験用の電源・測る相手の代わりの抵抗を、基板・部品表から外す印。`sch-core/lib.rs` の `Component.sim_only`(保存は立っているときだけ)、基板の取り込みは `cli/board.rs` と `app/board_editor/file.rs` の `netlist_of` が `!c.sim_only` で除く(ネットの中のその部品のピンは、基板に部品がないので無視される)。CLI は `simonly REF [off]`、アプリは `schematic/panel.rs` の部品の編集欄のチェックボックス。テスト: `sch-core/tests.rs` の `the_simulation_only_mark_is_saved_only_when_set`、`cli/tests/script.rs` の `a_simulation_only_part_simulates_but_is_left_off_the_board`。

- `board_editor/tools.rs` の `polygon_click`(2026-10-26): 外形・ゾーンのツールの多角形の描き方(ゾーンのツールの `zone_op` が足す/引く)。`PolyMode`(`mod.rs`: 直線 / 3点円弧 / 接線円弧 / 円 / 長方形)、`poly`(描きかけを短い直線にしたもの)、`poly_verts`(描きかけの頂点と円弧の通る点。確定すると `Shape` になる)、`arc_mid`(3点円弧の途中の点)、`pending`(円の中心・長方形の角)、`shape_round`(長方形の角の丸め)。円弧は `pcb_core::outline::arc_through`・`arc_tangent` で短い直線にして `poly` に足す。プレビューは `polygon_preview`(`draw.rs` の `draw_cursor`)。設定の行は `panel.rs` の `poly_mode_ui`。
- `board_editor/zoneedit.rs`(2026-10-26): 選んだベタの図形を、ポインタで直す。`zone_handle_at`(頂点・円弧の通る点)・`zone_edge_at`(辺)で当たりを見て、`interact.rs` の `pointer` がドラッグ(`vdrag`)・ダブルクリックで頂点を足す・右クリックのメニュー(`vmenu`、`zone_edit_menu`)を受ける。Delete は `canvas.rs` で、選んだ頂点(`vsel`)を先に消す。図形の操作は pcb-core の `shape.rs`(`nearest_edge`・`insert_vertex`・`remove_vertex`・`make_arc`・`make_line`)。
- シートごとの色分け(`board_editor/sheets.rs`): 回路図が複数シートのとき、取り込みで `Board.part_sheets`(部品番号→シート名。`netlist::import_sheets`。1シートだけなら空)に入れる。`draw_sheet_groups` が部品のまわりをシートの色(8色の輪)で囲み、グループの左上にシート名を出す。左パネルの `sheet_legend` に、色・シート名・個数のボタン(押すとそのシートの部品をまとめて選ぶ)と「シートごとに色分け」(`show_sheets`)。テスト `each_sheet_of_the_circuit_gets_its_own_colour`
- 距離を測るツール(`board_editor/measure.rs`、`Tool::Measure`、J3、2026-11-08): 2回クリックで 2 点の距離(mm・ΔX・ΔY・角度・mil)。1回目で始点、2回目で終点、3回目で測り直し、Esc で消す。クリックの点はパッド・ビア・配線の端に吸い付く(配線ツールと同じ `snap_object`)。状態は `BoardEditor.measure`(始点, 終点)と `measure_hover`(吸い付いたカーソル)だけで、基板は変えず、履歴にも入らない。表示は線・X と Y の脚・数字の札(ツールを選んでいる間だけ)。角度は上を正にしてある(基板の Y は下向き)。
