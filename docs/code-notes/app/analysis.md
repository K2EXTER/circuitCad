# app: 解析の窓と回路図の機能(インピーダンス・最悪ケース・極と零・バス・連動など)

(`docs/code-notes/app.md` の目次から分けた。内容は元のまま)

## インピーダンス(schematic/impedance.rs、2026-10-31)
解析タブの「インピーダンス (ネットから見た値)」。入力は `z_node`・`z_ref`・`z_remove`(外す部品)で、周波数は AC解析の欄を共用。結果 `ZView` は下の波形欄に |Z|(dBΩ)と位相の2段、左に両端の「何に見えるか」と山・谷の表。「回路図で選ぶ」は `noise_pick`(キャンバスの取り込み・Esc・バナー)を立てて `z_pick` で区別し、`pick_noise_node` から `pick_z_node` に回す。起動引数は `--z ネット 基準|- 外す部品|- [f0 f1 ppd]`。

## 最悪ケース(schematic/variation.rs、2026-10-31)
`run_mc` が `monte_carlo` のあとに同じ設定で `worst_case` を呼び、`McView.worst` に持つ。ばらつき解析の窓の左に「最悪ケース」(最小・最大と設計値からの%、ホバーで部品の組み合わせ、「現実的な範囲」の一行)、ヒストグラムに赤い縦線(軸も最悪ケースまで広げる)。電源の許容差は「許容差 %」の欄の「電源」(`mc_tol_v`、既定0)。最悪ケースとスペックの最悪行だけに使い、ランダムのばらつきは電源を変えない。

## 感度(schematic/sensitivity.rs、2026-11-09)
「温度とばらつき」の欄の「感度を計算 (効く部品の順)」。測る点・測るもの(DC電圧 / カットオフ / ステップ応答)は、ばらつき解析と同じ欄(`mc_out` `mc_kind` `mc_metric`)を使う。測るものの組み立ては `variation.rs` の `mc_measure()` に切り出して共有。結果は波形の場所(`WaveMode::Sens`)に、いちばん効く部品の一文、ほとんど効かない部品(効き 0.01 %/% 未満)の数、部品・値・1% 大きいとき・効き・棒(右=部品と同じ向き、左=逆向き)の表(40 行まで)。部品名をクリックで回路図の部品を選ぶ。起動引数 `--sens ノード [ac]`。テスト `variation_tests.rs`。

## 電源除去比(schematic/psrr.rs、2026-11-09)
解析タブの「電源除去比 (PSRR)」。揺らす電源(`psrr_source`、空なら最初の直流電源)と見る点(`psrr_out`)を選び、AC解析の欄の周波数で `run_psrr`。結果は AC のビューアー(`AcView.psrr_run`。自動で再計算すると `run_psrr` をやり直す)に、全ノードの信号として入り、見る点だけを選ぶ。除去比の数字(いちばん低い周波数・いちばん悪い所・100 Hz… の値と「揺れは 1/1k 倍」)は `AcView.notes` に入れて、グラフの上に警告とは別に出す。回路に IC(部品番号が U の、中に素子を持つ部品)があれば、モデルの除去比は実物よりよい、という注意を警告に足す。-3dB点の表は出さない。起動引数 `--psrr 電源|- ノード`。サンプル `psrr_filter.schjson`。テストは `psrr.rs`(ツェナーの例で、どこかのノードが揺れを減らす・見る点が空なら失敗)。

## 許容差の保存(schematic/tolerance.rs、2026-11-09)
「温度とばらつき」の許容差の欄(`mc_tol_r/c/l/v`)を、シートの JSON の `"tolerances"`(`{"r","c","l","v"}` の文字列)に保存する。既定(5/10/10/0)のままなら書かない(古いファイルは変わらない)。書き込みと読み出しは `with_tolerances`/`take_tolerances` で、スペック表・実測と同じ場所(`file.rs` の保存・自動保存・読み込み、`project.rs`、`files.rs`、`lessons/mod.rs` の `load_sample`)を通る。`adopt` で既定に戻す(ファイルが自分の許容差を持つ)。変えると未保存の変更になる(`saved_tol` と比べる)。ばらつき・最悪ケース・スペック表の許容差の範囲がこの値で決まるので、1% の抵抗で作る回路は開くたびに入れ直さなくてよい。

## 熱の結合の保存(2026-10-31)
部品どうしの熱抵抗 `A:B:K/W` は `Schematic.thermal_links`(`sch-core`。空なら書かない。シート全体で1つ。`set_thermal_link` は順序・大文字小文字を問わず置き換え、0 以下で消す)に持つ。画面の「結合」の欄(`htran_links`)は、欄を離れたとき(`lost_focus`、読める時だけ)と「温度の変化を計算」で `store_links` が回路図へ書く。回路図側が欄の元(`htran_links_seen`)と違う(ファイルを開いた・元に戻した)ときは、`panel_heat_tran` の先頭で欄を回路図に合わせる。CLI は `thermal link=Q1:RS1:150`(0 で消す)で保存し、`heattran` は `couple=` を省くと保存分を使う。

## 極と零(schematic/polezero.rs、2026-10-31)
解析タブの「極と零 (伝達関数)」。出力・入力のネット(「回路図で選ぶ」はクリック=出力、Shift+クリック=入力。`pz_pick` は `noise_pick` を共用して `pick_noise_node` から `pick_pz_node` へ)。`run_pz` が `sim_core::transfer_function` を呼び、`AcView`(`pz_run: true`)に「H 回路の応答」と「H 当てはめ」を入れて AC のボード線図で重ねる(自動で再計算するときは `run_pz` をやり直す)。パネルの下に `PzSummary`(極・零の一覧、複素数の対は Q と減衰、右半面は赤、当てはめの誤差が 2% 以上なら警告、安定の一言)。起動引数 `--pz 出力 入力|- [f0 f1 ppd]`。

## 値を動かしながら見る(候補 B9、2026-11-04)
- 部品の値スライダー(`panel.rs`)と「自動で再計算」(`wave.rs` の `live_update`)は前からあった。足したのは 2 つ: (1) **ペース調整**: 直前の再計算が 0.05 秒より長くかかった回路では、`live_cost` の 1.5 倍の時間が経つまで次の再計算を待つ(変更は `sch` に溜まるので、最後の値は必ず描かれる。`live_waiting` の間は canvas が 30ms 後に再描画を頼む)。軽い回路は毎回やり直す。(2) **変える前の線を残す**(`live_ghost`、既定オン): 0.6 秒以上の間のあとの最初の変更で、いまの過渡・AC の選んだ線を `tran_ghost` / `ac_ghost` でうすい「(前)」の線にして残す(同じ動かしている間は同じ線のまま)。手で「残す」ボタンで残した線は置き換わる。チェックボックスは、スライダーの「自動で再計算」の横。
- 収束しない値では、前の結果を残して理由を出す(前からの動作)。試験: `example_sim_tests.rs` の `live_recalculation_*`。
- 未実装: DC スイープ・パラメータスイープなど、過渡・AC・DC 以外は自動では再計算しない。

## バス(候補 B7、2026-11-04)
- **考え方**: ネットは前から「同じ名前のラベルは同じ配線」なので、バスの展開はいらない。バスは、(1) 見た目(太い青の線 `Schematic.buses`。何もつながない。`Sheet.buses` で、シートごと)、(2) バスのラベル `D[0..7]`(`D[7:0]`・`D[0-7]` も。`sch-core/bus.rs` の `parse_bus`・`bus_members`。**ネットの名前にならない**: `extract` が読み飛ばす)、(3) ERC の点検 `bus_problems` の 3 つ。ピンには、ふつうのラベル D0〜D7 を付ける。
- **点検**(`bus.rs`): バスのラベルがバスの線の上にない / バスの範囲の番号がどこにもつながっていない / ピン 1 つにしかつながっていない / 番号つきの配線がバスの範囲の外 / 同じ名前のバスの幅が食い違う(同じシートの中で)。すべて警告。
- **画面**: 「バス」ツール(`Tool::Bus`、配線ツールと同じ操作。`add_bus`)、`Sel::Bus`(選択・箱選択・移動・削除。`draw_buses`)。バスの線は**コピー&貼り付けに入らない**(`clipboard.rs`)。ラベルツールは `next_label`: テキストが `D[0..7]` なら、バスの線の上のクリックはバスの名前、それ以外のクリックは D0, D1, … と順に付ける(`label_k`)。普通の名前は、「番号を自動で進める」(`label_step`)で終わりの数字を進める。
- 未実装: バスエントリ(斜めの引き出し線。ラベルの連番で代える)・ネットリストの `D[0..7]` を使った部品のピンのバス(`D[0..7]` のピン名)・複数のバスの名前が違うものをつなぐ別名・ccad のコマンド(ラベルを `net` で 1 本ずつ作る)。
- 試験: `sch-core/src/tests.rs`(`bus_*`)、`schematic/select_tests.rs`(連番のラベル・選択と削除と Undo)、`example_sim_tests.rs` の `the_bus_sample_*`。

## 書き込み用ヘッダの点検(候補 B6、2026-11-05)
- 部品 JSON の `programming`(`[{name, pins:[ピン名…]}]`。形式は `docs/part-format.md`)が、回路図の部品の記号 `CustomSymbol.programming`(`sch-core`、`ProgInterface`)に入る。置いたときに記号へ写されるので、**この欄ができる前に保存した回路図には無い**(部品を置き直す)。
- 点検は `sch-core/programming.rs`(`erc` の中で動く)。書き込みの方法ごとに、ピン名ごとに「そのピンのネットに、ヘッダ(`Kind::Header`)か、番号が J・P・CN で始まるライブラリ部品が付いているか」を調べる。2 端子の抵抗・コンデンサ 1 つを挟んだ先も数える(リセットのコンデンサ経由の DTR や直列抵抗)。同じ名前のピンが複数(GND・VCC)なら、どれか 1 つで足りる。どの方法も全部そろっていなければ警告 1 つ(いちばん足りない数が少ない方法を message に、全部の方法の足りないピンを hint に)。
- 警告だけで、エラーにはしない(書き込み済みのチップを載せる、USB から書き込むチップなど、別の方法があり得る)。`sim_only` の部品は調べない。
- 入れた部品: ATtiny85(ISP)、ATmega328P(ISP と UART ブートローダ。リセットは UART の方に含めない=手動リセットでも書ける)、ATmega2560(ISP と UART0)。ピンの役割は AVR のデータシートのピン表どおり。他のマイコンは、部品を足すときに `programming` も入れる。
- 画面は ERC の一覧(新しい表示は無い)。サンプル `attiny_isp`。

## 回路図・基板・3D の選択の連動(2026-11-08)
- `link.rs` の `Focus{part, net}`(部品の参照名とネットの名前)。各エディタの `focus()`(回路図 `schematic/linked.rs`: 部品1つか、配線・ネットラベル1つのネット。基板 `board_editor/linked.rs`: 部品・配線・ビア・パッドの部品とネット)が、いま選んでいるものを返す。
- `App::sync_focus`(`main.rs`)が毎フレーム、前のフレームから変わったほうの `focus()` を、もう一方の `linked` に入れる(回路図が変わったら基板の `linked`、基板なら回路図の `linked`。同時なら回路図が先)。選んだ本人の `linked` は空にする(自分の選択は自分の描き方で見える)。3D 表示は基板の `linked` を読む。
- 見え方: 基板=ネットの銅が水色に光り(`netglow.rs` の `paint_net_glow`。ポインタの下のネットと同じ描き方)、部品はパッドを囲む水色の枠。回路図=ネットの配線を水色の太い線(`linked_wires` は `rev` と線の数が変わるまで覚える)、部品は枠。3D=ネットを光らせ(基板で選んでいないとき `linked.net` を使う)、部品は「選んだ部品」として強調し「選択部品へ寄る」が使える。
- 入口のスイッチ: 設定 → 「選んだ部品・ネットを回路図・基板・3Dで連動」(`Prefs.link_selection`。既定オン)。オフにすると `linked` を空にする。
- `--select R1` は、`.ccproj` を開いたときも回路図の部品を選ぶ(画面の確認用)。
- 確認: `tests/flow.rs` の `a_pick_in_one_editor_is_linked_to_the_others`、`schematic/linked.rs` のテスト、`mixed_signal` で R7 を選んで基板に枠が出ること(目で)。未確認: 回路図の側の見た目(枠・線)、3D での部品の強調の見え方。
- 未対応: 複数選択、パッドのピン単位の連動、基板で選んだネットが回路図のシートをまたぐ(階層)ときの飛び先。
