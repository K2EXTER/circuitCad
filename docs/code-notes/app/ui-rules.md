# app: 見た目の決まり(文字の大きさ・色・ボタン・窓の位置・左パネル)

(`docs/code-notes/app.md` の目次から分けた。内容は元のまま)

## 文字の大きさの決まり(startup.rs `install_japanese_font`、2026-11-01)
パネル・窓の文字は、整数の px だけを使う(この日本語フォントは、半端な大きさだとハイフンやマイナスの細い線が消える)。本文・ボタン 14、小さい文字(`.small()`・`ui.small`) 12(egui の既定は 9 で本文との差が大きく、注意書きが読めなかったので全体で上げた。窓ごとに上書きしない)、等幅 14。図(基板・波形・回路図の上のラベル)の文字は 10〜11 でよい(`painter` で直接描く所)。新しい文字を足すときは、この3つのどれかを使う。`RichText::size` で別の大きさを作るときは、ハイフンやマイナスが消えないか画面で確かめる(部品作成フォームのグラフの凡例には 13.5 がある)。

## 意味の色(`theme.rs`、2026-11-01)
`theme::ERROR`(赤、まちがい・不合格)・`WARN`(橙、注意)・`OK`(緑、よし)の3つだけ。パネル・窓の文字と、✔ ▲ ✖ の印は、新しい `Color32::from_rgb` を作らずこれを使う。以前は赤が7種・橙が7種・緑が3種の近い値に分かれていた(143か所を置き換えた)。基板の層の色(`view.rs` の `side_color`)・ビアなど、図の色は意味の色ではないので、たまたま近くても共通にしない。もっと明るい緑(90,190,110)や黄は、明るさを変えた別の用途なので残してある。

## 見た目の統一(`theme.rs`・`widgets.rs`、2026-11-05)
`theme::apply`(`startup.rs` から1回)が、行間(8×5)・ボタンの余白・角丸(ボタン4、窓8)・ボタンの灰色とホバーの枠・選択色をまとめて決める。窓ごとに `spacing` を上書きしない。意味の色のほかに `INFO`(水色。見出し・案内・「次にやること」)と `HIGHLIGHT`(金色。「次はこれ」・推奨の印)、アクセント `ACCENT`、余白の目盛り `SPACE_S/M/L`(4/8/12)がある。`widgets::primary_button(ui, enabled, label)` はパネルや窓の主役の操作に1つだけ(クイック追加・部品の保存)。ボタンは押していないときは全部グレーで同じ大きさなので、見た目は普通のボタンと同じ(押している間だけ `ACCENT`)。主役の操作をコードで探しやすくし、見た目を後でまとめて変えられるように関数にしてある、`widgets::section_heading` は窓の中の縦に並ぶ区切りの見出し(上に少し余白)、`widgets::heading_inline` は「閉じる」ボタンと同じ行にある窓の題名(余白なし)。表の見出し行・列名・系列名は見出しではないので `ui.strong` のままにする。パネルや窓の文字の色に新しい `Color32::from_rgb` は作らない。描画の色(配線・パッド・波形の系列色)は対象外。ステータスバーは「ヒント」の語だけ緑で、本文は普通の色(長いと1行に省略してホバーで全文)。タブの文字は14。
色は、意味色・`INFO`・`HIGHLIGHT` と波形の系列色(`plot.rs` の `PALETTE`)を、明度と彩度をそろえて色相だけで分ける(OKLCH で L 0.72〜0.78・C 0.14〜0.15)。青の3色(`INFO`・`ACCENT`・`SELECTED_BG`)は眩しくないよう控えめにした例外。選ばれているもの(タブ・ツール・リストの行)は `SELECTED_BG` + 白文字の1種類(`selection.stroke` は白。水色は `theme::INFO` を直接使う)。地色はパネル26・窓34・くぼみ15の3段。

## 左パネルの余白と折りたたみの一覧(`theme.rs`・`widgets.rs`・`schematic/panel.rs`、2026-11-05)
- **大きさ**: ボタンなどの最小の高さは 24px(`interact_size.y`。クリックの的として WCAG 2.2 の最小)。折りたたみの矢印の幅 `icon_width` 18、字下げ `INDENT` 20、行の間 `ROW_GAP` 5(`theme.rs` の定数)。
- **左パネルの余白**: 左パネル(`main.rs` の `sch_tools`)の内側は左右 12・上下 8。近いものは 4px(`SPACE_S`)、グループの間は `widgets::group_gap`(4 + 線 + 4)。
- **折りたたみ**: 最上段(基本の部品・ライブラリ部品)は `widgets::band_header(ui, id, title, open, flush, body)`。見出しの行が帯(閉じて 38、開いて 48、ホバーで +6 の灰色)の上に載り、開いている間は文字が太字。矢印の下の案内線は消す。`flush: true` なら中身が帯にすき間なく付く。**帯の全幅がクリックの的**(`ui.interact` を帯の上に重ねる。`id` は帯を区別する名前)。戻り値は `(応答, 帯が押されたか)` で、開閉の切り替えは呼ぶ側(`basic_open`/`lib_open`。2つは交代で開く)。
- **カード**(最上段の折りたたみの決まり): パネルの最上段の折りたたみは、帯 + 開いたら枠のカード。入れ子(部品の族・カテゴリ行・ひずみ率など)と窓の中は、文字と矢印だけ。カードは、見出しの帯から中身の下までを細い線(75、角丸 4)で囲み、中身の地色はパネルと同じ(26)。部品の一覧の中身は `widgets::well`(帯の幅いっぱいに左へはみ出す入れ物。余白 6。塗りも枠もなく、枠は `band_header` が描く)に全部入る。検索欄とカテゴリの選択は同じ高さ(28px)。一覧(`ScrollArea`)の高さは「窓の下端 − 今の位置 − 215」で自動(160〜900)。下に線を引き、端で切れた行が下の注記に重なって見えないようにしてある。
- **連結した帯**(`icons::segment_button`): 道具(選択・配線・バス・ラベル)と「元に戻す / やり直し」は、等幅・隙間なしの1本の帯(端だけ角丸、境目に細い線 58、選択中は青の塗りと水色の縁。中身とショートカットは中央)。モードを切り替えるものは連結、動作のボタンは単独、と見分ける。「クイック追加」は `widgets::primary_button_wide`(横いっぱい、文字は中央)。
- **文字だけのボタンの帯**(`widgets::segment_row`): 「部品を作る… / 選択を保存… / スニペット…」(選択がないと保存は灰色)と、点検の「設計の要件の表… / 選択を描きかけにする」。点検の ERC は `primary_button_wide`。区切り線は帯の下に1本ずつ(`panel_parts` の末尾の線は `panel_erc` の `group_gap` と重なるので置かない)。レッスンの強調(`lit`)は元の文言で一致を取るので、ボタンの文字を短くしても、`lit` には元の文言を渡す。
- **解析タブ・基板パネル**(`widgets::section_header(ui, id, default_open, title, hint, body)`): どの節にも帯(閉じて 38、ホバーで 46)があり、開いた節は帯が 48・太字(0.6px ずらして2度描く。フォントに太字がない)で、中身を帯と同じ幅の枠(カード)に入れる。字下げは 8px、案内線なし。行の全幅がクリックの的で、ホバーで指のカーソルと `hint` を出す。開閉は `id` で覚える(`CollapsingHeader` は使わない)。基板パネルの「作業の設定」「層構成」「① ② ③」「仕上げ」もこれ。解析タブの各節は「入力 → 横いっぱいの実行ボタン」の順。実行ボタンが「回路図で選ぶ」など別の部品と同じ行にいる節(ループゲイン・極と零・ノイズ・インピーダンス・パラメータスイープ・故障)は、幅をいっぱいにすると行があふれるので普通のボタンのまま。「すべて開く」も横いっぱいの普通のボタン。
- **幅の注意**: 左パネルは 400px で、1行に収まらない行(ラベルと選択肢を並べた行など)があると、パネルが広がってキャンバスを押す。1行で収まらない行は `ui.horizontal_wrapped` にする(温度とばらつき・故障シミュレーションで直した)。広がっていないかは、`section_header` の後に `ui.min_rect().right()` を一時的に出して、全部の節を開いた状態(右端 377px)で確かめた。
- **長い一覧は窓へ**(`schematic/result_tables.rs`): 解析タブの下のパネルには「ノード N 個・素子 M 個」と電力が最大の素子の2行だけを出し、DC結果の表(タブ: ノード電圧 / 素子)とネットリストは別の窓で開く(`State` が開閉・検索の文字・並べ替えを覚える。`panel.rs` の末尾で `result_windows` を呼ぶ)。検索は名前の部分一致(大文字小文字は無視)、並べ替えはノード=名前順/電圧が高い順、素子=名前順/電力/電流が大きい順。名前は `ui.link` で、押すと `goto_part`(部品を選んで画面の中心へ。別シートの部品ならそのシートを開く。`show_sheet` が `fit_pending` を立てるので、すぐ下げて合わせた画面を守る)。ネットの行は `goto_net` で、そのネットの最初のピンの部品へ。`Label::sense(click)` は効かなかったので `ui.link` を使う。
- **DC解析の電圧の表示**(`schematic/dc.rs` の `voltage_marks`、`DcView.marks`、2026-11-10): ピンごとではなく、**ネットごとに1つ**(シートごと。ラベルでつながった離れた部分にも繰り返さない。マイコンのピン1本ずつにラベルを付けたシートで、ラベルの数だけ値が並んでいた)。同じネットでも表示の文字が違うピン(基板の銅の抵抗の後ろ)は全部残すので、パターンの電圧降下は見える。GND はちょうど 0 V のときだけ出さない(銅の抵抗で浮いた GND のピンは出す)。回路のどこにも電圧がない(電源がない)ときは何も書かず、状態の行で「電源がない回路です」と言う(arduino_mega_usb は 233 個の「0 V」だった)。置く場所は、電源記号 → ネット名のラベル → 一番上(次に左)のピンの順。`pin_v`(全ピンの電圧)はテストの `pin_voltage` のために持つ。テスト `dc_overlay_*`。部品の電流(`draw.rs` の `draw_currents`)は 1 nA 未満(`MIN_SHOWN_CURRENT`。直流でのコンデンサ、何もつながらないピンの部品)を出さない(arduino_mega_usb でコンデンサごとに「0 A」が並んでいた。オペアンプの入力バイアスの数十 nA は残る)。
- **過渡解析の波形パネルの左側**(`schematic/tran.rs` の `tran_wave_panel`、2026-11-10): 上から「回路図で選ぶ / 選択をクリア / いまの波形を残す」の `segment_row`(残した後は3つ目が「前の波形を消す」)、信号の一覧(`horizontal_wrapped` で横に並べる。以前は一番下で、パネルの端で切れていた)、表を選ぶ `segment_bar`「基本 / ひずみ率 / ステップ応答 / 負荷の急変 / 電力と効率」、選んだ表を1つだけ、最後に「実測を重ねる」。以前は統計の表の下に4つの折りたたみが縦に積まれていた。選んだタブは `egui` のメモリ(`tran_metric`)に覚え、電力の信号が決まっていれば最初から「電力と効率」。左の列は全体で1つの縦スクロール、幅は 440〜580(5つのタブが1行に収まる幅)。「後半ほとんど動いていません」は短い1行+(?)。表の値は `eng`(有効数字4桁: 12.00 V・1.948 V・330.0 mV、0 は「0 V」)で、信号の大きさの 100万分の1 以下の AC実効値・振幅は計算の丸めとみなして 0 と出す(一定の 12 V が「0.04441pV」と出ていた)。波形パネルの最初の高さは 380。
- **AC の窓の左側**(`schematic/ac.rs` の `ac_wave_panel`。AC・ループゲイン・極と零・電源除去比が共用、2026-11-10): 過渡解析と同じ並び(「回路図で選ぶ / 選択をクリア / いまの特性を残す」の `segment_row`、残した後は「前の特性を消す」→ 横並びの信号の一覧 → 表 → 最後に「実測を重ねる」)。左の列は幅 360 で全体を縦スクロール。-3dB点が範囲にない信号は「—」(理由はホバー)。「安定性の余裕」は電源除去比と極と零では出さない。スペクトルの解析範囲の初期値は `format_value`(100u 〜 1m のように短く。以前は 1.000000e-4)。
- **信号の一覧**(`schematic/wave.rs` の `signal_list`。過渡解析と AC の窓が共用、2026-11-10): チェックボックスを横に並べ、高さ 84px(約3行)の中でスクロール。信号が 12 本を超えると上に絞り込みの欄(名前の部分一致、大文字小文字は無視。文字は `egui` の一時メモリ)。選んでいる信号はいつも先頭。名前の色は、`order` の中で選ばれた順の位置(グラフの線の色と同じ)。40 本ある mixed_signal で、一覧が表を押し出していたので作った。過渡解析の「部品の定格」は、注意か超過がある部品があるときだけ最初から開く。
- **dB のグラフの縦軸は量で書く**(`plot.rs` の `Style.db_ref` と `y_text`、2026-11-10): 曲線は dB のまま(対数の目盛り)で、目盛り・ホバーの読み・カーソルの値を「0 dB の値 × 10^(dB/20)」の量で書く。ノイズ(0 dB = 1 nV/√Hz → `V/√Hz`)、インピーダンス(1 Ω → `Ω`)、スペクトル(1 V ピーク → `V`)。以前は「51 dB」「-20 dBΩ」だけで、何の dB か分からなかった。範囲が 40 dB(2桁)以上で目盛りの間隔が 10 dB 以上なら、間隔を 20 dB の倍数にしてちょうどの桁(1µ, 10µ…)に置く。数は3桁で、末尾の 0 は消す(「1m」)。AC・電源除去比など、比(ゲイン)の dB は `None` のまま。テスト `db_values_are_labelled_with_the_quantity`。
- **結果と合う案内**(2026-11-10): 画面下のヒント(`schematic/hint.rs`)は解析ごと。温度スイープは DC スイープより先に見る(以前は後ろにあって一度も出なかった)。DC スイープは論理回路向けの「VIL・VIH」ではなく、線が折れる所の話。AC の窓はループゲイン・極と零・電源除去比で別のヒント(`AcView` の `loop_run` 等)。パラメータスイープ・故障の波形は `WaveMode`、波形のない故障シミュレーション・一括の故障・故障診断は、状態の行の書き出し(「故障シミュレーション:」「故障診断:」)で最後に動かしたものを見分ける。ループゲインが 1 を超えないときは、`AcView.notes` に「▲」で始まる注意を入れて上に橙色で出し(「⚠ 警告 N 件」に畳まない)、-3dB点の表は出さない。ほぼ 0(-100 dB 未満)なら「{部品} はループの途中にありません」。故障診断で 1 つの故障では説明できないとき(`unexplained`)は、見出しを「近い順 (どれも合いません)」にして割合と棒を出さない(割合は候補の間で 100% に割り振るので、合わなくても 1 位が 100% と出ていた)。テスト `a_cut_outside_the_loop_is_said_on_top_and_hints_follow_the_analysis`。
- **小さな直し(2026-11-10)**: 画面に合わせる(`symbols.rs` の `fit_view`)は、部品の名前と値の文字の幅も入れる(`text_bounds`。文字は 0.55 × ズーム px なので、まず部品だけで倍率を決め、その倍率の文字幅を足して合わせ直す。電源の「SIN(0 0.1 1k) AC 1」が左にはみ出していた)。ネットが見つからないときは、どの解析も `sim-core` の `dc::no_such_net`(「「X」という名前のネットがありません (ネット: …)」、候補は 30 個まで)。ばらつきのヒストグラムは、両端のほかに `nice_ticks` の目盛り(端の文字から 80px 以内は省く)。故障シミュレーションの結果は `plain_card` の枠に入れ、新しい結果が出たら1回だけそこまでスクロール(`fault_scroll`。一括の結果も同じ)。
- **英語の画面で長い文字**(2026-11-10): `segment_bar`/`segment_row` のボタンの文字がマスより長いときは、まず 1〜2px 小さく(整数の大きさだけ)、それでも入らなければ末尾を「…」で省く(全文はホバー)。英語は日本語より長いことが多い(過渡解析の表のタブ「Power and efficiency」)。解析の窓のエラー文(`ui.colored_label(ERROR, m)`)は `i18n::tr_dyn` を通す(通していなかったので、訳があっても日本語のまま出ていた)。
- **窓と画面合わせ(2026-11-10)**: 基板のレッスンの窓は左下のまま(右上は「物の表示とロック」の場所)で、基板の画面合わせ(`board_editor/view.rs` の `fit_view`)はレッスン中、その窓(`LESSON_WINDOW_PX` 390)と右の箱の間に基板を収める。回路図の画面合わせは、レッスンに加えてチャレンジの窓もよけ、キャンバスの大きさが変わったら合わせ直す(`canvas.rs` の `fit_if_needed`)。「発注の準備」の窓は画面の高さまで(以前は 640 で、4. 書き出しのボタンが下に隠れた)。クイック追加(`schematic/quick.rs`)は、ピン名は名前まるごとの一致だけ、説明文は英字なら単語の先頭だけ(日本語は途中でも)当て、ライブラリ部品の分類が基本の部品の名前を含むとき(「抵抗」「コンデンサ」…)はその別名(res・cap…)でも見つける(「res」で RESET ピンのある IC ばかり出て、ライブラリの抵抗が出なかった)。テスト `a_short_word_finds_the_kind_not_chips_with_a_pin_of_that_start`。
- **小さな窓の直し(2026-11-10)**: 3D の窓は `beside_panel()` に開く(位置の指定がなく左パネルの上に開いていた)。操作ガイドの窓は幅 760・画面の高さまで(640 × 560 では説明の列が数語ごとに折り返した)。ネットの一覧は件数と長さの1行を残し、並べ替え・ネット名のクリックの説明は (?) に。ネットの設定の窓の下の説明は「ほかのネットに切り替えるには (?)」。部品の点検(`part-lib` の `validate`)のメッセージから、使われていなかった「(name)」「(prefix)」の印を外した(部品作成フォームにそのまま見えていた)。
- **警告の折りたたみ**(`widgets::warning_lines(ui, id, lines, calm)`): 解析結果の警告が1件ならそのまま、2件以上は「⚠ 警告 N 件」の1行(閉じた状態)にまとめる。`calm` が真の行は注意書き(青い ⓘ)で、数えず外に出す(過渡解析の「普通のことです」)。DC・過渡・AC・ノイズ・DCスイープ・インピーダンスが使う(ループゲイン・極と零は未対応)。
- **結果の帯**(`panel_results` の末尾): 「結果の表…」「ネットリスト…」「SPICE書き出し…」を `segment_row` の1本にする。DC結果がないとき、結果の表は押せない(ホバーで理由)。
- **選ぶ帯**(`widgets::segment_bar(ui, items, selected)`): `segment_row` の「選んでいる1つが青く塗られる」版。選択中の項目は `selection.bg_fill` と太字、返す `Vec<Response>` の順は `items` と同じ。部品作成フォーム①基本の「部品の種類」(`part_form/kind.rs` の `PART_TYPES`。ホバー文は `bar[n].on_hover_text(PART_TYPES[n].2)`、切替のロジックは従来の `type_base` / `pending_type` のまま)と、その下の細かい種類(トランジスタ・ダイオード・コンデンサ・抵抗/コイル。`options` の配列)に使う。

- **基板パネルの帯とツール**(`board_editor/panel.rs`): 元に戻す/やり直しは回路図と同じ `segment_button` の2分割。① 取り込み+ピン名、向き・ゲート入れ替え・回路図に反映(あるものだけ)、② 自動で引く3つと手直し3つ(右端は「選んだネットだけ」。パッドを選んでいないと押せない)、③ 3D+発注の準備が `segment_row`。「部品を並べて外形を決める」と「DRC を実行」は `primary_button_wide`。帯に収めるため文字を短くし、説明はホバーに残す。ツールは `TOOL_GROUPS`(`mod.rs`。基本=選択/配線/ビア、銅・穴=ゾーン/穴付き/SMD/取付穴、外形・文字=矩形/多角形/シルク)の3つの帯(`tool_bar`)。ホバーは「正式名: 説明 (キー N)」。設定のあるツール(`has_tool_options`)を選ぶと、その帯の下の角を四角にし、すき間なしで `widgets::plain_card`(見出しなし・上が四角の枠)の設定をつなげる。アイコンだけの表示のときは従来どおり折り返して並べ、設定は全体の下に出す。「基板の外形」は、幅・高さ・角R を1行に並べ、その下に「矩形にする | 円・長円にする | 角を丸める」の帯(旧名は「矩形に設定」。DRC・発注前チェック・ヒント・docs の案内文も同じ名前にした)。

- **電流と電圧降下は ③ に**(`board_editor/width.rs` の `panel_widths`): 旧「高度な配線」の「配線の太さ (電流から)」の折りたたみはやめ、見出し「電流と電圧降下」の塊(電流の一覧の窓を開くボタン・細いネットの警告・配線の電圧降下)として ③ の「DRC を実行」の下に置く。ネットごとの電流と線幅は、ネットをクリックして出る窓(`netwindow.rs`)でも扱える。電圧降下を出したとき(`show_ir_drop`、CLI `--ir`)は `widths_open` を立て、`side_panel` が ③ の開閉状態(`board_sec_③ `)を開く(以前の、配線ツールへの切り替えはしない)。見出しの説明は (?) に入れ、「ネットの一覧 / 電流の一覧を別窓で開く」と「計算する / シミュレーションに反映」は `segment_row`、反映を「やめる」は「配線の電圧降下」の見出しの行の右端の `small_button`、色の目安は結果があるときだけ `help_small`(2026-11-10)。「高度な配線」はネットクラス・差動ペア・長さ合わせだけ。基板レッスン・操作ガイド・学習パスの案内文は ③ を指す。

## ボタンの決まり(`widgets.rs`、2026-11-01)
`ui.button` は、パネル・窓・手順の全体への操作(「DC動作点を解析」「DRC を実行」)。`ui.small_button` は、1行・1つの項目に付く操作(「削除」「外す」「解除」。要件の表の行の「削除」もこれ)。全部のボタンに `on_hover_text` を付ける(例外は、題名がそのまま説明になっているレッスンのメニューの項目)。結果の窓の「閉じる」は `widgets::close_button(ui, "波形")`(11か所)。窓を足すときは、これを使う。

## 窓の位置と幅の決まり(`widgets.rs`、2026-11-01)
左パネルを案内する窓(操作ガイド・発注の準備・値の決め方・組み立てて測る・実機の作業・シミュレーション設定・設計の要件・KiCad取り込み)は、`.default_pos(widgets::beside_panel())` で、パネルの右に開く(何もしないと左上に開いて、案内している左パネルを隠す)。レッスンとチャレンジの窓は、右上に固定で幅 440。表や図の窓は内容に合わせた幅(設計の要件 1200・部品作成 980・3D 900)。
- 基板のパネルの「③ 確認して発注」に表の中身(`board_editor/requirements.rs` の `requirements_table`)。行ごとに、基板が取り込んだか(✔/✖。ネットの行は、同じ名前のクラスにネットが入っているか。ほかは基板が持つ同じ行があるか)・理由(ホバー)・内容を出す。読み取りだけで、「回路図で表を開く」は `BoardEditor.open_sch_requirements` を立て、`main.rs` が回路図の表の窓を開く。届かない行があれば最初から開く。
- 用語集・索引(`glossary.rs`): `TERMS` に、語の名前・読み(ひらがな)・別名・種類(回路 / 操作)・短い説明を並べる。窓は「学ぶ」→「用語集・索引…」(`--glossary [語]` で語を開く)。検索は名前・読み・別名で、カタカナと大文字小文字は区別しない。一覧は読み順で、「ー」は前の母音として並べ、五十音の行ごとに見出しを出す。**索引は手で書かない**: 語がどのレッスンに出るかは、`schematic::lesson_texts()`(各レッスンのタイトル・目標・説明・手順・実物との違い・実機)から、語の名前か別名(2文字以上)を探して作る(`lessons_of`)。レッスンの窓の「このレッスンの用語」(折りたたみ)は同じ探し方(`terms_in`)で、語を押すと `SchEditor::glossary_request` を介して用語集が開く。語を足したら、テスト `every_term_is_used_by_a_lesson` が、どのレッスンにも出ない語(索引が空になる)を教える。
- 用語集に基板の言葉(`Kind::Board`。基板・配線・線幅・間隔・パッド・ビア・未配線・DRC・ガーバー・差動ペアなど)を足した。索引の対象は、回路図のレッスンに加えて**基板のレッスン**(`board_editor/lesson.rs` の `lesson_texts()`。レッスン `which` 0〜7 のタイトル・目標・手順。目標とタイトルと手順は `goal_of`・`title_of`・`steps_of` から引く)。`lessons_of` は `Target::Schematic(i)` / `Target::Board(which)` を返し、用語集の窓のボタンで、回路図のレッスンは `start_lesson`、基板のレッスンは `start_board_lesson` で始まる。
