# app: 開発用の検算・描画と波形・学習パスと操作ガイド・プロジェクトと未保存の確認

(`docs/code-notes/app.md` の目次から分けた。内容は元のまま)

## 開発用の検算 (xcheck)
- 開発用の検算 `xcheck.rs` / `xcheck_tran.rs`: `circuitCad --xcheck <file|dir>` が自前のDC動作点(電圧と電流)を、`--xcheck <file|dir> --tran` が過渡波形を(電源が時間変化しない回路は `xcheck_tran.rs` の `own_dynamics` の表の長さで。DC動作点が無くゼロ状態から始まった回路は ngspice にも `uic` を付ける。時間で重みを付けた規格化RMS誤差1%未満か、エッジ主体の波形はエッジ時刻のずれが周期の2%以内なら一致)ngspice と比べて `xcheck_report.txt` / `xcheck_tran_report.txt` に書く(ウィンドウは開かない。ngspice の場所は `--ngspice` か環境変数 `NGSPICE`、既定 `F:\Tools\ngspice\Spice64\bin\ngspice_con.exe`)。ngspice は reltol=1e-6 で解かせる(既定の1e-3だと ngspice 自身の電流が食い違う)。差が出たら gmin=1e-15 でも解き直し、それで一致すれば「gmin依存」。スイッチ(`S` と `.model SW`)は ngspice に `vw` が無いので、方言変換が自前と同じ滑らかな導通の B 電流源 `I=V(a,b)*exp(…)` に置き換える(これで降圧コンバータ・NE555・論理ICが ngspice と合う)。既知の差: 電源投入直後のフリップフロップなど双安定の回路は、自前が釣り合い点にとどまり ngspice が片側に倒れるので合わない(`logic_blinker`、`variable_supply`の浮いた2次側)。ngspice が止まる回路もある(トランス、`led_blinker`)。方言変換は `sch-core/src/ngspice.rs`(`to_spice_for(.., Dialect::Ngspice)`: if/step/limit/log/temp)。`--ourstep` `--ngstep` `--lte` で片方の刻みや許容だけ変えて、どちらのエンジンが粗い刻みに弱いかを見られる。

- AC解析の検算 `xcheck_ac.rs`: `circuitCad --xcheck <file|dir> --ac [--golden <json>]`。値に `AC` を含む電源のある回路を 10Hz〜10MHz・1デケード5点で自前と ngspice(`ac dec`、`wrdata` は周波数のあと実部・虚部の組)に解かせ、ノードごとの複素数の差を 相対0.1% + ノードの最大値の1ppm + 1e-12 で比べる。保存は `docs/xcheck/ngspice_ac.json`(実部・虚部の生の値)、CIのテスト `ac_sweeps_still_match_the_stored_ngspice_answers`。外してある回路: `bridge_rectifier` `variable_supply`(2次側が浮いていて共通電位が不定、差は合う)、`mixed_signal`(自前の動作点が収束しない)。ノイズ・DCスイープはまだ照合していない。
- AC解析のグラフに最初から出す信号(`schematic/ac.rs` の `run_ac`): 電圧のうち**応答が 1e-9 倍より大きいもの**(AC 電源が届く節点)の先頭 3 つ。届かない節点(電源ラインなど、直流の電源だけにつながる所)は 0 倍=−∞ dB の平らな線で、グラフの縦軸を引き伸ばし、−3dB の欄が「—」(以前は「範囲内にありません」)ばかりになるため、選ばない。どれも応答がなければ従来どおり先頭 3 つ。テストは `lessons_tests.rs` の `the_ac_run_selects_signals_that_respond_and_not_the_dc_supply`。
- CIでの検算: `docs/xcheck/ngspice_dc.json` に、同梱サンプルの ngspice のDC動作点(生の出力)が保存してあり、テスト `dc_points_still_match_the_stored_ngspice_answers` が自前の結果と比べる(ngspice は不要)。保存するのは既定設定で一致した回路だけ(`ip2332_charger` は gmin依存、`variable_supply` はズレなので外れている)。モデルを意図して変えたら `circuitCad --xcheck docs/examples --golden docs/xcheck/ngspice_dc.json --keep-set` で作り直し、差分を読む。`--keep-set`(DC・`--tran`・`--ac` のどれにも付く。`xcheck.rs` の `stored_set` `golden_files` `keep_set_note`)は、保存ファイルに今ある回路だけを回して書き直す: 回路の組が変わらず、前は保存していなかったサンプルが増えない。前は保存していたのに今回は合わなかった回路は、報告の最後の行に出る。回路の組そのものを見直すときだけ `--keep-set` を外す。

- 過渡波形のCI検算: `docs/xcheck/ngspice_tran.json` に、同梱サンプル32件の ngspice の過渡解析を「10個の窓ごとの平均・最小・最大」にまとめて保存してある(`xcheck_tran.rs` の `window_stats`)。テスト `transient_runs_still_match_the_stored_ngspice_statistics` が、保存した刻みで自前を走らせ、窓の平均(振れ幅の1%)・最小最大(3%、最初の窓は除く)・リップル(10%、`local_ripple`: 終わり5分の1を100分割した各区間のp-pの中央値。整定途中のゆっくりした揺れや1周期だけの外れ値に影響されない。終わり2窓の幅がリップルの10倍を超える波形、例えばパルス列は比べない)を比べる。リップルを「終わり2窓の最大−最小」で測ると、macOS だけ+12.6%ずれた(5ms でもまだ整定途中で、揺れの位相が CPU の丸めで変わる。周期ごとの山の中央値は3OSで一致)。波形そのものでなく統計なのは、スイッチング波形は点を間引くとエッジが崩れるため。降圧コンバータの出力コンデンサ違い2件は、定常のリップルを見るため5ms走らせる(`own_dynamics`)。作り直しは `circuitCad --xcheck docs/examples --tran --golden docs/xcheck/ngspice_tran.json`。

- `samples.rs`: 「ファイル → サンプル回路を開く」の一覧(`SAMPLES`。`docs/examples` と同じファイルを `include_str!` で埋め込む。足すときは1行と、タイトルが重ならないこと)。`SchEditor::open_sample` は未保存のシートとして開く(上書き保存でサンプルが壊れない)。`SchEditor::new_file` は `rev` を巻き戻さない(基板の「回路図と違います」の判定が `rev` をキーにしているため。巻き戻すと、別の回路を開いても古い判定が残る)。基板だけを開いたとき(回路図が空)は「回路図と違います」を出さない。
- スペック表の「実測」欄(`spec_table.rs`): 行ごとに `measured`(入力した文字のまま `.schjson`/`.ccproj` の `"specs"` に保存。無ければキーを書かない)。`sim-core::compare_measured` が差・近さ(Close/Some/Far)・理由の手がかりを返す。`add_measure_rows` は学習パスの「組み立てて、性能を測る」用(VIN・VOUT・電流の行を足してDC動作点を計算)、`compared_measurements` は比べられた実測の数(3以上で `build_psu` を完了にする。`main.rs`)。`measure_guide.rs` が案内の窓(`--measure-guide` で開く)。
  - 実測の判定(2026-11-09): 「実測」欄は `3.29, 3.31` のようにカンマ(`、` `;` `/` も可)で区切ると何枚分も入る(`sim_core::split_readings`)。`compare_readings` が1枚ずつ比べ、一番悪いものを行の判定にし、平均・最小〜最大と A/B/C ごとの ✓△× を出す。DC電圧と -3dB点の行は、実測があるときだけ、「温度とばらつき」の許容差(回路図と一緒に保存。`tolerance.rs`)での最悪ケース(`worst_for_spec`、キャッシュあり)を範囲として渡す(`tolerance_query` が `V(F1)` → ノード `F1`)。`compare_measured_in` は範囲の端からのずれで判定するので、範囲は「合う」側を広げるだけ(範囲がほぼ 0 の値 = IC が決める値は、今までと同じ判定)。範囲の幅がシミュレーション値の 0.2% 以下なら「許容差ではほとんど動きません」と出す(モデルが IC・ダイオードの個体差を持たないため)
- 実測を波形に重ねる(`schematic/bench_data.rs`、2026-11-09): 過渡と AC の波形の左の列の「実測を重ねる」。貼った表か CSV(`read_table`: `,` タブ `;` 空白で区切り、数字だけの行のうち、一番多い列数の行を採る。見出しやオシロの設定の行は飛ばす)を `BenchCurve{name, signal, x, y, phase, shift}` にし、`SchEditor.bench`(`BenchData{tran, ac}`)に持つ。保存はシートの JSON の `"bench"`(`with_bench`/`take_bench`、無ければキーなし。`.schjson`・自動保存・`.ccproj`)。`Schematic` の外に置くのは、回路の `signature` を変えない(結果が古い扱いにならない)ため。未保存の判定は `saved_bench` との比較。AC は「周波数 dB [位相]」か「周波数 入力 出力 [位相]」(`AcColumns`)。描画は `plot::Trace.dots`(点と細い破線。過渡は 60 点以下のときだけ点)で、色は「比べる信号」の色(`bench_color`)。AC は点ごとの差の表と、実測の -3dB点(`measured_cutoff`: 最初の点から 3dB 下)、過渡は「時間のずらし」と「立ち上がりを合わせる」(`first_edge`: 振れ幅の真ん中を最初に横切る時刻)、変化の 10→90%(`edge_time`。振れ幅の上下は 1%・99% の値で、雑音のとがりを除く)
- 部品名・値のラベル(`draw.rs draw_components`): 幅のある部品は名前を上、値を下に中央寄せで置くが、上下の辺の中央にピンがあるとき(IC の GND など)は配線の左側へ寄せる(電圧は常にピンの右側に出るため)。LED は光の矢印の分だけ名前を上へ(逆向きなら値を下へ)。電流の文字も、下に配線があれば左へ。

## 描画・波形・プロット
- 電源記号は値で形が変わる(`symbols.rs` の `source_symbol`: 直流=±の円、SIN=正弦波、PULSE=方形波、PWL/NOISE=折れ線)。
- `plot.rs` の `scale_bar` は横軸・縦軸(グループごと)の範囲入力・全体・自動(1行、過渡・ACの波形パネルの上に出る。拡大縮小は軸の数字の上のホイール)。
- `plot.rs` 波形描画 (`scale_bar`・`draw_group`・`PlotState`)。
- 軸の数字の上でホイール=その軸だけ拡大縮小(`draw_group`)。
- `PlotState.cursors` が測定カーソルA/B(クリックで置く、`cursor_report` が差・周期を出す)。

## 作ってみよう・学習パス・操作ガイド
- `schematic/challenge/` は「作ってみよう」(`mod.rs`=型・`CHALLENGES` の並び・開始/判定の入口、`basic.rs`/`power.rs`=チャレンジ1件ずつの `const`、`judge.rs`=模範解答・開始シート・判定、`window.rs`=窓)(目標だけ示して自分で部品を置き・配線し、「判定する」でシミュレーションして判定する。1つの模範解答とは比べない)。 **シミュレーションできない回路(マイコンの基板)は、`Check::Joined`(このピンたちが同じネット)と `Check::Between`(この2つのネットの間に、この種類の部品が min 個あり、値が範囲内)で、つなぎ方と値を判定する。部品は種類で探す(基本の C/R も、ライブラリのチップ部品 `C_100n_0603` も同じ種類)ので、番号を振りなおしても通る。`arduino.rs` の `DRAW_ARDUINO` が例(答えは `docs/examples/arduino_minimal.schjson`、開始は部品13個を置いたものと、U1・J1・V1 だけのもの)。**
- チャレンジは `CHALLENGES` のデータ(開始シート `parts0/parts1/grounds*/start_values`、答え=サンプルの `drop/values/labels/rename`、判定 `checks`: `Erc`/`Named`(出力ネット `VOUT`)/`Voltage`(負荷・入力を足して測る、値の範囲ごとの助言 `explain`)/`Stay`(入力を2点に振る)/`Current`/`Gain`(AC)/`Ratings`)。
- 足すときは `CHALLENGES` に1件とテスト(答えが通る)。
- いまは zener・divider・led・rc_lowpass・emitter_follower・opamp_inv・series_regulator・regulator_78xx と、最終課題 draw_psu(lesson は protection、学習パスの `Kind::Build` の項目から id で開く。部品の個数を調べる `Check::Has` あり、答えは `power_supply.schjson`)。
- `--challenge <id> [0|1] [--judge]`、通過は進み具合に `<id>+build`、レッスン窓の「チャレンジを始める」と学習パスの「作ってみよう」から開く。
- 基板のレッスンは3つ(`board_editor/lesson.rs`。`BoardLesson.which` 0=回路図から発注まで、1=配線の電圧降下、2=チャレンジ「発注前チェックをすべて通す」(`FIX_STEPS`、完了キー `board_fix`、`docs/examples/order_fix.ccproj`: 部品D1が基板の外・D1につながる配線が無い(未配線2本)・N$1とGNDに1.5 Aを設定済みで配線は0.25 mm・DRCルールが発注先より緩い。手順は発注の準備を開く→D1を中へ→配線→足りない配線を太く→発注先を選びルールを合わせ ✖ と ▲ を無くす。判定は `order_clean`=標準以外の発注先で `preflight` に Error/Warn が無いこと。`ccproj` は `regulator_led` を `ccad` で配置・配線→D1を+15.5 mm動かし配線と silk と文字を整える)。学習パスの `Kind::Board(n)`/`Action::Board(n)`、完了の記録は `finished_board_lesson`(`board` / `board_copper`)。2つ目は `docs/examples/thin_power_line.ccproj` をプログラムに埋め込み(`project::parse`)、`App::start_board_lesson(1)` が回路図と基板を差し替えて始める。手順の完了は `post_layout_fresh`(反映した直後 true、配線を太くすると false)と `net_currents` と `net_widths` で判定。`--board-lesson 0|1` は撮影用)。
- `learn.rs` の `NEXT_STEPS`: 「学習パス」窓の「この先へ: 使いこむための機能」(折りたたみ。進み具合が「いま学べる」すべて完了なら最初から開く)。レッスンのあとに使える機能(配線を整える・電流から配線の太さ・差動ペアと長さ合わせ・発注と購入リスト・故障・ばらつきと温度・ほかのソフトとの行き来・`ccad`)を、1件ずつ「何か」「どこにあるか(画面のボタン名のとおり)」で並べる。**ボタン名や場所を変えたら、`NEXT_STEPS` の `where_` も直す**(画面の文字と一致を調べるテストは無い)。
- `learn.rs` は学習パス(`PATHS` に段階と項目を書く。レッスンは `id` で指定、準備中は `planned` / `plan`。**樹形図**: 項目の `requires` に「先に済ませると分かりやすい」項目の id を書くと(別のパスの項目も指せる)、`recommended` が前提のそろった項目を複数返し、窓が `tree_map` で地図を描く。`requires: None` は「直前の項目」(従来の直線)、`Some(&[])` は根。鍵はかけない。`ARDUINO_PATH` が樹形図のパス。`--learn <パスid>` でそのパスを開く)と完了の記録(`%APPDATA%\circuitCad\progress.json`)と「学習パス」窓(`--learn`)。初回起動だけ `welcome_card`(引数なし・進捗なし・未回答のとき、`progress.json` の `"welcomed"` で一度きり)。学習パス窓の説明文は `spaced`(行の高さ)と `NOTE`(灰色)で読みやすくしてある。回路図のライブラリ部品の欄は初期状態で閉じている。
- 設計は `docs/learning-path.md`。
- `help.rs` は「操作ガイド」窓(ヘルプメニュー・F1・各パネルの「操作」ボタン、`--guide`。操作の説明は小さい文字で各所に書かず、ここの `SCHEMATIC`/`WAVEFORM`/`BOARD`/`VIEW3D` に足す)。

## プロジェクト・未保存の変更
- `project.rs` プロジェクト(`.ccproj`=回路図+基板を1つのJSONに。`version` つき。ファイル→プロジェクトを開く/保存、起動引数に `.ccproj`。`SchEditor::adopt`/`BoardEditor::adopt` で両方を置き換える。個別の `.schjson`/`.pcbjson` の保存も残してある)。
- 未保存の変更は `SchEditor::dirty`/`BoardEditor::dirty`(`rev` と `saved_rev`: 回路図は `commit_history`・`reset_history`、基板は `checkpoint`・`adopt` で進む。保存で `mark_saved`)で調べ、`files.rs` の `confirm_unsaved`(プロジェクトを開く・新規・開く・ウィンドウを閉じる。`--screenshot` の自動終了では聞かない)が rfd のはい/いいえ/キャンセルで確認する。
- 基板が回路図とずれているかは `BoardEditor::schematic_diff`(取込と同じ `netlist_of` で、追加/削除/値・形/つなぎを数える。回路図と基板の `rev` でキャッシュ)で、基板タブの ● と基板パネルの橙の文に出る。

## ファイル構成の補足 (main.rs まわり)
- `main.rs` ウィンドウ・メニュー(`App`)、`tips.rs` `TIPS`(豆知識)、`args.rs` 引数処理(`.schjson` と一緒に `--sheet N` で N 番目のシートを開く。画面保存用)、`files.rs` 保存・読込・未保存の確認、`screenshot.rs` 画面保存、`startup.rs` クラッシュログ・フォント、`schematic/title_block.rs` 図枠(`Schematic.title_block`: タイトル・版・日付・作者・メモ。ファイルメニューの窓で書き、SVG の右下に枠で描く。空なら何も出ず、ファイルにも書かない)、`autosave.rs` 自動保存と復旧(保存していない変更があるとき、1分ごとに `%APPDATA%\circuitCadutosave\` へ `sch.schjson`・`board.pcbjson`・`meta.json`(元のファイル名)を書く。ふつうに閉じる・保存した・「捨てる」で消える。引数なしの起動で残っていれば「復元する/捨てる」を聞く。復元したものは未保存の扱いで、元のファイル名を引き継ぐ)、`prefs.rs` 表示設定(アイコンのみ・ヒント表示)を `%APPDATA%\circuitCad\settings.json` に保存(設定メニューで変えたとき書く。`--icons-only` はその起動だけ上書き)、`schematic/glyphs.rs` の `overlay_glyph`/`overlay`(箱は残して中に印を描く記号: ロジックゲート `gate_*`=74HC00/02/04/08/14/32/86 の名前から自動・3端子レギュレータ `regulator`=IN/OUT/GND の3ピンから自動・フリップフロップ `ff_d`(74HC74)/カウンタ `counter`(4017・4020・4040・161・163・393)/シフトレジスタ `shift_reg`(595・164)=名前から自動。`comparator` は三角形+段の印で LM393 など。名前の推測は `sch-core` の `inferred_glyph`)、`schematic/symbols.rs` の `paint_kind_preview` / `paint_lines_preview` は部品リストの記号プレビュー(基本部品は `symbol`、ライブラリ部品は `symbol_lines`)、`icons.rs` の `help` / `help_small` / `help_label` は長い説明を「(?)」のホバーにまとめる(短い見出し+(?)。部品作成フォームの説明文はこれ)、ツールのアイコン(painterで描く。フォント不要)と「アイコン+文字/アイコンのみ」の切替(`icon_button`、設定メニュー、`--icons-only`)。ツールバーに足すときは `Icon` を増やして `icon_button` を使う、`tests/` 統合テスト(`flow.rs`)とサンプル生成(`examples.rs` の `write_*`、`--ignored` で実行)。
- 「ファイル → 回路図をSVGで保存」(`schematic/svg.rs` の `sheet_svg`/`export_svg`)は、画面と同じ `draw_wires`・`draw_components` などを、使い捨ての egui の `Context`(日本語フォントを入れて1回空で回す)に描かせ、出てきた図形(線・円・四角・多角形・文字)を SVG の要素に書き直す。描画コードを二重に持たないので、記号やラベルを足しても自動で SVG に出る。グリッド・選択・ERC の丸・編集の印は入れず、電圧・電流の数字と色は出ていれば入る。文字は egui が測った幅を `textLength` で守る(右寄せ・中央寄せの位置が、見る側のフォントで動かない)。起動引数 `--svg file.svg`(`--dc` などの後に書いて終了)。PDF は未対応(ブラウザの印刷でできる。`docs/candidates.md` の I2)。
- 「ファイル → 画面をPNGで保存」は eframe の Screenshot(`finish_screenshot`)で、起動引数 `--screenshot file.png` は数フレーム後に撮って終了(画面の確認・文書づくり用)。
- 回路図の PDF(`schematic/pdf.rs`、I2、2026-11-08): 「ファイル → 回路図をPDFで保存」と `--pdf file.pdf`。SVG と同じ図(`svg.rs` の `sheet_shapes` が egui の図形を作り、`shapes_to_pdf` が PDF にする)を、図の大きさに切った1ページにする。PDF は自前で書く(カタログ・ページ・内容の4つの物と xref。依存は文字の形を読む `ttf-parser` だけ)。線・円(ベジェ4本)・四角・折れ線は PDF の線と塗り、半透明は背景と混ぜた色にする(透明度は使わない)。**文字は同梱フォント(BIZ UD Gothic)のアウトラインを塗りつぶして描く**ので、フォントを埋め込まずに日本語がどの環境でも同じに出る。代わりに PDF の中で文字の検索・コピーはできない。字間は SVG の `textLength` と同じく egui の幅に合わせて広げ縮め(±0.3 文字まで)、行の高さの真ん中を字の上端と下端の真ん中に合わせる。図枠(J2)はそのまま入る。テストは `datasheet` の PDF リーダーで開いて、1ページ・インクあり・背景色を確かめる。目で見るには `CCAD_PDF=in.pdf CCAD_PNG=out.png cargo test -p app look_at_pdf -- --ignored`。
