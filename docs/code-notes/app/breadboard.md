## 左のパネルの並び (2026-11-24)

3 つの基板で同じ順にそろえてある (`breadboard/panel.rs` の `panel`、ストリップ基板とユニバーサル基板は `strip_view.rs` の `strip_panel`): 基板の種類の帯 (`widgets::segment_bar`) と「回路図を小窓で見る」・その基板の説明は「(?)」→ 回路図との照合 (`check_ui`) → 道具 (1 行。裏の絵では編集の道具だけ灰色で理由つき) と 元に戻す・自動で並べ直す → 電源 (`power_button`。ストリップ基板とユニバーサル基板は「組む順と通電」と並ぶ) と動かしている間の欄・テスター・オシロ → スケッチ → 折りたたみの帯 (`fold`。開け閉めは egui の一時データに保つ): 「基板の大きさ」(題に今の穴の数と mm。開くと大きさ・チップを裏に・印刷用の図)・「区画」(案を出すと開く)・「部品と差す穴」。パネル全体が 1 つのスクロール。道具の操作の説明は、ブレッドボードと同じく絵の上の 1 行 (`strip_legend`)。

## タブと学習のモードの方針 (2026-11-16・18 に決めた。候補の一覧の B 節から移した)

**学習向けと設計向けの分け方(2026-11-16 に決めた)**: 分けるのは**画面と入口**で、**回路のデータとシミュレータは分けない**。
- **画面は分ける**: B4・B6・B8・B9・B10・B11(音で聴く・ブレッドボード・デジタルを動かしながら見る・ブラウザで動く版・授業で使う形・部品の役割の説明)は学習のモードにし、学習パス・レッスン・ウェルカムカードから入る。設計の画面のパネルには並べない(U1 で減らした文字とボタンを増やさない)。コードも別のモジュール(例: `app/src/breadboard/`・`schematic/live_logic.rs`)にして、設計のエディタに混ぜない。単純にした見せ方(LED は光るか消えるかだけ・ゆっくり再生・真理値表を埋める)は学習モードの中だけで、設計の解析の結果には持ち込まない。
- **回路のデータは 1 つ**: ブレッドボードは同じ回路図の別の見え方で、別のファイルにしない。学習で組んだ回路が、そのまま本格の解析・基板・発注へ進めるのが Tinkercad との違いで、データを分けるとそこが切れる。
- **シミュレータも 1 つ**: 学習用に簡単なエンジンを別に作らない(「学習モードでは動いたのに解析では違う」が起き、手入れも 2 倍になる)。新しく要る「途中の状態を保って続きを解く」仕組みは sim-core の一般の機能として作り、設計にも使う(値を変えながら波形を連続で見る・実機とつないで回す W6・ファームと一緒に W5)。
- **一番上の画面を 4 つのタブにする(2026-11-18 に決めた)**: 今の画面は「回路図」と「基板」の 2 つ(`main.rs` の `Mode`)。ここに「試作」と「実機」を足し、**回路図 → 試作 → 基板 → 実機** と実物の作業の順に並べる(考える → ブレッドボードで組んで確かめる → 基板にして発注 → 届いた基板を組み立てて動かす)。名前を「学習」にしないのは、学習は段階ではなく全部の画面にまたがるから(レッスンは回路図でも基板でも進む)と、ブレッドボードやユニバーサル基板の試作は慣れた人もするから。学ぶ窓(学習パス・レッスン・ウェルカムカード)は入口として今のまま残す。**試作と実機の分け方**: 発注の前に組んで確かめるのが試作、届いた基板を動かすのが実機。**試作のタブ**に入るもの: B6 ①(ブレッドボード・ユニバーサル基板の配置図。中心)・② と B8(動かしながら見る)・③(テスターとオシロ)・④(壊れる)、B4(音で聴く)。学習のモード(ゆっくり再生・LED は光るか消えるかだけ)はこのタブの中の切り替えで、レッスンから入ると学習のモードで開く。中身の無いタブにしないため、試作のタブは B6 ① と一緒に作る(B8 は回路図の上で先に作り、タブができたらそこからも使えるようにする)。**実機のタブ**(B12。2026-11-18 に作った: `bench_tab.rs`、`docs/code-notes/app/bench-tab.md`)に入るもの: 組み立て(B3)・電源投入のガイド(B1 は済み。`power_on_guide.rs`)・組み立てて測る窓(`measure_guide.rs`)・実機作業の窓(`bench_guide.rs`)・合否(スペック表の「実測」)・修理の練習(`repair_practice.rs`)と、これから作る B7(写真と比べる)・N4(計測器とつなぐ)・L2(DMM の値を並べる)。今ある窓を集めれば成り立つので、**実機のタブは試作のタブより先に作れる**。ただのメニューのページにしない: 回路図と基板のタブは絵を触る画面なので、実機も真ん中に基板の配置図を置き、左に手順(組み立て → 電源投入 → 測る → 合否)を並べ、手順を選ぶと付ける部品・測る場所が絵の上で光る形にする。名前を「組み立て」にしないのは、電源投入・測定・修理が入らず、タブをさらに分けたくなるから。波形に実測を重ねる表示(`bench_data`)は、予測の波形がある回路図の側に残し、実機のタブからは飛ぶ入口だけ置く(試作のタブからも開ける)。
- **機能ごとに学習用の窓を作らない**: 別の描き方が要るもの(B6 のブレッドボード)は試作のタブ、今の画面の上で動くもの(B8・B4)はその画面に重ねる学習のモード(小さな操作の帯だけ足す)、今の画面の説明(Q10 データシートの読み方・B11 部品の役割)はその画面の中の案内にする。窓が増えると、どれを開くかで初学者が迷う(UI の決まり「増えていくものは決まった数 + 一覧」「深さは 2 段まで」)。B1 のような実機作業の手順は、実機のタブ(B12)の手順に並べる。
- **B2 は回路図の側、B1・B3・B7 は実機のタブ**: 電池の寿命(B2)は解析の結果なので回路図の解析に置く。電源投入のガイド(B1)・組み立てのチェック表(B3)・写真と比べる(B7)は、初めて基板を作る人の実際の作業の道具なので、実機のタブ(B12)の手順に置く(学習のモードにはしない)。B5(ユニバーサル基板)は試作のタブ。
