# 試作のタブとブレッドボード (B6 ①、`app/src/breadboard/`・`sch-core/breadboard.rs`)

一番上のタブの 2 つ目「試作」(`main.rs` の `Mode::Proto`)。回路図 → 試作 → 基板パターン → 実機 の順。回路図の部品を、はんだ不要のブレッドボードのどの穴に差すかを並べて描く。

## データ (`sch_core::breadboard`)

- 穴 `Hole`: `Strip { col, row }`(row 0..5 = a〜e、5..10 = f〜j)か `Rail { rail, col }`(`TopPlus`・`TopMinus`・`BottomMinus`・`BottomPlus`)。名前は基板の印刷どおり (`a12`・`上+5`)。
- 中のつながり `Node`: 列ごとに上半分と下半分 (5 穴ずつ)、レールは全長。
- `Layout`: 部品ごとの足の穴 (`Placed`、見た目 `Look` = 2 本足・IC・1 列)、ジャンパー線 (`Wire`)、ブレッドボードの外の電源・電池・信号源 (`OffBoard`、ピンごとに線の先の穴)、レールの役 (`rails`)。
- **回路のデータは 1 つ** (candidates の方針): 並べ方は回路図のシートの設定 (`SheetSettings::breadboard`、ファイルの `"breadboard"`) に入る。別のファイルにしない。画面を見ただけでは入れない (未保存の印を付けない): 手で動かしたか「自動で並べ直す」を押したときだけ。それまでは回路図から毎回並べる (`BreadboardView::layout`、回路図の `rev` と部品の数で作り直す)。読めない形 (古い・新しい) は捨てて並べ直す。

## 自動で並べる (`auto_layout`)

1. 電源: GND は上下の − レール、電源 (直流の電圧源・電池の +、電源記号のネット。PWL で立ち上がる電源も、名前が VCC・VDD・VIN・VBAT・+5V・3V3 のようなら) は上下の + レール (左の端の線で上下をつなぐ)。電源が 2 つなら 2 つ目は下の +。
2. IC (偶数本の足、4 本以上): 中央の溝をまたぐ。1 番ピンが左下 (f 行)、右へ数えて、上の行 (e) を左へ戻る。1 列あけて次の IC。
3. 1 列の部品 (3 本足のトランジスタ・レギュレータ・ヘッダ): e 行に横に並べ、本体は溝の側に描く。
4. IC・1 列の部品の足が電源のネットなら、その列から近い側のレールへ短いジャンパー。同じネットの別の列は、空きのある最後の列へ鎖のようにつなぐ (星形だと最初の列が埋まる)。
5. 2 本足の部品 (`place_two`): 両方が電源 → レールをまたいで差す。片方が電源 → もう片方のネットの列の外側の穴 (a か j) から、隣のレールへ縦に。どちらも電源でない → 同じ半分にある両方のネットの列の組のうち、両方に空いた行がある一番近い組に、横に寝かせて差す。無ければ片方のネットの新しい列を作る (隣のジャンパーは溝の側の穴、外側は部品用に残す)。**寝かせた部品は同じ行で重ならない** (`Builder::lying` に行と列の範囲を覚え、`clear_row` が重なる行を選ばない。2026-11-19): デコーダから表示器への 7 本の抵抗が a 行に重なって差せなかった。どの組でも重なるときは、両方のネットに 2 列あけた新しい列を作り (`fresh_strip_after_gap`、ジャンパーで自分のネットへ)、その間に寝かせる。テスト `lying_parts_never_overlap_on_a_row` (全サンプル)。
6. 1 本のネットは、最後の 1 穴を新しい列へのジャンパー用に残す (`usable` / `free_count`)。これが無いと、ピンの多いネット (74HC の VCC、7 個の LED のアノード) の列が埋まってつなげなかった。
7. ブレッドボードの外: 電源・電池・電流源・シミュレーション専用の部品は左に置き、ピンから線でレールかネットの列へ。

## 差し方どおりの回路 (`board_nets`・`SchEditor::board_circuit`)

電源を入れて計算するのは、回路図ではなくブレッドボードに差したとおりの回路。穴のグループ (列・レール・ジャンパー線) ごとに 1 つのネットにし、`sim_core::from_schematic_with_nets` で部品をそのネットにつなぐ (回路図の線は使わない)。名前は、グループの中の足の回路図のネットから取る (回路図どおりなら回路図と同じ名前): 2 つのネットが入ったグループ (ショート) は GND があれば GND (0 V のまま)、無ければ名前の順で最初。1 つのネットが分かれたら (外れた所)、足の多いグループが名前を持ち、ほかは `NET~2`。2 つ目の GND のグループは GND ではない (差していない GND の線と同じく浮く)。回路図でどこにもつながっていない足だけのグループは `BB.a12`。シミュレーション専用のピン (LDR の光・モーターの回転数。`SymPin::sim_only`) は穴に差さないので、回路図のネット (ボードでの名前) のままつなぐ。`net_at` も同じ名前を返す (テスター・オシロ・ブザーとモーターの印が、動いている回路の名前で読める)。ジャンパー線の色は `~2` を外した回路図の名前で。外の電源の線には 0.05 Ω (線とクリップ): 電源の + と − を直に差しても、答えの無い式ではなく大きな電流になる。

## 照合 (`check`)

穴・ジャンパー・外の部品の線でつながる穴をまとめ (union-find)、回路図のネットと比べる: 2 つのネットが 1 つにまとまる → `Short`、1 つのネットが分かれる → `Open`、1 つの穴に 2 本 → `SameHole`、部品か足が無い → `Missing`。メッセージは原因と直し方。テスト `every_sample_lays_out_without_a_short_or_an_open` は `docs/examples` の全部の回路図 (133 件) を自動で並べて問題 0 を確かめる (最初は 4 件が開いていた: 列が埋まる・PWL の電源)。

## 画面 (`app/src/breadboard/mod.rs`)

- 左: 説明、照合の結果 (✔ か、違う所の一覧)、「自動で並べ直す」、部品ごとの足の穴、外の部品。
- 真ん中: 板 (ベージュ)、穴、上下のレールの赤と青の線とネットの名前、溝。ポインタの下の穴とつながっている穴 (その列かレール) を黄色に。抵抗は色の帯 (`bands`、2 桁・乗数・金)、LED は赤い丸とカソードの平らな側、ダイオードは黒い本体とカソードの帯、コンデンサは青、コイルは緑、IC は黒い箱と 1 番ピンの丸。ジャンパー線は電源が赤、GND が黒、ほかはネットの名前で 5 色。
- 道具 (`Tool`、左のパネルで切り替え):
  - **動かす**: 部品のドラッグ (穴の単位、`moved`。IC は行を変えない、レールの足はレールの上だけ)、ジャンパー線の端のドラッグ (`wire_end_moved`。端は部品の足より先に拾う)、線をクリックで選んで Delete で消す (`without_wire`)、選んだ部品を R で回す (`rotated`: 2 本足は 1 本目の足を中心に 90°、1 列の部品は向きを逆に。IC・レールの足・はみ出す向きは回さず、ステータスに理由)。放すとシートに入る。回路図と違う足は赤い丸。
  - **ジャンパー線**: 穴を 2 つクリック (`with_wire`。色はつなぐネットから)。Esc でやめる。
  - **テスター** (B6 ③): 1 回目のクリックが赤い棒、2 回目が黒い棒。2 つの穴のネット (`net_at`: 穴の列・レールとジャンパー線・足でまとめたグループの中の足のネット) の DC 動作点の電圧の差を左に大きく出す。DC が無ければ道具を選んだときに 1 回だけ計算 (`dc_asked`)。電源を入れているときは、ブレッドボードに差したとおりの回路の今の電圧を読む (回路図と違う差し方でも読める)。電源を切っていて回路図と違う差し方のときは「電源を入れてから」。どこにもつながっていない穴は「定まりません」。
  - **レンジ** (`MeterRange`、2026-11-19): 電圧・電流・抵抗をテスターの上の 3 つのボタンで選ぶ。電流と抵抗は `sim_core::meter` で、ブレッドボードに差したとおりの回路 (焦げた部品は壊れたまま) に DC を 1 回解く (`meter_cache`: レンジ・2 本の棒のネット・電源・焦げた部品・回路図の変更・温度が同じ間は解き直さない)。**抵抗**は電源を切っているときだけ (入っていると理由を出して読まない): 電源 (部品のモデルの外の電圧源・電流源) を外して開放にし、赤から黒へ 100 µA を流して電圧から読む。2 V を超えたら OL (コンデンサ・開いた所)。回路につないだまま測るので、並んだ部品も一緒に読む。**電流**は電源を入れているときだけ: 2 本の棒の間をテスターの 0.1 Ω でつないで、そこを流れる電流 (赤 → 黒が +)。同じネットに当てたら 0 A と「線を外して直列に」、10 A を超えたら「ヒューズが切れました」(電源に並列に当てた)。撮影用 `--proto-meter-range amps|ohms`。テスト `the_meter_reads_ohms_with_the_power_off_and_amps_in_series`。
  - **オシロ** (B6 ③): 探り針の穴のネットの `V(net)` を、回路図の過渡解析の結果から左の小さな画面に描く (最大・最小・時間の幅)。結果が無ければ「過渡解析を実行」。
- **電源を入れる** (B6 ④): ブレッドボードの回路の DC 動作点を計算し (`SchEditor::board_dc`)、定格の点検 (`sim_core::check_ratings`) で `Over` の部品は煤と赤い ✕ (焦げた)、`Caution` は橙の枠。左に「壊れた / 熱い・余裕が少ない」と理由 (`message`) と直し方 (`hint`)。電源 (電圧源) が 2 A を超えて流すと「電源がショートしています」。
- **動かしながら見る** (B6 ②、`breadboard/live.rs` の `Live`): 電源を入れて回路図どおりに差してあると、`sim_core::TranRun` を開いたままにして、毎フレーム画面の時間ぶん解き進める (回路図の `live_logic.rs` と同じ形。パルスの電源は自分の波形のまま動く)。LED は今の電流 (`I(D1)`、明るさは電流の平方根で 20 mA が 1) で光る。押しボタン (`SW_PUSH`、マウスを押している間だけ入る) とスライドスイッチ (`SW_SLIDE`、クリックで切り替え) は、モデルの中の位置の電源 (`Vpress`・`Vpos`) を `set_source` で変える。部品の上に「入・切・押す・押している」の札。速さは 実時間・1/10・1/100・1/1000 (速い発振を目で追う)。1 フレームで 40 ms を超えて解いたら打ち切って遅れを出す (窓は固まらない)。テスターは今の電圧、オシロは画面の直近 3 秒の波形。モーター (部品名に MOTOR、SPD ピンは 1 V = 1000 rpm) は回る棒と回転数、ブザー (BUZZER) は + が − より 2.5 V 以上高いと波の輪と ♪ に加えて**音** (`breadboard/sound.rs`): 発振回路入りのブザーなので、高さは一定 (2.3 kHz、奇数の倍音を 3 つまで足した柔らかい矩形波)、電圧が高いほど大きく (2.5〜5 V を 4 段。段が変わると鳴らし直すので段は少なく)、逆向きでは鳴らない。1 秒ぶん (高さの整数周期なので継ぎ目でプツッと言わない) の WAV をメモリに作り、Windows の `PlaySoundW` (winmm、クレートを足さない) で繰り返す。音は 1 つだけで、鳴っているブザーのうち一番大きいもの。焦げたブザーは鳴らない。左の「ブザーの音を鳴らす」で消せる (ブザーが差してあるときだけ出る)。試作のタブを離れると止まる (`main.rs` が `silence`)。テストでは音を出さない (`cfg(test)` で空の関数)。**つまみ**: ブレッドボードの外の直流の電圧源 (実験用の電源・センサーの光の入力など) は、左のスライダーで動かしたまま電圧を変える (0〜回路図の値の 2 倍、`Live::set_knob` → `set_source`。外の箱にも今の値)。ブレッドボードに差した**ボリューム** (`Kind::Pot`) もつまみになる (0〜100 %、`Knob.pot` = 全体の抵抗。`set_knob` → `TranRun::set_resistance` で `VR1.A` と `VR1.B` を変える)。絵は青い四角につまみの丸と溝 (0 % で左下・100 % で右下、時計回り 270°)、下に「VR1 30%」。ボリュームは絵の上でも回せる: 押したまま右か上へ動かすと 3 番の側へ (200 点で端から端、`KNOB_DRAG`・`knob_dragged`)、ホイールは 1 目盛りで 5 % (`KNOB_NOTCH`。`MouseWheel` の出来事 1 つを 1 目盛り)。押している間は部品のドラッグにならない (`knob_drag`)。回した値は `knob_values` に残り、回路図の値は変えない。焦げたボリュームは、そのとき一番熱い半分 (`VR1.A` か `.B`) が断線する (`broken` には素子名、`element_of` で部品と結ぶ)。**周りの温度**: スライダーを放すと、その温度で回路を作り直して始めから (サーミスタ・温度センサー。`board_circuit` の `temp_c`)。つまみの値・スライドスイッチは、始め直しても残る。回路図が変わる (`rev`) と始め直す。**動いている間の定格の点検** (`Watch`): 毎フレーム `TranRun::snapshot` (今の動作点) に `SchEditor::board_ratings` (`check_ratings` + 電源のショート) をかける。電流と電力は時定数 0.1 s (回路の時間、`HEAT_TAU`) の平均で見る (部品は平均で熱くなる。正弦波の山で抵抗は焦げない)、電圧は今の値 (降伏はすぐ起きる)。`Over` が 20 ms (`BURN_HOLD`) 続いたら焦げる。焦げた部品は電源を切るまで焦げたまま (始めの動作点で超えていたらすぐ)。**焦げた部品は回路の中でも壊れる** (`broken`): その部品のよくある壊れ方 (`sim_core::burn_failure` = 連鎖故障 `chain.rs` と同じ: 抵抗・LED・コイルは断線、ダイオード・トランジスタ・コンデンサはショート) を `with_fault` で入れて、続きを始めから解き直す (つまみ・スイッチ・焦げた一覧は残る)。焦げた LED は消え、0805 の抵抗が先に焦げて切れれば後ろの LED は助かる。始め直した動作点でまた超えた部品はすぐ焦げる (連鎖)。電源を切るか、差し方・回路図を変えると元に戻る。左に「〜は断線 (オープン) になり…」。つまみで電源を上げると LED が焦げる。動いていないとき (始められなかったとき) は DC 動作点から。
- 撮影用の起動引数: `--proto [R1]`、`--proto-power`、`--proto-meter` (テスターを上の + と − の列に)、`--proto-flip SW1,SW2` (動き出したらそのスイッチを入れる)。
- 連動: ブレッドボードで選んだ部品は回路図と基板の `linked` に入り、回路図で選んだ部品はブレッドボードで光る。
- 起動引数 `--proto [R1]`。CLI `breadboard`。

## マイコンのスケッチ (B6 ⑤、2026-11-19)

- 部品 `ARDUINO_NANO` (`part-lib/examples/`、DIP 30 ピン・列の間 15.24 mm、Nano のピン番号どおり)。モデルは D0〜D13・A0〜A7 のそれぞれに、中の電源 `VpD13` と抵抗 `RpD13` (最初は 0 V・1 GΩ = 入力)。5V のピンは USB の 5 V を 0.2 Ω で出し、本体が 250 Ω (約 20 mA)。3V3・AREF・VIN・RST はモデルに無い。
- スケッチは回路図のシートの設定 `sketches` (部品番号 → 文、`tolerance.rs`。ファイルの `"sketches"`)。書いていない板は点滅の見本 (`sketch_ui::BLINK`) を見せる (見ただけでは保存しない)。
- 左のパネル (`breadboard/sketch_ui.rs`): 板ごとに「スケッチ (U1)」の欄 (コードの欄、パネルの幅まで)、打つたびに読んで「✔ 読めました」か「n 行目: 理由」、「点滅の見本に戻す」、動いている間はシリアルモニタ (最後の 12 行) と、動いている途中の誤り (行と理由)。
- 動かす (`live.rs`): 電源を入れると `Live::add_mcu` で板ごとに `sim_core::sketch::Machine` を作り、ピンのネット (`sketch_ui::pin_nets`: 記号のピンの名前 D13 → 番号 → ブレッドボードのネット) を覚える。すぐ `setup` を走らせる。`advance` はスケッチのある間、次に起きる時刻 (`delay` の終わり、待たないスケッチは 1 ms 後) まで解いてはスケッチを進める、をくり返す (1 フレームの予算 40 ms は同じ)。ピンの出力は `RunIo::drive`: 出力 0 / 5 V と 25 Ω、INPUT_PULLUP 5 V と 35 kΩ、入力 1 GΩ を `set_source`・`set_resistance` で。読みは今のネットの電圧。スケッチを変えると (`sketches_key`) 始めから。
- 「部品と差す穴」の一覧は、表をやめて 1 部品 1 行の折り返し (30 ピンの板の 1 行がパネルを画面の大半まで広げた)。コードの欄も幅いっぱいを求めない。
- サンプル `arduino_blink` (D13 → 330 Ω → LED) と `arduino_pot` (A0 のボリュームで D9 の LED の明るさ、シリアルに読んだ値)。生成 `write_arduino_examples`。テスト `the_arduino_sketch_blinks_the_led`・`the_arduino_reads_the_knob_and_sets_the_led` (`live.rs`)。

## ストリップ基板・ユニバーサル基板 (B5、2026-11-19)

- 試作のタブの左の上に「ブレッドボード / ストリップ基板 / ユニバーサル基板」(`BreadboardView::kind`、`BoardKind`)。ストリップ基板・ユニバーサル基板は並べ方を見せるだけ (動かす・テスター・ドラッグは無い。切り替えると電源は切る)。撮影用 `--proto-kind strip|perf`。
- 並べ方 `sch_core::stripboard::strip_layout` (部品とネットはブレッドボードの `read` と同じ): ネットの運び方 (`Carry`) を先に決める。電源・GND・外の部品につながるネット、いくつもの部品が共有するネットは上の帯 (`Home`、電源が上、GND が下、行 A から)。**チップのピン 1 つと 2 本足の部品 1 つだけのネットは帯を作らず、その部品を、ピンの片から相手のネットの帯へ縦に差す** (`Via`: 部品の足が線の代わり。デコーダの出力 → 抵抗 → 表示器)。部品は 1 つのネットの線にしかならず、相手のネットは帯を持つ (相手も `Via` の候補なら相手が帯になる)。チップのピンだけのネット (`Pins`) は帯を作らず、片の空いた穴から前のピンの片の空いた穴へ線を 1 本 (斜めでもよい。ビニール線)。足が 1 本だけのネット (`Alone`) は何もしない。`Pins` のピンがあるチップは、片の外側に 2 穴の余り (線の両端が 1 つの片に来ることがある)。`Pins` の線は、いちばん近いピンどうしから順につなぐ (最小全域木。前は書いた順の数珠つなぎ)。**線の列は、上の帯へ行くピン (`Home`・`Via`) だけ**が行の順に 1 本ずつ取る (前は全ピン)。**チップの並び** (`chip_order`) は、ピンどうしの線を最も多く共有するチップを隣に (カウンタの隣にデコーダ)。チップの区画の境目の切れ目は 1 列で共有する (前は 2 列)。2 本足の部品は 2 つのネットの帯をまたいで縦に、2 列ずつ。IC (`Look::Dip`) とトランジスタ・ヘッダ (`Look::Row`) は帯の下の段に、1 番ピンが左上で左の列を下へ、右の列を上へ戻る (列の間は 3)。ピンごとに帯を切って (× の穴: 区画の前・IC の 2 列の間・区画の後) 片を作り、片の端の自分の列から、そのネットの上の帯へ線 (`Link`) を縦に。線はピンごとに別の列なので重ならない。基板の外の電源は左の列から線で。どこにもつながらない足は、いちばん下に自分の帯。

## タブと学習のモードの方針 (2026-11-16・18 に決めた。候補の一覧の B 節から移した)

**学習向けと設計向けの分け方(2026-11-16 に決めた)**: 分けるのは**画面と入口**で、**回路のデータとシミュレータは分けない**。
- **画面は分ける**: B4・B6・B8・B9・B10・B11(音で聴く・ブレッドボード・デジタルを動かしながら見る・ブラウザで動く版・授業で使う形・部品の役割の説明)は学習のモードにし、学習パス・レッスン・ウェルカムカードから入る。設計の画面のパネルには並べない(U1 で減らした文字とボタンを増やさない)。コードも別のモジュール(例: `app/src/breadboard/`・`schematic/live_logic.rs`)にして、設計のエディタに混ぜない。単純にした見せ方(LED は光るか消えるかだけ・ゆっくり再生・真理値表を埋める)は学習モードの中だけで、設計の解析の結果には持ち込まない。
- **回路のデータは 1 つ**: ブレッドボードは同じ回路図の別の見え方で、別のファイルにしない。学習で組んだ回路が、そのまま本格の解析・基板・発注へ進めるのが Tinkercad との違いで、データを分けるとそこが切れる。
- **シミュレータも 1 つ**: 学習用に簡単なエンジンを別に作らない(「学習モードでは動いたのに解析では違う」が起き、手入れも 2 倍になる)。新しく要る「途中の状態を保って続きを解く」仕組みは sim-core の一般の機能として作り、設計にも使う(値を変えながら波形を連続で見る・実機とつないで回す W6・ファームと一緒に W5)。
- **一番上の画面を 4 つのタブにする(2026-11-18 に決めた)**: 今の画面は「回路図」と「基板」の 2 つ(`main.rs` の `Mode`)。ここに「試作」と「実機」を足し、**回路図 → 試作 → 基板 → 実機** と実物の作業の順に並べる(考える → ブレッドボードで組んで確かめる → 基板にして発注 → 届いた基板を組み立てて動かす)。名前を「学習」にしないのは、学習は段階ではなく全部の画面にまたがるから(レッスンは回路図でも基板でも進む)と、ブレッドボードやユニバーサル基板の試作は慣れた人もするから。学ぶ窓(学習パス・レッスン・ウェルカムカード)は入口として今のまま残す。**試作と実機の分け方**: 発注の前に組んで確かめるのが試作、届いた基板を動かすのが実機。**試作のタブ**に入るもの: B6 ①(ブレッドボード・ユニバーサル基板の配置図。中心)・② と B8(動かしながら見る)・③(テスターとオシロ)・④(壊れる)、B4(音で聴く)。学習のモード(ゆっくり再生・LED は光るか消えるかだけ)はこのタブの中の切り替えで、レッスンから入ると学習のモードで開く。中身の無いタブにしないため、試作のタブは B6 ① と一緒に作る(B8 は回路図の上で先に作り、タブができたらそこからも使えるようにする)。**実機のタブ**(B12。2026-11-18 に作った: `bench_tab.rs`、`docs/code-notes/app/bench-tab.md`)に入るもの: 組み立て(B3)・電源投入のガイド(B1 は済み。`power_on_guide.rs`)・組み立てて測る窓(`measure_guide.rs`)・実機作業の窓(`bench_guide.rs`)・合否(スペック表の「実測」)・修理の練習(`repair_practice.rs`)と、これから作る B7(写真と比べる)・N4(計測器とつなぐ)・L2(DMM の値を並べる)。今ある窓を集めれば成り立つので、**実機のタブは試作のタブより先に作れる**。ただのメニューのページにしない: 回路図と基板のタブは絵を触る画面なので、実機も真ん中に基板の配置図を置き、左に手順(組み立て → 電源投入 → 測る → 合否)を並べ、手順を選ぶと付ける部品・測る場所が絵の上で光る形にする。名前を「組み立て」にしないのは、電源投入・測定・修理が入らず、タブをさらに分けたくなるから。波形に実測を重ねる表示(`bench_data`)は、予測の波形がある回路図の側に残し、実機のタブからは飛ぶ入口だけ置く(試作のタブからも開ける)。
- **機能ごとに学習用の窓を作らない**: 別の描き方が要るもの(B6 のブレッドボード)は試作のタブ、今の画面の上で動くもの(B8・B4)はその画面に重ねる学習のモード(小さな操作の帯だけ足す)、今の画面の説明(Q10 データシートの読み方・B11 部品の役割)はその画面の中の案内にする。窓が増えると、どれを開くかで初学者が迷う(UI の決まり「増えていくものは決まった数 + 一覧」「深さは 2 段まで」)。B1 のような実機作業の手順は、実機のタブ(B12)の手順に並べる。
- **B2 は回路図の側、B1・B3・B7 は実機のタブ**: 電池の寿命(B2)は解析の結果なので回路図の解析に置く。電源投入のガイド(B1)・組み立てのチェック表(B3)・写真と比べる(B7)は、初めて基板を作る人の実際の作業の道具なので、実機のタブ(B12)の手順に置く(学習のモードにはしない)。B5(ユニバーサル基板)は試作のタブ。
