# app 詳細メモ (`crates/app/src`)

CLAUDE.md の地図から参照される、各機能の詳しい説明。

## 開発用の検算 (xcheck)
- 開発用の検算 `xcheck.rs` / `xcheck_tran.rs`: `circuitCad --xcheck <file|dir>` が自前のDC動作点(電圧と電流)を、`--xcheck <file|dir> --tran` が過渡波形を(電源が時間変化しない回路は `xcheck_tran.rs` の `own_dynamics` の表の長さで。DC動作点が無くゼロ状態から始まった回路は ngspice にも `uic` を付ける。時間で重みを付けた規格化RMS誤差1%未満か、エッジ主体の波形はエッジ時刻のずれが周期の2%以内なら一致)ngspice と比べて `xcheck_report.txt` / `xcheck_tran_report.txt` に書く(ウィンドウは開かない。ngspice の場所は `--ngspice` か環境変数 `NGSPICE`、既定 `F:\Tools\ngspice\Spice64\bin\ngspice_con.exe`)。ngspice は reltol=1e-6 で解かせる(既定の1e-3だと ngspice 自身の電流が食い違う)。差が出たら gmin=1e-15 でも解き直し、それで一致すれば「gmin依存」。スイッチ(`S` と `.model SW`)は ngspice に `vw` が無いので、方言変換が自前と同じ滑らかな導通の B 電流源 `I=V(a,b)*exp(…)` に置き換える(これで降圧コンバータ・NE555・論理ICが ngspice と合う)。既知の差: 電源投入直後のフリップフロップなど双安定の回路は、自前が釣り合い点にとどまり ngspice が片側に倒れるので合わない(`logic_blinker`、`variable_supply`の浮いた2次側)。ngspice が止まる回路もある(トランス、`led_blinker`)。方言変換は `sch-core/src/ngspice.rs`(`to_spice_for(.., Dialect::Ngspice)`: if/step/limit/log/temp)。`--ourstep` `--ngstep` `--lte` で片方の刻みや許容だけ変えて、どちらのエンジンが粗い刻みに弱いかを見られる。

- AC解析の検算 `xcheck_ac.rs`: `circuitCad --xcheck <file|dir> --ac [--golden <json>]`。値に `AC` を含む電源のある回路を 10Hz〜10MHz・1デケード5点で自前と ngspice(`ac dec`、`wrdata` は周波数のあと実部・虚部の組)に解かせ、ノードごとの複素数の差を 相対0.1% + ノードの最大値の1ppm + 1e-12 で比べる。保存は `docs/xcheck/ngspice_ac.json`(実部・虚部の生の値)、CIのテスト `ac_sweeps_still_match_the_stored_ngspice_answers`。外してある回路: `bridge_rectifier` `variable_supply`(2次側が浮いていて共通電位が不定、差は合う)、`mixed_signal`(自前の動作点が収束しない)。ノイズ・DCスイープはまだ照合していない。
- CIでの検算: `docs/xcheck/ngspice_dc.json` に、同梱サンプルの ngspice のDC動作点(生の出力)が保存してあり、テスト `dc_points_still_match_the_stored_ngspice_answers` が自前の結果と比べる(ngspice は不要)。保存するのは既定設定で一致した回路だけ(`ip2332_charger` は gmin依存、`variable_supply` はズレなので外れている)。モデルを意図して変えたら `circuitCad --xcheck docs/examples --golden docs/xcheck/ngspice_dc.json` で作り直し、差分を読む。

- 過渡波形のCI検算: `docs/xcheck/ngspice_tran.json` に、同梱サンプル32件の ngspice の過渡解析を「10個の窓ごとの平均・最小・最大」にまとめて保存してある(`xcheck_tran.rs` の `window_stats`)。テスト `transient_runs_still_match_the_stored_ngspice_statistics` が、保存した刻みで自前を走らせ、窓の平均(振れ幅の1%)・最小最大(3%、最初の窓は除く)・リップル(10%、`local_ripple`: 終わり5分の1を100分割した各区間のp-pの中央値。整定途中のゆっくりした揺れや1周期だけの外れ値に影響されない。終わり2窓の幅がリップルの10倍を超える波形、例えばパルス列は比べない)を比べる。リップルを「終わり2窓の最大−最小」で測ると、macOS だけ+12.6%ずれた(5ms でもまだ整定途中で、揺れの位相が CPU の丸めで変わる。周期ごとの山の中央値は3OSで一致)。波形そのものでなく統計なのは、スイッチング波形は点を間引くとエッジが崩れるため。降圧コンバータの出力コンデンサ違い2件は、定常のリップルを見るため5ms走らせる(`own_dynamics`)。作り直しは `circuitCad --xcheck docs/examples --tran --golden docs/xcheck/ngspice_tran.json`。

- `samples.rs`: 「ファイル → サンプル回路を開く」の一覧(`SAMPLES`。`docs/examples` と同じファイルを `include_str!` で埋め込む。足すときは1行と、タイトルが重ならないこと)。`SchEditor::open_sample` は未保存のシートとして開く(上書き保存でサンプルが壊れない)。`SchEditor::new_file` は `rev` を巻き戻さない(基板の「回路図と違います」の判定が `rev` をキーにしているため。巻き戻すと、別の回路を開いても古い判定が残る)。基板だけを開いたとき(回路図が空)は「回路図と違います」を出さない。
- スペック表の「実測」欄(`spec_table.rs`): 行ごとに `measured`(入力した文字のまま `.schjson`/`.ccproj` の `"specs"` に保存。無ければキーを書かない)。`sim-core::compare_measured` が差・近さ(Close/Some/Far)・理由の手がかりを返す。`add_measure_rows` は学習パスの「組み立てて、性能を測る」用(VIN・VOUT・電流の行を足してDC動作点を計算)、`compared_measurements` は比べられた実測の数(3以上で `build_psu` を完了にする。`main.rs`)。`measure_guide.rs` が案内の窓(`--measure-guide` で開く)。
- 部品名・値のラベル(`draw.rs draw_components`): 幅のある部品は名前を上、値を下に中央寄せで置くが、上下の辺の中央にピンがあるとき(IC の GND など)は配線の左側へ寄せる(電圧は常にピンの右側に出るため)。LED は光の矢印の分だけ名前を上へ(逆向きなら値を下へ)。電流の文字も、下に配線があれば左へ。

## 描画・波形・プロット
- 電源記号は値で形が変わる(`symbols.rs` の `source_symbol`: 直流=±の円、SIN=正弦波、PULSE=方形波、PWL/NOISE=折れ線)。
- `plot.rs` の `scale_bar` は横軸・縦軸(グループごと)の範囲入力・全体・自動(1行、過渡・ACの波形パネルの上に出る。拡大縮小は軸の数字の上のホイール)。
- `plot.rs` 波形描画 (`scale_bar`・`draw_group`・`PlotState`)。
- 軸の数字の上でホイール=その軸だけ拡大縮小(`draw_group`)。
- `PlotState.cursors` が測定カーソルA/B(クリックで置く、`cursor_report` が差・周期を出す)。

## 作ってみよう・学習パス・操作ガイド
- `schematic/challenge/` は「作ってみよう」(`mod.rs`=型・`CHALLENGES` の並び・開始/判定の入口、`basic.rs`/`power.rs`=チャレンジ1件ずつの `const`、`judge.rs`=模範解答・開始シート・判定、`window.rs`=窓)(目標だけ示して自分で部品を置き・配線し、「判定する」でシミュレーションして判定する。1つの模範解答とは比べない)。 **シミュレーションできない回路(マイコンの基板)は、`Check::Joined`(このピンたちが同じネット)と `Check::Between`(この2つのネットの間に、この種類の部品が min 個あり、値が範囲内)で、つなぎ方と値を判定する。部品は種類で探す(基本の C/R も、ライブラリのチップ部品 `C_100n_0603` も同じ種類)ので、番号を振りなおしても通る。`arduino.rs` の `DRAW_ARDUINO` が例(答えは `docs/examples/arduino_minimal.schjson`、開始は部品13個を置いたものと、U1・J1・V1 だけのもの)。**
- チャレンジは `CHALLENGES` のデータ(開始シート `parts0/parts1/grounds*/start_values`、答え=サンプルの `drop/values/labels/rename`、判定 `checks`: `Erc`/`Named`(出力ネット `VOUT`)/`Voltage`(負荷・入力を足して測る、値の範囲ごとの助言 `explain`)/`Stay`(入力を2点に振る)/`Current`/`Gain`(AC)/`Ratings`)。
- 足すときは `CHALLENGES` に1件とテスト(答えが通る)。
- いまは zener・divider・led・rc_lowpass・emitter_follower・opamp_inv・series_regulator・regulator_78xx と、最終課題 draw_psu(lesson は protection、学習パスの `Kind::Build` の項目から id で開く。部品の個数を調べる `Check::Has` あり、答えは `power_supply.schjson`)。
- `--challenge <id> [0|1] [--judge]`、通過は進み具合に `<id>+build`、レッスン窓の「チャレンジを始める」と学習パスの「作ってみよう」から開く。
- 基板のレッスンは3つ(`board_editor/lesson.rs`。`BoardLesson.which` 0=回路図から発注まで、1=配線の電圧降下、2=チャレンジ「発注前チェックをすべて通す」(`FIX_STEPS`、完了キー `board_fix`、`docs/examples/order_fix.ccproj`: 部品D1が基板の外・D1につながる配線が無い(未配線2本)・N$1とGNDに1.5 Aを設定済みで配線は0.25 mm・DRCルールが発注先より緩い。手順は発注の準備を開く→D1を中へ→配線→足りない配線を太く→発注先を選びルールを合わせ ✖ と ▲ を無くす。判定は `order_clean`=標準以外の発注先で `preflight` に Error/Warn が無いこと。`ccproj` は `regulator_led` を `ccad` で配置・配線→D1を+15.5 mm動かし配線と silk と文字を整える)。学習パスの `Kind::Board(n)`/`Action::Board(n)`、完了の記録は `finished_board_lesson`(`board` / `board_copper`)。2つ目は `docs/examples/thin_power_line.ccproj` をプログラムに埋め込み(`project::parse`)、`App::start_board_lesson(1)` が回路図と基板を差し替えて始める。手順の完了は `post_layout_fresh`(反映した直後 true、配線を太くすると false)と `net_currents` と `net_widths` で判定。`--board-lesson 0|1` は撮影用)。
- `learn.rs` の `NEXT_STEPS`: 「学習パス」窓の「この先へ: 使いこむための機能」(折りたたみ。進み具合が「いま学べる」すべて完了なら最初から開く)。レッスンのあとに使える機能(配線を整える・電流から配線の太さ・差動ペアと長さ合わせ・発注と購入リスト・故障・ばらつきと温度・ほかのソフトとの行き来・`ccad`)を、1件ずつ「何か」「どこにあるか(画面のボタン名のとおり)」で並べる。**ボタン名や場所を変えたら、`NEXT_STEPS` の `where_` も直す**(画面の文字と一致を調べるテストは無い)。
- `learn.rs` は学習パス(`PATHS` に段階と項目を書く。レッスンは `id` で指定、準備中は `planned` / `plan`。**樹形図**: 項目の `requires` に「先に済ませると分かりやすい」項目の id を書くと(別のパスの項目も指せる)、`recommended` が前提のそろった項目を複数返し、窓が `tree_map` で地図を描く。`requires: None` は「直前の項目」(従来の直線)、`Some(&[])` は根。鍵はかけない。`ARDUINO_PATH` が樹形図のパス。`--learn <パスid>` でそのパスを開く)と完了の記録(`%APPDATA%\circuitCad\progress.json`)と「学習パス」窓(`--learn`)。初回起動だけ `welcome_card`(引数なし・進捗なし・未回答のとき、`progress.json` の `"welcomed"` で一度きり)。学習パス窓の説明文は `spaced`(行の高さ)と `NOTE`(灰色)で読みやすくしてある。回路図のライブラリ部品の欄は初期状態で閉じている。
- 設計は `docs/learning-path.md`。
- `help.rs` は「操作ガイド」窓(ヘルプメニュー・F1・各パネルの「操作」ボタン、`--guide`。操作の説明は小さい文字で各所に書かず、ここの `SCHEMATIC`/`WAVEFORM`/`BOARD`/`VIEW3D` に足す)。

## プロジェクト・未保存の変更
- `project.rs` プロジェクト(`.ccproj`=回路図+基板を1つのJSONに。`version` つき。ファイル→プロジェクトを開く/保存、起動引数に `.ccproj`。`SchEditor::adopt`/`BoardEditor::adopt` で両方を置き換える。個別の `.schjson`/`.pcbjson` の保存も残してある)。
- 未保存の変更は `SchEditor::dirty`/`BoardEditor::dirty`(`rev` と `saved_rev`: 回路図は `commit_history`・`reset_history`、基板は `checkpoint`・`adopt` で進む。保存で `mark_saved`)で調べ、`files.rs` の `confirm_unsaved`(プロジェクトを開く・新規・開く・ウィンドウを閉じる。`--screenshot` の自動終了では聞かない)が rfd のはい/いいえ/キャンセルで確認する。
- 基板が回路図とずれているかは `BoardEditor::schematic_diff`(取込と同じ `netlist_of` で、追加/削除/値・形/つなぎを数える。回路図と基板の `rev` でキャッシュ)で、基板タブの ● と基板パネルの橙の文に出る。

## ファイル構成の補足 (main.rs まわり)
- `main.rs` ウィンドウ・メニュー(`App`)、`tips.rs` `TIPS`(豆知識)、`args.rs` 引数処理、`files.rs` 保存・読込・未保存の確認、`screenshot.rs` 画面保存、`startup.rs` クラッシュログ・フォント、`prefs.rs` 表示設定(アイコンのみ・ヒント表示)を `%APPDATA%\circuitCad\settings.json` に保存(設定メニューで変えたとき書く。`--icons-only` はその起動だけ上書き)、`schematic/symbols.rs` の `paint_kind_preview` / `paint_lines_preview` は部品リストの記号プレビュー(基本部品は `symbol`、ライブラリ部品は `symbol_lines`)、`icons.rs` の `help` / `help_small` / `help_label` は長い説明を「(?)」のホバーにまとめる(短い見出し+(?)。部品作成フォームの説明文はこれ)、ツールのアイコン(painterで描く。フォント不要)と「アイコン+文字/アイコンのみ」の切替(`icon_button`、設定メニュー、`--icons-only`)。ツールバーに足すときは `Icon` を増やして `icon_button` を使う、`tests/` 統合テスト(`flow.rs`)とサンプル生成(`examples.rs` の `write_*`、`--ignored` で実行)。
- 「ファイル → 画面をPNGで保存」は eframe の Screenshot(`finish_screenshot`)で、起動引数 `--screenshot file.png` は数フレーム後に撮って終了(画面の確認・文書づくり用)。

## 部品作成フォーム・ライブラリ・電源値フォーム
- 回路図の文字の重なり(`schematic/draw.rs`): ① 片側に3本以上ピンがある部品(IC)は、名前と値を本体の左中央ではなく、上と下に置く(`side_pinned`。左右の短い線とネットラベルでふさがるため。基本部品とピンが少ない部品は今まで通り) ② DC解析のピン電圧は、ネットラベルがそのピンの上にあるか、ピンから水平の短い線の先にあるとき、ラベルの外側に出す(`label_anchor`、`VoltageSpot`: 本体の右側のピン=名前の後ろ、左側のピン=ラベルの点の手前、上下の縁のピン=名前の上に積む(隣のピンが近いため)。電源シンボル(`Kind::Power`)の上のピンも、その値の文字の上に積む) ③ 電流の数字は、既定の位置がネットラベルに重なるとき、線の左→右の順にずらす(`first_clear`、`label_rects`)。テストは `draw.rs` の `tests`。
- 故障のスキャンの一覧の1行(`ScanRow`)は、いちばん動いたノードの「前 → 後」(`worst`、「VIN が 12V → 0V」)と、定格に近づく部品の名前(`at_risk`、「🔥定格超え (Q1・R3)」)を持つ。見出しのホバーに読み方の凡例
- 故障のスキャン(ボタンは「よくある故障を順に試す」)は、`sim_core::likelihood` が Rare の故障を省く(「まれな故障も含める」= `scan_rare` で入れる。省いた件数は状態の行に出す)。テスト `the_fault_scan_leaves_out_the_rare_faults_unless_asked`
- 故障のスキャン(`schematic/fault.rs` の `scan_plan`)は、「逆向きにつなぐ」(`Fault::Reverse`)を含めない。向き間違いは故障ではなく組み立てのミスなので、部品を1つずつ選ぶ方(`ALL_FAULTS` の並びと `--fault` の種類の番号は変えていない)だけで試せる。
- レッスンで今押すボタンを光らせる(`lessons/mod.rs` の `lit`): いまの手順の文の中で「」に入っている名前と同じラベルのボタンに、オレンジの枠を脈打たせる(解析パネルとパネルの `ui.button("…")` は `self.lit(…)` で包む)。手順のデータには何も足さない。ボタンの名前を変えたら、レッスンの文の「」も直す(光らなくなる)。テスト `lit_tests`
- 発注の準備の窓(`board_editor/order.rs`): 窓の中だけ、小さい注釈の文字(`TextStyle::Small`)を 12px にしている(標準は約9px で、初めて発注する人が読む説明が読みにくかった)。手順4に「ガーバー=工場に渡す設計図のデータ」の一行、書き出したあとに「発注先に渡すのは `<基板名>_gerber.zip` の1つ(部品実装も頼むなら BOM と CPL)」を緑で出す
- 3Dビューの案内(`view3d/window.rs`): 絵の下に、回す・動かす・拡大・戻すの操作と「ケース高さ」の一言を出し、一度でも絵を回す・拡大する・ダブルクリックしたら出さない(`View3d.touched`。窓を開き直すと、また出る)
- 学習パスの地図(`learn.rs` の `tree_map`): 箱は 196×60(タイトルの折り返しが不自然にならない幅)。「次のおすすめ」(`next_item`)の箱だけ黄色の太い枠と、上端に「★ 次はこれ」の札を付ける。ほかの「いま学べる」は橙の細い枠。地図の上に色の凡例(★・橙・緑・灰)

### schematic/stretch.rs — 配線が部品に付いてくる
部品をドラッグ(1個・複数選択)または回転すると、ピンの上に端がある配線は、その端がピンに付いてくる。斜めになる場合は1箇所だけ折れ曲がる(折れた先の線は配線の末尾に足す)。ドラッグ中は開始時の配線から毎フレーム計算し直す(`begin_stretch`/`apply_stretch`)ので、元の位置に戻せば配線も元に戻る。一緒に選んだ配線は平行移動するので対象外。ピンの途中に重なるだけの配線(T字)は付いてこない。

### schematic/erc_skip.rs — 描きかけの範囲
`Schematic.erc_skip`(最小角・最大角の組)の中にある ERC の指摘は `sch_core::erc` が捨てる(画面・CLI・チャレンジ判定とも共通。場所のない指摘=GNDなしなどは残る)。ERC ボタンの下の「選択を描きかけにする」で、選択物を囲む範囲(2マス余白)を足す。灰色の枠で表示(`draw_problems`)、×で外す。ファイルに保存され、Undo の対象。

### schematic/net_hints.rs — ネットの電流・差動ペア
ネットラベルを選ぶと、左パネルに「流れる電流 (A)」と「差動ペアの相手」が出る。`Schematic.net_currents`(ネット名→A)と `Schematic.diff_pairs`(+側,−側)に保存(空なら書かない)。基板への取り込み(`board_editor/file.rs` の `import_from_schematic`、CLI の `board import`)で `pcb_core::netlist::import_hints` が、基板にパッドがあるネットだけ `Board.net_currents` と `Board.diff_pairs` に入れる。電流は回路図の値で上書き、ペアは既にあれば足さない。基板側だけで決めた設定は消さない。ネット名はラベルの文字なので、自動名(N$1 など)のネットには指定できない。

### schematic/requirements.rs・board_editor/requirements.rs — 設計の要件の表
「学ぶ」メニューの「設計の要件 (表)…」で開く窓。設計全体(全シート)で1つの表を、3つの折りたたみで編集する: ネットの役割(名前・ネット・役割・線幅・間隔・電流・メモ)、近くに置く部品の組(部品・上限 mm)、離す組(A・B・下限 mm)。`Schematic.requirements`(`design_spec::DesignSpec`。空なら書かない)に直接書くので Undo は履歴の比較に乗る。カンマ区切りの欄は、打っている途中の文字を `req_buf` に持つ(読み戻すと、末尾のカンマが消えて打てなくなるため)。回路にない部品・ネット名は、窓の上にオレンジの ⚠ で出す(`Schematic::requirement_problems`。30 フレームごとと、変えたとき)。基板の画面は、左パネルの「③ 確認して発注」(DRC を実行 の下)に、取り込んだ組と距離のいまの配置での点検を出す(`requirements_check`。違反は組の部品を選ぶボタンつき)。サンプルは `buck_converter.schjson`(と `buck_cout_*`)。CLI は `req`・`board req`。ネットの役割の下の「詳細: 部品間の線幅」(折りたたみ。行ごとに 部品A — 部品B と幅。取り込みで `Board.link_widths` に)。「解析から入れる」(折りたたみ): 「DC解析の電流を調べる」で `dc_net_currents` から提案(`design_spec::suggest_from_currents`)を作り、チェックを付けたものを表に入れる。電流が空の行にはその行のネットの最大(2桁に切り上げ)、どの行にもないネットで 0.1 A 以上のものは行の追加(0.5 A 以上は役割 power)。書いてある電流と、スイッチングの行(DC では電流が出ない)は提案しない。CLI は `req suggest [apply=1]`。起動引数 `--requirements`(.schjson と一緒に。`--dc` も付けると、提案まで出す)で窓を開いたまま `--screenshot` できる。文字の欄は `add_sized` で幅を決める(グリッドの中の `desired_width` は、最初のフレームで残った幅に縮められて、名前の欄が数文字しか見えなかった)。 各行の「理由」(型では `note`)が空の行は、窓の上に「⚠ 理由が空の行が N 件あります」と名前を並べる(`DesignSpec::unexplained`)。数字は「何を」、理由は「なぜ」で、あとで読む人に意図を伝えるため。解析の提案で足した行は理由を空にしてある(書いてもらう)。同梱の降圧サンプルの表には、数字の理由を書いてある。 窓の「回路図の上に枠を出す」(`req_frames`、既定オン)で、回路図の上に表を重ねる(`draw_requirement_frames`): 近くに置く組は色つきの枠と「近くに置く: 名前 (N mm 以内)」、離す組は A・B の二重の枠と「離す A: 名前 (N mm 以上)」。その回路図(シート)にある部品だけ囲む(ネット名で書いた側は囲まない)。表を開かなくても、回路図を見た人に意図が伝わる。基板の側は `board_editor/requirements.rs` の `draw_requirement_marks`(「組と離す距離を基板の上に出す」、`show_req_marks`)。`pcb_core::requirements::marks` が数字(組の広がり・離す組のいちばん近い2パッドと距離・守れているか)を返し、組は緑(守れていれば)か赤の枠と「組「名前」 31.2 / 25 mm」、離す組はいちばん近い2パッドを結ぶ線と距離(足りなければ赤)を描く。

### schematic/snippet.rs — スニペット
選択を `.ccsnip`(クリップボードの `sch_core::Fragment` をそのまま JSON にしたもの)に保存し、別の回路で「スニペットを置く…」で貼り付ける。貼り付けは `paste_clipboard` と同じ(空き地を探す・部品番号を振り直す・ピン上のラベルも一緒)。自作部品は記号をファイルの中に持つので、ライブラリが無い回路でも置ける。基板の配置・配線のスニペットは未対応。

### 複数シート (`sch-core/src/sheets.rs`、`app/schematic/sheets_ui.rs`)
1つの `Schematic` に複数のシートを持てる。**編集中のシートは `Schematic` の `components/wires/labels/erc_skip` そのもの**、ほかのシートは `sheets`(`Sheet`)に預けてある(編集中のシートの欄は空)。`sheets` が空なら今までどおり1枚。切り替えは `switch_sheet`(`park`/`unpark`で中身を入れ替える)、追加 `add_sheet`、削除 `remove_sheet`(1枚に戻ると `sheets` は空に戻る)。履歴・保存・`.ccproj` は `Schematic` 全体を扱うので、そのまま複数シートに対応する(シート切り替えも1回のUndoになる)。
- **シートをまたぐ接続は、同じ名前のネットラベルと電源記号だけ。** ネット抽出・ERC・SPICE出力・シミュレーション・基板への取り込みは `Schematic::flat()`(全シートを `SHEET_STRIDE`=100000マスずつ右にずらして1枚に並べたもの)で処理する。`extract`・`net_at`・`erc`・`to_spice_for`・`from_schematic` の `build`・`netlist_of`(app と cli)が入口。座標がずれているので、シートが違えば線は絶対につながらない。
- ERC の指摘 `Problem.sheet` と `at` は、そのシートの座標に戻してある(`sheet_of`)。別のシートの指摘をクリックするとそのシートに切り替わる。
- 部品番号は `next_refdes` が全シートを見て振る(シートをまたいでもダブらない)。ダブりは ERC が見つける。
- 故障シミュレーション(部品の一覧・ピン・連鎖故障・安全の判定)とパラメータスイープは、全シートの部品を見る(入口で `flat()` にする)。限界: 回路図の上に重ねる電圧・電流の表示、コピー・スニペット・整列、「選択中の部品」で選ぶ操作は、開いているシートの中だけ。CLI は `sheet` 命令でシートを作れる(`ccad` の `sheet add`・`sheet move`。`net` で作った、配線なしでラベルだけの回路を、機能ごとに分けられる。複数シートのファイルを開いて解析・基板取り込みもできる)。ブロックを置いて同じ回路を繰り返し使う階層(子シート)は未対応。

### part_form/step3d.rs — 部品の3Dの形 (STEP)
部品を作るフォームの「基板の形」タブの下に、「3D の形 (メーカーの STEP ファイル)」。「STEP を読み込む…」で `pcb_core::step::read_step` を呼び、`thin_out`(頂点を格子に寄せて、12000三角形以下に間引く)してから `step_base` に持つ。向き(X・Y・Z 軸に90°)・「本体の中心をパッドの中心に」・「本体の底を基板の面に」を `step_apply` で `model3d` に反映する。上から・横からの小さな図(`mesh_view`。赤い枠がパッド、緑の線が基板の面)で確かめる。**図は `egui::Mesh` で描くこと**(`convex_polygon` は角が羽毛化されて、細長い三角形がトゲになる)。`PartDef.model3d`(ライブラリの JSON に入る。空なら書かない)→ 回路図から基板への取り込み(`board_editor/file.rs`、CLI の `board import`)で `Board.models3d` へ。基板の3D(`view3d/scene.rs`)は `Scene.meshes` を三角形ごとに描き、高さ・ケースの高さの確認にも使う(メッシュの `z` の最大)。`--form-step <file>` は撮影用。限界: 既存の部品を開いて3Dだけ付け直す入口はない(部品の編集そのものが無い)。

### 基板への取り込み: ライブラリの部品のフットプリント(2026-10-25)
- `import_from_schematic`(`board_editor/file.rs`)は、ライブラリの部品が自分のフットプリントを連れてくる。**ライブラリが起動時のままだと、起動後にフォルダへ足した部品(`ccad part import`、ファイルのコピー)のフットプリントが見つからず**「フットプリント … が見つかりません」になった。今は、`SchEditor.library` に無いときは、既定のライブラリのフォルダ(`part_lib::default_dir()`)を一度だけ読み直して探す。それでも無いときは、警告に「回路図の『ライブラリ』の『再読み込み』を押すか、部品を作り直してから、もう一度取り込んでください」を足す(`import_notes`)。テスト `a_missing_library_footprint_says_to_reload_the_library`。
- **シミュレーション専用の部品(`Component.sim_only`。2026-10-25)**: 試験用の電源・測る相手の代わりの抵抗を、基板・部品表から外す印。`sch-core/lib.rs` の `Component.sim_only`(保存は立っているときだけ)、基板の取り込みは `cli/board.rs` と `app/board_editor/file.rs` の `netlist_of` が `!c.sim_only` で除く(ネットの中のその部品のピンは、基板に部品がないので無視される)。CLI は `simonly REF [off]`、アプリは `schematic/panel.rs` の部品の編集欄のチェックボックス。テスト: `sch-core/tests.rs` の `the_simulation_only_mark_is_saved_only_when_set`、`cli/tests/script.rs` の `a_simulation_only_part_simulates_but_is_left_off_the_board`。

- `board_editor/tools.rs` の `polygon_click`(2026-10-26): 外形・ゾーンのツールの多角形の描き方(ゾーンのツールの `zone_op` が足す/引く)。`PolyMode`(`mod.rs`: 直線 / 3点円弧 / 接線円弧 / 円 / 長方形)、`poly`(描きかけを短い直線にしたもの)、`poly_verts`(描きかけの頂点と円弧の通る点。確定すると `Shape` になる)、`arc_mid`(3点円弧の途中の点)、`pending`(円の中心・長方形の角)、`shape_round`(長方形の角の丸め)。円弧は `pcb_core::outline::arc_through`・`arc_tangent` で短い直線にして `poly` に足す。プレビューは `polygon_preview`(`draw.rs` の `draw_cursor`)。設定の行は `panel.rs` の `poly_mode_ui`。
- `board_editor/zoneedit.rs`(2026-10-26): 選んだベタの図形を、ポインタで直す。`zone_handle_at`(頂点・円弧の通る点)・`zone_edge_at`(辺)で当たりを見て、`interact.rs` の `pointer` がドラッグ(`vdrag`)・ダブルクリックで頂点を足す・右クリックのメニュー(`vmenu`、`zone_edit_menu`)を受ける。Delete は `canvas.rs` で、選んだ頂点(`vsel`)を先に消す。図形の操作は pcb-core の `shape.rs`(`nearest_edge`・`insert_vertex`・`remove_vertex`・`make_arc`・`make_line`)。
- 部品の表示(`Visible.parts`、2026-10-26): 物の表示とロックの「部品」の目。隠すと、部品のパッド・シルクの外形・部品番号が描かれず、選べない(部品に属さないパッド・シルク・配線・ビアは、そのまま)。

- シートごとの色分け(`board_editor/sheets.rs`): 回路図が複数シートのとき、取り込みで `Board.part_sheets`(部品番号→シート名。`netlist::import_sheets`。1シートだけなら空)に入れる。`draw_sheet_groups` が部品のまわりをシートの色(8色の輪)で囲み、グループの左上にシート名を出す。左パネルの `sheet_legend` に、色・シート名・個数のボタン(押すとそのシートの部品をまとめて選ぶ)と「シートごとに色分け」(`show_sheets`)。テスト `each_sheet_of_the_circuit_gets_its_own_colour`
- ゲートの入れ替え: 左パネルの「ゲートを入れ替えて交差を減らす」(`actions.rs` の `swap_gates`。`Board.swap_specs` があるときだけ出る)。詳しくは `pcb-core.md` の `swap.rs`
