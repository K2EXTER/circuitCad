# pcb-core: ベタ(ゾーン)・島・仕上げ(角丸め・涙型・すき間埋め)・部品の外形・シルク文字

(`docs/code-notes/pcb-core.md` の目次から分けた。内容は元のまま)

- `body.rs` 部品の本体 `BodySpec`(四角/円+向きの印 点/棒/＋、部品JSONの `body`)→ シルク線 `body_lines`(パッドに重なる所は切る)。`PartDef::footprint` が `Footprint.silk` にして、`parts.rs` の `set_part` がシルクとして置く(`footprints.rs` の `outline` は内蔵フットプリントの本体)。部品作成フォームは `part_form/` の「本体の外形」「放熱パッド」(放熱パッドは中心の追加パッドになる)と、形のプレビュー `footprint_preview`(パッド・穴・シルク)
- `outline.rs` 曲線の外形(`round_corners`・`rounded_rect`・`ellipse`。外形は多角形のまま、曲線は細かい線分にする) / `model3d.rs` 3Dプレビュー用の部品の立体(`part_boxes`が部品ごとに複数の箱/円柱を返す。チップ+電極、ICの足、ヘッダのピン、円柱。種類は `part_kind`、高さは `part_style` でフットプリントから推測)。向きの印: ICの1番ピン側の白い点(`pin1_dot`、ピン名が「1」の部品)、ダイオード/LEDのカソード(ピン名 `K`)、電解コンデンサの−側の縞。高さは `Footprint.height`(部品JSONの `height`、`PartDef::footprint` が載せる)があればそれを使い(`part_height_on`)、無ければ名前から推測
- ベタとつながる判定(`drc/connectivity.rs` の `anchors_inside`)は、部品の中心か端がベタの外形の中にあるか、部品の縁がベタの外形の線にかかっているか。手で描いた多角形(GND以外のネットのベタなど)に、パッドが一部だけ重なっていてもつながる。テスト `a_pour_joins_pads_that_stick_out_of_its_outline`
- `merged_fills` は各ベタの `raw_fill` を1回だけ計算して使い回す(島の判定が同じネットの他のベタの塗りも要るため。以前は同じネットのベタの数だけ二重・三重に計算していた。4枚のBATのベタの基板で 24ms → 11ms)
- `slot.rs` の `closed_pieces`(銅のかたまりごとの閉じる計算。1かたまり 1〜6ms)は、配線の形と間隔 `d` が前回と同じなら、スレッドごとの記憶(`MEMORY`、1024件まで)から返す。1か所を編集したあとは、その配線のかたまりだけ計算し直す(あなたの基板で仕上げ全体が 30ms → 4〜6ms)
- `raw_fill` は、ベタの外形の外にあるクリアランスの図形(他ネットの配線・パッドなど)を、差し引く前に捨てる(小さなベタは、数個しか影響しない)。4枚の小さなBATのベタと2枚の全面GNDの基板で、ベタの計算が 12ms → 5.5ms
- すき間を埋める(`slot.rs`)は `Finish.slots`(既定は切。基板のチェック「すき間を埋める」、ネットクラスの上書き `FinishOverride.slots`)を入れたときだけ働く。「分かれ目を丸める」(`forks`)とは別(2026-10-27。埋める形が崩れる所が出たため)。
- 閉じる計算(`slot.rs slot_patches`)には、パッドを入れない(配線と整えの多角形とビアだけ)。パッドを入れると、パッドとそのそばを通る太い線のすき間(短い首をはさむ)が全部埋まり、首より広い台形の「じょうご」になった(2026-10-27、microohm の U4 の BATP)。切り欠きの判定(`notched`)は、パッドの位置を今までどおり使う。太さが 1.34 倍より違う線がつながる所(0.25 が 0.5 に入る T 字など)のすき間も埋めない(`unequal_tracks`。角は整えの丸め(フィレット)に任せる。埋めると縁がぎざぎざになった)。
- 幹の先(`smooth.rs` の `trunk_blocks`): 2本の首(`is_neck`。同じ向き・同じ長さ・軸に沿う)が出ているパッドの手前を、幹の太さ(首の外側の縁まで)で、パッドの面から幹の始点まで埋める多角形を、仕上げのときに足す。パッドの間の手前には、すき間と同じ幅の「凹型の円形」(U字で、先が半円。深さは すき間の幅の約1.6倍、ブロックの長さの7割まで)の切り欠きを空ける。パッドは離れたまま、はんだはパッドに残る。ブロックの形は、幹を引いた直後でなく、表示・ガーバーのときに毎回計算する(`Board.finish.forks` が入っているとき)。首の長さ `NECK_LEN` は、幹の丸い端(半径=幹の幅の半分)が切り欠きに入らないように 0.75mm(パッドの縁から)にした(以前は 0.4mm で、丸い端がパッドの間まで届いて、切り欠きが作れなかった)。`slot.rs` の「短いすき間は全部切り欠き」は、以前の 0.4mm の首で引いた幹のための備え。テスト `trunk.rs` の `finish_tests`
- 短いすき間は全部切り欠き(`slot.rs` の `notched`): すき間が、切り欠きの深さ(`NOTCH_DEPTH` × すき間の幅)より短くて、全部が切り欠きの中に入るとき(幹の首は、パッドの手前 0.4mm しかない)は、何も埋めない。以前は、切り欠きを丸く削った結果が空になって「切り欠きなし」の扱いになり、すき間が全部、パッドの間までひとかたまりで埋まっていた(幹のパッドの間が大きく埋まった原因)。普通の長いすき間は、これまでどおり、丸い切り欠きを残して埋める。テスト `slot.rs` の `a_slot_shorter_than_the_notch_is_left_open`・`trunk.rs` の `finish_tests`
- 仕上げの切り戻し(`smooth.rs` の `pad_clip`): 配線がパッドの面にまっすぐ(軸に沿って)入り、パッドが配線の向きと直角の方向には配線の太さより大きい(丸い端が収まる)のに、配線の向きには浅い(丸い端が反対側の面を越える)とき、首にはせず、丸い端の先がパッドの反対側の面にちょうど触れるまで、配線を縮める。はみ出した丸だけが切れて、太さは変わらない。ほかの配線とつながる継ぎ目(涙型の根元など)の端には使わない(2度かけても同じ結果にするため)。`pad_neck` と `pad_fillet` より先に判定する。パッドの手前の面にできる丸み(涙型、`pad_fillet`)は、切り戻しといっしょに残す(`Edit.live` に、切り戻しの `trims` と、丸みの多角形を入れる)。テスト `a_wide_track_entering_a_narrow_pad_from_the_side_is_cut_at_the_far_face_of_the_pad`
- 仕上げの首(`smooth.rs` の `pad_neck`。パッドの向きと直角の方向にも配線より細いとき、または斜めに入るときに使う。パッドの面に垂直に入る配線の `pad_fillet`(面での丸み)より先に判定する。横から入る短い配線では、`pad_fillet` が先に採用されて、首がつかず、反対側の丸い端がはみ出していた。首の太さは、配線の端の位置から見た、パッドの中に丸い端が収まる最大(中心なら短い辺。端に近いほど細く、基板の最小線幅が下限)。配線が短くても、首と広がりを縮めてつける): パッドの短い辺より太い配線がパッドの中心で終わると、配線の丸い端が、パッドの両脇にはみ出す。パッドの短い辺と同じ太さの首を 0.35mm(配線が短ければ縮める)つけ、その先を、配線の太さまで 1.5 倍の長さでなだらかに広げる(`pad_taper` の逆。パッドのほうが細いときだけ。首がルールの最小線幅より細くなるとき・同じ所から別の配線が出ているとき・配線が短すぎるときはしない。`apply_checked` が、新しい違反が出るものを取り下げる)。トラックの太さがパッドと同じか細いときは、これまでどおり。テスト `a_wide_track_on_a_narrow_pad_gets_a_neck_as_wide_as_the_pad`
- ベタの分断(`drc/pour.rs` の `split_pour_checks`・`pour_split_airwires`・`pour_splits`): `connectivity` は、ベタの外形の中にあるものを同じネットなら全部つなぐ(外形で判定)ので、ベタが他のネットの配線やパッドで切れ切れになっていても、切れ端の中のパッドが、残りとつながっているとして扱われる。そこで、ベタなしの接続 `connectivity_without_pours` と、ベタの実際の銅(`merged_fills` のかたまり)から、ネットごとに「パッドを持つ銅のグループ」を、ベタのかたまりごとにつなぎ直し、つながらなかったパッドを見つける(残りの中でパッドがいちばん多いかたまりが本流)。`zone_checks`(発注前チェックの「ベタ」の警告)に含め、エディタの未配線の線(`cached_airwires`)にも、切れ端のパッドから本流の最も近いパッドへ、1本足す。`drc::check`・基板エディタの「DRC を実行」・ルーターの `ratsnest`・`connectivity` の本体は、まだ外形で判定のまま(計算が重い。ルーターが何度も呼ぶ)。ネットのビアもパッドと同じ扱い(`Spot`。ベタの塊の中に実際に載っていなければ、切れ端になる)。基板エディタの「DRC を実行」は、最後に `ratsnest::open_violations`(未配線の線1本=指摘1件、文頭が「未配線」)を足す(2026-11-06。以前は DRC が未配線を数えず、ベタから切れた GND のビアも黙っていた)。`drc::check` 本体(ルーターが何度も呼ぶ)は変えていない。Mega 基板のレッスンは、文頭が「未配線」の指摘を除いて「違反 0 件」を判定する(`lesson.rs` の `rule_findings`)。テスト `tests_via.rs` の `a_pour_cut_in_pieces_…`
- ベタの上書き(`zonefill::pours_covered_by_later` と `drc/pour.rs` の `covered_pour_checks`): 同じ層で、あとから置いたほかのネットのベタが勝つ(前のベタはそこをくり抜く)。前のベタの輪郭の `COVERED_SHARE`(50 %)以上があとのベタに覆われていたら、`zone_checks` が「あとから置いたゾーン (NET) に上書きされています」と警告し、発注前チェックは別の項目にする(`fab.rs`)。小さい前のベタを大きい GND のベタの上に重ねるのは「あとに置いたほうが勝つ」ので、直すなら GND を先に(ゾーンの並びの前に)置く。実例: ミリオームメーターの基板で、裏面の DRN(16×16 mm)と guard の GRDA・GRDB が、基板全体の GND のベタ(後)に 100 % 覆われて、銅が出ていなかった。
- `labels.rs` 部品番号のシルク文字を、配線・パッド・ビア・穴・ほかの文字・ほかの部品の枠・基板の外に重ならない場所へ動かす(`avoid_overlaps`)。候補は、いまの位置→部品の上→下→さらに上→さらに下→右→左。重なりの点数は、銅(配線・パッド・ビア・穴)が3、ほかの文字が2、ほかの部品の枠が1、基板の外が20で、点数がいちばん低い所を取る(同点は先の候補)。すでに何にも重ならない文字と、手で動かした文字(`label_offsets` にあるもの)は動かさない。動かした位置は `label_offsets` に入れるので、部品を動かしてもついてくる。アプリは基板の「仕上げ (任意)」の「文字を配線からよける」、CLI は `board labels`。あなたの基板(13部品)で 5個を動かし、3個は空きがなく重なったまま。テスト `labels.rs`
- `zonefill.rs` の島の判定(`remove_islands`)は、同じ層・同じネットのほかのベタ(重なる・接する)とつなげた塊(`union`)で調べる。以前は自分のベタの中にパッド等が無いと、隣に足した同じネットのベタが「島」として丸ごと消えていた。描画は `merged_fills`(同じ層・同じネットのベタを1つにまとめる。重なりの二重塗りと境目が消える。ガーバーは従来どおりベタごと)。テスト `a_pour_of_the_same_net_beside_another_is_not_an_island`・`merged_fills_join_overlapping_and_touching_pours_of_one_net`
- `zonefill.rs` ベタの銅を図形として求める(`zone_fill`: ゾーン ∩ 外形 − 他ネットの配線・パッド・ビア・取付穴・基板端のクリアランス − 同じ層で後から作った別ネットのゾーン(後のほうが勝ち、クリアランスの隙間をあける)。`i_overlay` で計算、曲線は誤差 `CURVE_TOLERANCE` 以下の短い線分)。エディタの描画(`board_editor/draw.rs`、`geometry_key` でキャッシュ)とガーバー(`gerber.rs` の `zones`)が同じ結果を使う / `outline.rs` の曲線は `ARC_TOLERANCE` で半径に応じて細かくする / `gerber_view.rs` の `Preview` は 2×2 で描いて平均する(縁がなめらか)
- `smooth.rs` 配線の仕上げ(角丸め・段差・涙型・分かれ目の凹み)。設定は `Board.finish`(`Finish{corners,radius,tapers,forks}`。スイッチは無く、どれか1つでも入っている(`finish_active`)と、配線そのものは変えず、表示・ガーバー・DRC(`drc::check_final`、発注前チェックも)のときだけ `smooth::finished(board)` で毎回計算した形を使う。結果は `Finished{board=派生した配線のボード, patches=多角形の銅}`)。編集の処理(自動配線・押しのけ・`drc::check`)は元の配線のまま。表示はエディタが `geometry_key`+設定でキャッシュ(`board_editor/smoothing.rs` の `finished`)。
  - 角丸め `corner`(同じ太さの2本がつながる角を `radius`(既定0.5mm)の円弧=22.5°ごとの短い線に。各配線は1つの端につき長さの半分まで=短い配線は半径が小さくなる。30°未満の曲がりは触らない=円弧の継ぎ目を丸め直さない)
  - 太さの段差 `taper`(差が0.1mmより大きい時、太い側の端を段差0.08mm以下の中間の太さの配線でなだらかに)と、パッド・ビアに入る根元 `pad_taper`(涙型。四角いパッドは縁の長さと同じ幅から配線の太さへ、縁から太さの差の1.5倍の長さ。反対の端がパッド・ビアでない配線は、残りの長さ(-0.05mm)までを使い、足りなければ傾斜を縮める(太さの差の0.3倍=最低0.15mmまで。自動配線のリードのような短い線にも付く)。反対の端もパッドの配線は、従来どおり長さの半分ずつ丸・長円・ビアは中心から直径の幅で始める。同じ場所から別の配線も出ている端は、涙型が重なるので何もしない)
  - 分かれ目 `fork`(1つの点から同じ太さの2本が8〜60°で出ている所の、間の細いくぼみを、両方の縁に接する自由な円(半径=配線の太さ)の手前まで埋める多角形の `Patch`。凹んだ丸い先端になる。経路は変えない。丸い端の配線で埋めると縁との継ぎ目にとげができるので多角形にした)。パッチは、別のグループの銅が `min_clearance` 以内にある・中にある時は作らない(`drc::patch_clear`)ので、DRCはパッチを知らなくてよい。ガーバーは `G36` の領域として書く
  - 角丸めも、整えた形の表示・出力では円弧の多角形(`corner` の `Live`。外側と内側の円を4°ごとに標本した帯。つなぎ用に15°ごとの粗い配線を内側に置く)。確定では22.5°ごとの短い配線
  - 段差と涙型は、確定(配線に書き込む)では短い配線の階段、整えた形の表示・出力(`finished`)では多角形(`Edit.live`)で作る。多角形の縁は滑らかな曲線(`band`、`ease`=両端でなだらかな増減)。丸・長円・ビアの涙型は、配線の縁から円に引いた接線。配線の端は短い配線(`Live.pieces`)でつないで連結を保つ。多角形は、他のネットの銅が近いと作らない(その編集は丸ごとやめる)
  - T字 `junctions`(3本以上が1点に集まる所=分岐の先が別の配線の途中に付く、または3本が端で出会う。パッド・ビアの上は除く。1点から出る向き(`Ray`)を角度順に並べ、となり合う2本の間の角ごとに `notch_fill`=両方の縁に接する半径 `radius` の凹んだ円弧の手前まで埋める多角形。太さが違っても、縁の交点を連立方程式で求める。曲がりが8°未満・172°超、または配線が短くて入らない時は作らない)。1点が2本だけの鋭角は `fork`、3本以上は `junctions`(同じ点に両方が働かないよう、`fork` は途中を通る3本目があれば譲る)。どれも `forks` の設定と「整えた形で表示・出力」のときだけ働く
  - ネットごとの整え方 `NetClass.finish`(`FinishOverride`: 各項目が `None`=基板に従う。`plan` は `groups` でネットを「上書きのあるクラスごと」と「残り」に分け、グループごとの設定で `plan_one` を回して、そのグループのネットだけに関わる編集を残す。分かれ目のパッチ(`trunk_blocks`・`slot_patches`)も同じグループ分け)。形が特性を決める線は `FinishOverride::off()`(3つとも切る)。旧 `Board.finish_exclude` は読み込み専用で、`migrate_finish_exclude`(エディタの `adopt`・CLI の `board open`)が、そのネットのクラス(無ければ線幅を引き継いだ専用クラス)の `off()` にする
  - パッドの辺の肉づけ `pad_fillet`(整えた形の表示・出力のときだけ。`plan(live=true)`): 四角いパッドの辺から垂直に出る配線の端ごとに、両側の隅を凹んだ円弧で埋める多角形(根元はパッドの辺に平らで、側面は配線へなめらかに入る。1本の配線につき1つの多角形)。半径は、パッドの角まで・隣の配線との隙間の半分(同じ辺から並んで出る2本は、半分ずつで合わさり、隙間の端が半円のアーチになる)・上限 `MAX_FILLET`(0.4mm)・配線の残りの長さの最小で、`MIN_FILLET`(0.1mm)未満の側は作らない。配線は変えない。垂直でない出方・丸いパッド・ビアは、従来の段の涙型(`pad_taper`)。配線に確定する処理(`plan(live=false)`)は、段の涙型のまま
  - 太い配線の縁に細い配線がT字で付く所 `edge_junctions`(中心線上でない端を中心線まで延ばして、両側のすき間を `notch_fill` で丸く埋める。`Kind::Fork`、配線は変えない)。配線に確定する段の涙型は `BAKE_STEP`(0.02mm)刻み(表示は多角形でなめらか)
  - `drc/slit.rs` の `slit_checks`: 同じネットの銅箔どうしが最小間隔より近いのに触れていないすき間(太い配線と枝の間・ヘアピン・配線とパッド)。間に別の銅箔が入っていれば除く。`check` には入れない(同じ接続グループは違反にしない)。発注前チェックの警告と、基板エディタの「DRC」の一覧に出る。`fill_slits`(「つないで埋める」・`board slits`)は、DRC と設計の要件の指摘が増える埋め方を採らない(パッドの脇の細い隙間を埋めると、検出の線がパッドの外側へ近道して `tap` が崩れた例がある)
  - 仕上げは全部まとめて試してDRC違反が増える/接続が切れるなら、1つずつ試して無害なものだけ採用(`apply_checked`)。1つずつ試すとき、DRCに違反が無い基板では、変えた配線だけが原因の違反を数える(`drc::violations_of_items`。1回の `connectivity` と `ratsnest_in` を使い回す)。違反がある基板は、従来どおり全体を調べる。ふくらみ(パッチ)が他の銅箔から離れているかの判定は、銅箔の一覧を1回だけ作り、外接矩形で絞る(`drc::PatchCheck`)。LED基板で、整えた形の計算 0.59秒→0.013秒、仕上げ後のDRC 0.60秒→0.016秒、整えた形の確定 1.75秒→0.62秒。結果は、40サンプルと、40通りの位置のテスト(`tests_smooth.rs`)で、変更前と一致
  - 配線に確定する `smooth_tracks`/`smooth_selected`(角丸めと段差だけ。パッチは基板に保存しないので分かれ目は確定できない。`smooth_selected` で選んだ配線が関わる所だけにもできるが、GUIのボタンは無い。「整えた形を配線に確定する」ボタンと `--smooth` は、段差が見えて重くなるので2026-11に外した。表示・ガーバーは `finished` から作るので確定は要らない)。GUIは「仕上げ (任意)」の「配線を整える」。3Dビューの銅の絵はガーバーと同じものから作るので整えた形が出る。ネット強調(`view3d/glow.rs`)も整えた形と多角形のパッチを使う。3Dの絵は「更新」で作り直す
  - `autoroute::Router`(障害物の格子を1回作って使い回し、`path(net, a, b, side, vias, margin, budget)` で任意の2点間の経路を探す。探すのは2点を囲む箱(`margin`)の中だけ、`budget` を超えたら諦める。エディタのライブ経路探索用。`tests_router.rs` の `timing_on_a_large_board`(--ignored、release)で、100×80mm・約600パッドの基板で、格子の構築4.5ms、10mmの経路0.7ms、90mmの経路45ms)
- 速さの注意: `drc::connectivity` が、ベタが銅箔の何かに触れるかを見るとき(`anchors_inside_in`)、ベタと品物の箱で先にふるう(ガードのベタは辺が数百ある。ふるわないと 2300 個 × 辺の距離で 80 ms かかった)。基板エディタの左パネルの「サーマルビア」の数は、`zonefill::geometry_key` が変わったときだけ数える(毎フレーム全部のベタを塗っていた)。
- `par.rs` `par_map`: 独立な仕事を全コアに配る(結果は元の順)。ベタ(`merged_fills`・`PourFills`)、仕上げの角と根元(`smooth::plan_one`)、スロット(`slot_patches`)がこれで動く。ガード付きの 190 部品の基板で、仕上げ `smooth::finished` が 1.5 秒 → 0.25 秒、ベタ全部 150 ms → 56 ms(8 コア)。ベタの塗りは `zonefill` が基板の状態ごとに覚えている(`FILL_CACHE`・`MERGED_CACHE`)。
- `copper.rs` 配線のあとに足す銅: `add_guard_tracks`(検出ネットの表の配線の両側にガードの線を、オフセットして角で交点にそろえて置く。線にはネットが無く DRC が見ないので、試すときは先端に小さなガードのネットのパッドを仮に置いて見る。連なりごとにガードのネットのビア 1 個。置けた割合は配線の長さと周りの混み具合しだいで、mmUser では A が約 3 割、B が約 5 割だった)、`add_guard`(旧い。検出ネットの配線ごとの長方形のベタをガードのネットで置く。検出線で切れた片側のベタは、ガードのネットの銅に触れないと島として消えるので、実際に囲めた割合は 1〜5 %。`mode=pour`)、`add_copper`(長方形のベタを層ごとに置き、ビアをネットのパッドの近くから置く)。
- `slot.rs` 仕上げ(`Board.finish.forks`)の細長いすき間埋め(`slot_patches`)。同じ銅のかたまりを幅の0.8倍(角の半径が小さければそれ)だけふくらませてから同じだけ縮めて(クロージング。`i_overlay` の `outline`)、足された部分を多角形の `Patch` にする(2本が並んで走って合流する所のすき間、ヘアピン)。**ほかのパッチ(分かれ目・T字)は銅として一緒にふくらませる**: それらが残す丸いくぼみ(半径=配線の太さか角の半径)に届かない大きさ(0.8倍)にしてあるので、くぼみは埋まらない(`tests_smooth.rs` の2つのテストがこれを守る)。角の内側の丸みだけの小さな破片(`MIN_PIECE`)は捨て、`SINK`=0.02mm 銅に食い込ませて継ぎ目の細い線を消す。ほかのネットの銅が近い所は `PatchCheck` が断る。配線は変えない。`arduino_mega_usb` で仕上げに +0.17秒(release、配線746本)
  - **パッドの手前の切り欠き(`notched`)**: 埋めるすき間が、同じネットの2つ以上のパッド(例: QFN の2本の LX ピン、ピッチ 0.65mm)に挟まれて終わるときは、パッドの縁からすき間の幅の1.4倍(`NOTCH_DEPTH`)だけ手前までを埋めずに残し、先を丸くする(すき間と、パッドの間のすき間につながる)。残す形は、パッドを1.4倍分だけ丸く広げた領域とすき間の共通部分を、すき間の幅の0.45倍(`NOTCH_ROUND`)で開く(縮めてから広げる)ことで丸めたもの。offset は既定が面取りなので、ここだけ丸い継ぎ目(`LineJoin::Round`)にした。パッドが1つだけのすき間や、パッドのないすき間は、今までどおり端まで埋める。画像の緑の U(2026-10-22、利用者の基板)の形。テスト `slot.rs` の `the_slot_between_two_pads_…`・`a_slot_not_between_two_pads_…`。形を目で見る道具は `tests_label.rs` の `dump_finish`(`CCAD_BOARD=<基板> CCAD_OUT=<json> cargo test -p pcb-core dump_finish -- --ignored`)
- 島(そのネットのパッド・ビア・配線に触れない銅)は、いつも銅から外す(`remove_islands` は、ファイルの互換のためだけに残した)。外した島は `zonefill::dropped_islands` で調べ、画面がうすい灰色の破線で描く。
- ベタは図形のリスト(2026-10-26): `Zone.shapes: Vec<ZoneShape{shape: Shape, op: Add|Sub}>`(`model.rs`)。`Shape`(`shape.rs`)は頂点と、頂点から次の頂点への円弧の通る点(`Vertex.arc_mid`)を持ち、`flatten` で短い直線の多角形にする(`outline::arc_through`)。ベタの面は `zonefill::zone_region`(足す図形の和 − 引く図形の和。`Zone::region`)で、塗り(`raw_fill_uncached`)・DRC の接続(`drc::connectivity`)・ガーバーのサーマル・抵抗(`irdrop`)が使う。古いファイルの `polygon`・`holes` は、読み込みで足す図形・引く図形になる(`ZoneFile`)。`merge_zone_outline`・`bake_zone`・`tidy_zones` が「頂点に確定」、`add_zone_cut`・`clear_zone_holes` が引く図形の追加・削除。CLI は `board zones [merge|bake]`・`board keepout`。画面は、ゾーンのツールの「足す/引く」と、選んだベタの図形の一覧。まだ穴を見ないもの: `board_editor/select.rs` のベタの選択(`Zone::covers` で図形だけを見る)。
