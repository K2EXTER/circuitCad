# pcb-core: 自動配線・押しのけ・引き直し・まとめ・蛇行・差動ペア・故障の仕込み

(`docs/code-notes/pcb-core.md` の目次から分けた。内容は元のまま)

- 幹の首と電流の判定(`current.rs` の `is_neck`): パッドから出る 1.2mm 以下の細い短い配線で、反対の端が同じネットの、より太い配線(幹の丸い端も含む)の銅の上にあるものは、首として、「配線の太さの判定」(`net_widths` の最も細い配線)・「推奨幅にする」(`widen_net`)・ネットの窓のスライダーの対象から外す(首はわざと細く、パッド1つぶんの電流だけを運ぶ)。以前は、幹の首 0.25mm が「最も細い配線」になり、幹が 0.9mm あっても「足りません」と出ていた。テスト `trunk.rs` の `neck_tests`・`neck_widen_tests`
- `diffpair.rs` 差動ペア(`DiffPair{p,n,gap,max_skew}` は `Board.diff_pairs` に保存)。`pair_report`(長さ・スキュー・並走の長さ・間隔)、`check_pairs`(片方だけ配線/長さの差/間隔のずれ/並走が少ない。DRC実行と発注前チェックに出る)、`tune_length`(短いほうの1本に蛇行を足す=その所は間隔がずれる。平行な2本は山ごとに同じだけ長くなるので、いっしょに曲げてもペア内の差は直せない。DRCが悪化するなら何もしない)、`match_pairs`(ペアどうしの長さ合わせ。ペアの長さ=2本の平均で、いちばん長いペア(または指定の長さ)に、短いペアの2本へ同じ長さの蛇行を足す=ペア内の差は変わらない。蛇行は `meander::tune_pair`(2本を入れ子の山でいっしょに曲げる。下の `meander.rs`)を先に試し、入らなければ線ごとの蛇行。ペアごとに元の盤を控えて、片方の線で失敗したらそのペアは元に戻す。画面は差動ペアのパネルの「ペアどうしの長さを合わせる」、CLI は `board matchpairs`)、`suggest_pairs`(`USB_DP/USB_DM` `D+/D-` などネット名から探す)。ペア配線は `autoroute::route_pair`(＋側を引いてから、－側は `RouteOptions.follow` で＋側の隣のセルが安くなる)。GUIは `board_editor/pairs.rs`(配線パネルの「差動ペア」)、「全部」自動配線もペアを先に引く。
- `shove.rs` 押しのけ配線(`add_tracks`=新しい配線を足して邪魔な別ネットの配線を脇へ寄せる、`move_track_shoving`=配線を1本動かす、`rip_up_net`=ネットの配線を全部消す。パッド/ビアに付いた端は動かさず、両端が固定の配線は `dogleg` で5本に分けて途中を45°の斜めで脇へ膨らませる(障害物の端から `√2×必要間隔` 手前から斜めを始める。短くて斜めが入らない・障害物が配線と同じ向きに近いなら押しのけない)、最大 `MAX_SHOVE`、差動ペア(`Board.diff_pairs`)の片方が押されたら、相手線との距離を「ペアの `gap`、ただし元の距離より広げない」まで保つように相手線も押す(`resolve` の `pair_gap`。破片は `parent` で元の配線をたどる。テスト `a_shoved_pair_keeps_its_gap`)、DRC違反が減らず接続が切れるなら採用せず普通に足す)。GUIは `board_editor/shoving.rs`(経路プレビュー `route_preview`=橙の線で押しのけられる配線の今の位置(細い線)と動く先(太い線)をカーソルに合わせて出す/赤=違反。基板は変えない。1回の計算が60ms(`PREVIEW_BUDGET`)を超える基板では、結果を250ms保って間引く=約450本の配線(release)から。小さい基板は毎回計算、選択ツールで配線をドラッグ、選択パネルの「このネットの配線を全部消す」。ツール設定の「押しのけ配線」で切替)
- `meander.rs` 長さ合わせ(蛇行配線。`tune_net(board, net, extra, opts)`=ネットのまっすぐで長い配線(長い順に4本)の片側に、山(幅=間隔=`max(3w, 2w+クリアランス+0.1)`)を並べて `extra` mm 長くする。山の高さは、角の形で長さが減る分を、長さが合うまで直して決める(`MeanderStyle`: 四角/面取り=45°で切る/丸=15°ごとの円弧)。両側を試し、DRCが悪化するもの・長さが合わないものは採用しない。`match_nets`=選んだネットを一番長いもの(または指定の長さ)に合わせる、`length_of`=ネットの配線の長さ(ビアは除く)。`tune_pair(board, pair, extra, opts)`=ペアの2本が並んで走るまっすぐな所(長い順に3か所)に、入れ子の山をいっしょに入れて、2本とも `extra` mm 長くする(`PairFrame`=2本の座標系、`pair_layout`=山の幅・ピッチ・数、`pair_bumps`=山の座標。山は向きを交互にして外側の線が入れ替わる。平行にずらした曲線は山ごとに同じ長さなので、増えるのは2本とも同じ。角は、外側の線を内側より間隔ぶん(丸=半径+d、面取り=+(2−√2)d)大きくして平行を保つ。深さは長さが合うまで直して決める。DRC悪化・長さのずれは採らない)。`diffpair::pair_report` の相手選びは、いちばん近い平行な線(他の部分のほうが明らかに近い線は相手にしない)差動ペアの `diffpair::tune_length` もこれを使う)
- `breakage.rs` 基板に故障を仕込む(修理の練習。`inject(board, Fault, seed)`: `BypassFar`=バイパスコンデンサを IC から遠くへ・`CutTrack`=配線を1本切る・`ThinTrack`=ネットの配線を最小線幅より細く・`ShortCircuit`=別ネットのパッドの間に余計な配線・`PartOutside`=部品を基板の外へ。部品を動かす故障は、エディタと同じく配線が付いてこないので、パッドに付いていた配線と、行き止まりになった残りを消す=`move_part_ripping`。同じ seed は同じ壊れ方。点検に引っかからない壊れ方は取りやめて、基板を元のまま返す)。`health(board)`=点検が見つける数(DRC の違反・未配線・基板の外の部品・バイパスが遠い IC)、`repaired(before, now)`=どれも故障の前より増えていない。`possible(board)`=その基板に仕込める故障。症状(実機で見えること。原因は書かない)と、原因と直し方の文を持つ。画面は基板レッスン8(`board_editor/repair.rs`)、CLI は `board break`・`health`・`reveal`。同梱の材料は `attiny_blinker.schjson` と `work_in_progress/attiny_blinker_board.pcbjson`(`ccad` で作る)。テスト `tests_breakage.rs`
- `reroute.rs` 配線の引き直し(`improve_routes(board, opt, from, only)`。
  - 遠回りしている・ビアのあるネットを、外して引き直す。
  - コスト=配線長+`VIA_WEIGHT`(10mm)×ビア数。
  - 最短の木(パッドを直線で結ぶ最小全域木)より `MIN_EXCESS`(2mm)以上長い順に1本ずつ、単独→邪魔している近所のネット(パッドの箱を `REACH`=4mm 広げた中に配線があるもの。多い順に `NEIGHBOURS`=4)との組の順に試す。
  - 組は2本とも外して、先にそのネットを引き、近所のネットはあとから引く。
  - 全部つながり・DRC違反が増えず・コストが `MIN_GAIN`(0.3mm)以上下がったときだけ採用し、1回の実行は最大 `MAX_NETS`(16)本・`BUDGET`(5秒)。
  - ベタのあるネット・未配線のネットは触らない。
  - `from=Some(n)` は引いた直後に使うとき用(番号n以降の配線があるネットだけ。パッド8個を超える木は除く=GNDなど大きいネットは時間がかかるわりに得が少ない)、`None` は手でのボタン用(基板全体、大きい木も)。
  - 引き直した配線にはパッドの根元そろえと一直線のまとめを行う。
  - 総合デモの手動配線(`board improve`)で配線 389→349mm・線分 242→192本・ビア 2→3個・DRC違反0、自動配線の直後に使っても得は小さい(同梱サンプル43個を「ベタ→配置→配線」した合計で、配線長 2605→2607mm・ビア 53→51個・DRC違反0)ので、自動では行わない(`ccad board route improve=1` で試せる)。
  - 手で引いた配線の10本ほどが対象になり、V5 のような大きいネットの遠回りが主な得になる。
  - `tests` はその場で組んだ「他のネットのふくらみを避けて遠回りした配線」が直ること、範囲指定、毎回同じ結果)
- `autoroute::autoroute_sized`(宣言した電流のあるネットは、その電流に要る太さ(`current::width_for_current`を0.05mmに切り上げ)で先に1本ずつ引き、残りを普通の太さで引く。通らなかった太いネットは、最後の普通の太さの走りで引き直す。`RouteReport.wide` に太く引けたネットと太さ。エディタの「全部」と `ccad board route` が使う。エディタは電流が未宣言なら、回路図のDC電流を先に取る=`route_after_currents`。ガイド付きレッスン中は取らない)
- `merge.rs` 一直線の配線をまとめる(`merge_collinear(board, from)`。端と端が出会い、同じ面・同じ太さで、1本の直線をなす2本を1本にする。その点にパッド・ビアがある所、3本以上が集まる所(T字)、折れている所・折り返している所はそのまま。`from` 以降の番号の配線だけが対象で、古い配線が絡む所は触らない。銅の形はまったく変わらないので、DRCと接続は同じ。端の位置は1e-4mmに丸めて探し、順番は配線の番号順で毎回同じ結果。繰り返して鎖を1本にする)。自動配線の後(エディタは `padentry` の後、`ccad board route` はすぐ後)に新しい配線へ使う。同梱サンプルの自動配置→自動配線で、配線の本数が約2〜4割減り(総合デモ 245→167)、DRCと未配線は変わらない(`tests_merge.rs`)。
- `padentry.rs` パッドの根元をそろえる(線が細いパッドの端からはみ出す所は、まっすぐな部分をパッドの中心線へずらす=`shift_run`。
  - 次の配線は線の上を滑るだけで、段は作らず、残りは `MIN_LEG` 以上。
  - 自動配線のあと、一直線にまとめてからもう一度かける。
  - 端がビアで終わる所は動かせない)(`align_entries(board, opts{lead, spread}, only)`。
  - 四角・長円パッドに入る・出る配線の根元を、辺に垂直な長さ `lead`(既定0.5mm、縁から)の区間にして、その先を水平・垂直・45°の線で元の配線につなぐ。
  - パッドの上の短い配線が続くときは、つながった数本(`chain`)を1本の流れとして扱い、手前の短い配線は消す。
  - 同じ点から2本が出ている幅広パッド(2本ぶんの幅+間隔が入るもの)は、長軸の両端に寄せて並べて出す(`spread`。画面のチェックは無く、常に入る。出る向きが交差しないよう、行き先の位置で左右を決める)。
  - つなぎ方は、折れの角度がいちばん小さいものを選ぶ(水平・垂直・45°の線で、短い配線の続きのどこかに合流する候補と、続きの配線の端(続きがなければ、向こう側の端がパッド・ビアのとき、その端)までを45°の経路で引き直す候補を比べる。引き直した配線も、その先のパッドの処理の対象に入る。角度が0.1rad(約6°)以内の差なら短いほうを選ぶ。パッドに垂直に出て、垂直に曲がってから斜めに入る「Z字」は、45°ずつの折れで済む候補があればそちらにする)。
  - 段差を作らない工夫: パッドが格子の線から少しずれている(横に0.3mm以内)とき、先で配線がパッドの縁から垂直に出る向きに走っていれば、根元をパッドの縁に沿ってずらして1本の直線にする(`slide_foot`。パッドの幅に収まる範囲だけ)。
  - つなぎの折れが `MIN_LEG`(0.25mm)より短くなる候補は採らない(短い45°の段差に見えるため。候補が無ければ何もしない)。
  - すでに垂直なもの、丸いパッド、すき間がなくて候補が無い所は何もしない。
  - パッドごとに試して、DRC違反が増える・接続が切れるなら元のまま。
  - エディタは自動配線の直後に新しい配線へ自動で使い(`pad_lead` が入っているとき)、「パッドの根元」のボタンから、全部の配線・選んだ配線へ)
- `ratsnest.rs` 未配線(`Airwire`。`ratsnest` は銅でつながっていない接続だけで、配線・配置の処理が使う。**利用者に見せる数は `open_connections`**: それに、ベタが分断されて銅がつながっていないパッドの線 `drc::pour_split_airwires` を足したもの。画面・`ccad board status`・発注前チェック・`board picture` が同じ数を出す) / `autoroute.rs` 格子A*の自動配線 (`RouteOptions.pad_lead=Some(L)` のとき、四角・長円パッドは4つの辺のどれかから垂直に、縁から `L` 出た点を探索の出発点・到着点にする=`end_cells`。点までの直線の格子が空いている辺だけが候補で、どの辺も空いていなければ従来どおり「パッドの隣のどの格子点からでも」。出た点から最初の格子点までの短いつなぎ(0.14mm以下)が付く。) (`autoroute`, `route_airwire`、DRCで検証して採用) リードの形(`end_cells`): パッドが格子の線から横にずれているとき、線の中心がパッドに収まる範囲(縁から0.05mm内側まで)で、リードの根元をパッドの縁に沿ってずらし、格子点まで1本の直線にする(段差なし)。
  - ずらせない・ずらした線が塞がれている時は、中心から出て格子点より先まで伸ばさず手前で止める(行って戻る突起を作らない)。
  - 探索の費用はどちらの形でも同じ(経路の選び方が変わらない)。
  - `route_airwire` はずらす→ずらさない→リードなしの順に試し、リードを置けないパッド(間隔が狭いIC)の端も、パッドの中心から水平・垂直・45°の線(`padentry::bend45`)で格子点へつなぐ(中途半端な角度を作らない)。
  - 1本の接続ごとの判定(`route_airwire_with`): 引いた配線だけが原因の違反(`drc::violations_of_added`。幅・端の位置・ビアの穴・アニュラリング・別グループとの間隔・基板の端との間隔・ネット短絡。全体の `check` と同じ結論を出すことを試験で確かめてある)を、1回の `connectivity` と一緒に調べる(基板全体の `check` を前後で2回走らせていた。73部品のLED基板で1回の配線が13.5秒→5.7秒、40サンプルの配線結果は変更前と完全に一致)。
  - 速くなった分、12秒の上限の中に再試行が入り、LED基板は132本が全部通る。
  - さらに、銅の接続グループ(`drc/connectivity.rs` の `groups`)と間隔の検査(`clearance`)は、全部品の組を調べるのをやめ、外接矩形がx方向に重なる組だけを掃引で調べる(`near_pairs`。`clearance` は間隔ぶん広げた箱で、出力の順番は同じ)。
  - LED基板の1回の配線は5.7秒→1.8秒(元は13.5秒)、`check` は約2.7倍速く、結果は変わらない(40サンプルの配線と、間隔を厳しくした規則での `check` の出力が全部一致。力任せの計算との一致を `drc/tests.rs` の `sweep_tests` で確かめる)。
  - 探索のA*の前に、始点から終点へ行けるかを格子の塗りつぶしで調べ(`reaches_goal`。動き方はA*と同じ)、行けないならA*を走らせない(通らない接続1本で、基板全体の約160万状態を4回調べ尽くしていた)。
  - 探索の費用・親の表は、スレッドごとに使い回し、触った所だけ戻す(`Scratch`。毎回約140万要素×2を作っていた)。
  - ここまでで、LED基板の1回の配線は13.5秒→約0.9秒(再試行を含めて132本が約2.6秒)。
  - 結果は変更前と完全に一致。
  - `autoroute` は未配線が残るときだけ、ずらさない形で全体をもう一度引いて、未配線が少ないほうを採る。
  - 配線の再試行(`autoroute`): 未配線が残るときは、通らなかったネットを先に引き直す(最大3回。さらに、リードを中心から出す形でも。新しい走りは `RETRY_BUDGET`=12秒を超えると始めない)。
  - 同梱サンプル40個で未配線 2→0、LED基板は68本中67〜68本。
  - リードなしの端(`tidy_entry`): 格子点が少し横にずれているだけなら根元をパッドの中でずらして1本の直線に、そうでなければ水平・垂直・45°の折れ。
  - 最後の手段だけが自由な角度。
- 自動配置の最後の仕上げ `orient_connectors`(`connectors.rs`。`autoplace` が呼ぶ): 一直線に3つ以上パッドが並ぶ部品(ピンヘッダ)を、向き4通り×1mm刻みの±12mmの位置で試し、**種類の違うネットの未配線がたがいに交差する数**(`ratsnest::crossings`。GNDはベタが引き受けるので除く)が最小になる所へ置く。
  - 条件: 未配線の長さが5%+1mm以内・ほかの部品に近づきすぎない(`crowded`)・配置の範囲の中・DRC違反が増えない(増えたら全部元に戻す)。
  - ヘッダのピンの並びは回路図で決まっているので、効くのは向きと位置だけ。
  - 未配線が250本を超える基板では何もしない(`MAX_TANGLE_WIRES`。試すたびに交差を数え直すため)。
  - `PlaceReport.crossings`(CLI `board autoplace` の `airwire_crossings`)が配置後の交差数。
  - `arduino_minimal` で 80→34(刻みと範囲を変えた中でこれが最少の部類で、基板レッスンの自動配線も通った。刻み1.5mm・範囲±12mm は交差35でも、レッスンの配線にすき間の違反が3件残った: 配置が少し変わるだけで自動配線の結果は変わるので、変えたら `the_arduino_board_lesson…` のテストも見ること)。
  - 同梱サンプル(`quality_bench.py`)は配線長 -0.8%(`arduino_minimal` -4.4%)・ビア +3(117→120)・problems 変わらず(39→39)・時間 +10%(debug)。
  - マイコンの足そのものの並び(ポートの機能順で、D2→D3→D4 の順には並ばない)は変えられない
- `bridge.rs` 隣り合う同じネットのパッドを先に銅でつなぐ(`bridge_pads`。同じ部品・同じネット・同じ面・表面実装のパッドで、一直線に並び、パッドの縁どうしが2.5mm以内、間に同じ部品のパッドが無いもの。つなぎの太さはパッドの短い辺とそろえてパッドからはみ出さない。DRCが増えるなら置かない。GNDとベタのネットは除く)。自動配線の前に呼ぶ(アプリの「未配線を全部つなぐ」と CLI の `board route`。`bridge=0` で止める)と、ルーターには1つの銅に見えて、出口が1本になる(2つのLXピンから2本が並んで走って合流する、間に細長いすき間ができる形を避ける)。応答は `pads_bridged`
- `trunk.rs` 隣り合う同じネットの2つのパッドから、太い1本の幹を出す(`fan` = 首2本と幹の始点・向き・太さ、`add` = DRCで新しい違反が出なければ追加、`check_pair`)。首は線幅(パッドの短い辺より細く)で、パッドの縁から 0.4mm。幹は2つの首の外側の縁までの太さ(ピッチ + 首の太さ)で、始点は首の端の中点(丸い端が首の端を覆う)。縦か横の1列の SMD パッドだけ。理由つきで断る(同じパッド・ネットが違う・列でない・行き先が近すぎる・間隔が足りない)。アプリの配線ツールの「幹で引く」(`board_editor/trunk.rs`)が使い、幹の先は `route_points` の曲げ方(45°など)。自動配線の `bridge.rs`(パッドを先に銅でつなぐ)と同じ考え方の、手で引く版。テスト `trunk.rs`
- 自動配線の接続の端は、パッドだけ(`autoroute.rs` の `pad_ratsnest`)。以前は `ratsnest` のままで、ネットの途中に手で置いたビア(配線が行っていない)が「いちばん近い端」になると、パッドからビアへは引けず、その接続が通らなかった(マイクロオームメーターの GN4〜6 が、ビアを置いたあとで全部失敗した原因)。テスト `a_via_of_the_net_that_no_track_leads_to_does_not_stop_the_route`
- ルーターの探索の重みは `RouteOptions.via_cost`(ビア 1 個を何 mm の配線と数えるか。既定 3)と `bend_cost`(45° 曲がるごとにグリッド何個分か。既定 0.4)。`reroute.rs` の `improve_routes` は、引き直しの探索を `via_cost` 10(`VIA_WEIGHT`)・`bend_cost` 1.0 で行い、採否のコストも「長さ + ビア × 10 + 曲がり × 0.7mm(`BEND_WEIGHT`)」にした(曲がり = 同じ層の 2 本が 1 点で出会い、一直線でない所)。細かい折れ(階段)の多い配線は、長さがほとんど同じでも引き直しの候補になる(2 つまでの曲がりは数えない)。マイクロオームメーターの基板で、ビア 378→367・配線 1477→1452 本・長さ −36mm。テスト `a_route_of_many_small_jogs_is_straightened_though_it_is_hardly_longer`
- `quality.rs` 配線の見た目を数字にする(`measure(board) -> (Quality, Vec<NetQuality>)`): 配線の長さ(全体・層ごと)・ビア・線分の数・**折れ**(同じ層の 2 本だけが 1 点で出会い、一直線でない所。`bends_by_net`。`reroute.rs` のコストもこれを使う)・短い線(0.4mm 未満。階段の段)・45° の長さ・軸に沿った長さ・それ以外の角度の長さ・**並走**(軸に沿った配線のうち、同じ層で別のネットの配線が 0.7mm 以内に 0.5mm 以上並んで走る長さ。バス)。ネットごとには、パッド数・長さ・ビア・折れ・線分・パッドをつなぐ最短の木(直線)の長さ・層ごとの長さ。`NetQuality::detour()` は長さ ÷ 最短の木(1.0 が最短、大きいほど遠回り。ベタのネットはビアで落とすので意味が薄い)。CLI は `board status` の `quality` と、`board quality [top=10] [sort=bends|vias|detour|length|segments] [net=A,B] [poured=1]`(悪いネット順。ベタのネットは `poured=1` でないと出さない)。手動配線と自動配線を同じ配置で比べる物差し(マイクロオームメーターで 手動 折れ 292・ビア 57・裏面 26%・並走 24% に対し、自動は 折れ 369・ビア 75・裏面 41%・並走 9%)。テスト `quality.rs`・`cli/tests/script.rs` の `status_and_quality_give_the_numbers_of_the_wiring`
- 自動配線の層の重み `RouteOptions.pour_layer_cost`(既定 1.2。1.0 で無効): ベタ(ネットのあるゾーン)がある層では、1 歩の費用がこの倍になる(配線がベタを割るため。ベタの層は空いていれば避ける)。`Grid.layer_cost`。マイクロオームメーターの基板を同じ配置で全部自動配線すると、裏面(GND ベタ)の配線の長さ 1511→1145 mm・通らない接続 11→8 本・ビア 232→267 個。同梱サンプル(`arduino_mega_usb` を除く)は 配線長 2823→2805mm・ビア 55→64 個・問題 0 のまま(1.5 にするとビアがもっと増えたので 1.2 にした)。
- `merge.rs` の `remove_covered`(`merge_collinear` の最初に呼ぶ): 同じ層の、同じか太い別の配線の中に両端が収まる配線(同じ配線が二重・パッドから出て戻る突起)を消す。銅も接続も変わらない。自動配線の鋭角の注意が 61→51 か所、配線の長さ −90mm、折れ −52(マイクロオームメーター)。テスト `a_track_drawn_over_another_or_a_stub_that_goes_out_and_comes_back_is_taken_out`
- 並べ方の比較(マイクロオームメーター、ベタ→配置→自動配線): シートの塊も格子も無し 89×84mm・配線 3431mm・コンデンサまでの距離の中央値 3.3mm / 格子だけ(既定)94×94mm・3761mm・3.6mm / シートの塊だけ 110×91mm・3889mm・5.1mm / 両方 113×106mm・4051mm・5.6mm。
- ネットの役割と、細かい格子のはしご(`autoroute.rs` の `autoroute_sized`。`route_pass` が 1 回分、その外側が格子のはしご): `NetClass.role`(`model.rs` の `Role`: なし・大電流・スイッチング・検出・アナログ・ロジック。優先順は `Role::priority`: 0 大電流、1 スイッチング、2 検出、3 アナログ、4 ロジック、5 なし)。`route_pass` は、幅(電流・クラス)か役割のあるネットを、役割の順に 1 本ずつ先に引き(役割のない幅広のネットは大電流と同じ順)、そのあとに残りを引く。**検出**のネットは `no_vias`(パッドと同じ層だけ)で引き、通らなくても、残りの引き(`RouteOptions.skip`)で、ビアつきで引き直さない(`failed` に残る)。そのため、検出に役割のあるネットがあると、元の「幅広が通らないなら普通の引きに戻す」は使わない。**格子のはしご**(`RouteOptions.grid_ladder`、既定オン): 通らない接続が残ったら、格子の 1/2、1/4(0.05mm まで)で `route_pass` をもう一度する(0.5mm ピッチの IC の足の間も通る)。CLI は `board class 名前 role=...`(一覧にも `role`)と `board route ladder=0`、アプリはネットの窓の「役割」。マイクロオームメーターの区画配置を `layers=outer` で全部引き直すと、通らない接続 7→3 本(はしごだけ。時間 36→59 秒)。役割(検出・アナログ・スイッチング)も付けると 10 本だが、検出線 A・B・SA・SB・GRDA・GRDB のビアは 14→0(はしごだけだと、A に 6 個・B に 8 個のビア)。テスト `what_stays_open_is_tried_again_on_a_finer_grid`・`a_sensing_net_gets_no_vias_and_the_nets_go_in_the_order_of_their_roles`
- `autoplace/` の `airwire_length` は、配線も ビアもまだ無い基板では、ネットごとのパッドの最短の木の長さの和(ベタのネットは除く)を使う(`ratsnest` は、ベタにつながるパッドを調べるので遅い)。ミリオームメーターの自動配置が 約 10 秒 → 約 2 秒。格子のはしごの下限は 0.1mm、25 秒で打ち切る(0.05mm まで行くと、パッドの根元をそろえたあとに、わずかに近すぎる銅が出た)。
- `breakout.rs` 足の間隔が細かい IC(行のピッチ ≤ 0.8 mm、8 パッド以上)の足から、出口の短い線を先に引く(`breakout`。辺の真ん中の足はまっすぐ `MID_LEN`、両端の足は `BASE + STEP * 端からの順` まで出てから外向きに `RUN`。近くの別ネットのパッド・線との間隔と、同じネットの狭いすき間を見て、置けない足は飛ばす。IC ごとに DRC が増えたら取り消す)。`autoroute_sized` が、全体の配線で通らない接続が残ったときだけ、この線を引いてやり直し、通らない接続が少ないほうを採る(`RouteOptions.breakout`、既定オン。同数なら引かないほう)。ミリオームメーターの既定の配置で 通らない接続が 7 → 4 本(ADC 周りは全部通る)、同梱サンプル 67 件は変化なし(`arduino_mega_usb` は時間が +30 秒)。常に引くと tp5100 の配線が +17〜24% 長くなるため、失敗したときだけにした。端の足を先に置く案・出口の帯を広げる案は、バイパスコンデンサが遠くなって悪化し不採用。
## ネットクラスの数の上限: ビア数と細い配線(2026-11-05)
- 点検は `requirements.rs` の `net_findings`(長さの上限と同じ所。1本ごとに `FindingKind::Net` の指摘、`item` がネット名、`actual`/`limit`)。ビアは `CopperIndex::net_of` で数え、細い配線はトラックの幅が `track_width − 1e-6` 未満のものの長さの合計。
- 画面は回路図の「設計の要件」の「詳細: 配線の性質」の表(「ビアの上限」「細い配線の上限」)。CLI は `req net … max_vias= max_neck=` と `board class … max_vias= max_neck=`(答えにも出る)。
- 他のソフトとの対応: Altium の Maximum Via Count と Routing Neck-Down(細い区間の合計の長さの上限)、KiCad の `via_count`。

- `drc/` DRC (`mod.rs`=`check`・`clearance`・`shorts` / `connectivity.rs` 銅の接続グループ / `path.rs` 2つのパッドの間の銅の道筋(トラックとビアをたどる。長さ・ビア数・層・分かれ目)・ネット間の間隔・ガードの被覆 / `geo.rs` 距離計算 / `silk.rs` シルクとマスク帯 / `thermal.rs` サーマルビア / `pour.rs` ベタ(細いかけら・島・分断・上書き) / `decoupling.rs` バイパスコンデンサ / `acute.rs` 鋭角 / `tests.rs`) / `current.rs` 配線の太さと電流 / `irdrop.rs` 電圧降下 + レイアウト後シミュレーション用の配線抵抗 (`wiring_resistances` → `sim-core::from_schematic_with_wiring`) / `diffpair.rs` 差動ペア
- `breakage.rs` 基板に故障を1つ仕込む(修理の練習。バイパスが遠い・配線が切れる・細い・ショート・部品が基板の外。`health`=点検の数、`repaired`。基板レッスン8、`ccad board break`/`health`/`reveal`)
- `reroute.rs` 遠回りした配線・余分なビアの引き直し(手で引いた配線向け。「配線を短くする」ボタンと `ccad board improve`)
- `merge.rs` 一直線の配線を1本にまとめる(自動配線の後。銅の形は変えない)
- `breakout.rs` 細かいピッチの IC の足から出口の短い線を先に引く(辺の真ん中はまっすぐ、両端は外向きに曲げる。全体の配線で通らない接続が残ったときだけ使う。`ccad board breakout`)
- `padentry.rs` パッドの根元をそろえる(垂直な出入り・2本は両端寄せ。自動配線の直後と全部の配線に)
- `quality.rs` 配線の見た目の数字(折れ・ビア・並走・層ごとの長さ。`ccad board status`/`board quality`。手動と自動の比較に使う)
- `meander.rs` 長さ合わせ(蛇行配線。ネットを目標の長さに)
- `ratsnest.rs` 未配線 / `autoroute.rs` 自動配線 / `shove.rs` 押しのけ配線
- `bridge.rs` 隣り合う同じネットのパッドを先に銅でつなぐ(自動配線の前) / `trunk.rs` その手で引く版(2パッドから首2本+太い幹) / `slot.rs` 仕上げで並走する同ネット配線のすき間を埋める
