## 74HC4017(十進カウンタ)の簡易モデル(2026-10-25)
- `part-lib/examples/74HC4017_DIP-16.part.json`。**生成した**もの: 74HC74 のモデルのフリップフロップ(`S1`〜`S22`。名前を `_1`〜`_5` に付け替えた)を 5 個、ジョンソンカウンタ(`D1 = QB5`、`Dk = Q(k-1)`)につなぎ、10 個の AND ゲート(NAND + インバータ。74HC08 と同じ形)で復号する。復号: Q0 = !J1·!J5、Qi = Ji·!J(i+1)(i=1〜4)、Q5 = J5·J1、Q(5+j) = !Jj·J(j+1)(j=1〜4)。CO = !J5(Q0〜Q4 の間 High)。MR は `!MR` を作って、すべてのフリップフロップのクリア(`clr`、負論理)に入れる。
- 電源の GND ピンと VCC ピンに対して動く(0 V 基準ではない)ので、電源が −1.8 V〜+3.0 V のような浮いた電源でも使える。
- 限界: CE(クロック禁止)は扱わない、遅延なし、不正な状態からの自己復帰なし(実物は数クロックで戻る)。電源を入れたら MR を一度 High にする(DC の動作点は、MR が Low だと、フリップフロップの状態が決まらない: 全体の DC は、レンジが決まらない)。
- テスト: `tests_parts_power.rs` の `the_74hc4017_counts_one_output_at_a_time_and_wraps_after_ten`(クロック 12 回で、Q0 → Q1 → … → Q9 → Q0 → Q1 → Q2。CO も確認)。

- **疎行列 LU の順序(`dc/linalg.rs`、2026-10-25)**: 未知数が 60 以上の系は、列を**最小次数順**(`min_degree_order`: A + Aᵀ の模様で、隣が一番少ない未知数から消し、隣どうしをつなぐ)に並べ替えてから消去する(`Factor.perm`・`Symbolic.perm/pos`。`solve` が元の順に戻す。`refactor` は元の模様を比べてから列を並べ替える)。自然な順序だと、500 未知数ほどの回路(オペアンプのマクロモデル + スイッチで組んだロジック)でフィルインが元の約 15 倍(`u` が 4〜5 万要素)になり、1 回の完全な因数分解が約 100 ms、DC 解析が 36 秒かかっていた。順序づけで同じ回路が 1.5 秒(25 倍)、レンジ切り替えの過渡解析(8 ms)が数分から 3 秒になった。答えは桁まで同じ。60 未満の小さい系は、ラッチがピボットの選び方に敏感なので自然な順序のまま。テスト: `linalg.rs a_big_system_is_solved_in_minimum_degree_order_with_little_fill`。

- **速度の改善(2026-10-25。ADA4522 のマクロモデル入りの回路図で測った)**: 過渡解析の時間は、行列の組み立て(約 48 %)、`refactor`(約 35 %)、残りで、1 回の解き直しは約 0.3 ms(515 未知数)だった。①`expr.rs` の式の評価(`POLY`・`VALUE` の素子)は、式の木の節ごとに勾配の `Vec` を確保していた → `Grad`(8 変数までスタックに置く。それ以上は `Vec`)にした。**結果は 1 ビットも変わらない**。②`linalg::refactor` は、列を並べ替えた行のコピー(`permute_columns`)を毎回作っていた → 列を `w` に散布する側で `pos[c]` に読み替える(散布は行の並びに依存しない)。③`monte_carlo`(各回と感度)と `param_sweep` を `par_map` で並列にした(乱数は `(seed, 添字)` の関数なので、結果の順序と値は同じ)。CLI の `sens` も、部品ごとに回路図を複製して `par_map` で解く。実測: ADA4522 入りの 0.2 ms の過渡 10.0 秒 → 8.1 秒(出力は完全一致)、`sens`(20 部品)24.0 秒 → 4.3 秒(出力は完全一致、8 コア)。
- 過渡解析で時間がかかる主因は、ADA4522 のマクロモデル(`C1`・`C2`・`Cdm` などの内部コンデンサと、LC の共振)が刻みを約 10 ns に抑えること(1 ms の窓で 78,214 点)。許容誤差(`lte_reltol`)を緩めると波形が変わり、後退オイラーにすると点が 6 倍に増えた(試した)。整定時間を調べるときは、`MCP6001` のような簡易モデルに替えると、1 ms が約 1 秒(2,186 点)で済む。

- **PSpice 形式のメーカーのモデル(TI の `TPS62933P_TRANS.lib`)を読むための直し(2026-10-25)**: ①ファイル先頭(どの `.subckt` の外)の `.param` は、1 行ずつ順に評価していて、`noc={2.8*en_fccm+...}` のように、あとの名前を使うと失敗した → 全部読んでから、評価できるものを繰り返し評価する(`spice_flat.rs` の `top_params`。サブサーキットの中の `.param` は前から順不同だった)。②`gain_adder=` の次の行に `{...}`(`=` のあとの空白、`a = 5`)→ `assignments` でつなげる。③`ccad part import` が、メインの `.subckt` だけを取り出していた → そこから呼ばれる別の `.subckt`(`X... 名前`、その先まで)と、ファイル先頭の `.model` / `.param` / `.func` の行を一緒に束ねる(`cli/src/libcmd.rs` の `with_dependencies`)。節点の数えで `PARAMS:` を数えていた不具合も直した。テスト: `tests_flat.rs` の `top_level_params_may_use_names_defined_later...`、`libcmd.rs` の `the_nodes_stop_at_params_and_the_helper_blocks_come_along`。
- この TI のモデル(869 行、`asymmetric_delay` などのデジタルのゲートをアナログ素子で作っている)は、読めるが遅い: `uic` で 5 µs が 18 秒。1.2 MHz の降圧の起動(2 ms)を見るのは、このシミュレータでは数時間かかる。
- **過渡解析の刻みが下限に張りつく問題(2026-10-25。TI の TPS62933P のモデルで見つけた)**: 刻みを決めるのは `tran.rs` の誤差見積もり(`step_error_ratio`)で、容量の電圧の 3 階の差分を、`許容 = lte_reltol × 電圧 + 1 µV` と比べる。TI のラッチ(`srlatchrhp_basic_gen`)は、**N = 0.01 の鋭いクランプ用ダイオード**を使い、その接合電圧が 1 ステップごとに ±49 µV で符号を反転する数値的な振動(台形則のリンギング)を起こした。電圧の許容が 1 µV では、刻みを下限(最大の刻み × 1e-4)まで縮めても比率が 32.5 のまま下がらず、17,086 / 17,200 ステップ(99 %)が下限の 50 ps になった(最大の刻みを緩めるほど点が増えた: 5 ns で 2,520 点、500 ns で 17,292 点)。SPICE は接合を**電荷**で見る(`CHGTOL` = 1e-14 C)ので、同じにした: ダイオード・トランジスタの接合は、許容電圧 = max(1 µV, 1e-14 C ÷ 接合の容量)(`lte_abs_voltages`。容量は新しい電圧での `dq/dv`)。普通のコンデンサは従来どおり 1 µV。効果(TI のモデル、`uic`、最大の刻み 500 ns): 5 µs で 17,292 点・82 秒 → 795 点・8 秒。100 µs が 20 分以上で終わらなかったのが、P 品 233 秒・F 近似 137 秒。既存のテストは全部通る。テスト: `tran.rs` の `a_small_junction_has_a_wide_voltage_tolerance_and_a_capacitor_does_not`(仕組み。**症状の再現は、自分で書いた小さな回路ではできなかった**)。
- 診断の仕方(刻みが小さいと思ったとき): ①`tran` の点の数と所要時間を、最大の刻みを変えて比べる(最大の刻みを緩めて**点が増える**なら、刻みの制御が縮めている)。②`step_error_ratio` が返す最悪の素子(`worst_at`)と比率を、数千ステップごとに出す(テスト用の `WORST` が使える)。比率が刻みによらず一定なら、振動している。③その素子の履歴(`hist` の容量電圧)を数ステップ並べると、符号の反転が見える。

## 74HC74 を Seq ベースにした(2026-11-04)
`part-lib/examples/74HC74_DIP-14.part.json` のモデルを、スイッチで作った NAND ラッチ(S1〜S44)から、`U1 dff(1) $G_DPWR $G_DGND pre clr clk d q qb D_DFF IO_STD` の2行(`Element::Seq`)に替えた。理由: ゼロ遅延のマスタースレーブをゲートで組むと、クロックの立ち下がりでマスターが開くのとスレーブが閉じるのが同時になり、16bit(約390ゲート)のアキュムレータで過渡解析が収束しなかった。Seq の FF なら競合がなく、2561 ゲート + FF 512 個でも 1 ms(100 クロック)が 72 秒で通る(ゲートの FF は 388 ゲートで 33 秒、RC で許可信号を重ならなくして初めて通った)。
- 違い: 出力は 0 V / 5 V 固定、入力のしきい値は 2.5 V(電源が 5 V でないと合わない)。VCC ピンは見ない。状態の変化は最大で 1 刻み遅れる。PRE・CLR は負論理のまま。
- `74HC4017` のモデルは、この部品を元にした生成物(`S1`〜`S22`)なので、そのまま(スイッチ版)。
- 出力は 60Ω の抵抗を通す(`R1 q1i q1 60` など)。理想の電圧源のままだと、サンプルの LED の電流が 9.25 mA になり、`logic_blinker` のテスト(2〜8 mA)が落ちた。
- ngspice は `U dff(1)` を読めない。`app/src/xcheck.rs` の `our_side` は、`dff(` などを含む部品があれば「対象外」にし、`docs/xcheck/ngspice_dc.json` から `logic_blinker` を外した(`mixed_signal` は元から保存の対象外)。
- サンプル(`logic_blinker` `mixed_signal.schjson` `mixed_signal.ccproj`)は回路図の中に部品の定義(`custom`)を持っているので、74HC74 の `sim` を新しいものに置き換えた(波形の周波数・デューティは前と同じ。`logic_blinker` の内部ノード `U2.m1` などは無くなった)。

→ この後、`Y` 行のセルに替えた(下の「デジタルセル」)。ここにある「出力は 0 V / 5 V 固定」「電源に追従しない」は、いまは当てはまらない(電源のピンに追従する)。

## 74HC00/02/04/08/32/86 を式で表した(2026-11-04)
部品 JSON の `sim` を、スイッチと抵抗(1ゲートに多数)から、**1ゲート = B 電圧源 1つ + 出力の 60Ω + 入力の漏れ 1GΩ**に替えた。`B1 o1 gnd V=V(vcc,gnd)*(式)`、式は入力ごとに `x = 0.5+0.5*tanh((V(a,gnd)-0.5*V(vcc,gnd))/(0.05*V(vcc,gnd)+0.001))`(0〜1 のなめらかな値)を、AND は `x*y`、NAND は `1-x*y`、OR は `1-(1-x)(1-y)`、NOR は `(1-x)(1-y)`、XOR は `x+y-2xy`、インバータは `1-x` にしたもの。電源電圧に追従する(3.3V の真理値表のテストが通る)。74HC14(シュミット)と 74HC4017 はスイッチ式のまま。
- 速さ(アキュムレータ 256bit = 2561 ゲート + Seq の FF 512 個、1 ms = 100 クロック): スイッチ式 71.8 秒 → 26.7 秒。規模を2倍にしたときの時間の伸びは 2.2〜2.7 倍 → 約 2 倍。
- 出力の抵抗は、High 約 80Ω・Low 約 40Ω から、どちらも 60Ω になった(`logic_basics` レッスンの数値: DRV 4.4 V → 4.5 V、R1=100Ω で 3.7 V → 3.9 V)。
- 入力の漏れ 1GΩ は、使わない入力を「GNDへのDC経路がありません」と警告させないため(スイッチ式の制御端子は警告の対象外だった)。
- **DC の `guess`(`.nodeset`)の効き方を強くした**(`dc/mod.rs` の `Strategy::Gmin`): 式のゲートは出力が強く(60Ω)、gmin と同じ強さで引くだけだと、対称なラッチは指定と反対の状態に落ちた。今は、gmin が 1e-2 から 1e-12 に下がる間、シードを引く強さを 1e-2 S に保ち(`Ctx.seed_g`)、最後にシードを放して解き直す。
- CLI の `dc states`(`other_states`)に、中間の電圧で止まっているネット(対称なラッチの不安定な中点)を、1つおきに High・Low にした出発点を2つ足した。全部 High・全部 Low の出発点は、対称なので中点に戻ってしまう。
- ngspice でも読める書き方(B 電圧源と `V(a,b)`)なので、検算の対象のまま。

## 74HC14 も式で表した(2026-11-04)
シュミットトリガのヒステリシスは、**そのゲート自身の出力を式に入れる**(正帰還)ことで作った: `B1 o1 gnd V=Vcc*(1-(0.5+0.5*tanh((V(a1)-0.3568*Vcc-0.2864*V(o1))/(0.02*Vcc+0.001))))`。出力が High のときは切り替わりが高く(0.6 Vcc)、Low のときは低く(0.4 Vcc)なる。係数 0.3568・0.2864 は、なめらかさ(幅 0.02 Vcc)のぶんだけ折り返しが内側に寄るのを直して、切り替わりが 0.6 Vcc と 0.4 Vcc になるように決めた値(折り返し点は `0.5*sech²(z)*k/w = 1` の所)。ヒステリシスの帯では DC の解が3つある(以前のスイッチ式の分圧と同じ)。`Element::Seq` の SCHMITT は、出力レベルが電圧の定数なので、電源電圧に追従させるには使わなかった。
- 発振の周波数: `logic_blinker` の 74HC14 の発振は 2.5 Hz → 2.27 Hz(出力の抵抗が 60Ω に、切り替わりが少し変わったため)。

## 74HC4017 を Seq ベースにした(2026-11-04)
スイッチで作った FF(74HC74 の旧モデル)5個と NAND+インバータ10組から、**`A … DFLOP` の FF 5個(`Element::Seq`)と、復号の式(B 電圧源 11個)**に替えた。ジョンソンカウンタの接続(`D1 = QB5`、`Dk = Q(k-1)`)と復号の論理は同じ。
- `Seq` の出力レベルは電圧の定数なので、**0〜1 に正規化した信号の上で動かす**: `Bcp cpn 0 V=V(cp,gnd)/(V(vcc,gnd)+0.001)`(MR も同様)、FF は `Vhigh=1 Vlow=0 Ref=0.5`、復号は `0/1` の代数(`Q0 = (1-J1)*(1-J5)` など)、出力は `B gnd 基準 V=V(vcc,gnd)*(式)` に 60Ω。こうして、GND と VCC のピンを基準に動く性質(電源が −1.8 V〜+3.0 V のような浮いた電源でも、出力が両方のレールまで振れる)を保った。
- MR は FF のリセット(正論理)に直接入れる。電源を入れた直後は FF の状態が 0 なので Q0 が High(MR を High にした状態と同じ)。
- 入力 CP・MR・CE には 1GΩ の漏れ(使わない入力の警告を出さないため)。
- ngspice は `A … DFLOP` を読めないので、この部品を使う回路は ngspice との検算の対象外(同梱のサンプルには、使っているものがない)。

## デジタルセル(`Element::Cell`、`dc/digital.rs`、2026-11-04、候補 G3 の M1)
ゲート・FF・ラッチ・シュミットを、**回路の方程式の外で評価する素子**にした。設計は `docs/digital-engine-design.md`。
- **書き方**(部品の `.subckt` の中の 1 行): `Y<名前> 種類 out outb vss vcc rout vt vh set_low reset_low 入力…`(`spice_in.rs` の `'Y'`)。種類は `and nand or nor xor xnor buf inv dff tff jkff srff dlatch srlatch schmitt lut rom`(lut / rom は下の「表のセル」)、入力の並びは `SeqKind` と同じ。レベルは `v(vcc) - v(vss)` に対する割合なので、電源が浮いていても、3.3 V でも動く。`vt` は入力のしきい値(割合、0.5)、`vh` はヒステリシスの半幅(シュミット。0.1 で 0.6/0.4)。使わない出力は `0`。`0` の入力は Low につないだもの。
- **デジタル網**: セルのピンだけがつながる節点(抵抗・LED・電源などが付かない節点)は、`Dig::lv` の 0/1 で持ち、方程式には入れない(節点は gmin だけの行として残り、解を出したあとに `fix_nodes` が電圧を書き戻すので、波形には出る)。ほかの素子が付く節点に出る出力は、`rout` の抵抗の向こうの電源(Norton 形。行列は変わらず、右辺だけが変わる)。入力が アナログ節点のときは、節点電圧を電源に対する割合にして、しきい値と比べる。
- **評価**(`dig_update`、採用した解のあとに呼ぶ): ①ゲートを 1 つずつ(出力をすぐ反映)落ち着くまで、②入力が変わった FF・ラッチをまとめて(データはクロックの前の値)、①②を繰り返す。ゲートの帰還(NAND ラッチ)は片方の状態に落ちる(全部を同時に更新すると鳴り続けた)。FF の出力が変わると、同じ回で次の段の FF が評価される(波及。`ripple` カウンタが動く)。回数の上限を超えたら打ち切る(遅延なしの発振)。
- **過渡解析**: アナログ節点の出力が変わったら、フリップフロップと同じように、そこで刻みを小さくやり直す。変わらないとき(デジタル網だけ)は刻みに影響しない。
- **DC の `guess`(`nodeset`)**: デジタル網の `nodeset` は、そのラッチの出発点(`dig_seeds`)。電源は DC の解から読む(`dig_update` が解いた電源の電圧が動いたら、解き直す)。
- **速くなった理由**: 回路が線形(B 電圧源がない)になるので、行列の因数分解が使い回せる。コンデンサ・コイルがない回路では、行列は刻みの大きさによらない(`solve_linear` のキーから刻みを外した。これまでは、刻みが変わるたびに数千行の行列を組み直していた)。
- 測定(リリース版、アキュムレータ、1 ms = 100 クロック、2561 ゲート + FF 512 個の 256bit): スイッチ式 71.8 秒 → 式 28 秒 → **セル 1.35 秒**。512bit(5121 ゲート + FF 1024 個)で 4.05 秒。`mixed_signal` の過渡 8 ms は 2.26 秒 → 1.39 秒、`logic_blinker` の 2 秒は 1.65 秒 → 0.13 秒。
- 置き換えた部品: 74HC00/02/04/08/14/32/86/74/4017。サンプル(`logic_basics` `logic_blinker` `mixed_signal`)の埋め込みも置き換えた。
- **ngspice は `Y` 行を読めない**。`xcheck.rs` は、`Y` 行のある部品を使う回路を「対象外」にする。
- **見直したこと**: ①DC の `nodeset` を放す段階(`Strategy::Gmin`)で、シードのない節点にも引く力が掛かっていた不具合(`seeded` で直した)。②線形回路の因数分解のキャッシュのキーに、シードの強さが入っていなかった。
- 未実装(M2 以降): 遅延(`td`)、エッジの時刻合わせ(しきい値をまたぐ時刻を刻みの途中に)、`Y` 行を出す UI/CLI(部品作成フォーム)、デジタル波形の表示。

## 記録する信号の絞り込み(`transient_with`、2026-11-04)
`transient_with(circuit, settings, keep)`: `keep` が受け入れる名前(`V(節点)` / `I(素子)`)の信号だけを記録する。`None` は全部(`transient` はこれ)。時間の点と、記録した信号の値は、全部を記録したときと同じ(テスト `a_filtered_run_keeps_only_the_wanted_signals_with_the_same_values`)。素子の電流が1つも要らないときは、素子ごとの電流の計算も省く。
- CLI の `tran`: `record=probes` で probe= の信号だけ、`record=all` で全部。**どちらも付けないとき**、probe= があり、記録する値の数(節点 + 素子)× 刻みの数 が 1000 万を超える回路は、自動で probe= だけにして、注意を出す。probe にない信号を使う `spec`・`settle`・定格の注意(`tran_notes`)は、その信号が無いので動かない(`spec` は「結果にありません」と言う)。アプリは全部を記録する(波形の窓で後から選ぶため)。
- **効果は思ったより小さかった**: 512bit のアキュムレータ(5121 ゲート + FF 1024 個)で、記録の絞り込みは 4.05 秒 → 3.7 秒(約 1 割)。256bit は 1.34 秒 → 1.19 秒。時間の大半は別の所にある(下の「刻みごとの処理」)。記録する値の数は、512bit で約 5000 万(約 400 MB)から 6 点 × 2754 点に減るので、効くのは主にメモリ(測っていない見立て)。

## 刻みごとの処理を減らした(2026-11-04)
512bit のアキュムレータ(5121 ゲート + FF 1024 個、100 クロック)の `tran` の時間の内訳を測った(リリース版、CLI。全体 約 3.6 秒): スクリプトの組み立て 0.6 秒、`erc` コマンド 1.2 秒、**`tran` の中の ERC の関門(`erc_gate`)1.2 秒**、回路の組み立て 0.09 秒、`transient_with`(動作点を含む)0.44 秒、定格の注意 0.03 秒。**過渡解析そのものは全体の約 1 割で、大半は ERC**(256bit では約 0.25 秒だったので、規模を2倍にすると 4〜5 倍。規模の2乗に近い見立て)。
- 過渡解析の刻みごとの内訳(2754 刻み): 行列の解 0.18 秒、セルの読み直し(`dig_update`)0.21 → **0.11 秒**、デジタル網の電圧の書き戻し 0.03 → 0 秒。
- やったこと: ①電源のピンの組が同じセルは、電源の電圧を1回だけ読む(`DigStatic::groups`)。②2回目からは、アナログ節点を入力に持つセルだけを調べる(`analog_cells`。ほかのセルは、それを駆動するセルから波及で届く)。③デジタル網の電圧は、刻みごとに解に書き戻さず、記録するときにセルから読む(`Compiled::node_voltage`。動作点の結果だけ `fix_nodes` で書き戻す)。④ゲートの待ち行列の目印を使い回す。⑤アナログ節点に出力があるセルだけ、行列に出力を入れる。
- 次に効くのは **ERC**(`sch-core/netlist.rs`)。動作点と過渡解析(合わせて 0.44 秒)より、ERC(1.2 秒)のほうが遅い。→ 下の「ERC の高速化」で 1.2 秒 → 0.2 秒にした。

## ERC の高速化(`sch-core/netlist.rs`、2026-11-04)
512bit のアキュムレータ(約 6000 部品)の ERC は 1.2 秒、規模を2倍にすると 3.4〜3.9 倍(256bit で 0.3 秒、128bit で 0.09 秒)だった。部品とピンの数の2乗で増える所が3つあった。
- **ピンごとに、全部のネットのピンを走査**していた(`erc_all`): 「名前の付いたネットにあるピンか」「そのピンのネット」「部品番号から部品」「電源記号と同じ名前のネット」。最初に一度だけ、`HashMap`・`HashSet`(`net_of`・`named_pins`・`comp_index`・`net_by_name`・`no_connect`)を作って引くようにした。
- **配線ごとに、既知の全部の点を走査**していた(`connectivity`): 配線の上にある点を探すのに。点を列ごと・行ごとに並べた索引を作り、縦・横の配線は範囲の検索にした(斜めの配線は、これまでどおり全部の点を見る)。
- **線の端がどこにもつながっていないかを、全部のピン・ラベル・配線と比べていた**(`dangling_wire_ends`): ピンとラベルは集合に、配線は行と列の索引にした。
- 結果: 512bit の ERC 1.2 秒 → 約 0.2 秒。同梱サンプル 107 件の ERC の出力は、前後で完全に同じ(旧版の実行ファイルと比べた)。縦・横・斜めの配線で点が結ばれることと、線の端の判定は、新しいテスト `a_wire_joins_the_points_on_it_in_every_direction`。

## デジタルセルの伝搬遅延(`td=`、`dc/digital.rs`、2026-11-04、候補 G2)
- **書き方**: `Y` 行の `reset_low` の後ろに `td=10n`(上がり・下がりとも)、`tplh=`・`tphl=`(別々に)を、入力の前に置く(順不同)。`CellSupply::tplh`・`tphl`。
- **慣性遅延**: 出力が変わると決まったら、`遅延`後の出来事(`Dig::heap` の到着の出来事)にする。遅延が終わる前に、入力が戻って出力が元と同じになれば、出来事は取り消される(遅延より短いパルスは通らない。テスト `a_pulse_shorter_than_the_delay_is_swallowed`)。FF・ラッチは、状態はすぐ変わり、出力だけが遅れる(クロック→Q)。
- **時間のあるループ**(`dig_update(x, Some(t))`): 出来事を時刻の順に取り出す。同じ時刻の出来事は、到着した出力をまとめて反映してから、それを読むセルを評価する(今までの「ゲートは1つずつ、FF はまとめて」の落ち着かせ方。`settle`)。**デジタルの中の時間は刻みによらず正確**(遅延 10 ns のバッファを 100 個つないだ鎖は、刻みが 500 ns でも 1 µs の遅れ。テスト `a_long_chain_of_delays_is_exact_whatever_the_step`)。アナログとの境目だけが刻みに量子化される。
- **アナログ節点から読む入力**は、前の呼び出しとの間の線形補間で、しきい値をまたいだ時刻を見積もる(以前は最大で 1 刻みの遅れ。`d.afrac` の前の値と `t_prev`)。複数の入力が同じ刻みの間にまたいだときは、いちばん早い時刻で評価する。
- **アナログ節点に出る出力で、遅延のあるもの**は、到着の時刻に刻みを合わせる(`dig_next_event` → `tran.rs` の刻みの上限)。到着したら、フリップフロップと同じように、そこで刻みをやり直す。遅延のない出力は、これまでどおり刻みの終わりに反映する(最大 1 刻みの遅れ)。デジタル網だけの出力は刻みを区切らない。
- **静的な解**(動作点、`dig_update(x, None)`)は遅延を使わず落ち着かせる。**過渡解析の開始**(`dig_begin_run`)は、そこで入力と合っていないゲート(奇数個のインバータのリングには、合う状態がない)を、遅延つきで動かし始める。
- **部品**: 74HC00 8ns、74HC02 8ns、74HC04 7ns、74HC08 10ns、74HC32 9ns、74HC86 11ns、74HC14 11ns、74HC74 クロック→Q 14ns、74HC4017 クロック→Q 12ns + 復号 8ns。**データシートの値を覚えている範囲で書いた代表値で、確かめていない**(部品のモデルの説明にも、その旨を書いた)。サンプルの埋め込みも置き換えた。
- 測定(512bit、5121 ゲート + FF 1024 個、100 クロック、CLI のスクリプト全体): 1.5 秒 → 1.6 秒(遅延ありでも、ほとんど変わらない)。
- 未実装: セットアップ/ホールドの点検(G4)、アナログに出る出力でのパルス幅の保存(遅延のない出力は刻みの終わりの値)、立ち上がり・立ち下がりの違い(`tplh`・`tphl` は書けるが、同梱の部品は同じ値)。

## セットアップ時間・ホールド時間の点検(`tsu=`・`th=`、`dc/digital.rs`、2026-11-04、候補 G4)
- **書き方**: `Y` 行の `reset_low` の後ろに `tsu=20n`(セットアップ)・`th=3n`(ホールド)。エッジで動く FF(`dff` `tff` `jkff` `srff`)のデータ入力だけが対象(ラッチは対象外)。0 または書かないときは点検しない。
- **点検**: 入力の変化の時刻を覚えておき(`Dig::last_change`。アナログ節点の入力は、しきい値をまたいだ補間の時刻)、クロックの立ち上がり `te` で、データが `te` より `tsu` 以上前から変わっていなければセットアップ違反、立ち上がりの後 `th` 以内に変わればホールド違反。同じ時刻に変わったときは、セットアップ違反(間隔 0)。違反は、FF とその種類ごとに、回数・最初の時刻・最小の間隔をまとめる(`TimingViolation`)。
- **出力**: `TranResult::timing`(`TimingReport`: 違反の一覧と、セットアップの余裕が最小だったクロックの立ち上がり `tightest`)。違反は `TranResult::warnings` にも日本語の文で出る(アプリの過渡解析にも出る)。CLI の `tran` の答えには `timing`(`violations`、`tightest` と、その FF だけで決まるとしたときの最大クロック周波数の目安 `max_clock_hz_estimate`)が付く。余裕が負なら、目安の周波数は、いまの周期より低い値になる(クロックを遅くする向きの目安)。
- **違反しても、出力は不定にしない**: 古いデータを取り込んだ値のまま(警告の文にも書いた)。実物のメタステーブルは表さない。
- **部品**: 74HC74 に `tsu=20n`(代表値、**未確認**。ホールドは 0 とみなして点検しない)。サンプル `timing_check`。
- 最大クロック周波数の目安は、セットアップの余裕が最小の 1 つの FF だけで決める(データの経路の遅れは、いまのまま)。クロックの周期が一定でないときの目安は粗い。

## 3 ステート・オープンドレイン・バス(`oe=`・`oel=`・`od=`、候補 H1、2026-11-04)
- **書き方**: `Y` 行の `reset_low` の後ろ(`td=` などと同じ場所)に `oe=<節点>`(出力許可)、`oel=1`(Low で許可)、`od=1`(オープンドレイン)。`CellSupply::oe` `oe_low` `od`。出力許可の節点は、入力の枠を 1 つ増やして持つ(`DCell::oe`、入力のあとのスロット)。
- **出力の状態**: 許可されていない出力と、オープンドレインで High の出力は、**Hi-Z**(つながない)。`Compiled::drives`。内部の状態(FF の中身)と遅延は、Hi-Z と関係なく動く。
- **複数の出力がつながるデジタル網**(`DigNets::drivers`): 出ている出力が 1 つ、または全部同じなら、その値。**違う値が 2 つ以上: 衝突**(Low にして、警告)。**出ている出力が無い: 浮き**(前の値を保って、警告。その網を読むセルがあるときだけ)。2 値のまま(4 値論理にはしない)。ドライバが 1 つで、いつも出ていて、オープンドレインでもない網(`DigNets::simple`)は、今までどおりの速い道(出力がそのまま網の値)。警告は節点ごとにまとめ、過渡解析の警告と、DC の警告(`bus_warnings`)に出る。
- **アナログ節点に出る出力**: Hi-Z のときは行列に入れない。**出るか出ないかが変わると行列が変わる**ので、因数分解のキャッシュのキーに数 `Dig::epoch`(変わるたびに増やす)を入れた。入れ忘れると古い行列で解く(キーから外すとテスト `open_drain_outputs_with_a_pull_up_make_a_wired_and` が落ちることを確かめた)。
- **設計との違い**: 出力許可の切り替えには**遅れを付けていない**(`td` は出力の値の変化だけ。許可・禁止の時間は表さない)。設計書(`digital-parts-design.md`)は「tplh・tphl を許可・禁止にも使う」としていたが、まだ。
- **試験**: `tests_cells.rs` の 3 ステートのバス(許可・衝突・浮き)、`oel=1`、オープンドレイン 2 つ + プルアップ(ワイヤード AND)、プルアップのないオープンドレインの浮き。速さは変わらない(512bit のアキュムレータ 1.6 秒)。

## 表のセル(`lut` / `rom`)・DAC・ADC(候補 H4・H5、2026-11-04)
- **`lut` / `rom`**(`CellKind::Lut`、`Y` 行の種類): 入力がアドレス(最初の入力が最下位ビット)、`table[アドレス]` が出力。`table=<16 進数>,<16 進数>,…`(アドレス順に 1 ワード。足りない分は 0)と、`outs=<ノード>,<ノード>,…`(ワードのビット 0 から順に出力のノード。省略すると `out` の 1 本)を付ける。`outs=` の本数だけ、アドレスの入力を共有した別々のセルになる(`spice_in.rs` の `'Y'` で展開する。2 本以上のときは名前に `.0` `.1` …を付ける)。**エンジンには多出力の仕組みは足していない**: 1 セル = 1 出力のまま。表は `Element::Cell.table`(`Arc<Vec<bool>>`、出力 1 ビット分)で、`DCell.table` に写す。組み合わせのセルなので、遅延(`td=`)・出力許可(`oe=`)・Hi-Z・複数の出力の解決は他のゲートと同じ。アドレス入力は 1〜16 本、出力は 64 本まで。
- **ROM32x8**(教材用): `rom` 1 本(出力 8 本)。中身は正弦波 1 周期(オフセット 128)。OE 負論理、遅延 50ns(一定の見積もり)。別の中身にするには、部品のモデルの `table=` を書き換える。
- **DAC**: エンジンの変更なし。R-2R のはしごは、セルの出力(出力抵抗 60Ω)に付けた普通の抵抗。2R = 20kΩ・R = 10kΩ なら、出力抵抗の誤差は 0.3% 程度(試験の許容は 30mV)。
- **ADC4_FLASH**(教材用): 比較器 15 個(`buf` セルで、入力のしきい値 `vt` を k/16 にして、アナログの AIN を直接読む)→ D-FF 15 個(CLK の立ち上がりで保持)→ サーモメータ → 2 進のエンコーダ。値は floor(16 × AIN ÷ 電源)。基準は電源(`vt` が電源に対する割合なので、3.3V でも同じ)。入力抵抗は無限大。比較器のヒステリシス・オフセット・サンプルホールドは無い。ピンの名前は `AIN`(`VIN` にすると ERC が電源ピンと見なす)。
