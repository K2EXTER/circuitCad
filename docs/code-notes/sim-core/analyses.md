# sim-core: 自己発熱・インピーダンス・最悪ケース・ループゲイン・極と零など、解析の個別の記録

(`docs/code-notes/sim-core.md` の目次から分けた。内容は元のまま)

## selfheat.rs (抵抗の自己発熱)
`self_heat(&Circuit, &[Heater], t_amb)`: 電流の流れる抵抗が `P·θ` だけ温まり、温度係数(`tc1`/`tc2`、27 ℃ からの差)で値が変わり、電流と電力が変わる、の不動点を求める(直流の定常状態)。1回目は全部品が周囲温度の「冷えた」答え(`cold`)、そのあと温度を `0.6` の歩幅で動かしながら `dc_op` をやり直し、動きが 1e-6 K を切ったら終わり(最大60回)。温度が 1000 ℃ を超えると熱暴走として `SimError::Invalid`。`Heater` は部品1つ(ライブラリ部品の中の抵抗は `REF.` で始まる名前で集め、1つの温度を共有)。`heaters_from_schematic` は `Component.theta`(K/W。0 なら `default_theta` = 85 K ÷ パッケージの定格電力。定格が分からなければ 100)と `Component.tc_ppm`(0 ならモデルの `TC=` = `Circuit.tempcos`)から作る。熱の広がり(基板・隣の部品)はシミュレーションせず θ にまとめる。半導体は自己発熱させない(周囲温度 `at_temperature(t_amb)` のまま)。CLI `heat` / `thermal`、画面は解析タブの「自己発熱」。
資料: ROHM 64AN040J(GMR シリーズの抵抗体〜端子の熱抵抗 9.5 K/W、一般品 31 K/W。基板の銅箔は厚く・面積が広く・多層ほど温度上昇が小さい)。

## heat_tran.rs (温度の時間変化: Q1 と RS1 のような部品の熱)
`heat_tran(&Circuit, &[ThermalNode], &[ThermalLink], t_amb, &TranSettings)`: 過渡解析の電力(抵抗 `I²R`・ダイオード/BJT/MOSFET `I·V`。負の電力は0)を、部品ごとの熱の1段(熱容量 `cth` と周囲への熱抵抗 `θ`)に入れて温度の上昇 `u(t)` を出す。`C·du/dt = P − u/θ − Σ(u − u_相手)/θ_結合` を、過渡解析の時間点で後退オイラー(電力は区間の両端の平均)。`ThermalLink` は2つの部品の間の熱抵抗(基板の銅を通る熱。`couple=A:B:K/W`)。`cth = 0` の部品は電力に即座に追従する(定常値。短いパルスには高すぎる)。温度係数のある抵抗と、ダイオード・BJT・MOSFET は、**電力で重みを付けた平均の温度**(部品が電力を出している間の平均)で値・モデルを決め直して過渡解析をやり直す(最大8回、0.001 K で収束。熱は秒、回路はミリ秒で落ち着くので「ゆるい連成」)。半導体は `Circuit::at_temperatures(周囲, &[(素子名, 温度)])`(`temperature.rs`。`at_temperature` と同じ式を素子ごとの温度で)。1回目の(冷えた)実行は `HeatTran.cold` に残り、CLI の `moved` は、冷えた実行と最後の実行の節点電圧の差(部品の電力が半分以上ある最後の時刻での値)。平均の温度は、パルスの終わりの最高温度より低いので、半導体への戻りは控えめに出る。結果の `added_by_neighbours_k` は、結合を外したときとの差(相手から受けた熱。熱を逃がす側は負になる)。CLI は `heattran`、θ・cth・tc は `thermal REF theta= cth= tc=`(`Component.cth`)。
- 検算: パルス 1 s・0.25 W・100 K/W・0.05 J/K(τ=5 s)で 25(1−e^(−0.2)) = 4.53 K (`heat_tran.rs` のテスト)。短いパルスの上昇は、ほぼ `P·t / C` で、θ にはあまり依らない(熱容量が効く)。
- 資料にない数字は推測: Q1 の過渡の熱応答(NDT3055L のデータシート図 11 は画像で、数値を読めていない)、RS1 の熱容量、Q1-RS1 間の熱抵抗。画面は解析タブの「自己発熱」の下(`schematic/selfheat_tran.rs`)。

## coverage.rs (シミュレーションが知らないこと)
`model_coverage(&Schematic)` が全シートの部品を見て、`ModelCoverage` を返す: `ignored`(カスタム部品でモデルが無い。`from_schematic.rs` が回路に入れずに警告にするもの)・`generic`(基本のダイオード・LED・NPN。標準の値で計算している)・`caveats`(ライブラリのモデルの `limits`)・`test_sources`(`sim_only`)・`total`(記号とピンヘッダを除いた部品数)。抵抗・コンデンサ・コイルは理想の素子として数えない(ESR などは値の欄に書いた分だけ)。CLI は `coverage` と、`dc`/`tran`/`ac` の答えの `models`。画面は解析タブの「モデルの前提」(`schematic/coverage.rs`。`rev` ごとに計算し直す)と、モデルが無い部品があるときの解析タブの上の ⚠ の1行。マイクロオームメーターの回路(190 部品)では、モデル無し 2(SB1・UADC)・汎用 10(LED)・注意書き 56・試験用 7。テスト `coverage::tests`、CLI `coverage_lists_what_the_simulation_guesses_and_the_answers_carry_the_counts`。

## 発振回路の反転での空振りを減らす(2026-10-31)
マルチバイブレータ・ラッチの反転は「古い状態の近くに解が無い」瞬間で、そこでの素朴ニュートン反復は 150 回さまよって収束しない(周期でも這い寄りでもなく、成功する時も運)。`led_blinker` の過渡は 41 万回の線形解のうち 76% がこの空振りだった。2 つ直した(`tran.rs`):
- 反転を越えて最大の刻みで着地した刻みは、誤差の再判定で捨てない(`jumped`)。捨てても同じ着地を最大 12 回(`rejects` の上限)繰り返すだけだった。
- すでに最小刻みの 64 倍以下で失敗したら、4 回目を待たず最大の刻みをすぐ試す(`SNAP_EARLY`)。端の時刻は刻み幅の千分の一以下の精度で決まる。
結果: `led_blinker` 3.2 s → 0.8 s、`logic_blinker` 1.05 s → 0.34 s。端の時刻は旧版と最大 1 ms(刻みの半分)ずれるが、刻みを 1/10 にした基準との差は元から数 ms あり、同程度。片方だけでは遅い(着地を捨てない: 1.7 s、早く着地: 2.8 s)。
試して効かなかったこと: 反復の進み具合(最良の誤差が更新されない回数)で早く切る — 成功する這い寄りと失敗が区別できない(最大の停滞幅は両方 100 前後)。

## impedance.rs (ネットから見たインピーダンス、2026-10-31)
`impedance_analysis(circuit, node, reference, remove, settings)`: 回路を複製し、`remove` の部品を外し、すべての電源の AC を切り(直流の値は残す。動作点は同じ)、`Ztest`(AC 1 A の電流源、基準→ネット)を足して `ac_analysis` を呼ぶ。Z = V(ネット) − V(基準)。小信号の部分は AC解析と完全に同じなので、BJT の容量・飽和するコイル・配線の抵抗(`from_schematic_with_layout`)もそのまま入る。電源ラインは `remove` なし(電源は短絡)、段の出力インピーダンスは負荷を、入力インピーダンスは信号源とその直列抵抗を `remove` で外してその先のネットを見る(V/I の比で割る方式にしなかったのは、電流の向きの約束を使う人に覚えさせないため)。
`z_extrema(freq, mag, min_db)` は |Z| の山(並列共振)と谷(直列共振)。隣の極値との差が両側とも `min_db`(画面・CLI は 3 dB)以上のものだけ。`character(phase)` は位相 ±45° で「コイル/コンデンサ/抵抗に見える」。CLI は `zout`、画面は解析タブの「インピーダンス」(`schematic/impedance.rs`。「回路図で選ぶ」は `noise_pick` の仕組みを `z_pick` で分けて共用)、サンプルは `rail_impedance.schjson`(ケーブル L1 100n + R1 50m の先に電解・10µ・100n のコンデンサ。山は 224 kHz、谷は 2 MHz)。

## worstcase.rs (最悪ケース解析、2026-10-31)
`worst_case(circuit, &WcSettings)`: 許容差のある部品(抵抗・コンデンサ・コイルと、`tol_v` があれば直流電源。名前に `.` を含む部品の中の寄生分は除く)を1つずつ上の端・下の端に動かして結果の変化を見る(`WcPart.low/high`)。結果を大きくする向きにそろえた回路(角、コーナー)を**実際に解いて** `max`、小さくする向きで `min`。部品が全部同じ向きに効くとは限らないので、角の中で各部品を反対の端に替えたものを並列に解き、良くなる部品を替える(1回だけ。全部いっぺんに替えて悪くなったら、いちばん良くなる1つだけ)。設計値の回路も取りうる回路なので `min ≤ nominal ≤ max` に丸める。参考値として、各部品の効きの足し算 `min_sum/max_sum` と、二乗和の平方根 `min_rss/max_rss`(部品が無関係にずれるなら現実的な範囲)。1つの端が収束しない部品は `unsolved` に入れ、その端の変化は 0 とみなす。測るものは `McMeasure`(DC電圧・カットオフ・ステップ応答)で、`montecarlo.rs` の `measure` を共有。`monte_carlo` は電源をばらつかせない(`McSettings` の作り方が多いので足していない)ので、画面のばらつき解析は `WcSettings::from(&McSettings)`(`tol_v` = 0)で最悪ケースを出す。CLI は `worst`(`tol_v=` で電源も)、画面はばらつき解析の窓の左に「最悪ケース」と、ヒストグラムの赤い線(起動引数 `--mc ノード [ac]`)。

**検証 (2026-11-02、`tests_worstcase.rs`)**: 近道(各部品を単独で動かす → 押す向きの角 → 1回だけ裏返す)は厳密な探索ではない。2^n 個の角をすべて解いた真の最大・最小と比べた。手で選んだ DC・AC(カットオフ)・過渡(行き過ぎ量)の回路(分圧器・ブリッジ・はしご・RC・2段 RC・ウィーンブリッジ・RLC)は、すべて一致した。ランダムな抵抗回路では、許容差 ±5% は 2000 回路で取りこぼし 0、±30% は 2000 回路中 2 件 (最大で範囲の 0.12%)、±60% は 1000 回路中 11 件 (最大で範囲の 0.98%)。許容差の内側のランダムな点が端の角を超えた例はなかった (端だけを見る前提は崩れなかった)。時間のかかる統計は `cargo test -p sim-core stress_random -- --ignored --nocapture`。過渡の指標 (行き過ぎ量) は、計算が短くて最終値が落ち着いていないと、指標そのものが不安定になり、内側の点が上限を超える (最初の設定の tstop 5 ms は、減衰の遅い角で足りなかった)。

## sensitivity.rs (感度、2026-11-09)
`sensitivity(circuit, &SensSettings{output, measure, step})`: 値のある部品(抵抗・コンデンサ・コイル・直流の電圧源と電流源。名前に `.` を含むモデルの中の部品は除く)を1つずつ `1±step`(画面は 1%)倍して、`measure`(`McMeasure`、ばらつき・最悪ケースと共有)を解き直す。中心差分で `per_percent`(部品が 1% 大きいときの結果の変化、結果の単位)と `elasticity`(結果の相対変化 ÷ 部品の相対変化。種類の違う部品を同じものさしで比べる)。上げたときと下げたときの変化が 1/4 以上違えば `bent`(まっすぐ動かない)。DC電圧を測るときは、値で結果が変わらないコンデンサとコイルを並べない。許容差は使わない(最悪ケースの `WcPart` は許容差の幅での効き。こちらは「どの部品を精度のいいものにすべきか」を許容差を決める前に見る)。単位は `McMeasure::unit()`(ばらつき・最悪ケースと共通にした)。CLI の `sens` は、回路図の値の文字列を書き換える別の実装のまま(`V(a,b)`・`I(部品)` を測れる)。

## psrr.rs (電源除去比、2026-11-09)
`supply_sources(c)`: 揺らせる電源(モデルの中でない、0 でない直流の電圧源)。`with_supply_ripple(c, source)`: その電源だけに `ac = (1, 0)` を付け、ほかの電圧源・電流源の AC を外した回路(名前は大文字小文字を区別しない。無ければエラー)。これを `ac_analysis` すると、各ノードの「1 V の揺れのうち届く分」が出る。`psrr_summary(freq, gain_db)`: 除去比(= −ゲイン dB)の、いちばん低い周波数での値・いちばん悪い周波数と値・100 Hz/1 k/10 k/100 k/1 M/10 MHz(範囲内だけ、対数で補間)。同梱の IC のモデル(LDO・オペアンプ)は多くが中で電源を見ないので、IC の分は実物よりよく出る(画面と CLI で注意を出す)。テストは RC フィルタ(角 159 Hz の上で 20 dB/デケード)と、信号源の AC が外れること。

**インピーダンス・ループゲイン・極と零の検証 (2026-11-02、`tests_accuracy_ac.rs`)**: 手計算の厳密な答えと比べた。①インピーダンス: R・L・C をランダムに直列・並列に組んだ 300 回路 (25500 点)。回路の尺度 (部品のインピーダンスの大きさ) に対する誤差は 1e-7 未満 (測定 9e-8)。インピーダンス自体に対する相対誤差は、共振の深い谷 (|Z| が 0.14 Ω まで落ちる所) で 2e-5 まで大きくなるが、引き算の桁落ちで、1e-6 を超えたのは 25500 点中 1 点。位相誤差 3e-5 度。理想コイルの並列 (直流でどちらも短絡) は `Singular` になる (SPICE と同じ。表示は「電圧源のループや並列接続…」)。試験では巻線抵抗 1 mΩ を直列に入れた。②ループゲイン: 2 つの極を持つループ (利得 3〜5e5、極の位置を 4 通り) を R1・R2 のどちらで切っても、厳密な T = A·H の式と相対誤差 2e-6 以内 (測定 2.0e-6)。位相余裕は 0.001 度、交差周波数は 1e-6 の相対誤差で厳密な値と一致 (位相余裕 0.213 度の場合も)。③極と零: 緩衝器でつないだ段の連鎖 (極・零の位置が分かる) で、極 1〜5・零 0〜4 の位置の誤差は 1e-8 以下、複素共役の極 (RLC) は実部・虚部とも 1e-3 以内 (測定は 4 桁以上一致)。限界: 応答がピークの 1e-9 (180 dB) より下がる所は当てはめが無視するため、そこにある上側の極・零は見つからない (極 16 Hz〜16 MHz の 5 段では、見える下側 3 極だけが正しく見つかり、残差 0.4% で「良い当てはめ」と出る)。極・零が 6 桁にわたって交互に並ぶ (ゲインがあまり下がらない) 5 極 4 零は、厳密に見つかる。まだしていないこと: 実物のオペアンプ (マクロモデル) でのループゲインの位相余裕、ngspice との突き合わせ。

**実物のオペアンプモデルでのループゲインの検証 (2026-11-02、`tests_loopgain_parts.rs`)**: 同梱の LM324・LM358・MCP6001・MCP6002・NE5532・TL072 で、ボルテージフォロワ・非反転増幅 (×10)・反転増幅 (×−10) を、出力の容量負荷なしと 10 nF ありで組み (36 通り)、`loop_gain` を使わない側の答えと比べた。①閉ループ応答の整合: 通常の AC 解析の閉ループ応答 H が、H = (H∞·T + H0)/(1+T) (H∞ は理想の増幅率、H0 は最初の増幅段 `Eop` のゲインを 0 にした同じ回路の AC 解析) と一致する。不一致は最大 3.3e-8 (ループが単一なら、この式は厳密に成り立つ)。(H0 を高い周波数の値で代用すると 1e-4〜1e-3 の差が出る。容量負荷があると H0 自体が周波数で変わるため。) ②LM358 のモデルは 1e5 の増幅・10 Hz の極・出力 50 Ω・入力 2 MΩ なので、フォロワのループゲインを手計算した (帰還抵抗 100 Ω〜47 kΩ、負荷容量 0〜1 µF の 5 通り)。誤差は最大 5.6e-6。**注意: 同梱の 6 モデルは同じひな形 (増幅 → 極 1 つ → 出力抵抗) の単極モデルで、無負荷のフォロワの位相余裕は 90 度になる。** 実物の部品は第 2 の極を持ち、余裕はもっと小さい。このモデルで出る位相余裕は、負荷 (出力抵抗と負荷容量) による分だけで、実物の値ではない。(10 nF の負荷で、NE5532 のフォロワは 10 度、TL072 は 13 度、LM358 は 32 度。)

**2026-11-11 の変更**: 同梱のオペアンプのモデルをデータシートの typ に合わせた (`docs/model-policy.md`、`docs/models/opamps.md`)。最初の増幅段は `Eop` (電圧) から `Bgm` (電流、`limit` でスルーレートを決める) に変わったので、①の「ループを殺す」は `Bgm` を 0 A の電流源に置き換える。②の LM358 の手計算は、モデルの文から gm・Rp・Cp を読む (`lm358_gain_stage`)。TL072 は第2の極を持つので、無負荷のフォロワの位相余裕は 56 度 (ほかは 90 度)。10 nF の負荷での余裕の上限を 35 → 45 度にした (LM358 の GBW が 1 → 0.7 MHz になり、負荷での落ち方が小さくなった)。

## ひずみ率 THD(spectrum.rs の `thd`、2026-10-31)
`thd(t, v, f0, t0, t1, max_harmonic)`: 窓を**ちょうど整数周期**に切り(`periods = floor((t1-t0)·f0)`)、1周期 2048 点に線形補間で取り直し、k·f0 でのフーリエ和をそのまま取る。FFT の窓関数(Hann)だと山が隣のビンにもれて振幅が 1.4 dB まで落ちるので、THD には使わない。この方式なら振幅 A の正弦波が A、その3次 1% が 1% に読め(テスト)、基本波以外が何も無ければ THD+N も THD に一致する。`f0` を省くと `estimate_frequency`(平均を下から上へ横切る点の最初〜最後の間隔。2% の幅のヒステリシス付き、3 回以上の横切りが要る)。`Thd.points_per_period` は元の波形の1周期あたりの点数で、40 未満なら画面・CLI が「刻みを小さく」と注意する(点を結ぶ直線そのものがひずみになる)。THD = √(2〜N次の振幅² の和) / 基本波、THD+N = √(交流分の実効値² − 基本波² / 2) / (基本波/√2)。CLI は `thd`(直前の `tran` の結果。範囲を省くと最初の 1/5 を除く)、画面は過渡解析の波形の左「ひずみ率 (THD)」(範囲はスペクトル表示中なら解析範囲、そうでなければ表示中の時間範囲。基本周波数の欄は空欄で自動)。サンプルは `amp_clipping.schjson`(`opamp_amp` の入力を `SIN(0 0.4 1k)` にして出力を頭打ちに。THD 約 16%、0.1V なら 0.000%)。

## スペックの最悪ケース(spec.rs、2026-10-31)
`SpecKind::DcVoltageWorst` / `AcCutoffWorst`(`is_worst()`)。解析の結果ではなく回路から `worst_case` を呼ぶ種類で、`evaluate_worst(spec, &WorstCase)` が「最小と最大の**両方**が範囲に入っていれば合格」と判定し、`note` に最悪ケースの範囲と、外れる側・量を書く(`value` は設計値)。`measure`(結果から読む関数)は、この種類にはエラーを返す。`SpecKind::ALL` の末尾に足したので、`--spec` の番号と保存済みのファイルは変わらない(`key` は `dc_voltage_worst` / `ac_cutoff_worst`)。画面は `schematic/spec_table.rs` の `worst_for_spec`(許容差は「温度とばらつき」の欄の R・C・L。回路図の署名・許容差・周波数・ノードが同じ間は `worst_spec_cache` に残す。毎フレーム解かない)、CLI は `spec dc_voltage_worst NET LO HI [tol_r= tol_c= tol_l= tol_v= f=]`。対象は両方ともノード名(AC のカットオフも `V(...)` ではなくネット名)。

## loopgain.rs (ループゲイン、注入法、2026-10-31)
`loop_gain(circuit, 部品, 向き, 設定)`: ループの途中の2端子の部品(抵抗・コンデンサ・コイル)の出力側の端(x)に新しいノード `Zbreak.m` を作って部品をそこへ付け替え、`Zbreak.m`(x)と元の入力側の端(y)の間に直列の電圧源 `Zbreak.V`(V(y)=V(x)+vt)、y に接地からの電流源 `Zbreak.I` を入れる。ほかの電源の AC は切る(直流は残すので動作点は同じ)。2回の AC 解析: 電圧注入(vt=1)で `Tv = −V(x)/V(y)`、電流注入(It=1、vt=0 なので直列の源が電流計)で `Ti = I_x/I_y`(I_x = −I_w、I_y = It + I_w、I_w = −I(Zbreak.V)。x→y の針金の電流)。**T = (Tv·Ti − 1)/(Tv + Ti + 2)**。導出: 切り口の Z 行列(z11 z12 / z21 z22)で Tv = (z11−z12)/(z22−z21)、Ti = (z22−z12)/(z11−z21) となり、1+T = det Z / (z11 + z22 − 2·z21)。片方の注入だけだと、両側のインピーダンスが違うとずれる(電圧注入は x 側が低い、電流注入は高いのが前提)。テスト(`loopgain.rs`)は制御電源のアンプで、解析解 `A·ZL/(Rp+ZL)·β` と 1e-6 で一致、切る場所を変えても同じ(1+T は切る場所によらない)、向きが逆だと小さい値(逆向きの伝わり)になる。`Auto` は両向きを試して最大の |T| が大きいほう(1 を超えないときは警告)。CLI は `loopgain PART F0 F1 [from=NET]`、画面は解析タブの「ループゲイン」(`schematic/loopgain.rs`。結果は AC の波形欄に信号 `T ループゲイン`(Tv・Ti も)として出し、余裕の表・カーソルはそのまま使う。`AcView.loop_run` で、自動再計算も `run_loop` に戻る)。サンプル `loop_cap_load.schjson`(`series_regulator` の出力に 10µF と 100Ω の負荷: 位相余裕 約 10°、元は約 90°。生成 `write_loop_cap_load_example`)。

## polezero.rs (極と零、2026-10-31)
`pole_zero(freq, h, max_poles, tolerance) -> PoleZero{poles, zeros, dc_gain, error, fitted}`: 周波数応答の標本に、実数係数の分数 N(s)/D(s) を当てはめ、N と D の根を零と極にする。`transfer_function(circuit, 出力, 入力, 設定, 次数, 許容)` は `ac_analysis` の V(出力)/V(入力)(入力なしなら V(出力) そのもの)にそれをかける。
- 当てはめは Sanathanan-Koerner の繰り返し(最大12回)。重みは 1/(|H|·|D|) で、相対誤差を最小にする(阻止域の -80 dB も通過域と同じ重さ)。未知数は a0..am と b1..bn(b0 = 1)。周波数は中央の周波数 w0 で割った `x = jω/w0` にして、単項式の大きさをそろえる。連立方程式は列を長さ1にそろえてから Householder の QR(法線方程式にしない)
- 次数: (零の数 m ≤ 極の数 n ≤ max_poles) を m+n の小さい順に試し、最大の相対誤差が `tolerance`(画面・CLI は 0.02)を下回った最初のものを採る。どれも届かなければ誤差が一番小さいものを返す(呼び出し側が `error` で「分数の式では表せない」と言う)。RC フィルタが「極1つ・零なし」になるのは、この順で一番小さい次数を採るから
- 根は Aberth-Ehrlich 法(多項式の実数係数、複素数の根は共役の片方だけ `pair=true` で並べる)。`Root::q()`・`damping()`・`right_half()`。零の位置は右半面なら位相だけが遅れる零(昇圧型電源など)
- 限界: 積分器(原点の極)は b0 = 1 に固定してあるので、ごく低い周波数の極として出る。時間遅れ(むだ時間)は分数の式にならない。6 桁を超える極の離れ方と 6 次を超える次数は、単項式の桁落ちで当てはめが荒れる(誤差が出るので分かる)
- テスト: 1極・極2つ+零・複素数の対(Q = 5)・右半面の零・点数不足。CLI は RC 2段の極の積 1/(R1C1R2C2)、サンプルは RLC の f0 = 1/(2π√LC) と Q = √(L/C)/R に合わせてある

## モーター (DC_MOTOR) と、その故障・連鎖故障 (2026-11-10)
- 部品は `part-lib/examples/DC_MOTOR.part.json` の副回路。電気: `RW`(巻線の抵抗)→ `LW`(巻線)→ `VS`(電流を測る 0V)→ `BE`(逆起電力 = Ke × 回転数)。機械は電気に置き換える: 回転数 = ピン `spd` の電圧(1V = 1000rpm = 104.72 rad/s)、トルク = 電流(1A = 1N·m)。`BT` が Kt × 巻線電流を `spd` に流し込み、慣性 J は `CJ`(J × 104.72 F)、摩擦 B は `RB`(1 / (B × 104.72) Ω)。負荷のトルクは、利用者が `spd` から電流源で引き出す(一定のトルク = 重りと同じなので、止まっているモーターを逆に回す。サンプルは負荷を 50ms から PULSE でかける)。Ke = Kt = 3mV/(rad/s)。
- 故障(`fault.rs`): `motor_inside(c, name)` が、`<部品>.LW`(兄弟に `RW` がある)を巻線、`<部品>.CJ`(兄弟に `BT`)を軸と見分ける。`breakable` はこの 2 つも返し、`faults_of(c, name)` が巻線 = 断線・レアショート 10/20/50%、軸 = ショート(= 軸のロック: 回転数 0 で逆起電力が消え、拘束電流が流れる)。`with_fault` は `faults_of` で確かめる。レアショートの巻線の抵抗は `winding_resistance`(`<名前>.DCR` か、モーターの `<部品>.RW`)。起こりやすさはどれも「ときどき」。名前は `describe_fault` が「モーターの軸がロック (回らない)」など。故障診断(`troubleshoot.rs`)も `faults_of` を使う。
- 定格(`ratings.rs` の `dissipation`): モーターは巻線の抵抗 `RW` の電力だけを熱とする(入る電力のほとんどは回転になる)。ヒントも専用。
- 連鎖故障(`chain.rs`): `overs` が、モーターの巻線の発熱 = 後半の平均の I(<部品>.LW)² × RW を、部品の `p_max`(無ければ 1.5W)と比べ、超えたら `Over.inside = (<部品>.LW, 断線)`(「巻線が焼けて断線」)。最初の段は、モーターの中の素子でも部品名と `describe_fault` の言葉で出す。壊す前から定格を超えていた部品は `ChainReport.already_over` に入れ、まとめに「連鎖から外した。起動の電流が入っているなら終了時間を長く」と出す(10ms では起動の突入電流が後半に入り、モーターが最初から外れる)。
- サンプル `motor_driver.schjson`(3V、AO3400A のローサイド、1N5819 のフライバック、ゲート 5ms から、負荷 1mN·m を 50ms から)。テスト `tests_isource.rs`(無負荷 約 8.6krpm → 負荷で 6.87krpm・0.447A、起動のピーク 1.3A 超。軸のロックで Q1 がショート → 巻線が焼ける。レアショート 50% で RW が半分)。記号は `glyphs.rs` の `motor`(M の丸、SPD は軸)。起動引数 `--fault <部品> <種類> chain` は `--tran` の時間を先に入れ、故障の節を開く。
