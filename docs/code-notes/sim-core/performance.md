# sim-core: 解析の速さ、収束の補助と失敗の原因

(`docs/code-notes/sim-core.md` の目次から分けた。内容は元のまま)

## 解析の速度(2026-10-19)
`vendor_xcheck_tran` が自前と ngspice の所要時間を出す(`TIME` 行、最後に `TIMES` の中央値・最大・合計)。`tran_profile`(`SPICE_MODEL_DIR` `SPICE_DUMP_FILE` `SPICE_DUMP_TOP` で1つ指定)は、1つのモデルの過渡の点数と、行列の因数分解を使い回せた回数を出す。
- **測った結果(公開モデルの過渡 20µs、47個)**: 中央値は自前 0.065 秒、ngspice 0.061 秒(プロセスの起動を含む)でほぼ同じ。合計は自前 39 秒、ngspice 5 秒。遅いのは大きなマクロモデル(行列が 130〜300)と、刻みが小さくなってしまう少数のモデル。
- **時間の内訳**(`OPA197`、行列 132): ニュートン法の1反復あたり約 200µs のうち、行列の組み立て 約 30%、**因数分解 約 65%**、解く部分 2%。因数分解は毎回「ピボットの選び直し+疎な消去+行の作り直し」を最初からやっていた(係数は 867 個、因数分解後 2935 個と、うめ込みは小さい。時間は構造の探索と配列の確保に使われていた)。
- **直し1: 因数分解の使い回し**(`dc/linalg.rs` の `Symbolic`・`refactor`、`dc/newton.rs` の `solve_reusing`): 前の因数分解のピボットの順と、うめ込みの模様(`Symbolic::plan` が模様だけから作る。値がたまたま 0 でも模様には入れる)を覚え、同じ模様の行列は、探索なしで数値だけ計算し直す。使い回した答えは残差(`residual_ok`、相対 1e-8)で確かめ、悪ければ最初から因数分解してやり直す。**行列が 60 より小さいときは使わない**(小さな回路のマルチバイブレータの反転は行列がほぼ特異で、そこでのニュートン法の動きがピボットの選び方に左右され、使い回すと 2 つのテストが収束しなくなった)。
- **直し2: 過渡の通常のニュートン法の反復上限を 40 に**(`newton_with` の `plain`): 収束しない刻みの試行が全反復の 75% を占めていた(`OPA197`: 21566 反復のうち、解けた回の合計は約 5200)。線探索つきの試行は 150 のまま(上限を全部の試行に 40 としたら、マルチバイブレータの反転で収束しなくなった)。
- **効果**(過渡 20µs): `OPA197` 4.4 → 1.6 秒、`LM5106_TRANS` 10.2 → 5.8 秒、`TSV912` 1.8 → 1.35 秒。検算の一致数は変わらない(DC 65、過渡 45)。
- 残る遅さ: `74HCU04`(MOSFET の LEVEL 3、31 万点)は刻みが最小に張りつく。`LM5106_TRANS` は刻みの数が 1.3 万点で、因数分解の次は行列の組み立てと刻みの棄却(1810 回)が重い。

### ピボットの使い回しが、大きな回路でほとんど効いていなかった(2026-11-12)
- 測り方(一時的な計測で、コードには残していない): `newton_with` の組み立てと `solve_reusing` の時間、`REFAC`(使い回し/最初から)の数、使い回しが失敗した理由を数えた。
- `mixed_signal`(未知数 157)の動作点: 時間の **92% が解く側**。使い回しはほぼ失敗(widen で 0 回、最初から 2702 回)。形(パターン)は毎回一致していて、失敗の 9 割は**残差の検査 `residual_ok`(相対 1e-8)**だった。スイッチ・デジタル出力・ダイオードでコンダクタンスが何桁も動くと、前のピボット順では数桁を失う。
- 直し1: **反復改良**(`solve_reusing`): 残差の検査に落ちたら、同じ因数で `b - A x` を解いて足す、を 2 回まで。合格の基準は同じ `residual_ok`。
- 直し2: **消去の順の使い回し**(`linalg::factor_ordered`): 最初からの因数分解でも、最小次数の順(`min_degree_order`、HashSet で重い)は形だけで決まるので、計画(`Symbolic`)の形と同じなら前の順を使う。結果はビット単位で同じ。
- 直し3: **行の確保を減らす**: 組み立ての行(`Compiled.rows_spare`、解いたあとの行を次の `Mna::new` が埋め直す)と、`refactor` の消去後の行(`factor_spare`)を使い回す。行 `i` は行 `i` に戻るので、容量が合ったまま。計算の順は変わらず、結果はビット単位で同じ。
- 効果(リリース): `mixed_signal` の widen 0.650 → 0.073 秒、gmin 2.92 → 0.25 秒。全サンプルの動作点(戦略ごと単独)は widen 0.79 → 0.18 秒、gmin 3.08 → 0.40 秒で、**解ける数と解けない回路の一覧は同じ**。過渡(小さい系、直し3だけが効く)は `ne555_blinker` 0.395 → 0.28 秒、`buck_converter` 0.482 → 0.39 秒、`cmos_inverter` 0.094 → 0.071 秒。
- 続き(小さい系、同じ日): 未知数 60 未満の系は毎反復で最初から因数分解する。その中の作業用の配列(列ごとの行の一覧 `col_rows` が n 本、`merged`・`cand`、何度も伸び直す `ops`)をスレッドごとの `linalg::Scratch` に残して使い回した(`ops` は前回の長さで確保)。`newton_with` が毎反復 `std::env::var_os("CCAD_TRACE")` を読んでいたのを `OnceLock` で1回にした(Windows の `var_os` は環境のロックと検索で、1反復 5 µs の系では効く)。過渡は `ne555_blinker` 0.28 → 0.18 秒、`buck_converter` 0.39 → 0.245 秒、`cmos_inverter` 0.071 → 0.045 秒、`logic_blinker` 0.016 → 0.008 秒。効かなかったもの: `xn.clone()`(1反復に1回の確保)をやめても差は誤差の範囲だった。
- 組み立ての内訳(同じ日、一時的な計測。素子の種類ごとに「その種類だけ飛ばす」組み立てを 2 万回繰り返し、全部との差を出した): `mixed_signal`(未知数 157)は 1 回 8.8 µs のうち **B 素子 18 個が 4.6 µs**(1 個 0.25 µs、ダイオードの約 5 倍)、行の並べ替え `compress` 2.1 µs、抵抗 44 個 0.9 µs。`buck_converter` は 1.6 µs のうち B 素子 4 個が 1.1 µs。`ne555_blinker` は 1.2 µs のうち `compress` 0.5 µs、スイッチ 10 個 0.6 µs。
- 直し: 式の評価(`expr.rs`)で、関数の引数を毎回 `Vec<D>` に集めていたのを、3 個までは配列にした。`eval` が勾配を毎回 `Vec` で返していたのを、組み立てでは `eval_with`(スライスを渡す)にした。B 素子 18 個 4.6 → 3.6 µs、過渡 `buck_converter` 0.245 → 0.219 秒。結果はビット単位で同じ。
- 効かなかったもの: `compress` の `sort_unstable` を挿入ソートにしても差は出なかった(戻した)。残る B 素子の 0.2 µs は、木をたどる評価そのもの(節ごとに値と 8 個の勾配を作る)。速くするなら評価器をバイトコードにする大きな作り直しになる。
- **決まった位置への書き込み**(同じ日、`mna.rs` の `StampPlan`): 素子の書き込み(`gn`・`at`)は、行ごとの `Vec` に push して `compress` で並べ替え・まとめていた。今は1本の `log`(行・列・値)に書き込み順で積み、最初の組み立てで「各書き込みがどの位置に、どの順で足されるか」の表を作る。次からは (行, 列) の並びが表と同じか確かめて(線形の比較)、値を決まった位置に足すだけ。並びが違えば(条件つきの書き込み: BJT の交差項 `cx != 0`、セルの出力がアナログ節点を駆動するかなど)表を作り直す。同じ列の重複は**書き込み順**で足す(前は `sort_unstable` の順。2 つまでなら同じ値、3 つ以上で最後の桁が変わりうるが、ベンチの時間以外の出力とワークスペースのテストは同じだった)。過渡 `ne555_blinker` 0.18 → 0.163 秒、動作点 `mixed_signal` gmin 0.25 → 0.22 秒、全サンプルの gmin 0.34 → 0.31 秒。
- **1 反復の内訳**(同じ日、一時的な計測): 小さい系(未知数 16)は 1 反復 2.8〜3.4 µs で、組み立て 40〜45%、毎回の最初からの因数分解 38〜43%、前進後退代入 5%、その他 12%。ニュートン反復の外(刻みの制御・デジタル)は `ne555` 15%、`buck` 18%、`cmos_inverter`・`logic_blinker` は 34〜36%。大きい系(`mixed_signal`、gmin)は 1 反復 17.9 µs で、組み立て 42%、数値の再分解 31%、代入 10%、残差の検査 7%。
- 小さい系の因数分解の無駄(同じ日): `factor_ordered` の `done`・`pivot_row`・`ops` と `Factor::solve` の作業ベクトルを `Scratch` に残して使い回す(`pivot_row`・`ops` は `Factor` に入り、`Factor::into_rows` で戻る。`refactor` も同じ)。消去した行は `merged` から写さず入れ替える。ピボットの選び方と計算の順は同じで、結果はビット単位で同じ。過渡 `ne555_blinker` 0.163 → 0.150 秒、`buck_converter` 0.22 → 0.20 秒、`cmos_inverter` 0.045 → 0.040 秒。効かなかったもの: 消去のマージの内側を「両方の行が残っている間」と「残り」に分ける書き方(差は誤差の範囲、戻した)。
- **ニュートン反復の外の内訳**(同じ日、一時的な計測。`transient_with` の区間ごとに時計を入れ、5 回の平均): 1 点あたりの外の時間は 1.7〜3.3 µs(`ne555` を除く)。
  - `ne555_blinker`(151 ms): **52% が開始前の動作点**。発振回路なので `DC_ORDER` の 4 つの方式が全部失敗してゼロから始める(direct 0.7 ms、gmin 25 ms、source 0.8 ms、gmin_long 53 ms)。反復の外のほかは記録 10%。
  - `cmos_inverter`(43 ms、コンデンサ状態 5 個): **刻みの誤差の見積もり `step_error_ratio` が 23%**(状態ごとに `pts` と `divided_difference` の `Vec` を作る)、記録 8%、刻みの決定 4%。`reactive_state`・`lte_abs_voltages` は各 2%。
  - `logic_blinker`(8 ms): デジタルの更新 `seq/dig` 13%、記録 9%、誤差の見積もり 6%、刻みの決定 5%、`x`・`vj` の複製 3%。
  - `buck_converter`(204 ms): 記録 9%、誤差の見積もり 6%(ニュートン 78%)。`led_blinker` はニュートンが 93%。
- 直し(同じ日): `step_error_ratio` の点の列と `divided_difference` の作業列を、`Vec` から長さ 4 の配列にした(点は 3 か 4 個)。計算の順は同じで、ベンチの時間以外の出力は同じ。過渡 `cmos_inverter` 0.040 → 0.031 秒、`buck_converter` 0.20 → 0.19 秒。
- 注意: 反復改良で、使い回した解の最後の桁が前と変わるので、大きな系(未知数 60 以上)ではニュートン法の道筋が少し変わる(`mixed_signal` の直接だけの反復 469 → 507、ソース 678 → 727。どちらも以前から失敗する方式)。

### 配線を反映した過渡解析が遅かった(2026-11-12)
- 症状: 総合デモ(`mixed_signal.ccproj`)で基板の配線を回路図に反映(post-layout)して過渡解析(10 ms・10 µs)をすると、開発ビルドのアプリで 14 秒(配線の反映 1.8 秒 + 解析 10 秒余り)。反映なしは約 1 秒。素子は 155 → 571、未知数 436、計算点は 3 361 → 24 087、刻みの中央値は 0.49 µs → 4.7 ns。
- 原因 1(刻み): 刻みを決めていたのは、ほとんどがコンデンサのピンの配線のインダクタ(`C3.2.LW` など)の電流。2 つのバイパスコンデンサの間で 6〜9 MHz・Q 20 ほどで揺れ、振幅は約 0.7 mA(そのピンのピーク 180 mA の 0.4%)。誤差の許し幅が「いまの電流 × `lte_reltol`(1e-4)」なので、ゼロを横切るたびに許し幅がほぼ 0 になり、刻みが ns まで縮んでいた。ほかに、刻みごとに符号が変わる数 nA の振動(`C6.1.LW`)も、絶対の下限 1 nA で追っていた。
- 直し 1: 配線のインダクタ(名前が `.LW` で終わる、`tran.rs` の `WIRING_INDUCTOR`)だけ、絶対の下限を「それまでに流れた電流のピーク × `lte_reltol`」に上げる。計算点 24 087 → 6 125、解析(リリース)7.7 → 3.3 秒。精度: 判定を 10 倍厳しくした基準の答えに対し、CLK の立ち上がりの時刻のずれは前も後も最大 2 µs 前後(Q2 は前 34 µs、後 3.4 µs)、電源(V5・V3V3)の差は µV 以下。テスト `bypass_capacitors_ringing_through_their_wiring_do_not_hold_the_steps_down`(2 つのコンデンサと配線: 9 100 → 3 200 点、レールの差 0.2 mV 以内)。
- 原因 2(配線の反映): `pcb_core::irdrop::wiring_resistances` が 1.07 秒(リリース)、ほぼ全部が GND のベタ(格子 3 891 点、33 パッド)。パッドごとに、(a) ベタの抵抗網を共役勾配法で解き直す(1 回 20 ms、計 0.67 秒)、(b) 供給パッドからの最短路(O(n²) のダイクストラ)を解き直す(1 回 12 ms、計 0.40 秒)。
- 直し 2: (b) 最短路の木は出発点だけで決まるので、ネットごとに 1 回(`lowest_resistance_tree`)。答えはビット単位で同じ。(a) 抵抗網を 1 回だけコレスキー分解し(`EnvelopeCholesky`: 逆 Cuthill-McKee の順、各行は最初の非零から対角まで)、パッドごとに前進・後退代入だけ。共役勾配法との差は相対 3e-12 以下(全サンプルの基板で比べた)、経路は同じ。格納が `MAX_ENVELOPE`(2000 万)を超える網は共役勾配法に戻る。1.07 → 0.13 秒(リリース)、開発ビルドで 0.17 秒。
- 全体: 開発ビルドのアプリ(起動と画面保存を含む)で 14.2 → 6.6 秒。
- 試して入れなかったもの: 部品モデルの中のインダクタ(電解コンデンサの ESL `C1.Lesl` など、名前に `.` を含むもの)にも同じ判定を使うと 6 125 → 4 541 点(2.7 秒)になるが、配線を反映しない普通の解析の答えまで変わるのでやめた。
- 残り: 1 反復 74 µs(未知数 436)× 1 刻み平均 5.3 反復。

### 刻みの決め方を調べた(2026-10-19)
`tran_profile` が、刻みを決めたのは何か(`STEPS by limit`: 1 折れ点・2 棄却のあと・3 後退オイラーの再試行・4 最大刻みのまま・0 誤差の見積り)と、誤差の見積りで最悪だった容量・コイル(`ERROR CONTROL worst element`)と、刻みの分布を出す(`tran.rs` の `STATS`/`WORST` はテスト用)。
- **`LM5106_TRANS`(刻み 1.3 万点)**: ほぼすべての刻みが誤差の見積りで決まり、最悪は `LT_EN_*` — 自前の伝送線路(`T_EN`、Z0=1k、TD=4ns)のはしごのコイルだった。損失のないはしごは、エッジで高い周波数のモードが励起されると**いつまでも減衰せずに鳴り続け**、刻みが 0.1ns に張りつく。直し: はしごの**各コイルに 20·Z0 の抵抗を並列**に入れる(`ladder`)。DC と信号の帯域には影響せず(コイルは DC で短絡、信号の帯域では 20·Z0 に流れる電流は無視できる)、最高のモードだけが数 ns で減衰する。刻み 12928 → 5620 点、5.8 → 2.6 秒。
- **`OPA197`・`TSV912`**: 最悪はモデル内の容量(`C12` など)で、本当に速く動く節点。刻みは正当。
- **`74HCU04`(31 万点)**: 最悪は `L2.Xu04`(6.87nH の接地のボンディングワイヤ)。1.5pF との共振(1.6GHz、周期 0.64ns)が減衰せず、誤差の許容 1e-4 だと 1 周期 26 点で追う。ngspice の許容(reltol 1e-3 × trtol 7 ≒ 7e-3)は自前の 70 倍ゆるい。
- **許容 `lte_reltol` を 1e-3 にすると**: 点数は 25〜35% 減るが(`LM5106` 5620 → 3972、`OPA197` 1561 → 1045)、アプリのテスト(`buck_sample_regulates…` と保存した ngspice の統計との比較 `transient_runs_still_match_the_stored_ngspice_statistics`)が落ち、検算の一致も 45 → 44 になる。1e-4 のままにする。許容を緩めて速くするのではなく、速さと正確さの釣り合いは今の値でとれている。

### 小さな系の因数分解で使わない計画を作っていた(2026-10-31)
- 測り方(一時的な計測で、コードには残していない): 反復ごとの時間を「組み立て」「因数分解+解く」に分けると、`led_blinker` で組み立て 26%・解く側 70%。
- 原因: `linalg::factor_sym` が、毎回 `Symbolic::plan`(因数分解と同じ消去を記号だけでもう一度やる)まで作っていた。60 未満の系は使い回さないので、捨てていた。`factor_planned(n, rows, want_plan)` にして、`n >= REFACTOR_MIN_SIZE` のときだけ計画を作る(`factor` は作らない)。数値は変わらない(`ccad tran` の点数・統計が3サンプルで同じ)。
- 効果(`ccad tran`、リリース): `logic_blinker` 2.1 → 1.05 秒、`buck_converter` 1.1 → 0.52 秒、`led_blinker` 3.4 → 2.6 秒。
- 調べて採用しなかったもの: (1) 小さな系の通常の反復の打ち切り: `led_blinker` の反復の 94% は失敗した試行(通常 150 + 線探索 150)だが、失敗は「乱れ」ではなくゆっくりした収束で、40 反復目の動きでは成功と失敗を見分けられない。成功のうち 40 反復を超えるものが 1% あるので、切ると解けていた所が解けなくなる。(2) 失敗のあとの刻みを `h_min` に引き上げずに覚える案: 反復が 44.5万 → 53万に増えた(`h_min` への引き上げがフリップのあとの探索を助けている)。
- `led_blinker` の失敗の出方: フリップごとに「最大刻みで着地して 12 回棄却される」ステップ(失敗 52〜65 回、失敗全体の約46%)と、刻みが 1e-7 → 1e-10 まで縮むステップ(失敗 7〜9 回、約36%)が出る。

### 動作点の戦略の順(2026-10-31)
- `tests_bench.rs bench_dc_strategies` が、戦略ごとの所要時間を出す。`mixed_signal`(41部品)の `dc_op` は 1.94 秒で、そのうち約 1.6 秒は**失敗に終わる gmin ステッピング**だった(gmin ≈ 6.5e-5 の壁。減衰つきの再試行が1回 70〜100 ms ×7、最後の `newton_long`=反復上限40倍が 1.1 秒で失敗)。ソースステッピング(0.06 秒・失敗)のあとのスイッチ拡大(0.16 秒)が解く。
- 直し: `Strategy::Gmin` は、刻みを細かくしても通らない所で諦める。`newton_long` つきの版を `Strategy::GminLong` にして、`DC_ORDER`・`DC_ORDER_WIDEN` の**最後**に置く(`[Direct, Gmin, Source, (Widen,) GminLong]`)。ゆっくり収束するだけの回路(飽和したゲート・TL431 など)は、ほかが全部失敗したあとで、今までと同じ長い反復で解く。
- 効果: `mixed_signal` の `dc_op` 1.94 → 0.87 秒(答えは同じ。スイッチ拡大・143 反復)。41部品の故障のスキャン(138件、直列)245 → 101 秒、中央値 1.93 → 0.79 秒。ワークスペースのテストは全部通った。
- 注意: gmin(短い版)が失敗して、昔は `newton_long` で解けていた回路は、先にソース・スイッチ拡大で解かれる。答えが一意の回路は同じだが、2つの状態を持つ回路は別の状態を選ぶことがある(`dc_op` の `strategy` の名前は「gmin stepping」でなくなる)。公開モデルの一括試験(`vendor_bulk`)は手元にモデルが無く、まだ回していない。回せる人は `SPICE_MODEL_DIR` で、読めて解けた割合(93.3%)が下がらないか確かめる。
- 残り: `mixed_signal` の 0.87 秒のうち約 0.5 秒は、失敗する gmin の減衰つき再試行(`newton_damped` の10通り)。

### 擬似過渡解析(PTA)を試作して、採用しなかった(2026-10-31)
- 作り方: 全ノードに擬似容量(後退オイラー)を足す。対角に `1/h`、右辺に `(1/h)×前の電圧`(gmin の「グラウンドに引く」を「前の解に引き留める」にしたもの)。`h` を 1 ms から、反復の少なさに応じて ×2〜×8 で伸ばし、失敗は ×¼。`h ≥ 1e4` から毎回、擬似容量なしで仕上げを試す。
- 結果(`bench_dc_strategies_all`、同梱 67 サンプル、各戦略を単独で): PTA は 62 件(`coin_cell_led`・`li_ion_cell_charge`・`tp5100_cell_charge` を落とし、6.9 秒)。`mixed_signal` も解けず 5.5 秒。gmin 65 件 0.7 秒、スイッチ拡大 **67 件 0.22 秒**より悪い。
- 失敗の原因: 電池モデルの `BT1.soc` のような、`limit()` で両側が平らな B 素子(TL431 のときと同じ型)。全ノードをゼロに引き留めると、その入力が悪い領域に入り、最初の1歩のニュートン法が 2 点(0.5 ↔ −0.86)を往復する。`h` を縮めても(1e-3 → 1e-7)直らない。調整の問題ではなく、方式の問題。
- 見つかったこと: スイッチ拡大(`Widen`)は、67 件すべてを 0.22 秒で解く(gmin は 65 件・`mixed_signal` と `ne555_blinker` を落とす)。順序を変える材料になるが、2 つの状態を持つ回路の答えが変わりうるので、まだ変えていない。

### スイッチ拡大を、直接のあとに試す(2026-10-31)
- `DC_ORDER_WIDEN`(`dc_op`)を `[Direct, Widen, Gmin, Source, GminLong]` にした(以前は `Widen` が `Source` のあと)。`Widen` は同梱 67 サンプルを単独で 0.22 秒で全部解く(gmin は 0.7 秒で 65 件)。`DC_ORDER`(過渡・AC・ノイズの出発点)は変えない(発振・ラッチは「動作点なし」と答えてゼロから始める決まり)。
- 答えの比較(一時のテストで、旧順序と新順序の全ノード電圧を 67 サンプルで比べた): 全部一致(相対差 1e-6 未満)。解いた戦略の表示だけ、`ip2332_charger`・`tp5100_charger` が「gmin stepping」から「switch widening」に変わる。
- **利用者の初期推定(`guess=`、`nodeset`)があるときは、旧順序のまま**(`solve_op` が `Widen` を `Source` のあとへ動かす)。推定を守るのは gmin ステッピング(ノードを推定の電圧へ引く)だけで、`Widen` は推定をほぼ無視する。同梱サンプルには推定つきの回路が無く、比較では見えなかった。CLI のテスト `a_latch_built_from_gates_has_two_answers_and_guess_picks_one` が、先に `Widen` を試すと別の状態に落ちて失敗したことで見つかった。

- 注意: 推定なしの 2 つの状態を持つ回路(ラッチ)で、直接が解けないとき、昔は gmin の状態、今は `Widen` の状態が出る。同梱サンプルとテストでは差が出ていない。

### AC・ノイズの動作点は、だめなら `Widen` でやり直す(2026-11-10)
- `dc::small_signal_op`: AC(`ac.rs`。ループゲイン・極と零・電源除去比もこれを通る)とノイズ(`noise.rs`)は、まず `DC_ORDER` で動作点を探し、`NoConvergence` のときだけ `[Widen]` で探し直す。見つかったら警告に「スイッチの切り替わりをなだらかにして求めました。ラッチは状態の1つに、発振する部分は止まった状態にして計算しているので目安です」を足す。`mixed_signal`(555 とフリップフロップ入り)は、DC の画面は解けるのに AC は「収束しませんでした」で止まっていた。過渡解析の出発点(`tran.rs`)は `DC_ORDER` のまま(発振・ラッチが「動作点なし」で 0 から始まるのは意図どおり)。テスト `ac_runs_on_a_mixed_signal_sheet_and_says_how`。
- それでも求まらないときの画面の文(`schematic/dc.rs` の `small_signal_error`、AC・ノイズ・電源除去比): 「まず動作点を求める解析で、それが求まらなかった。DC動作点の解析で同じように失敗するか確かめ、ヒントに沿って直す。発振する部分を外す・『収束しやすく』も手」と、DC と同じ `diagnose` のヒント。

## 過渡の素朴なニュートン反復の打ち切り(40回)と、プラットフォームによる収束の差
- `dc/newton.rs` の素朴な反復(`plain`)は、過渡の刻みでは `PLAIN_CAP`(40)回で打ち切る(刻みを小さくして再試行したほうが速いため)。ただし打ち切るのは、**大きい系(未知数 `REFACTOR_MIN_SIZE`=60 以上)の、再試行の最初の `CAPPED_TRIES`(6)回だけ**(`Dyn.capped`)。小さい系は、これまで通り上限(150)まで粘る。
- 経緯: d9a931a で、全部の系・全部の再試行に 40 回の打ち切りを入れたところ、Linux と macOS の CI で `logic_blinker`(未知数 40、双安定のロジック。Windows の過渡では最大 39 回で、40 回に1回足りない所まで来ていた)が `NoConvergence` で落ちた(Windows は通る)。最初は「最初の6回だけ打ち切る」に直したが、それでも Linux・macOS は落ちた(打ち切りの対象が小さい系にも及んでいたため)。ピボットの再利用(`solve_reusing`)は 60 未満の系では動かないので無関係。
- 手元(Windows)の調べ: 刻みの更新(`powf`)に相対誤差 -1e-15 を足すと同じ失敗が再現する(Linux の `libm` との最後の桁の違いの代わり)。exp/ln/pow/tanh の最後の桁を入力ごとにばらつかせる実験(40通りの種)では、この回路は落ちなかった。Linux だけの失敗を Windows で完全には再現できていないので、小さい系を打ち切りの対象から外して、d9a931a より前の挙動(Linux で通っていた)に戻した。
- マルチバイブレータの弱点(直した): `tests_blinker` の無安定マルチバイブレータ(特に `symmetric_circuit_and_zero_state_start_also_run` の `uic=true`)は、数値の揺らぎで `NoConvergence` になることがあった。原因は、フリップの瞬間に、コンデンサ電圧を固定した代数方程式が古い状態の近くに解を持たない(折り返し点)こと。`tran.rs` の対策は「4回失敗したら最大刻み(`tstep`)を1回だけ試す」で、その1回で着地できないと、元の刻みと最大刻みの間の大きさは誰も試さず、刻みを 1e-14 まで縮めても収束しなかった。直し: 最大刻みから 1/16 ずつ、失敗中の刻みの 64 倍まで段階的に試してから元の刻みに戻る(`h_first`)。試行の上限は 12 → 16 回。揺らぎを入れた実験(エミュレートした `libm` の誤差を入力ごとにばらつかせた40通りの種のうち 1〜16、ステップ幅の更新の相対誤差 ±2e-16〜3e-15)で、直す前は失敗していた種・揺らぎ(3, 7, 9、-3e-16、-1e-15)を含め、`tests_blinker` の5件と sim-core の全テストが通った。

## オペアンプのマクロモデルの巻き込みと、DC が収束しないときの場所の表示(2026-10-24)
- **巻き込み**: ライブラリのオペアンプ(LM324・LM358・MCP6001・MCP6002・NE5532・TL072)は、`Eop`(利得)→ `Rp`/`Cp`(支配極)→ 出力の制限、という作り。出力が電源に張り付いている間も `n0`(極の後ろの節点)は `A0 × 入力差` に向かって伸び続け(入力差 1V・20ms で数万V)、入力が戻ってから出力が戻るまで数 ms〜数十 ms かかった(実物は約 1µs)。
- **直し方**: `n0` に、電源の外側 0.5V(+ダイオードの順方向電圧)でダイオードのクランプ(`Dtop`/`Dbot`、`Vtop`/`Vbot`)を足した。**駆動(`Eop`)は制限しない**: `limit()` で駆動を絞ると、戻るときの目標値まで絞られて、かえって遅くなる(試して外した)。`Rp` を 1k → 1Meg、`Cp` を 16µ → 16n(時定数は同じ)にして、クランプに流れる電流を 1/1000 にした。
- **2026-11-11**: データシートに合わせたモデルでは、駆動が `Bgm`(電流)になり、`limit` でスルーレートの分に絞っている(`Cp` 1 nF、`Rp` は開ループ利得 ÷ gm)。クランプ `Dtop`/`Dbot` はそのまま `n0` にあり、飽和からの戻りのテスト `an_op_amp_left_saturated_for_long_recovers_in_microseconds` は通る(絞りがスルーレートの値なので、戻りもスルーレートで決まる)。
- 検証: `tests_parts.rs` の `an_op_amp_left_saturated_for_long_recovers_in_microseconds`(20ms 張り付いたあと、200µs で出力が反対側へ)。直す前は LM324 で 200µs 後も 3.48V のまま。
- **利用者のライブラリ(`%APPDATA%\circuitCad\library`)には、初回に同梱部品がコピーされる**ので、すでに使っている人には古いモデルが残る。反映するには、その部品のファイルを消して再起動する(同梱版が入り直す)。
- **収束しなかった場所の表示**: `dc/newton.rs` の `note_stuck` が、繰り返しの上限に達した最後の反復で、許容に対して最も動いている節点を覚え、`solve_op` が全部の戦略が失敗したときに文にする。`sim_core::last_convergence_trouble()` が返し、`diagnose` が `NoConvergence` の先頭に出す(アプリの DC 解析のヒントと、`ccad` の `dc` の失敗の `ヒント:` に出る)。`ライブラリ部品の中の節点`(`U1.y1` など)なら「部品 U1 の中のノード」と言う。`tran` の途中の失敗には出さない(古い値が残るため)。
- 調べた例: 電池低下の検出(TL431 + LM393 + ヒステリシス)と LT3045 の SET モデルを同じ回路に入れた DC が、電圧によって収束したりしなかったりした。表示で、古い MCP6001 のマクロモデルの内部節点 `U1.y1` が 2×10⁷ V へ発散していることが分かった(巻き込みとは別の、クランプ後段の暴走)。

## 収束しない原因は、両端が平らな B 素子(TL431)だった(2026-10-25)
- 症状: 電池低下の検出(TL431 + LM393 + ヒステリシス)を、オペアンプのマクロモデルと LT3045 のモデルがある回路に入れると、DC が電圧によって収束したり、しなかったりした。`tran` も収束しなかった。部品を外していく切り分け(delta debugging)では、どの部品を外すかで結果が変わり、原因の部品が決まらなかった。
- 見つけ方: `CCAD_TRACE=1` で反復ごとの最大変化の節点を出す(`dc/newton.rs`)と、gmin を下げていく途中(約 2.7×10⁻³)の 150 反復が、TL431 の基準端子の節点 `VREF` の **−30.57 V と 0.7395 V の 2 周期の往復**だった(`ratio` は動かない)。
- 原因: TL431 のカソード電流が `limit(200*(V(ref,an)-2.495), 0, 0.1)`。傾き 200 A/V が効くのは 0.5 mV の幅だけで、両側は完全に平ら(傾き 0)。ニュートン法は、平らな所では「次の点」を平らな線から外挿して遠くへ飛び、もう一方の平らな所へ着地する。ダイオードのように junction limiting が効く素子ではないので、B 素子ではこれを止められない。
- 直し方: 滑らかな膝(softplus: `k·w·(0.5(x+|x|) + ln(1+e^-|x|))`、`x=(V(ref,an)-2.495)/w`)にした。`w=0.3 mV`、`k=200 A/V`。傾きがどこでも 0 にならず、右側は直線(ニュートン法は 1 回で解く)、左側は指数のすそ。上限 0.1 A は外した(回路の抵抗が決める)。基準は 1 mA 以上で 2.494 V(誤差 1 mV 以内)。`w=3 mV` だと 2.478 V(0.7 %)まで下がるので、狭くした。
- 検証: 回路の DC が電池 9.6〜4.9 V の全点で収束(ヒステリシスの帯の中も)。`tran` も収束。テスト `the_tl431_converges_from_zero_at_any_supply_and_holds_the_reference_within_a_millivolt`。
- ほかのモデルの `limit()` は、出力の振れ幅を決める電圧出力で、低インピーダンスの負荷につながる使い方なので、同じ平らな往復は起きにくい。見直さなかった。**傾きが大きく、両側が平らな `limit`/`step` の電流源を B 素子で作るときは、この膝の作り方にする。**
- 前に疑った `MCP6001` の `y1`(出力制限の段)は、往復の結果として暴走した値で、原因ではなかった。`CCAD_TRACE` の出力はそのまま残してある(環境変数があるときだけ)。

## gmin 段階の収束の補助に、刻みを抑えた反復も使う(2026-10-25)
- きっかけ: 10 レンジの電流源(`MCP6001` のマクロモデルがループ、RS を 8 つ切り替え)で、3 kΩ(100 µA)以降のレンジだけ DC が収束しなかった。`CCAD_TRACE=1` では、gmin を 10⁻⁵ まで下げたところで、ほかのどの節点も落ち着かず、モデルの内部節点が往復した。同じ回路で ADA4522 のループにすると収束した。
- 直し方: `Strategy::Gmin`(`dc/mod.rs` の `run`)の `newton` を `newton_damped` に替えた。普通の反復(と backtrack、0.5・0.2 倍)で収束しなければ、その後で 0.3・0.1 倍と、1 回の変化を 2 V・0.5 V・0.1 V に抑えた反復を試す(`newton_damped` は元からあった。`Widen` だけが使っていた)。収束する回路は、これまでと同じ答え(最初の `newton` が通るため)。
- 効果: 上の電流源の 3 kΩ〜3 MΩ レンジが収束した(読みの誤差 0.09 % 以内)。メーカーの MCP6001 マクロモデル(Microchip Rev G)のボルテージフォロワは、入力 0〜5 V の 7 点中 3 点から 4 点に増えた(0・1・3 V は収束しない: 出力段の `TABLE` の電流源 `GD51`/`GD52`(1 mV あたり 1 A)が、TL431 と同じように傾きの違う2つの面の間を往復する。`TABLE` を滑らかに扱うのは未着手)。
- 限界: メーカーのモデルには、内部の節点が 100 V 以上になるもの(MCP6001 の `G32`: 電源電圧に比例した基準を 1 Ω で作る)があり、1 反復の変化を 0.1〜0.5 V に抑えた反復は、そこまで行くのに 150 反復では足りない。

## 刻みの上限に「大きさに比例する分」を足した反復と、その答えの警告(2026-10-25)
- `newton_damped` の刻みを抑えた反復(1 回の変化を 2 V・0.5 V・0.1 V に)に、**自分の大きさの 20 % / 50 % を足して動ける**版を足した(`REL_STEP`、`newton_with` の `part`)。内部の節点が正当に 100 V にいるモデル(Microchip の MCP6001 の `G32`)は、0.1 V ずつでは 150 反復で届かないため。
- 効果: Microchip の MCP6001(Rev G)のボルテージフォロワが、入力 0〜5 V の6点すべてで収束した(1 V → 0.9995 V、5 V → 4.980 V)。
- 副作用: 555 の点滅 (無安定) 回路の DC が、乱数で変えた 300 組すべてで「答えが出る」ようになった(釣り合いの点。実際には不安定)。以前は 20 組中に答えが出ないものがあり、それで「過渡解析を」とヒントを出していた。そこで、**刻みを抑えた反復で見つけた答えには、警告を付ける**ことにした(`LIMITED_USED` → `dc_op_with` が `DcResult.warnings` に「この答えは、ふつうの方法では収束せず…2つの状態を持つ回路や発振回路では、実際には落ち着かない点が出ることがあります。…「過渡解析」を使ってください」を足す)。アプリの DC のパネルと `ccad dc` の `warnings` に出る。
- テスト `a_555_blinker_without_an_operating_point_points_to_the_transient_run`(`app/src/tests/converge.rs`)は、答えが出ない場合のヒントか、この警告かのどちらかが、過渡解析に誘導していればよいことにした。

## 降圧(`BUCK_DEMO`)の出力を、回路の GND にできる(2026-10-25)
- 電池の − 側を IC の `gnd` ピンにして、インダクタの先(出力の + 側)を回路の 0 V にする配線(IC は浮いた負の電源の上)で、出力が 1.8 V にならなかった(1.48 V)。モデルの中の電圧が、`gnd` ピンではなく**ノード 0** から測っていたため(`V(fb)`、`V(vin)`、`V(comp)`、`V(ctl)`、`V(ramp)`)。すべて `V(x,gnd)` にした。普通の配線(`gnd` が 0 V)では、同じ値になるので、既存のサンプルは変わらない。
- 検証: テスト `the_buck_demo_works_with_its_output_as_the_system_ground`(9 V → 1.8 V、負荷 1.8 Ω、6〜8 ms の平均が 1.8 V ± 0.05)。直す前は 1.478 V で失敗する。
- 使い方の注意: この配線の DC 動作点は、スイッチングを平均化していないので、出力は出ない(電流源のレールは過渡解析で見る)。回路全体の DC は、理想電源 `VRAIL` で 1.8 V を与えて計算している。
- 限界(モデルのまま): 軽負荷で間欠動作をしない(無負荷で出力が 2.1〜2.2 V まで上がる)、負荷の急な変化への応答が遅い(1 A のステップで出力が一時的に 1.1 V まで下がる)、ダイオードの電圧降下と IC の抵抗で効率が低く出る。実在の降圧 IC(ピークではなく、強制 PWM の低ノイズのもの)を選ぶときは、データシートで確かめる。
