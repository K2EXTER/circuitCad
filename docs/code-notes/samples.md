# サンプル回路・同梱部品のメモ

`docs/examples/*.schjson` と `part-lib/examples` の同梱部品について。生成は `crates/app/src/tests/examples.rs` の `write_*` テスト(`cargo test -p app <名前> -- --ignored`)。

- Arduino 互換の最小ボードは `arduino_minimal.schjson`(ATmega328P + 16MHz水晶 `XTAL_16MHz_3225` + FTDIヘッダ + ICSP + D13のLED + 余ったI/Oを出すヘッダ2つ、部品16個・パッド85)。**`write_*` テストではなく名前ベースのスクリプト `arduino_minimal.ccad` から作る**: `cargo run -p cli -- docs/examples/arduino_minimal.ccad` のあとに `save` / `board ...` を足す。マイコンはシミュレーションモデルなしなので、DCで見えるのは電源(5V)とリセットのプルアップ程度。水晶は R-L-C + C0 の等価回路(AC解析で直列共振16MHz)。基板の品質ベンチマークの「大きめの実戦の題材」(`tools/quality_bench.py` が自動で拾う)。学習パスの題材にもする予定。
- 水晶のレッスン(24「水晶とクロック」、`lessons/micro.rs`)は `crystal_response.schjson`(V1 → 水晶 Y1 → 50Ω の R1 → GND、生成 `write_crystal_example`)。AC解析で 16.000MHz に幅約1kHzの山(利得0.55)、約16.027MHz に深い谷(並列共振)。**山が細いので、1デケードあたり10万点・範囲 15.9〜16.1MHz で見る**(`ac.rs` の点数の上限を 1000 から 10万に広げた。全体の上限 10万点は従来のまま)。1M〜100MHz・100点では山を見落とす(これも手順2で体験させる)。R1 を 5k にすると山が約80kHzに広がる。テスト: `crystal_sample_passes_only_near_16mhz_and_has_a_notch_just_above`、`the_crystal_lesson_ticks_its_steps_and_the_wide_sweep_misses_the_peak`。手順の完了判定は、画面の入力欄ではなく、実行した結果の周波数の範囲を見る(`conditions.rs` の `ac_run_range`)。
- リセット回路のレッスン(25「リセット回路」、`lessons/micro.rs`)は `reset_circuit.schjson`(V1=5V、V2=DTR `PULSE(5 0 1m 1u 1u 8m 20m)`、R1=10k で VCC→RESET、C1=100n で DTR→RESET、生成 `write_reset_example`)。数値: 100nF で RESET が約0Vまで落ち、1V未満が約0.23ms(時定数 R1×C1=1ms の 0.22倍)。220p だと最小 1.6V で届かない。R1=100k だと約2.2ms。DTR が戻る(9ms)と RESET が約10V に跳ね、RESET→VCC のダイオード(アノードが RESET)で約5.6V。手順4の判定 `reset_clamped` は、回路に `D` が RESET(A)と VCC(K)につながっていて、実行が最新で、V(RESET) の最大が 6.5V 未満のとき。テスト: `the_reset_sample_gives_the_numbers_of_its_lesson`、`the_reset_lesson_ticks_its_four_steps`。
- バイパスコンデンサのレッスン(26、`lessons/micro.rs` の `DECOUPLING`)は既存の `cap_impedance.schjson` を使う(電解100µF・セラミック10µF・並列の |Z|。10kHzで電解0.26Ω/セラミック0.94Ω、1MHzで0.24Ω/0.02Ω、並列は100kHzで0.17Ω。1Ωとの分圧なので 0.2Ωを超えると実際より小さく出る)。手順2の判定は V(ZP) がグラフに選ばれていること(`zp_shown`)。テスト `the_decoupling_lesson_ticks_and_its_numbers_hold`。
- プルアップのレッスン(27、`PULLUP`)は `pullup_input.schjson`(V1=5V、R1=10k プルアップ、R2=ボタン(100Meg=離す/10=押す)、C2=5pF ピンの容量、C3=2pF でノイズ源 V2 `SIN(0 5 100k)` から結合、生成 `write_pullup_example`)。数値: 離す→IN 5.0V(ノイズ±0.06V)、押す→5mV・R1に0.5mA、R1=100Meg(プルアップ無し)→IN 2.5V中心で 1.1〜3.9V に揺れる(100k で±0.6V、1M で±2.8V)。テスト `the_pullup_lesson_ticks_its_four_steps_and_its_numbers_hold`。
- ピンの LED のレッスン(28、`PIN_LED`)は `pin_led.schjson`(V1=5V=ピンの High、R2=25Ω=ピンの出力抵抗、R1=330Ω、D1=LED、生成 `write_pin_led_example`。**R1 が先に作られて R1 番になる**)。数値: 330Ω→8.6mA・ピン4.79V、1k→3.1mA、150Ω→17mA、100Ω→23mA、47Ω→39mA、0Ω→99mA。手順4は「値の決め方」の「LEDの電流制限抵抗」が開いたこと(`led_calc_open`)。テスト `the_pin_led_lesson_ticks_its_four_steps_and_its_numbers_hold`。
- レベル変換のレッスン(29、`LEVELS`)は `level_shift.schjson`(V1=5V、V2=3.3V、V3=5V側の信号 `PULSE(0 5 10u 20n 20n 40u 100u)`、R1=100Ω 出力抵抗、R2=1k+R3=2k の分圧→D33、BSS138 Q1(G=V33、D=H、S=L)、R4=10k で H→5V、R5=10k で L→3.3V、生成 `write_level_shift_example`。BSS138 のピン番号は G=1 D=3 S=2)。数値: D33 は 0〜3.23V・立ち上がり瞬時、L は 0〜3.30V・立ち上がり約0.46µs(R5=100k で約4.2µs、1k で約60ns だが Low が0.3Vに上がる)、R3=10k だと D33 が4.5V。テスト `the_level_shift_lesson_ticks_its_three_steps_and_its_numbers_hold`。
- シリアルのレッスン(30、`SERIAL`)は `uart_line.schjson`(V1=文字 'A'=0x41 の UART フレーム `PWL`、9600bps・8N1、100µs から。R1=100Ω、R2=1k+C1=100p のケーブル、受け側 RX。生成 `write_uart_example`)。受け側の読み方は「各ビットの真ん中の電圧を 2.5V と比べる」。数値: 100p→0x41、C1=100n(τ≈110µs)→0x01(6ビット目の1が1.9Vまでしか上がらず0と読む)、R2=100Ω+100n→0x41、47n→0x41(ぎりぎり)。テスト `the_serial_lesson_ticks_its_three_steps_and_the_receiver_misreads_the_slow_cable`。
- データシートのレッスン(31、`DATASHEET`)は `datasheet_diode.schjson`(V1=5V、R1=100Ω の `R_2512`(抵抗自身の定格が焦点を邪魔しないよう大きい形)、D1=1N4148(100V・0.2A・0.5W)、生成 `write_datasheet_example`)。R1 を変えて 42mA(✔)/125mA(定格内だが2倍の余裕に足りず ✖)/185mA(93% 注意)/267mA(134% 超過)。手順1は D1 を選んでいること(`d1_selected_and_measured`)。テスト `the_datasheet_lesson_ticks_its_four_steps_and_the_ratings_are_judged_as_it_says`。
- USB の電気の基本は3つ。(32 `USB_POWER`) `usb_vbus.schjson`(V1=5V、R1=0.5Ω ホストのスイッチ、L1=500nH+R2=0.25Ω ケーブル、VBUS に C1=10µF と負荷 R3=50Ω、生成 `write_usb_vbus_example`): 100mA で VBUS 4.93V、R3=5Ω(0.87A)で 4.35V、R2=1.2Ω+R3=10Ω で 4.27V。**「ゼロ状態から」(`tran_uic`)で差し込みを表す**(レッスン開始時に入る): C1=10µ で突入 5.6A・18µs、100µ で 6.4A・174µs、1µ で 3.7A・VBUS 5.6V に跳ねる。ホストの電流制限は含まない。(33 `USB_SPEED`) `usb_speed.schjson`(V1=3.3V、R1=1.5k=D+プルアップ、R2=100Meg=D−プルアップ(なし)、R3・R4=15k ホストのプルダウン、生成 `write_usb_speed_example`): フルスピードで DP 3.00V、R1/R2 を入れ替えると DM 3.00V、両方なしで 0V。(34 `USB_SIGNAL`) `usb_signal.schjson`(V1 `PULSE(0 3.3 20n 1n 1n 82n 166n`)、R1=40Ω、C1=100p ケーブル、C2=5p ESD、生成 `write_usb_signal_example`): 立ち上がり 10-90% は C2=5p で 9.2ns(規格の約4〜20ns内)、200p で 26ns、500p で 47ns・ビットの真ん中(60ns)でも 2.7V。テスト `the_usb_power_lesson_ticks_its_four_steps_and_its_numbers_hold` ほか2つ。USB のプロトコルは扱わない。
- PWM のレッスン(35、`PWM`)は `pwm_filter.schjson`(V1=Arduino の PWM `PULSE(0 5 0 20n 20n 1.02m 2.04m)`=490Hz・50%、R1=10k、C1=1µ、負荷 R2=1Meg、生成 `write_pwm_example`、レッスン開始時にゼロ状態から `tran_uic`、100ms)。数値: 1µ→平均2.47V・揺れ0.26V・90%到達19ms、100n→揺れ2.3V・0.6ms、10µ→揺れ35mV・217ms(100msでは未到達)、1µ+負荷10k→平均1.25V。テスト `the_pwm_lesson_ticks_its_four_steps_and_its_numbers_hold`。
- LDO のレッスン(36、`supply.rs` の `LDO`)は `ldo_compare.schjson`(V1=5V、U1=AMS1117-3.3(ドロップアウト1.1V・入力15Vまで)、U2=MCP1700-3302(0.2V・6Vまで)、それぞれ 33Ω `R_2512` の負荷と容量、生成 `write_ldo_example`)。数値: 5V→OUT1 3.30V・OUT2 3.27V、4V→2.90V・3.27V、3.3V→2.20V・3.07V、12V→U2 入力超過・U1 発熱の注意(約0.87W)。テスト `the_ldo_lesson_ticks_its_four_steps_and_its_numbers_hold`。
- TL431 のレッスン(37、`supply.rs` の `TL431`、id `tl431_ref`)は `tl431_reference.schjson`(V1=12V、R1=390Ω `R_2512`、U1=TL431(カソード=VOUT、アノード=GND、REF=分圧)、R2=R3=10k、負荷 R4=100k `R_1206`、生成 `write_tl431_example`)。数値: VOUT 5.01V・REF 2.495V・TL431 に17.6mA、R2=15k→6.27V、R4=330→5.01V(TL431 は2.5mA)、R4=100→2.44V に崩れる(R1が出せるのは約18mA)。TL431 を流れる電流は内部の電流源 `U1.Bk` の電流で読む。テスト `the_tl431_lesson_ticks_its_four_steps_and_its_numbers_hold`。
- フライバックのレッスン(38、`micro.rs` の `FLYBACK`)は `flyback_coil.schjson`(V1=12V、コイル L1=100m+R1=100Ω `R_2512`、Q1=2N7000 のローサイド(ピン G=2 D=3 S=1)、ゲート V2 `PULSE(0 5 1m 1u 1u 3m 10m)`、生成 `write_flyback_example`)。ダイオードなし: DRAIN が数千V(モデルは降伏を持たないので**桁は目安**。テストは100V超かどうか)、学習者が足す(アノード=DRAIN、カソード=VCC): 最大 12.86V。判定 `flyback_diode_added`(向きが逆だと通らない)。L1=1H で電流の減りが10ms。テスト `the_flyback_lesson_ticks_its_three_steps_and_the_diode_holds_the_drain`。
- チャタリングのレッスン(39、`DEBOUNCE`)は `button_bounce.schjson`(V1=接点 `PWL`: 1msで閉じ、2.1msまで4回ばたつく、R1=10k プルアップ、C1=1n、生成 `write_bounce_example`、6ms)。IN が 2.5V を下向きに横切る回数 = マイコンが数える押下: C1=1n→4回、10n→4回、47n→2回、100n→1回(約2.5ms、遅れ約1.5ms)、220n→1回(3.3ms)、1µ→0回(6msで3.2V)。テスト `the_debounce_lesson_ticks_its_three_steps_and_the_microcontroller_counts_as_it_says`。
- 温度センサのレッスン(40、`TEMP_SENSORS`)は既存の `temperature_sensors.schjson`(LM35/TMP36 + 100k、NTC_10k_B3950 + R3=10k。RT1)を使う。回路の温度(「DC動作点」の「回路の温度」`temp_c`)を変えて見る。27℃: LM35 0.27V・TMP36 0.77V・NTC 2.39V、100℃: 1.00V・1.50V・0.33V、−20℃: LM35 0.00V(負は出せない)・TMP36 0.30V。NTC の感度(mV/℃): R3=10k で 27℃ 54.7・100℃ 8.6、R3=1k で 27℃ 19.5・100℃ 34.3。R3=1k・100℃ で VNTC 2.06V。テスト `the_temperature_lesson_ticks_its_four_steps_and_the_voltages_are_as_it_says`。
- 光センサのレッスン(41、`LIGHT_SENSORS`)は既存の `light_sensors.schjson`(V1=5V、V2=LDR の光(1V=100lx)、V3=フォトダイオードの光(1V=1mW/cm²)、R1=10k+RL1=LDR_GL5528、R2=22k+D1=BPW34)。光は電圧源の値を書き換えて変える。数値: 暗い(0,0)→VLDR 4.95V・VPD 5.00V、(0.5,1)→1.82V・3.35V、(5,2)→0.63V・1.70V(光2倍で電流2倍)、V3=5→VPD −0.35V(飽和)、R2=4.7k に→約3.2V。テスト `the_light_lesson_ticks_its_four_steps_and_the_voltages_are_as_it_says`。
- 電流センサのレッスン(42、`CURRENT_SENSORS`)は既存の `current_sensors.schjson`(V1=5V、V2=BUS 1V、R1=シャント10m `R_2512`、U1=INA180A2(×50)、U2=ACS712-05B(2.5V+185mV/A)、C1=1n、負荷 R2=2Ω `R_2512`)。数値: (V2=1,R1=10m)→0.50A・VINA 0.249V・VACS 2.592V、V2=0.05→25mA・12mV・2.505V、V2=5→2.49A・1.243V・2.960V(負荷 R2 に「超過」)、V2=5+R1=100m→VINA 4.80V で頭打ち(計算は11.9V)・VACS 2.94V。テスト `the_current_lesson_ticks_its_four_steps_and_the_amplifier_runs_out_of_range`。
- Arduino Mega 2560 互換(シールドなし)は `arduino_mega_usb.schjson`(`arduino_mega_usb.ccad` から。U1=ATmega2560-16AU、U2=CH340G、J1=USB コネクタ、Y1=16MHz+C1/C2、Y2=12MHz+C3/C4(CH340G の水晶)、バイパス(VCC×4・AVCC・AREF・CH340G の VCC/V3 に100n、VBUS に10µ)、リセット R1=10k+C15=100n(DTR)、D13 の LED、ICSP(J2)、ポート別ヘッダ J3〜J13、CH340G のモデム線ヘッダ J14。部品36個・パッド262)。部品は KiCad 公式ライブラリ(CC-BY-SA 4.0)のシンボルとフットプリントを**ピン表と寸法の確認に使い**、自分の形式で書き直したもの(`part-lib/src/tests.rs` の `write_kicad_mega_parts`、`CCAD_KICAD_DIR` に取得したファイルを置く)。USB の D+/D- は CH340G の UD+/UD- へ。**基板は自動配線で通らない**: 標準(CLI `board route`)で未配線47本、ベタ先でも37本、グリッド0.1mm で18本、部品を広げても8〜20本(自動配線は上面と下面だけを使い、内層は使わない)。基板ファイルは同梱しない。

### 総合デモの速さと発振周期(2026-10-19)
`tests/mixed.rs` の `mixed_signal_speed`(過渡 8ms・10µs 刻みの所要時間と点数)と `mixed_signal_oscillator`(555 の発振周期を自前・ngspice・理論 `0.693(R1+2R2)C` で比べる)。どちらも `--ignored`。
- 速さ: 解析の高速化(因数分解の使い回しなど)の前 2.75 秒 → 後 **1.6 秒**(2617 点、棄却 365 回、`cargo test -p app --release`)。同じ回路を ngspice(`reltol=1e-4`)で走らせた時間とほぼ同じ(1.65 秒)。
- 555 の周期: 自前は **1.47 ms**(立ち上がり6回のうち最後の周期。理論 1.455 ms と 1% 以内、最初の周期は起動のぶん 1.92 ms)。素の ngspice 書き出し(`tran 10u 8m`、`uic` つきも)では発振が始まらず `OSC` が 0V のまま(起動の違い)。アプリの検算(`--xcheck … --tran`)では 33 ノード中 9 ノードがズレ(エッジのずれが周期の 5.4%、TH は自前11・ngspice1 とエッジの数が違う)。どちらの周期が正しいかは決めていない。
