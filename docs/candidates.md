# 機能の候補と優先順位

2026-11-09 更新。**まだ残っているものだけ**を書く。実装したものは行ごと消し、詳細は `docs/code-notes/` に残す。着手するときは、ここの該当行を消してから作る(残りがあれば行を小さくして残す)。

## 優先順位の基準

1. 初学者のつまずきを減らすもの(いちばん先)
2. 初学者が育って使い続けるための機能(中級者・上級者向け。画面は折りたたみで隠す)
3. 専門的な機能(対象外のものは最後の節)

調べた相手: Quadcept(国内のクラウド電気CAD)と Altium Designer(機能紹介のページと、その詳細のドキュメント)、そのほか J 節の出典。機能の紹介が中心なので、細部は実装のときに公式の説明を読み直す。

## 優先して進める順

1. U(画面の改善)。紹介ページと README の「今後の展望」でも先頭に置いている。版ごとに少しずつ
2. 評価基板の仕上げ(サーマルビアとルールの警告、スペック表の「実測」欄、組み立てと測定の手順書)。シミュレーションが実物と合うことを示す(`eval-board/`)
3. E1 の残り(USB・ジャック・ブザーなどの形)→ E2 の残り(ねじ柱・コネクタの穴あけ位置)
4. 確認だけの作業: DXF をケースの CAD で開く(基板の DXF の書き出し・読み込み)、KiCad の回路図の回転 90〜270° を実物で確かめる(I1)
5. A2(秋月・DigiKey の型番。店のページで確かめながら少しずつ)、J の残り(J4〜J15 から、使って困った順に)
6. E3 → E4 → E5(STEP の書き出し → マルチボード。長期)、D(デジタルの残り。波形の表示など)
7. M(部品のモデル)。おすすめは M9(記録なしの 33 個をデータシートから)→ M2 の残り。作り直したあとの手順は `docs/model-policy.md` の進み具合

通しの点検(`docs/beginner-walkthrough.md`)は、新しい機能を足すたびに行う。

## C. 基板の機能

| # | 内容 | 規模 | 理由 |
|---|---|---|---|
| C4 | 自動配置で裏面を使う / 必要層数の目安 | 中 | 2026-10-17 に保留。再開するなら、まず同梱サンプルで測る |
| C5 | 角を丸めたパッド(`PadShape::RoundRect`、半径は短い辺に対する割合。KiCad の既定は 25%)。DRC の距離・ガーバー(マクロか領域)・ベタの逃げ・3D・部品フォーム・KiCad の取り込み(今は `part-lib/src/kicad.rs` で `roundrect` を四角にしている)・同梱部品の既定。**仕上げ(`Board.finish`)ではなくパッドの形のデータとして持つ**: 角丸の効き目(すき間が広がる)を使うのは配線と DRC なので、表示・ガーバーのときだけ丸めると、配線と DRC は四角のまま計算して効き目が出ない。仕上げは配線から銅を足す処理で、部品ごとに決まって銅を削る角丸とは性格が違う。仕上げの側は、涙型(`pad_fillet`)と切り戻し(`pad_clip`)を角丸の形に合わせるだけ。手間を減らすには「表面実装の四角いパッドを 25% の角丸にする」ボタン(押した時点でデータを書き換える)と、新しく作る部品の既定を角丸にする。**重さ**: DRC は形のまま式で距離を出す(`drc/geo.rs` の `shape_geo`。角丸=「r だけ縮めた四角までの距離 − r」で点は増えない)、3D は銅を絵として貼るので三角は増えない(光る表示 `view3d/glow.rs` だけ)。ベタの逃げ(`zonefill.rs` の `pad_path`)は四角の 4 点が約 30 点になる(`circle_steps` に合わせる。リード部品の丸いパッドは約 41 点)。エディタの絵は、マルチサンプリングのとき四角が三角 2 つ(`ribbon.rs` の `add_rect`)で、egui の `rect_filled` に角の半径を渡すと描けるが、長円と同じく、まとめたメッシュがパッドごとに切れて重くなる → `add_disc` と同じように四隅を扇にした `add_rounded_rect` を `ribbon.rs` に作り、1つのメッシュに入れ続ける(三角 10〜20。長円もこれで描けば今の切れ目も無くなる)。ついでに、四角いパッドの逃げが今は角のとがった四角で、角ではすき間が √2 倍に広がっている。角を丸めた形にそろえる | 中 | 細かいピッチ(0.4 mm の QFN、0201 以下)や 45° に置いた部品では、四角い角どうしが一番近くなって、発注先の最小間隔を守れないことがある。メタルマスクからのはんだの抜けもよくなる。IPC-7351 の新しい版も角丸を勧めている。0805・リード部品の手はんだでは差は小さい |

## H. 熱の解析(2026-11-12、基板の銅を θ に入れた `heat_copper.rs` のあとに出したもの)

いまの仕組みは `docs/code-notes/sim-core/analyses.md`(selfheat・heat_tran)と `docs/code-notes/pcb-core/heat_copper.md`。おすすめの順は H1 → H2 → H3(H4 と一緒に)。

| # | 内容 | 規模 | 理由 |
|---|---|---|---|
| H1 | 定常の自己発熱(`selfheat.rs`)で半導体も温める。`heat_tran` と同じく `Circuit::at_temperatures` で、ダイオード・BJT・MOSFET を部品ごとの温度にして不動点を回す(電力は `I·V`) | 小 | いまは抵抗だけ温まり、レギュレータのトランジスタや LED の VF の温度のずれが定常で見えない。仕組みは過渡の側にもうある |
| H2 | 温度の上限と定格の下げ方の点検。部品に `tj_max` と下げ始める温度(抵抗は 70 ℃から下げる曲線など)を持たせ、自己発熱の結果で「Tj / 上限 / 余裕」の表と ERC 風の指摘を出す(`ratings.rs`) | 中 | 初学者がいちばん知りたい「この部品は大丈夫?」に直接答える。いまは温度で許容電力を下げる処理も、上限を超えたかの判定も無い |
| H3 | 過渡の熱を多段に。データシートの過渡熱抵抗(Zth)の曲線を Foster 形の 3〜4 段(`zth: [[R, τ], …]`)で部品 JSON に持ち、`heat_tran` で解く | 中 | いまは 1 段(cth と θ)で、短いパルスの温度の山が合わない。MOSFET のスイッチングや突入電流で効く |
| H4 | 過渡の熱で、電力で重みを付けた平均だけでなく、最高温度とその時刻も表と波形に出し、H2 の判定に使う | 小 | 平均は山より低く、危ない瞬間を見落とす |
| H5 | θ をチップ→ケース(θjc)とケース→周囲(θca)に分ける。基板の銅(`heat_copper`)とヒートシンクは θca の側にだけ効かせる | 中 | いまは銅を θ 全体に並列で足している。ヒートシンクを入れる土台にもなる |
| H6 | ヒートシンクと銅の面積の計算(`designcalc.rs` と `CALCS`)。損失・周囲温度・目標の Tj から、要るヒートシンクの θ と、`copper_conductance` を逆に解いた銅の面積を出す | 小 | 「どれだけ銅を広げればよいか」を設計の前に知りたい |
| H7 | **熱の地図と、熱を回路図に反映する。** 基板を薄い板として格子(0.5 mm 程度)で熱伝導を解く: 層ごとに銅か FR4 かで熱の伝わりやすさ(銅は `zonefill` の塗りと配線から)、ビアは層の間の熱の道、表面から空気へ h ≈ 10 W/m²K、熱源は自己発熱の結果の部品の電力をパッドに。約 6 万の未知数の疎な連立方程式を共役勾配で解く(数十〜数百 ms)。<br>**地図**: 基板エディタに温度の色を重ねる(サーマルカメラ風。「目安」と表示する)。発熱する部品どうしが近いときは `keep_apart`(設計の要件)の候補を出す。<br>**反映**: 熱は電力に線形なので、発熱する部品ごとに 1 W を入れて格子を解き、熱抵抗の行列 R(部品 j の 1 W で部品 i が何 K 上がるか)を「回路図に反映」のときに一度だけ作る(N 回の解を並列に)。定常の自己発熱は `ΔT = R·P` で不動点を回す(格子は解き直さない)。過渡(`heat_tran`)には R の逆行列 G を渡す: 対角でない成分が部品どうしの熱結合(`ThermalLink`)、行の和が周囲への θ。点だけに縮めた形なので結合は負にならない。熱容量 `cth` は部品の値のまま。配線の抵抗にも、地図の局所の温度で銅の +0.39 %/K を掛ける(大電流のパターンが温まって電圧降下が増える)。<br>**`heat_copper` の扱い**: 反映した基板があれば格子の値を使い、当てはめの式(NDT3055L の 3 点)は基板が無いときの目安に残す。最初のテストは格子でその 3 点を再現できるか。<br>**限界**: h は ±30 % ほど不確か、部品の本体から空気への熱は θ に含めるしかない、内層と FR4 の厚さ方向は粗い | 大 | 熱の置き方の失敗が目で分かる。部品どうしの熱結合(いまは手で入れる `couple=A:B:K/W` の推測の数字)が基板から自動で出る。H9 で本物のサーマルカメラの画像と並べられる。下の熱起電力の点検の土台にもなる。`pcb-core` に解く部分 400〜600 行、画面・サンプル・説明で同じくらい |
| H8 | 周囲温度を振る解析(例: −20〜85 ℃)を、自己発熱も込みで。温度の最悪ケースとしてまとめる | 小〜中 | M8(モデルの温度の変化)と組むと効く |
| H9 | 実測で合わせる。評価基板で NTC や熱電対の温度を測って `bench_data` で重ね、`heat_copper` の `k`・`n` を NDT3055L の 1 本の曲線だけでなく実測で合わせ直す | 中 | いまの銅の式は 1 つのデータシートの曲線でしか確かめていない。自作測定器・評価基板とつなげられる |

## K. CERN の KiCad 部品ライブラリ (2026-11-12)

CERN が社内の KiCad 部品ライブラリ (1万7千点以上、記号とフットプリント) を 2026-05-07 に CERN-OHL-P-2.0 (寛容型) で公開した (https://gitlab.com/ohwr/cern-kicad-libs 、FabScene の記事で知った)。Altium の元のライブラリを `kicad-cli` で毎晩変換したもの。KiCad の「データベースライブラリ」(SQLite と ODBC)。**3D モデル・データシートは入っていない** (メーカーの権利のため)。SPICE モデルの記述も無い。同梱はせず (重い・出典の表記が要る)、利用者が取ってきたものを読む形にする。

## 熱起電力(ゼーベック電圧)の点検の案(2026-10-30)

違う金属の接点に温度差があると、数 µV〜数十 µV の電圧が出る。ミリオームメーターの 3 mΩ レンジ(フルスケール 35 mV 級、1 count = 10 µV)では、この大きさで読みが動く。自己発熱(`selfheat.rs`)で出る「部品の温度上昇」を使い、検出のパッドや線が、発熱する部品(RS1 など)の近くにないか・左右の温度差が出る置き方でないかを、設計の要件の表で点検する案(測定 `gap` の応用: 発熱部品と検出パッドの距離の下限)。対策の考え方は、電流の向きを反転して平均する(ミリオームメーターは実施済み)、検出の2点を同じ金属・同じ温度にする。

## 対象外にしたもの

初学者から中級者向けの circuitCad には重すぎる、または需要が違うもの。

- リジッドフレックス基板、材料ライブラリ(製造業者ごと)
- 高密度接続(HDI)、ブラインドビア・ベリードビア、バックドリル
- DDR メモリのバス配線、xSignals(高速信号の経路の制約)
- バリアント管理、ActiveBOM(リアルタイムの部品表)。マルチボードは E に移した(3Dビューの改善のあとで検討)
- ODB++ 出力(Quadcept にある。個人の発注では使わない)

## すでに持っているもの(比較の結果)

SPICE シミュレーション(Altium・Quadcept より解析の種類が多い)、押しのけ配線、配線の整理(`reroute.rs`)、パッドへの垂直な出入り(`padentry.rs`)、長さ合わせ、差動ペア、SPICE ネットリストの書き出し、KiCad の部品の取り込み、DFM に近い発注前チェック(`fab.rs`)、購入リスト、CLI と MCP、自動保存と復旧、回路図の図枠。
