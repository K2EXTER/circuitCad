## 優先順位の基準

1. 初学者のつまずきを減らすもの(いちばん先)
2. 初学者が育って使い続けるための機能(中級者・上級者向け。画面は折りたたみで隠す)
3. 専門的な機能(対象外のものは最後の節)

調べた相手: Quadcept(国内のクラウド電気CAD)と Altium Designer(機能紹介のページと、その詳細のドキュメント)、そのほか J 節の出典。機能の紹介が中心なので、細部は実装のときに公式の説明を読み直す。

## N. 設計の点検と道具(2026-11-16)

初めて基板を作る人の失敗を、作る前に減らす設計向けの道具。設計の画面(ERC・解析・実機作業の窓)の側に置く。コードに無いことは語で探して確かめた(電源の予算表・SCPI・回路図の自動整形)。おすすめの順は N4。

| # | 内容 | 規模 | 理由 |
|---|---|---|---|
| N4 | **計測器と直接つなぐ**: SCPI(USB・LAN の計測器の命令)と、シリアルで値を送る DMM(自作の測定器を含む)から値を直接読み、実測の重ね表示(`bench_data.rs`)とスペック表の「実測」に入れる。計測器の操作(レンジ・トリガ)は最小限にし、読むだけから始める。L2(CSV の読み込み)の次の段、W6(実機で確かめる流れ)の土台 | 中 | 測った値を手で写さずに、予測と並べられる。自作の測定器のプロジェクト(Ladder Lab)でもすぐ使える |
| N5 | **熱起電力(ゼーベック電圧)の点検**(2026-10-30 の案): 違う金属の接点に温度差があると、数 µV〜数十 µV の電圧が出る。ミリオームメーターの 3 mΩ レンジ(フルスケール 35 mV 級、1 count = 10 µV)では、この大きさで読みが動く。自己発熱(`selfheat.rs`)で出る「部品の温度上昇」を使い、検出のパッドや線が、発熱する部品(RS1 など)の近くにないか・左右の温度差が出る置き方でないかを、設計の要件の表で点検する案(測定 `gap` の応用: 発熱部品と検出パッドの距離の下限)。対策の考え方は、電流の向きを反転して平均する(ミリオームメーターは実施済み)、検出の2点を同じ金属・同じ温度にする。 | 小〜中 | µV を測る回路(抵抗計・熱電対・精密な増幅器)だけに効く。設計の要件の測定 `gap` はもうある |

## R. RF の解析(2026-11-15)

いま持っているもの: AC 解析・ノイズ解析・ネットから見たインピーダンス、断面の電界ソルバ(`pcb-core/fieldsolve/`。線幅と層構成から Z0・遅延)、SPICE の `T` 行を無損失の LC のはしごにしたもの(`spice_flat.rs` の `transmission_line`)。ここから、高周波の回路(フィルタ・整合・小さな増幅器)を「周波数ごとの反射と通過」で見られるようにする。おすすめの順は R1 → R2 → R4 → R3。

| # | 内容 | 規模 | 理由 |
|---|---|---|---|
| R1 | **S パラメータ解析**: 回路図にポート(番号・基準インピーダンス、既定 50 Ω)を置き、AC 解析から S11・S21(2 ポートなら S12・S22 も)を出す。dB と位相、リターンロス・VSWR・挿入損失・群遅延。グラフは波形表示に S の表示を足す。新しい解析の手順(`sim-core/sparam.rs` + 画面 + `ANALYSIS_SECTIONS` + サンプル)どおり | 中 | 高周波のフィルタ・整合回路は、電圧ではなく「どれだけ跳ね返り、どれだけ通るか」で評価する。AC 解析の上に作れる |
| R2 | **スミスチャートと整合の計算**: S11 を Smith 図に描く(周波数の印・カーソルで Z を読む)。`designcalc.rs` に L 型・π 型の整合回路の計算(負荷 Z と周波数から L・C の値と、E 系列に丸めた値)を足し、`CALCS` に並べる | 小〜中 | 整合回路は初めての人がいちばん迷う所。図と計算がそろうと、値を変えたときの動きが見える |
| R3 | **Touchstone(.s1p / .s2p)の読み込みと書き出し**: メーカーが配る S パラメータのファイルを部品のモデルにして、AC 解析と S パラメータ解析で使う(周波数の表を補間)。過渡解析では使えない(対象外と明示する)。解析の結果も .s2p に書き出す | 中 | RF 部品(フィルタ・バラン・チップアンテナ・増幅器の IC)は、SPICE モデルではなく S パラメータで配られることが多い |
| R4 | **損失のある伝送線路の素子**: RLGC(線路の単位長あたりの抵抗・インダクタンス・コンダクタンス・容量)に、表皮効果(R が √f で増える)と誘電損失(tanδ)を入れる。AC と S パラメータ解析では式のまま、過渡では今の LC のはしごに損失を足す。基板の配線の RLGC は電界ソルバ(L・C)と層構成の銅の厚さ・tanδ から出す | 中〜大 | 今の線路は損失が無く、長い配線や GHz の減衰が出ない。下の S2 の土台にもなる |
| R5 | **増幅器の評価**: 2 ポートの S から最大有能利得と安定係数(K・μ)を、ノイズ解析から雑音指数(NF)を出す。小さな RF 増幅器のサンプル | 小〜中 | 増幅器が発振しないか(安定)と、どれだけ雑音を足すかは、RF の増幅器で最初に確かめること |
| R6 | **部品の高周波の振る舞い**: チップ部品の寄生(コンデンサの ESL・自己共振、抵抗の並列容量、パッドの容量)を同梱部品のモデルに入れ、AC で自己共振が見えるようにする(データシートの値か、メーカーの S パラメータで確かめたものだけ) | 中 | 数百 MHz からは、100 nF のコンデンサがコイルとして働く。初学者が驚く所なので、サンプルで見せる |

## S. 高速デジタルの解析(シグナルインテグリティ、2026-11-15)

いま持っているもの: 配線の長さの上限・ビア数・差動ペアと等長(蛇行)・インピーダンスの目標(電界ソルバ)・「シミュレーションに反映」(配線の抵抗と結合を回路図に)。足りないのは、配線を**伝送線路として**波形で確かめること。初学者のマイコン基板でも、速いクロック・SPI・USB で反射やリンギングが出るので、「どの配線が長すぎるか」から入る。おすすめの順は S2 → S5 → S3 → S4 (S1 の伝送線路として扱う長さの点検は `pcb-core/tline.rs`)。

| # | 内容 | 規模 | 理由 |
|---|---|---|---|
| S2 | **反射のシミュレーションと終端の計算**: 基板の配線を、長さ・幅・層から(R4 の)線路の素子にして「シミュレーションに反映」に入れる(今は抵抗と結合だけ)。ドライバ(出力抵抗・立ち上がり)→ 線路 → 受け(入力容量)の過渡で、オーバーシュート・アンダーシュート・リンギング・しきい値を横切る時刻を `measure` で出す。終端(直列・並列・テブナン・RC)の値を `designcalc.rs` で計算し、付ける前と後を並べる。サンプル: 長いクロックの配線に 33 Ω の直列終端 | 中〜大 | 「なぜダンピング抵抗を入れるのか」を波形で見せられる。既存の過渡解析と測定の上に作れる |
| S3 | **IBIS モデルの読み込み**: IC のメーカーが配るドライバ・レシーバの I-V と V-t の表(.ibs)を部品のピンのモデルにして、S2 のドライバ・受けに使う(ピンのパッケージの R・L・C も) | 中〜大 | 実在のマイコンの出力の速さで反射を見るには、ほとんどの場合 IBIS しか手に入らない |

## F. FPGA まわりの設計と解析(2026-11-15)

目標は、自作の高度な測定器(速い ADC をつないだオシロスコープ・ロジックアナライザ・周波数カウンタなど。`bench/` の測定器の先)を circuitCad だけで設計できること。FPGA の中身の論理(HDL の合成・配置配線)は FPGA メーカーとオープンなツールに任せ、circuitCad は**FPGA の外側**(ピン・電源・コンフィグ・基板・速い I/O の信号とタイミング)と、その間のつなぎを受け持つ。最初の対象は、オープンなツールチェーン(yosys・nextpnr)で使えて手はんだできるパッケージもある Lattice iCE40 を考えている(パッケージとピンはデータシートで確かめてから)。おすすめの順は F1 → F3 → F2 → F4 → F6 → F5 → F7。

| # | 内容 | 規模 | 理由 |
|---|---|---|---|
| F1 | **ピンの割り当てと制約ファイル**: FPGA の部品に、ピンごとのバンク・I/O の種類(汎用・クロック入力・差動の P/N・設定用・電源)を持たせる(ピンの表はメーカーの表から取り込む。`part_form/pin_import` の延長)。回路図のネット名から制約ファイル(iCE40 の .pcf、ほかに Xilinx の .xdc・Intel の .qsf・Lattice の .lpf)を書き出し、逆に読み込んで回路図とのずれを指摘する | 中 | ピンの割り当ての食い違いは、FPGA の基板でいちばん多い失敗。回路図と制約ファイルが 1 つの正しい表から出れば起きない |
| F2 | **ピンの入れ替え(スワップ)**: 基板で配線しやすいように、同じバンク・同じ種類のピンどうしを入れ替え、回路図と制約ファイルに戻す(`backannotate.rs`・`pcb-core/swap.rs` の延長。差動ペアは P/N を組で、クロックはクロック入力のピンだけ) | 中 | BGA や多ピンの QFP は、ピンを入れ替えないと配線が交差して層が増える。入れ替えてよい組を道具が知っていれば安全にできる |
| F3 | **FPGA の ERC**: バンクの I/O 電圧(VCCIO)と、つながる相手の信号の電圧が合っているか、差動ペアが P/N の決まったピンにあるか、使わないピン・設定用ピン(モード・リセット・DONE など)のプルアップ・プルダウン、コンフィグ用の SPI フラッシュと JTAG のつながり。メーカーごとの決まりは部品のデータとして持つ(確かめたものだけ) | 中 | 電圧の合わないバンクや、設定用ピンの処理の忘れは、基板を作ってから動かないと分かる。ERC で先に止める |
| F4 | **電源のレールと立ち上げの順序**: コア・VCCIO(バンクごと)・補助・PLL のレールの一覧と、レールごとの電流(メーカーの電力見積もりの道具の値を入れる)。立ち上げの順序と時間を過渡解析で確かめる(レギュレータの起動の遅れ・パワーグッドの連鎖)。バイパスコンデンサの数と値は S7(PDN)と組む | 中 | FPGA はレールが多く、順序を守らないと起動しない・壊れることがある。今の過渡解析とレギュレータのモデルで見られる |
| F5 | **BGA の引き出し**: 0.8〜1.0 mm ピッチの BGA の、ドッグボーン(パッドから斜めにビア)の自動配置と、内側の列を出すのに要る層数の目安(C4 の層数の目安と組む)。ビアインパッドとブラインドビアは対象外(「対象外にしたもの」の HDI) | 中〜大 | 測定器の速い ADC と FPGA は BGA が多い。引き出しの手作業がいちばん重い |
| F6 | **速い I/O のタイミング**: 速い ADC と FPGA の間の LVDS(源同期のクロックとデータ)で、基板の配線の遅延(長さ × 電界ソルバの遅延)とばらつきから、FPGA の入力遅延の制約(`set_input_delay` の最小・最大)を計算して制約ファイルに書く。データとクロックの長さの差の許容(セットアップ・ホールドの余裕)を、等長の点検(差動ペア・蛇行)の目標にする。波形は S2〜S5(反射・アイパターン・クロストーク) | 中〜大 | オシロスコープの帯域とサンプリングの確かさは、ADC から FPGA までの数 ns のタイミングで決まる。基板の長さとタイミングの制約を手で合わせるのは間違えやすい |
| F7 | **測定器の信号の鎖の見積もり**: クロックのジッタと入力の周波数から ADC の SNR の上限(SNR = −20·log10(2π·f·tj))、ADC の分解能・入力のノイズ・アンチエイリアスのフィルタから実効のビット数(ENOB)とダイナミックレンジ、サンプリングの速さと記録の長さからメモリと転送の速さ。`designcalc.rs` の計算と、`chain` の解析の延長 | 小〜中 | 測定器の仕様(何 MHz まで何ビットで測れるか)を、部品を選ぶ前に数字で決められる |
| F8 | **論理の中身の検算(連携)**: FPGA の中の論理は外部のシミュレータ(Icarus Verilog・Verilator。ライセンスを確かめてから)に任せ、その波形(VCD)を読み込んで、ボードの過渡解析の波形と同じ時間軸に重ねる。小さな論理は、今の論理式のフォーム(`part_form/logic.rs`)とデジタルのエンジンで、FPGA の部品の中に置いて回路と一緒にシミュレーションする | 中 | 基板の配線と FPGA の論理の両方が絡む問題(クロックの位相・リセットの順序)を 1 つの画面で見られる |

対象外: HDL の合成と FPGA の中の配置配線・タイミング解析(メーカーとオープンなツールの仕事)、ビアインパッド・ブラインドビアの BGA、DDR メモリのタイミングの管理。

## W. ファームウェア・FPGA のプログラムとの連携(2026-11-15)

**回路図(と部品のピンの表)をピンの正本にする**。ファームのピン定義と FPGA の制約ファイルはそこから作る生成物にし、食い違いは点検で見つける。生成するのは専用のファイル(例: `board_pins.h`)か目印で囲んだ区画だけで、手で書いた部分は消さない。生成物も git に入れ、差分で変化が見えるようにする。画面のボタンと同じことを `ccad` でもでき、GitHub Actions で「回路図とファームが食い違っていないか」を毎回検査できるようにする。最初は自作の DMM(Arduino Mega / Pico、`bench/`)と iCE40 の .pcf(F1)で使う。おすすめの順は W3 → W6 → W5 (W1・W2・W4 は済み)。

| # | 内容 | 規模 | 理由 |
|---|---|---|---|
| W3 | **ピンの機能の点検**: マイコンの代替機能の表(どのピンが UART の TX・SPI・I²C・ADC・PWM・割り込みになれるか)を部品のデータに持たせ、「このピンは UART の TX にできない」「ADC の入力でないピンにアナログの信号がつながっている」「I²C にプルアップが無い」を指摘する。表はデータシートで確かめたものだけ入れる | 中 | ピンの機能の取り違えは、基板を作り直すことになる失敗。マイコンの表は大きいので、使う部品から少しずつ |
| W5 | **一緒にシミュレーションの残り**: (b) 本物のファーム (AVR) は 2026-11-26 に済み (`crates/avr-sim`、simavr。試作のタブの「本物のマイコンの命令で動かす」、`docs/code-notes/avr-sim.md`)。PWM・`tone` のパルス、シリアルモニタから送る欄、ADC の変換時間 (simavr の不具合を直した) も同じ日に済み。Arduino Mega (ボードの部品・ATmega2560・ボードの横に置く) も同じ日に済み。残り: ③ ATtiny などほかのチップ ⑤ ライブラリ: コアに付いてくるもの (EEPROM・SPI・Wire・SoftwareSerial・割り込み・`tone`) は確かめた。残りは Servo (ダウンロードが要る) と、I²C・SPI の相手の部品のモデル (今は Wire は応答なし、SPI は MISO のレベルだけ) ⑥ (a) ファームの動きを論理式・状態機械で近似する ⑦ FPGA は外部のシミュレータの波形を重ねる (F8) | ③⑤ 小・⑥ 中 | ファームの変更で回路の波形がどう変わるかを、基板を作る前に見る |
| W6 | **実機で確かめる流れ**: 自作の測定器で基板を測り、`bench_data` に入れてスペック表で合否を出す。ファームの変更 → ビルド → 書き込み(W4)→ 測定 → 合否を、`ccad` のスクリプト 1 本で回す | 中 | シミュレーションと実機の両方で、変更のたびに同じ合否を確かめられる。自作の測定器の目的(`bench/`)とつながる |

## 対象外にしたもの

初学者から中級者向けの circuitCad には重すぎる、または需要が違うもの。

- リジッドフレックス基板、材料ライブラリ(製造業者ごと)
- 高密度接続(HDI)、ブラインドビア・ベリードビア、バックドリル
- DDR メモリのバス配線、xSignals(高速信号の経路の制約)
- バリアント管理、ActiveBOM(リアルタイムの部品表)。マルチボードは E に移した(3Dビューの改善のあとで検討)
- 3D-MID (立体の成形品の上の回路)・プリンテッドエレクトロニクス・ワイヤボンディング・部品を内蔵する基板 (Altium にある。2026-11-21 の突き合わせ)
- ワークスペースとクラウドの部品管理・承認の流れ・PLM への公開 (Altium 365。個人と授業の使い方では要らない)
- ODB++ 出力(Quadcept にある。個人の発注では使わない)
- 形状カーネル `solidcore` の組み込み(元の E10)。試したが release の exe が +25 MB・ビルド時間が 2 倍になり、寸法から作る形は外部の SolidCraft で間に合うので見送り(2026-11-15)。コードと記録はブランチ `solidcore-template`(`docs/code-notes/solid-shape.md`)。見直すのは、cargo の feature で配布物から外せるか、solidcore が三角形にする機能を持ったとき
- ASIC の設計(RTL の合成・チップの中の配置配線・シリコンの DRC と LVS・寄生の抽出・GDS の出力)。基板の CAD とは道具も検査も別物で、製造プロセスの SPICE モデル(PDK の BSIM4 など)は今の MOSFET のモデルでは読めない。オープンな PDK と道具(SkyWater SKY130、OpenROAD・Magic・KLayout)がすでにある。FPGA と同じく、中は専用の道具に任せ、circuitCad は外側(作ったチップを測る評価基板)を受け持つ。代わりに、トランジスタで組む論理回路の教材を D 節に置いた(2026-11-15)
